# Plan 30-04 style dispositions

Fourteen bullets in eleven workflow `## Stop conditions` sections gained a trailing
`checkpoint: <id>` tag. **No bullet's sentence was reworded, reordered, split or removed.** The tag
is appended as the bullet's last token and nothing else on the line moved.

**The judgement is written here; the table below is only its coverage.** A row proves that a changed
clause was considered. It proves nothing about whether the consideration was right — that is a named
human reading these rows against the diff.

## What forced the change

Requirement AUTO-01 asks that every human stop be enumerated into a closed, exported checkpoint set
that is DERIVED from the kit rather than hand-listed beside it. Set-literal drift — a hand-maintained
list that rots while every gate over it stays green — is this milestone's founding defect class, and
a roster typed into TypeScript beside a corpus that declares the same stops in prose is that defect
with two declarations instead of one.

`scripts/checkpoints.ts` now walks these sections through the tree's one section locator, collects
the tagged ids, and compares the derived set against the exported roster in BOTH directions. For that
comparison to have anything to compare, the bullets have to carry the tags. That is this diff.

## The corpus amendment this diff rests on

Decision D-01 named two tag corpora: the 17 role `## Hard limits` sections and the 19 workflow
`## Stop conditions` sections. The role sections contain **zero markdown bullets** — they are prose
paragraphs, and `agent-factory/roles/orchestrator.md`'s carries four distinct prohibitions in one
sentence run. D-02's rule, "the trailing backticked token is the last token of the bullet", has no
referent there, and one trailing tag on that paragraph would attach a single id to four prohibitions.

The user amended D-01 at plan 30-04's Task 1 checkpoint: **the tag corpus is the workflow sections
alone, and the role-tier stops come from `SAFETY_FLOORS`**, which D-04 already makes the canonical
floor list. The role paragraphs are therefore untouched by this diff and no row below names one.
Three of the orchestrator paragraph's four prohibitions are covered by the roster anyway — two
through the floor arm, and "never exceed WIP without a written reason" through `exceed_wip_limit`,
tagged at `09-daily-sweep.md`. The role prose loses no coverage; it loses a second declaration.

## Which bullets were tagged, and which were not

Of the 38 bullets in the 19 sections, 3 live in `agent-factory/workflows/05-pr-quality-gate.md`,
which plan 30-05 owns — two plans must not own one file, so those are tagged there and are absent
from this diff. Of the remaining 35, **14 carry a tag and 21 do not**. The rule applied, and approved
by the user before any file was edited:

- **tagged** — the bullet withholds a *permission*: it stops the agent from proceeding with work a
  human or a named owner must authorize, resolve or accept;
- **untagged, invariant** — the bullet's substance is one of the `NON_DIALABLE_INVARIANTS`
  (`no-fabrication`, `refuse-self`, the sanctioned-writer refusal). D-04 records those as
  permanently outside the matrix, and a dialable cell over one of them could be set to `off`, which
  would authorize fabrication. That is the one thing a checkpoint may never do;
- **untagged, routing** — the stop moves work between board columns or hands to another agent role,
  with no human gate and no waivable permission;
- **untagged, capability** — the agent cannot read or act (an unmappable repo, an unreadable config).
  That is an error, not a policy dial.

The 14 tags produce **9 distinct ids**, because an id is global: the same human stop tagged in two
workflows is one roster member with a recorded site count of two.

## Why 31 rows for 14 tagged bullets

The gate segments a **changed line** into clauses and names every clause on it, whichever side of the
diff it fell on. Appending a tag rewrites the line, so each tagged bullet's own untouched sentences
enter the diff alongside the tag. The 31 rows below are 14 tag rows — exactly one per tagged bullet,
which is an independent reconciliation of the tagging list — and 17 rows for sentences that are
**byte-unchanged**, recorded rather than passed over so the omission would have to be deliberate.

Row count is therefore driven by the gate's per-clause matching rule, not by the file count. The
file-level obligation is checked separately and holds: the 11 files named by these rows are exactly
the 11 files this diff edits.
