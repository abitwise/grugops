Wording that differs from the review's suggested fixes, and why:

- **Workflow 06.** The review's single sentence on the hook and the dial counts 26 or more words, over the 25-word bound for a
  descriptive sentence (WP-03). It is split in two: what the hook checks, and the default `off`. The first sentence keeps plan
  41-27's grant clause and changes "binds" to "can bind". The review's "which for this lane means `all`" is left out: neither
  Workflow 06 nor the recipe names the `by` role of the lane's finding, so the text says the default `off` gates no note, which
  holds for every role.
- **The recipe.** The review asks for one clause, "at the default `off` no note is gated". The plan adds it, plus the roles
  `high-severity` gates and a `note.js` sentence, so the recipe holds the detail Workflow 06 leaves out.
- **install/README.md.** The review's example adds "only `propose_note` on a Claude Code plugin install, behind its hook, can".
  That restates a binding with no dial condition, which is CR-01's defect, so it is left out. The hook paragraph at lines 1941-1943
  already says which install loads the hook. The residual id stays out too, because the install guide cites no residual anywhere.
- **The scan (WR-02, no row).** The review suggests splitting with a lookahead at `.`, `;` and `:` and at a spaced dash. The scan
  splits differently: a split at `:` cuts inside a code span such as `context.human_admission: all`, a lookahead on the next
  character misses a sentence that starts in lower case, and a spaced dash also splits prose dashes. It cuts blocks at list
  markers, headings, table rows and blank lines, then splits at every `.`, `;`, `!` or `?` outside a code span. It adds two rules
  the review does not name: R3 for a binding claim that names no install, and R4 for a plugin binding whose block names no dial.
