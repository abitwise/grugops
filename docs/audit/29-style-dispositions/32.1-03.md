## The three frozen rows, and why a row for them already existed

`docs/audit/29-style-dispositions/31-29.md` already carries a row for these three clauses. It binds
none of them, and the reason is worth recording rather than working around: that row packs all three
sentences into ONE `after` cell, and the gate matches a row to a finding by normalizing a single cell
and comparing it to a single clause. A cell holding three sentences normalizes to a string equal to
no clause at all, so a row that reads correctly to a human matched nothing. The three rows written
here carry one clause each. Nothing in `31-29.md` is edited to reach that: a register is a record of
what a plan recorded, and correcting an earlier plan's row would destroy the very trail it exists to
keep.

Their `companion` cells name the per-position price the repository states in two other artifacts —
`T-31-18-01` inside `PROMOTE_ADMITTED_RESIDUALS`, and `governanceRootOf`'s docstring, both in
`scripts/context-io.ts` — and the case that holds the three in agreement,
`31-29 — WR-28` in `scripts/context-io.test.ts`, which reads all three files and fails unless each
one prices each position. Each cell says where its count is DERIVED — by subtraction, in that case's
`forge` helper, which builds the forged root from a chosen subset of the constructions and counts the
operations it performed — rather than restating the number, because a companion cell that restates a
number is a fourth place for that number to drift.

**One honesty note about "same-commit".** The commit that produced these three clauses, `daa5e586`,
SPLIT a single 30-word sentence under WP-03's descriptive bound; it changed word order and moved no
number. The pricing itself — the correction that created the three positions — landed in
`a81ba78d`, the immediately preceding commit of the same plan, `31-29`, which is where
`T-31-18-01`, the docstring and the binding case were all written together. The companion cells say
so. The agreement between the three artifacts held across the split because the case checks it on
every run, and that is the property the companion records.

## The fix that was available and was refused

Four weakenings would each have cleared all 40 findings without a single row being written. The
gate's own remedy text names them, and so does `README.md:112-115`:

1. **narrowing the watched corpus** — these four workflows would stop being watched, and every
   future rewrite of the kit's UAT, context-write, task-claim and compaction instructions would be
   admitted without being looked at;
2. **adding an override tier** — a per-file hatch, which would then require auditing every change
   already admitted under the strict rule to find which ones would have taken it;
3. **moving the recorded base commit forward** — the findings disappear because the evidence for
   them is no longer in the comparison; `00-base.md`'s own body says outright that moving this SHA
   is not a remedy for a red gate;
4. **loosening the clause comparison** — the clauses stop being derived at the granularity that
   found them, which clears these 40 and every future one of the same shape.

A fifth is available only to this plan, because this plan's share contains the frozen rows: **writing
a companion cell that satisfies the length floor without naming a real companion edit.** That is
refused too. The three companion cells below each name an artifact that exists, at a path that
resolves, bound by a case that runs.

**None was taken.** `git diff --exit-code -- docs/audit/29-style-dispositions/00-base.md
agent-factory/ .planning/WINDOWS.md` exits 0 across this plan: the base document is untouched, not
one byte of any watched document was edited, and no ledger row was waived. The only file this plan
adds to the repository's prose is this one.

## What this document does not claim

It does not claim the 40 clauses are well written. Many of them are one sentence of a source line
carrying dozens, which is why 37 of the 40 findings land on six line numbers. It does not claim the
Phase-31 authors would have written the same dispositions; they are reconstructed from the commits,
the decisions and threat ids those commits cite, and the text itself. And it does not claim that the
gate exiting 0 makes any judgement below correct — only that every changed clause is now recorded as
having been considered, which is the whole of what this register was built to prove.
