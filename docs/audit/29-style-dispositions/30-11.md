# Plan 30-11 style dispositions

Red-team surface A, round 2, finding `RA2-6`. `agent-factory/workflows/05-pr-quality-gate.md` gained
one rule where it previously carried an enumeration, and its terminal result became a consequence of
the verdict emission rather than a sibling of it. One bullet in the frozen `## Stop conditions`
section changed with it, because a rule stated in two places and enumerated in a third is the shape
this repository keeps closing.

**The judgement is written here; the table below is only its coverage.** A row proves that a changed
clause was considered. It proves nothing about whether the consideration was right — that is a named
human reading these rows against the diff.

## What forced the change

**An enumeration was one exit code short, and it was enumerated twice.** Step 3 already branches on
three test-integrity exit codes and says of exit `2` — the checker failed to run — that it is *"an
error distinct from a clean fail, recorded as such and never read as a pass."* Step 4 and Step 5 then
each enumerate the human-only failures and name only exit `1`. Exit `2` is not agent-fixable (the
bounded self-fix loop covers lint and UI/E2E only), is excluded from the human-only set in both places
it is written down, and reaches Step 5's terminal mapping with no arm that forces a block. The gate
could therefore publish `READY_FOR_HUMAN_REVIEW` — the recommendation a human acts on — for a run
whose trace-integrity checker never ran.

The fix is not a third enumeration with `2` added to it. It is the rule the enumeration was
approximating: **any test-integrity result other than exit `0` is human-only.** That covers `1`, `2`
and any code the checker gains later, and it cannot fall one short again.

**The only backstop was silent with respect to the terminal result.** `emit-verdict` refuses on
`unknown` and writes nothing — measured, exit `1`, zero files — but Step 5 contemplated that refusal
without ever requiring the terminal result to change, and no machine consumer of the emitter's output
exists anywhere in the tree (grepped). So a green recommendation could be published with no verdict
behind it: a success statement the run did not establish, which is the same shape closed twice in code
in the same round (`A-3`, `A-7`). The terminal result is now a consequence of the emission —
`READY_FOR_HUMAN_REVIEW` only after `emit-verdict` exits `0` — and the failure direction is bounded
exactly as D-11 already bounds the notify tier: an unrecordable pass is not a pass.

**The new freedom, named.** The terminal result now depends on a write succeeding, so an unwritable
context root blocks a genuinely green run. That is the same trade D-11 already made for an
unrecordable lowering, and it is bounded the same way: the result names the write failure rather than
presenting as a test failure, so a human reads "the trace could not be written" and not "the tests
are red".
