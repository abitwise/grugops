# Plan 34-17 style dispositions (phase 34 D-20; WR-07, the installer does not set GRUGOPS_PROJECT_DIR)

Plan 34-17 fixes review finding WR-07. **The clause stated a mechanism no code has.** Workflow 16
said that tier 2 of the governance-root resolution order is "the installer-set
`GRUGOPS_PROJECT_DIR`", and that "the installer sets it, not the agent". No code under `install/`
writes that variable: `git grep -n GRUGOPS_PROJECT_DIR -- install/` prints nothing, and
`install/README.md` never tells the user to set it. On every host other than Claude Code, Pi
included, tier 2 is therefore empty unless a human or the host's launch environment sets the
variable, and tier 3 (the upward walk) decides the `human_admission` dial.

The workflow now says what the code does. `trustedRepoRoot` in `scripts/context-io.ts` reads
`GRUGOPS_PROJECT_DIR` from `process.env` through `TRUSTED_ROOT_ENV_ORDER`, so the variable is honoured
when something sets it. The grugops installer does not set it. Where nothing sets it, the third step
decides. The old sentence also carried a trust claim: the installer, not the agent, names the root.
That claim fell with the mechanism. The replacement states the true trust position: an agent that
runs `scripts/context-io.js` itself builds that process's environment, so it controls the variable
there. That capability is the accepted residual `R-31-15-01` in `TRUSTED_ROOT_RESIDUALS`, which the
workflow already names below the tier list.

The program side changes in the same commit. `TRUSTED_ROOT_TIERS` entry 2, the `TRUSTED_ROOT_ENV_ORDER`
docstring and the `trustedRepoRoot` docstring said "installer-set" or "INSTALLER-SET"; each now says
the same as the workflow. `scripts/context-io.test.ts` asserts the workflow's tier lines equal
`TRUSTED_ROOT_TIERS` in both directions, and that test passes. The resolution order itself does not
change: the same five tiers, in the same order, read the same names.

No changed clause lies in a frozen section (`## Hard limits`, `## Stop conditions`, `## Commit`) or
in a registry-anchored block. Line 32 sits under `## Steps`, line 56 under
`## The governance-root resolution order`, so no row owes a companion edit.

The earlier audit records that quote the old text (`31-27.md` row for line 56, `32.1-03.md` rows for
line 32) are not rewritten. They record what earlier plans changed, and rewriting them would falsify
the audit trail.

clause was considered, not that the consideration was right.
