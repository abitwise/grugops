## The pointer reconciliation, performed rather than assumed (T-29-56)

Three of these six are single-source documents the rest of the kit points at rather than restates.
`16-context-read-write.md` is pointed at by all seventeen roles plus `_role-switch-protocol.md`, and
by `17-task-claim.md` and `18-context-compaction.md`; `18-context-compaction.md` is pointed at by
the same role set. A change to a sentence those pointers **quote** silently turns single-sourcing
into paraphrase, so the quote check ran **before** either file was opened for editing.

**Method.** Two derived scans, both reusing `normalizeSentence()` from `scripts/voice-model.ts` —
the same normalizer `guard_diff_disposition` and `guard_role_clause_uniqueness` use, so a match here
is a match there:

1. **Exact-sentence scan.** Every sentence of six or more normalized words in the target file,
   looked up in an index built from all 18 role files and all 19 workflow files.
2. **Eight-word shingle scan.** Every 8-gram of normalized words in the target file, looked up in
   the same corpus. This catches a *partial* quote that the sentence scan would miss.

**Result — no role file quotes any prose from either workflow.** Every one of the eighteen role
pointers references the workflow by **path**, in the form
``Context I/O: read and write the shared context per `agent-factory/workflows/16-context-read-write.md` — that workflow is the single source; this role references it and does not restate it.``
The only 8-gram shared between a role file and either target is the file path itself. **No role
pointer sentence quotes a sentence this plan changed, so no role pointer needed an edit**, and
`node scripts/check-foundation-guards.js` exits 0 afterwards — the mechanical check that no role
pointer broke.

## Recording conventions, restated rather than left to be noticed

Both are inherited from `29-08.md` and hold here.

1. **The pipe.** `readDispositionRows()` splits a row on `|`, so a cell containing a literal pipe
   fails the seven-column check and the row is **never read**. `15-security-audit.md` quotes
   `` `L1 | L2 | L3` ``; its rows write `/`. `normalizeSentence()` folds every non-alphanumeric to a
   space, so `|` and `/` normalize identically and the clause match is unaffected. `18`'s
   `` `warn | block`-only `` is handled the same way.
2. **Why unchanged text gets a row.** A workflow paragraph is a **single source line**. `git diff
   --unified=0` reports the whole line as touched when any clause on it moves, and the gate derives
   every clause on that line. A share of the rows below are unchanged text on a changed line, each
   marked as such.
