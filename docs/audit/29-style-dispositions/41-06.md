## How these rows were made

The gate was run as `node scripts/check-diff-disposition.js` with no row in this file, and its output was read from a file. Each
finding got one row, and the raw fragment came from the base or the working tree. The other changed role clauses in these two
files carry no safety fact and sit outside `## Hard limits` and `## Stop when`, so the D-30 stand-in admits them, and they owe no
row here.

The removed spawn clause carries the `wip-limit` fact, and the three new sentences sit in `## Hard limits`, so the gate holds them
back from the stand-in. Each of those rows reads `pending (named human):` followed by the agent's comparison. That comparison is
advice. The disposition is the named human's, and it stays pending until the named human reads the row against the diff.

The README rows sit in the block claim C-28-033 registers, so `docs/audit/28-claim-registry.md` changes in the same commit, and
each row names that file in `companion`. The bullet keeps five lines, so no later anchor shifts. The gate compares whole lines, so
each row pairs one removed line with the added line that carries its words.

The junior item of `## Stop when` in `agent-factory/roles/software-engineer.md` is frozen, so it owes a row. The `## Levels` sentences
sit outside the frozen sections and carry no safety fact, so the D-30 stand-in admits them, and `check-role-rules` holds each
`junior:` fact they carry. The named human's read still covers the first paragraph of `## Levels`, because the stop depends on it.

The gate proves that each changed clause has a row. It does not prove that a disposition is right: a named human reads these
rows against the diff.
