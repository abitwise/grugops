# Plan 41-22 style dispositions (the read route through the seal check)

Plan 41-22 adds `read` to `tools/grugops/note.js`. `node tools/grugops/note.js read <folder>` prints the sealed notes of a
task's current state in full and names on a `skipped` line each file in `notes/` that the seal check did not read as a note.

now both workflows named a read through `context-io.ts`, which no host has. The finding is WR-12 of
`.planning/phases/41-orchestrator-flow-guidance/41-REVIEW.md`, and IN-11 of review `1786df78` changed `install/README.md`. The
decision is D-42 of phase 41, ruled by Olger in 41-UAT.md test 7 on 2026-11-11.

is the gate's removed side at that base and `after` is its added side in the working tree. `—` is an empty side.

## How these rows were made

The gate was run as `node scripts/check-diff-disposition.js` with no row in this file, and its output was read from a file. It gave
16 findings: 4 on line 19 of Workflow 16, 11 on line 27 of Workflow 16 and 1 on line 60 of Workflow 17. A row names a removed
clause in `before` and an added clause in `after`, so one row with both cells covers two findings. The 13 rows below cover the
16 findings. `install/README.md` and `CHANGELOG.md` are not in the watched corpus, so the gate gives no finding for them.

The gate reports every clause of a changed line on both sides. The four rows whose `before` and `after` are the same sentence
record clauses this plan kept word for word on a line it changed. Line 60 of Workflow 17 replaces
`Read the subtask's shared context per WF16 (\`readContext\` / \`render\`) before the work starts (role).`. That clause was added
after the base, so the gate reports only the new clause, as added.

The plan wrote step 1 as four sentences. Two of them were 27 and 22 words against the 20-word bound for a step (WP-02), and
one used the modal `could` in a step (WP-05). `node scripts/check-imperative-lexicon.js` was run on the plan's text and gave
those 3 findings. The rows below record the split text that meets both rules.

Each row reads `pending (named human):` followed by the agent's comparison with `runRead` in `scripts/runnable-ref/note.ts`.
That comparison is advice. The disposition is the named human's, and it stays pending until the named human reads the row
against the diff. No changed line sits in a frozen section: line 19 is in `## Inputs required`, and lines 27 and 60 are in
`## Steps`. So every `companion` cell is `—`.
