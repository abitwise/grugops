# Plan 31-30 style dispositions (D-28's non-establishment answered at the caller)

Every clause plan `31-30` changes in the watched corpus is recorded here, one row per clause, per the
contract in this directory's `README.md`. `scripts/check-diff-disposition.js` reads this directory on
every run and refuses any changed clause that has no row.

## Why this file changed

`D-28` (plan `31-25`) holds the `{0,1,2}` exit-code contract at two decided boundaries — one per file
and one per process — and its own "what D-28 does NOT establish" block names the gap plainly:

> A fault that terminates the process WITHOUT UNWINDING — an out-of-memory kill, or a signal — is
> caught by no `try` and is outside both boundaries.

That is a true statement about the runnable, and the runnable cannot fix it: a process killed by a
signal runs no `catch` clause. The CALLER can. `agent-factory/workflows/05-pr-quality-gate.md` step 3
branched on exit codes `0`, `1` and `2` and said nothing about a run that produced no exit code at
all, so the outcome fell to whatever the reading agent's default happened to be. A check that never
ran, reported as anything other than could-not-run, is the single failure this phase exists to
prevent.

**Measured before the edit, not asserted.** The arm set derived from this workflow's own prose had
cardinality **3** (`0`, `1`, `2`). The runnable was then spawned for real against a 40-spec probe
repository and killed mid-run:

```
$ node scripts/runnable-ref/uat-spec-integrity.js <probe-repo>   # SIGKILL at 80 ms
EXIT CODE: null    SIGNAL: "SIGKILL"    STDOUT: 0 bytes    STDERR: 0 bytes
$ ... same drive with SIGTERM
EXIT CODE: null    SIGNAL: "SIGTERM"    STDOUT: 0 bytes    STDERR: 0 bytes
```

No arm in the derived set matched `null`. After the edit the derived set has cardinality **4**, and
the three pre-existing arms' clause text is **byte-identical** to what it was before — the change is
an addition to a paragraph other gates bind to, never a rewrite of it.

**Scope note.** The rows below cover the four clauses this plan AUTHORED in this file. The remaining
38 clauses this gate reports against `05-pr-quality-gate.md` are the standing `31-05`/`31-06`/`31-08`
debt recorded in `.planning/phases/31-autonomous-manual-testing/deferred-items.md`; they are not
re-claimed here, because a row that vouches for a change its author did not make is the reason those
rows were never written.

**Sentence length.** The added sentences are short because the Phase 29 writing profile bounds a
procedural sentence at 20 words. `npm run check:imperative-lexicon` is green over the edited
paragraph: `0 findings over 19/19` steps elements and `0 findings over 48/48` sentence-form elements.

## What this file does not settle

The gate's fourth arm is prose an agent reads. `scripts/uat-gate-exit-contract.test.ts` binds it in
three ways — the arm set is derived from the prose with a cardinality of four, the runnable's own
reachable return values are derived from its syntax tree and asserted to be a subset of the outcomes
the arms handle, and a seeded mirror removing one arm moves the count by exactly one. What no gate
reaches is whether an agent that reads the arm then behaves that way; that judgement is the same one
this directory's `README.md` already records as human.
