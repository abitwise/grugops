# Phase 43.1 plan 14 style dispositions (the deploy floor names the repository and the deploy path, WR-08 and IN-10)

Plan 43.1-14 closes the page and kit-doc part of review findings WR-08 and IN-10, gap G-43.1-8. Plan 43.1-11 made every
statement of the production hard floor say the environment holds a deploy only when the deploy credentials live solely in
it: a stored deploy secret lives only in its secrets, and an OIDC trust policy accepts only tokens whose subject names it.
That condition had two gaps. Its OIDC part named only the environment, so a trust policy that accepted that environment
from any repository met it (WR-08). It had no job part, so a deploy that no job referencing the environment runs, such as a
hosting platform's own Git integration or a pull-based GitOps controller, met it and never reached the reviewer (IN-10).
The human chose on 2026-11-20, in UAT test 8 (`.planning/phases/43.1-close-v3-0-p1-debt/43.1-UAT.md`), to fix both in this
phase. Plan 43.1-13 widened the condition at its source (`install/README.md` § 5, the floor model and `docs/GUARANTEES.md`).
This plan carries it to the pages and kit docs that restate the floor: the environment gates a deploy only when every
production deploy runs as a job that references it and the deploy credentials live solely in it, with the OIDC part naming
this repository and that environment.

**The base commit is `e8d7802ccf8ebf428a47703f6001327325e3aea3`**, read from `00-base.md`. This change
does not move it. `before` is the gate's removed side at that base and `after` is its added side in
the working tree. `—` is an empty side.

## How these rows were made

The gate was run as `npm run check:diff-disposition` after Task 1's edits, with no row in this file, and its output was
read from a file. It reported 1 finding: the `- Enforcement:` bullet in `AGENTS.md` on its removed side (line 104 at the
base). The rows that `docs/audit/29-style-dispositions/33.1-08.md`, `43.1-07.md` and `43.1-11.md` wrote for that bullet have
an `after` this plan replaces, so they no longer match anything (CR-04), and the gate reports the base-side clause again.
Those files are left as they are; they record their plans' changes. The row below matches the base-side clause and the new
bullet. The other changed lines in `AGENTS.md`, `agent-factory/README.md` and `docs/concepts.md` are the registered verbatim
of C-28-018, C-28-023, C-28-001 and C-28-060; their companion edit is the registry change in the same commit, which rewrites
each row's verbatim and `mechanism`, and the gate admitted them without a row.

The gate proves that each changed clause has a row. It does not prove that a disposition is right: a
named human reads these rows against the diff.
