## The measurement, before and after

`npm run check:diff-disposition` is a pre-existing FAIL on this tree and has been since `31-31`: it
compares against the recorded base `4d2b8f0` and reports every clause added since then whose plan
left no row. The standing number `31-31` recorded, and `31-32` through `31-41` each re-measured
unmoved, is **78 finding(s) over 39 elements**. Measured here, in order:

```
at the round-9 base (HEAD 71a4009)                78 finding(s) over 39 elements
after this plan's recipe edits, before any rows   78 finding(s) over 39 elements
after the rows below                              78 finding(s) over 39 elements
```

**The number does not move, and the reason is recorded rather than left to be inferred.**
`agent-factory/checklists/browser-uat-recipe.md` is NOT one of the 40 markdown files in the
`LANG-03` watched corpus — that corpus is the 17 roles, the 19 workflows and the public-document
residue, and a checklist is none of those. So the gate owes this plan nothing and would stay green
with this file absent.

**The rows below are written anyway, and that is a deliberate over-disclosure.** `UATX-06`'s whole
content is that the recipe's published claim equals what the checker decides, and this recipe is the
document that claim lives in. A prose change to it that no record names is exactly the shape round 8
found one register over. `31-35` set this precedent for the same file and the same reason; this plan
follows it. The standing 78 is unmoved: the base commit was not moved forward and the clause
comparison was not loosened, because both clear a finding by deleting its evidence.

## What forced the recipe edits

**`WR-37`.** `SURFACE_TRUNCATION_ARMS` is introduced in the module as "Every way the walk can stop
early, DERIVED from the record above rather than re-typed". The derivation is real and its subject
was a hand-authored record, so the arms derived from sentences somebody wrote rather than from the
positions the walk stops at. Deriving the set from the walk's own syntax tree finds NINE positions.
FIVE of them failed open — four the review named and a fifth, the declaration-adding helper's own
catch, that no review named. The recipe carried no published arm list at all, so a reader could not
count causes against the checker's own record. The new bullet publishes the arms BY VALUE, in the
same strict grammar the four ban sets and the input boundary are already read by.

**`IN-19`.** The skipped-directory disclosure fires on essentially every host run, on the stream the
`D-12` contract reserves for could-not-run reasons, and the recipe's measured CONTROL of zero bytes
was taken on a probe tree carrying none of the watched names. The claim is corrected against a REAL
host reading of this repository rather than adjusted by argument.
