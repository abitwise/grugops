# Plan 41-04 style dispositions (the flow guidance in Workflow 17, and the role's last act in Workflow 16)

Plan 41-04 makes `agent-factory/workflows/17-task-claim.md` the one home of the flow guidance, and adds a step to
`agent-factory/workflows/16-context-read-write.md` that tells a spawned role its last act. The human decisions are D-01 to D-30 of
phase 41, made on 2026-11-04 (`.planning/phases/41-orchestrator-flow-guidance/41-CONTEXT.md`). The plan also edits
`agent-factory/config/factory.config.md`, which the gate does not watch, so that file owes no row.

**The base commit is `e8d7802ccf8ebf428a47703f6001327325e3aea3`**, read from `00-base.md`. This plan does not move it. `before`
is the gate's removed side at that base and `after` is its added side in the working tree. `—` is an empty side.

## How these rows were made

The gate was run as `node scripts/check-diff-disposition.js` with no row in this file, and its output was read from a file. A
temporary script outside the repository took each finding, asked `changedClauses` which sides carry the clause, and read the raw
fragment from the base or the working tree. The gate compares whole lines, so a sentence that stayed word for word on an edited
line also owes a row: its `before` and `after` are the same text. A reworded sentence takes two rows, one per side. The file is
regenerated whole after each task, so its line numbers stay true.

The clauses in `## Stop conditions` of Workflow 17 are frozen. Each of those rows carries a filled `companion` cell, and its
disposition reads `pending (named human):` followed by the agent's comparison. That comparison is advice. The disposition is the
named human's, and it stays pending until the named human reads the row against the diff. `## Commit` of Workflow 17 did not
change, so it owes no row.

The gate proves that each changed clause has a row. It does not prove that a disposition is right: a named human reads these
rows against the diff.
