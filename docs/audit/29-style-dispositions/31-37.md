## Why the workflow changed

`WR-36` of `31-REVIEW.md`. `TRUSTED_ROOT_TIERS[0]` said tier 0 is a channel the agent cannot write and
left a reader to infer a channel with a source of its own. On the Claude Code hook path its VALUE is
derived from `CLAUDE_PROJECT_DIR` — the tier-1 AMBIENT name — read inside the frozen PreToolUse
wrapper and promoted under the tier-0 name. What makes the channel trustworthy is that the HOST builds
that subprocess's environment and the wrapper is byte-frozen, not that the name is a second variable.
The tier entry now states that provenance, and this workflow is asserted equal to the tier array in
both directions, so the prose could not have stayed as it was.

`D-38` in `31-CONTEXT.md` carries the decision, including the amendment it makes to `D-29`'s tier-0
sentence.
