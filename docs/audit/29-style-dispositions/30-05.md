# Plan 30-05 style dispositions

Two bullets in `agent-factory/workflows/05-pr-quality-gate.md`'s `## Stop conditions` section gained a
trailing `checkpoint: <id>` tag, and two paragraphs in `## Steps` gained the mechanism they had been
describing without it. **No stop bullet's sentence was reworded, reordered, split or removed.** The tag
is appended as the bullet's last token and nothing else on those two lines moved.

**The judgement is written here; the table below is only its coverage.** A row proves that a changed
clause was considered. It proves nothing about whether the consideration was right — that is a named
human reading these rows against the diff.

## What forced the change

Three things, all of them the same requirement seen from different ends.

**AUTO-04 — the workflow described a mechanism that did not exist.** Step 5 told the agent that the
verdict emitter was exposed by `node scripts/context-io.js`. It was not: the dispatch handled
`validate`, `admit` and `render`, and every caller of the emitter in the tree was a test. The sentence
was false when it was written and had stayed false since. It is corrected here in the same change that
creates the `emit-verdict` verb, so the tree is never green on a claim it cannot support.

**D-15 and D-16 — the test-integrity dial had no point of effect.** `quality.test_integrity` was a
validated config enum that nothing consulted at the moment a green verdict was written. It is now a
required, positional third argument to `emitVerdict`, and anything that is not exactly `clean` — a
recognized non-clean state, a misspelling, a wrong type, an empty string, an absent value — refuses
before a single character of the note is composed. Step 5 now says so, and says what that refusal is
worth: the gate supplies the argument, which is a different tier from a hook reading its own
environment in a separate process. Naming the residual is the difference between a described mechanism
and an overstated guarantee.

**D-19 — the gate run had no banner.** The banner was printed on the hook path only, so a gate run said
nothing about which checkpoints were lowered. Step 3 now prints it as the run's header before any check
output, and requires the header and the terminal result to agree.

## The two tags, and the bullet that stays untagged

Plan 30-04 tagged eleven workflow files and deliberately left this one alone: two plans must not own one
file. It also recorded, before this plan started, exactly what tagging this file would move — and it
moved precisely that:

| quantity | before | after |
|---|---:|---:|
| files carrying tags | 11 | 12 |
| `CHECKPOINT_SITE_COUNTS.exhaust_self_fix_budget` | 4 | 5 |
| roster members | 13 | 14 |
| `RECORDED_TOTAL_SITES` | 14 | 16 |

The self-fix-budget bullet takes `exhaust_self_fix_budget`, an id four other workflows already carry, so
tagging it adds a **site** and not an id. The human-only-failure bullet takes the new id
`accept_human_only_failure`: a UI/E2E visual-baseline acceptance and a test-integrity exit `1` are both
stops that withhold a permission only a named human owner can grant, and neither is a stop any other
tagged bullet already names. The id, its `block` default, its recorded site count and the total were
added to `scripts/checkpoints.ts` in the same commit as the tag, because the two-sided comparison is red
on either half alone.

The third bullet — `SPLIT_REQUIRED` on a ticket too large to land cleanly — stays **untagged**. It is
routing: the ticket goes back for splitting, no human grants anything, and there is no permission a dial
could waive.

## Why 28 rows for 4 changed lines

The gate segments a **changed line** into clauses and names every clause on it, whichever side of the
diff it fell on. Appending a tag rewrites the line, so each tagged bullet's own untouched sentences enter
the diff alongside the tag. Six of the rows below are those byte-unchanged sentences, recorded rather
than passed over so the omission would have to be deliberate. Two are the tags themselves — exactly one
per tagged bullet, which is an independent reconciliation of the tagging list. The remaining twenty are
the new and corrected prose in Steps 3 and 5.
