# Plan 45-16 style dispositions (BR-03, ARCH-02; the reservation holds on every path)

Plan 45-16 keeps a deviation or floor-conflict request reserved for a named human's withdrawal on
every path: filed new, merged into an existing request, or edited after filing (gap G-45-9b, review
finding WR-07). No role file changes, and no program changes.

`agent-factory/workflows/20-upstream-sources.md` (Workflow 20), `## Build requests` step 13: the
first sentence is unchanged. The next three sentences become three new ones. The first merges the
old withdrawal sentence with the old `human:<name>` sentence, so "that human" no longer needs an
antecedent two sentences back. The second keys the reservation on a mark BA/PM does not control
through the request text: a ticket in the request's `## Blocks` that holds a human-stop bullet, which
only a named human's word removes. The third keeps the `## Question` statement as a second mark, now
written by step 3 as well as step 4. The section keeps 13 contiguous steps, and `## Stop conditions`
does not change, so `WORKFLOW_STOP_BULLET_COUNT` stays 59.

`## Build requests` step 3 (Task 2): its three sentences are unchanged, and two are appended. When
the merged observation records a deviation or a floor conflict, BA/PM also says so in `## Question`,
and names that change in the same `edited` line (WR-07, D-09). A merged request then carries the
same mark a new request carries from step 4. After this edit the gate reported 2 more findings and
0 once their rows were written.

`agent-factory/contracts/build-request.md` (the build-request contract), `## Lifecycle`: one bullet
is added after the `edited` bullet. An edit never removes a deviation or floor-conflict statement
from `## Question`, and never removes from `## Blocks` a ticket that holds a human-stop bullet. The
second rule is the planner's addition: without it, BA/PM could edit the held ticket out of
`## Blocks` and then withdraw alone. It fails closed, and the request otherwise stays editable until
answered (refines D-07). The contract is outside the watched corpus, so it needs no row here.

**The base commit is `e8d7802ccf8ebf428a47703f6001327325e3aea3`**, read from `00-base.md`. It is not
moved by this plan. Workflow 20 is new since the base, so each changed clause is an added clause. The
gate reported 3 findings after the Task 1 edit with no row, none of them frozen, and 0 once these
rows were written. The rows were generated from the gate's own clause segmentation, so each `after`
cell is the clause the gate derives. Where a clause rewords an earlier one, the `before` cell gives
the earlier text. The 45-13 rows for the old step 13 sentences now match nothing, which is not a
failure (CR-04).
