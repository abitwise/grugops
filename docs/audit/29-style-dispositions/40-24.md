## How these rows were made

The gate was run as `node scripts/check-diff-disposition.js`, with its output written to a file. A temporary script outside
the repository read each finding from that file: its file, line, side, clause, and its frozen region when it had one. It
grouped the findings by file and clause, and marked a group as both sides when the same clause was also a changed clause on the
other side in `changedClauses` from `scripts/check-diff-disposition.js`, taken against the base in `00-base.md`. It read each
raw fragment from `git show e8d7802:<file>` for the removed side or from the working tree for the added side, split the line the
way `segmentClauses` splits it (sentences at `.`, `?` or `!` followed by whitespace; clauses at a spaced em dash, en dash,
semicolon or colon), and took the fragment whose `normalizeSentence` equals the clause, with any leading list marker dropped.
It would have stopped and written nothing if a fragment was missing, if a fragment held a pipe character, or if a finding named
a file outside `agent-factory/roles/` and `agent-factory/workflows/`.

The procedure ran twice. The first run read the gate's output after the side-aware match (CR-04) alone: 24 findings, 24 rows,
rule cell `CR-04, D-30, human decision 2026-11-03`. The second read the output after the frozen-section hold (CR-03) was added
to it: 292 findings, all role clauses in `## Hard limits` or `## Stop when`, 285 rows, rule cell `CR-03, D-30, human decision
2026-11-03`. The second run's rows follow the first run's in the table below.
