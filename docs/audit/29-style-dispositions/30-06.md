# Plan 30-06 style dispositions

Plan 30-06 retires the `autonomy` configuration scalar (D-05). The scalar was documentary: it graded
`diff | branch | pr` in prose and no mechanism read it. Every shipped surface that named it as a live
mechanism is rewritten here to name the enforced `checkpoints` matrix instead, and the structure
validator now refuses a configuration that still carries the retired key.

**The judgement is written here; the table below is only its coverage.** A row proves that a changed
clause was considered. It proves nothing about whether the consideration was right — that is a named
human reading these rows against the diff.

## What forced the change

**D-05 leaves no coexistence mode.** The scalar is refused when present, so a document that instructs a
reader to set it, or that cites it as the mechanism behind a safety promise, is instructing them into a
configuration the validator rejects. Leaving the prose alone was not an option that preserved anything:
it would have preserved the words while the thing they named stopped existing.

**The substitutions are one-for-one and mechanical.** A configuration-key list gains `checkpoints` where
it had `autonomy`. A sentence that cited `autonomy=pr` as the reason an agent stops at a pull request now
cites `checkpoints.open_pr`, the floor-tier cell whose default is `block` — the same stop, named by the
mechanism that enforces it. A sentence that cited `autonomy=branch` now cites
`checkpoints.commit_to_branch`. No promise is widened, no stop is removed, and no behaviour changes.

**Two rows carry more than a substitution.** `agent-factory/roles/software-engineer.md` had a sentence
that spelled the grade's three values outright; it is replaced rather than patched, because there is no
three-value grade left to rename. `agent-factory/workflows/04-ticket-to-pr.md`'s `## Commit` section is a
frozen structural region, and its row carries the companion reason that freeze demands.

## Why the role rows all read the same

Seventeen role files carry the same `## Reads` bullet with the same configuration-key list. The edit is
identical in all seventeen, so the disposition is identical in all seventeen — and the set was derived
rather than hand-walked: the files were enumerated with the kit's own `listRoles()` and the count of
files edited was asserted against the count that lister returned. Seventeen listed, seventeen edited,
none missed. Writing seventeen rows with one rationale is the honest shape; collapsing them into one row
would be a row that names no file.

## Two anchored public claims moved with their registry rows

`AGENTS.md:16` is registry claim C-28-012 and `agent-factory/README.md`'s zero-config paragraph is
C-28-032. `scripts/check-claim-anchors.js` compares the registry's recorded claim text to the bytes at
its anchor, byte for byte, and is red if either side moves alone. Both the recorded text and the row's
`mechanism` note were updated in the same commit as the document, so the two never disagree.
