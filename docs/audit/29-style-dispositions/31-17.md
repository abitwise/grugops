## Why this file changed

Plan `31-17` closes `WR-19` and `WR-20` from `31-REVIEW.md`, each independently reproduced in
`31-VERIFICATION.md` round 4. Both left the recipe stating something that was not true of the
mechanism, in the two different ways this phase keeps being caught by:

- **The chain-bound residual said the wrong thing about the bound's UNIT.** The sentence the recipe
  quotes verbatim from `UNRESOLVABLE_CALLEE_RESIDUALS` claimed a chain reaching the bound "yields no
  path rather than a truncated one". After D-18 (1) made the resolver recursive, the bound restarted
  on every frame, so a deep chain yielded neither — it exhausted the interpreter's stack and printed
  nothing at all. The sentence now states that the bound is ONE allowance for a whole resolution and
  that the descent into a call link spends a step, which is what the mechanism does.
- **The canonicalisation prose carried no scope caveat at all.** It stated that a rename is
  canonicalised "before the head segment is read, from the import declaration's own literal text",
  with nothing about what happens when the file itself declares that name. The mechanism refused a
  legitimate spec and named a construct absent from it. Two new paragraphs state the declared-name
  rule and, separately, state plainly that it is FILE-SCOPED rather than lexical — a reader must not
  be left to infer block scoping from a rule that does not have it.
- **The exit-code contract did not say what happens to a spec the checker cannot finish.** It is now
  stated as a could-not-run reason for that file, with the consequence for the visited total spelled
  out, because "the exit code is inside the contract" is a different claim from "the exit code is
  inside the contract by decision on every path".

Every sentence in this section of the checklist explains a safety property — what the gate refuses,
what it does not refuse, and what an exit code means — so all of it is written in CLEAR VOICE. The
project's voice discipline reserves the caveman register for text that is not a safety explanation,
and none of the changed clauses qualify.
