# Plan 45-13 style dispositions (ARCH-01, ARCH-02, BR-02, BR-03; the floor stop with no side door)

Plan 45-13 rewrites the floor rule of `agent-factory/workflows/20-upstream-sources.md`
(Workflow 20) so that a floor conflict files its build request before the stop, and every deviation
or floor-conflict ticket keeps a human-stop bullet that only a named human lifts (gaps G-45-1 and
G-45-9). It changes one watched document. `agent-factory/contracts/board.md` gains the human-stop
bullet form under `### Ticket body sections`; the contract is not in the watched corpus, so it needs
no row here.

`## Agents involved`: the named-human bullet adds lifting a human-stop bullet to the human's list
(G-45-9).

`## Upstream architecture`: the given-input sentence and the ADR bullet carry the floor exception
(G-45-9 (c), D-14). The floor paragraph no longer transcribes a floor list. It points at the floor
rows of the `checkpoints` roster in the config reference, names each `SAFETY_FLOORS` id, and names
the §14 gate and the security and NFR gates (human UAT decision 2). A new paragraph and six bullets
order the floor-conflict path: the observation, the BA/PM filing per `## Build requests` steps 1 to
5, both bullets, the Orchestrator's check and stop, the human's decision and the lift (G-45-1,
D-17). The closing line "The floor does not move." is unchanged.

`## Build requests`: step 1 names the kind in the hand-off and confirms the human-stop bullet
afterwards; step 5 gives a deviation or floor-conflict ticket the human-stop bullet, raised by the
observing role (human UAT decision 1).

`## Stop conditions`: the floor bullet is reworded so BA/PM files the request before the stop. It
stays one untagged bullet, so `WORKFLOW_STOP_BULLET_COUNT` stays 58 in `scripts/checkpoints.ts`.

The floor paragraph names the config reference by file name, `factory.config.md`, not by its kit
path. `node scripts/check-kit-refs.js` (Assertion 1, D-08.1) refuses an `agent-factory/config/`
path in a workflow, and its exemption is counted and limited to the config reference itself.

**The base commit is `e8d7802ccf8ebf428a47703f6001327325e3aea3`**, read from `00-base.md`. It is not
moved by this plan. Workflow 20 did not exist at the base, so each changed clause is an added clause.
The gate reported 25 findings in Workflow 20 after the Task 1 edits with no row, 1 of them frozen,
and 0 once these rows were written. The rows were generated from the gate's own clause segmentation,
so each `after` cell is the clause the gate derives. Where a clause rewords an earlier one, the
`before` cell gives the earlier text.
