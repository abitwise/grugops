# Plan 31-09 style dispositions (CR-05 / WR-11)

Every clause plan `31-09` changes in the watched corpus is recorded here, one row per clause, per the
contract in this directory's `README.md`. `scripts/check-diff-disposition.js` reads this directory on
every run and refuses any changed clause that has no row.

## Why these three files changed

Plan `31-09` closes `CR-05` from `31-REVIEW.md`, reproduced live in `31-VERIFICATION.md` round 2:
`appendNote` consulted the admission authority for `artifact-ref` only, so a `finding` carrying a
fabricated `§14-gate#<id>` stamp was written unrefused and rendered into `index.md` as verified
evidence. The fix deletes the kind axis rather than widening it — the writer now consults `admit()`
unconditionally and expresses no opinion about which kinds admission applies to.

Three prose sites described the previous mechanism, and prose naming a route that skips a safety
check is a live defect rather than a documentation lag: the agent most likely to be misled by it is
the one these workflows instruct.

- **Workflow 17 step 4** named `appendNote` as the sanctioned writer and stated the admission for the
  `artifact-ref` kind only, which read as though a `finding`'s stamp were checked there too. It was
  not.
- **Workflow 18 step 4** claimed *"Phase-21 admission still fires on every promoted note"* — false for
  a promoted `finding` under the mechanism as it then stood (`WR-11`). Under the mechanism as it now
  stands the claim is TRUE, which is why the correction states it positively rather than narrowing it.
- **Workflow 18 step 5** described `admit()` as the thing that "re-admits cheaply", which a reader
  could take as the write path performing the re-verify. It does not; the writer performs the
  refusal, and step 5's loop is the bounded repair around it. The two are now distinguished.
- **Workflow 16 step 3's non-Claude-Code degrade sentence** promised the four non-CC CLIs "the
  in-script `admit()` refusal". On the route workflow 17 prescribes that refusal did not exist for a
  `finding`. The sentence now names the scope the writer actually has.

Every rewrite in this plan also had to satisfy `guard_imperative_lexicon`'s `WP-02` 20-word
procedural bound and `WP-08` one-instruction rule, which is why several corrections land as two or
three short sentences rather than one long one. That is a `WP-02`/`WP-08` consequence, recorded here
so the sentence count is not read as emphasis.

## What this file does NOT dispose

`scripts/check-diff-disposition.js` compares against the recorded `00-base.md` base commit, so its
findings include clauses changed by earlier plans. Measured on this tree: **78** undispositioned
clauses existed BEFORE this plan's first prose commit (reproduced against `012364d` on a hermetic
clone), across `agent-factory/workflows/05-pr-quality-gate.md`, `06-uat-pack.md`, `17-task-claim.md`
and `18-context-compaction.md`. Those belong to plans `31-05`, `31-06` and `31-08`, none of which
wrote a disposition file.

They are **not** dispositioned here, and this file must not be read as covering them. Writing rows
for another plan's clauses would put a reason in this register that this plan cannot vouch for, which
is the same defect — a claim broader than what was measured — that `31-09` exists to correct. They
are recorded as a deferred item instead, with the measurement above, so the remainder is a number
rather than a silence.
