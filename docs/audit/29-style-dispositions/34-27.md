# Plan 34-27 style dispositions (phase 34 D-26; G-34-2, the kit route for hosts with no Claude Code adapter)

Plan 34-27 closes the AGENTS.md half of gap G-34-2 (34-UAT.md test 2). After a scripted install the
kit lives in a separate kit home, not in the repository. The last bullet of the `AGENTS.md` "Kit vs
state" rule said the kit root "is resolved by the adapter only", and a host with no Claude Code
adapter (Pi, Copilot, Codex, OpenCode, Gemini) has no adapter, so it stopped under the STOP rule with
no way to reach the Orchestrator. The human decided the route at plan 34-27 Task 1 (D-26, "marker"):
the kit root is the `kitRoot` field of `.grugops/install.json`, which `writeMarker` in
`install/install.ts` records on every install.

The bullet now says, in this order: a Claude Code adapter names the kit root on its `KIT=` line;
then `KIT_ROUTE` (`install/host-tools.ts`), byte for byte; then the minimal copy install (no
`.grugops/install.json`: the kit is this repository's own `agent-factory/`); then the STOP sentence
and the re-run sentence, unchanged. The bullet stays one physical line, so no other claim anchor
moves. Lines 37-39 and the blockquote at line 43 (`C-28-016`, the SC2 sentence that
`scripts/check-kit-refs.ts` pins) are not touched.

**The changed line lies in a registry-anchored block** (`C-28-015`, lines 37-40), so the row owes a
companion edit: `docs/audit/28-claim-registry.md` changes in the same commit. Its verbatim block's
fourth line is the new bullet, and its mechanism now names `KIT_ROUTE`, `writeMarker`'s `kitRoot`,
the doctor's kit-route check (`kitRouteFindings`) and `install/kit-route.test.ts`. The line range
stays 37-40.
