# Plan 30-10 style dispositions

Plan 30-10 is red-team surface B (D-21). It attacks the derived checkpoint set, the collapsed
governance reader, the structure validator, the guarantees render, the freshness gate and the run
banner, and it fixes what it finds. Its own edits are to TypeScript sources and their compiled
artifacts, which the LANG-03 watched corpus does not cover — a clause is a unit of prose and none of
this plan's source edits produce one.

**Three watched clauses are dispositioned here nonetheless, and they are not this plan's edits.** They
are plan 30-09's, and this file exists because round 1 of surface B found the gate red at HEAD over
them. Recording them under this plan's number rather than back-dating them into `30-09.md` keeps the
audit trail honest about WHEN the obligation was discharged, which is the whole point of a trail.

**The judgement is written here; the table below is only its coverage.** A row proves that a changed
clause was considered. It proves nothing about whether the consideration was right — that is a named
human reading these rows against the diff.

## What forced the change, and what the round found

D-17 and D-18 make `docs/GUARANTEES.md` the one place a reader learns which safety claims still hold
on a repository, and AUTO-05 requires the three public entry documents to point at it. Plan 30-09 added
that pointer as one anchored generated line in `README.md`, `AGENTS.md` and `agent-factory/README.md`.
Each of those three files is in the LANG-03 watched corpus, so each added line owed a disposition row,
and none was written.

**The gate was red at HEAD when round 1 began.** Measured: `npm run check:diff-disposition` reported
`3 finding(s) over 39 elements`, one per pointer line, attributed to carrier `b2b7612`
(`feat(30-09): pointer lines and the settings-file residual row`). Plan 30-09's SUMMARY records nine
gates in its verification table and this is not among them — the one gate its change could redden is
the one it did not run. That is recorded as finding **B-4** in
`docs/audit/30-redteam-surface-b.md`, because a companion obligation nobody discharges and nobody
measures is indistinguishable, from the outside, from one that does not exist.

## Why the three rows read the same

The three documents carry the SAME added sentence, differing only in the relative link target
(`docs/GUARANTEES.md` from the repository root, `../docs/GUARANTEES.md` from inside `agent-factory/`).
The edit is identical, so the disposition is identical. Writing three rows with one rationale is the
honest shape; collapsing them into one row would be a row that names no file.

The sentence is a POINTER, not a claim. It states where the guarantees document is and what joins it
to the live matrix; it asserts nothing about what any guarantee says. That is deliberate and it is what
makes the addition safe under D-18: the claim text lives in exactly one generated place, and a document
that merely points at it cannot come to disagree with it.
