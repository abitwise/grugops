# Phase 43.1 plan 11 style dispositions (the deploy floor's condition covers OIDC deploys, WR-04)

Plan 43.1-11 closes the public-page part of review finding WR-04, gap G-43.1-3. Plan 43.1-07 made every statement of the
production hard floor say it holds only when the deploy credentials live solely in the production environment's secrets.
That condition named only a stored secret: a deploy that gets its credential through OIDC, under a trust policy that also
accepts a branch or the whole repository, met it and still bypassed the environment's required reviewer. The human chose on
2026-11-19, in UAT test 3 (`.planning/phases/43.1-close-v3-0-p1-debt/43.1-UAT.md`), to widen the condition. Plan 43.1-10
widened it at its source (`install/README.md` § 5, the floor model, `docs/GUARANTEES.md` and three kit docs). This plan
carries the same three phrases to the pages and workflows that restate the floor: the environment is the hard floor only
when the deploy credentials live solely in it, a stored deploy secret lives only in its secrets, and an OIDC trust policy
accepts only tokens whose subject names it. The same decision folds in Workflow 05 step 3, which named the git host as the
hard floor for deploys with no condition.

**The base commit is `e8d7802ccf8ebf428a47703f6001327325e3aea3`**, read from `00-base.md`. This change
does not move it. `before` is the gate's removed side at that base and `after` is its added side in
the working tree. `—` is an empty side.

## How these rows were made

The gate was run as `npm run check:diff-disposition` after Task 1's edits, with no row in this file, and its output was
read from a file. It reported 1 finding: the `- Enforcement:` bullet in `AGENTS.md` on its removed side (line 104 at the
base). The row that `docs/audit/29-style-dispositions/43.1-07.md` wrote for that bullet has an `after` this plan replaces,
so it no longer matches anything (CR-04), and the gate reports the base-side clause again. That file is left as it is; it
records plan 43.1-07's change. The row below matches the base-side clause and the new bullet. The other changed lines in
`AGENTS.md`, `agent-factory/README.md` and `docs/concepts.md` are the registered verbatim of C-28-018, C-28-023, C-28-001
and C-28-060; their companion edit is the registry change in the same commit, which rewrites each row's verbatim and
`mechanism`, and the gate admitted them without a row.

After Task 3's edits the gate was run the same way, with no Task 3 row in this file. The first run used the plan's
one-sentence wording in both workflows; `node scripts/check-imperative-lexicon.js` then refused it (WP-02 bounds a step's
sentence at 20 words and WP-03 a descriptive sentence at 25), so the condition was split into shorter sentences, each
of the three phrases still on one line, and the gate was run again. That second run reported 33 findings needing a row,
and the rows below answer them.

On `agent-factory/workflows/12-release.md` line 9 it reported 5: the base-side hard-floor sentence on its removed side,
and the four new sentences on their added side. The rows in `43.1-05.md` for the hard-floor sentence have an `after`
this plan replaces, so they match nothing (CR-04). Here the hard-floor sentence has one row whose `before` and `after`
match its two findings, and each of the other three new sentences has one row with an empty `before`. The 6 unchanged
clauses of line 9 still match their empty-`after` rows in `43.1-05.md`.

On `agent-factory/workflows/05-pr-quality-gate.md` line 31 (step 3, unchanged since the base until now) it reported 28:
the three new sentences on their added side, and 25 unchanged clauses of the step on their removed side, which the gate
reports because the line they sit on was rewritten. Each new sentence has one row with an empty `before`, and each
unchanged clause has one row with an empty `after`. Two more findings on that line, both from the first run, are frozen
by the registry arm, because their text equals a registered verbatim clause:
`If a command is unknown, the gate records UNKNOWN - verify rather than faking a pass.` (registered by C-28-059), on both
sides. (The first run's one-sentence wording also equalled the sentence C-28-060 and C-28-072 register, so it was frozen
too; the split sentences do not.) Their companion is the registry change in the same commit: C-28-059, which is measured
against step 3, is re-measured there, and the gate admits the frozen findings without a row. The changed lines in
`docs/dogfood-human-runbook.md` and `CHANGELOG.md` are not in the watched corpus.

The gate proves that each changed clause has a row. It does not prove that a disposition is right: a
named human reads these rows against the diff.
