## How these rows were made

The gate was run as `node scripts/check-diff-disposition.js` with no row in this file, and its output was read from a file. After
the `AGENTS.md` edit it gave 1 finding: `AGENTS.md:32 (added) — no disposition row`, the precedence line. The first row below takes
that finding.

After the protocol edit the gate gave no finding: the role-rule inventory stand-in (D-30) admitted the five new clauses of
`agent-factory/roles/_role-switch-protocol.md` line 18, and its count rose from 956 to 961. The five rows after the first still record
them, because this file records every clause the plan changed; with them in place the rows take the five clauses and the stand-in's
count is back to 956. The line sits under step 2 of `## The 5 steps`, outside `## Hard
limits` and `## Stop when`.

Each row is written as `pending (named human):` followed by the agent's reading of the change. That reading is advice. The
disposition is the named human's, and it stays pending until a named human reads the row against the diff. No changed line sits
in `## Stop conditions`, `## Commit`, `## Hard limits` or `## Stop when`, and the precedence line sits outside every claim anchor's
region (a blank line separates it from the list that follows the C-28-014 anchor), so each `companion` cell is `—`.

The registry's `## Adjudicated as NOT a claim` table gains one row for the precedence line, because it is an imperative to the
agent. `docs/audit/28-claim-registry.md` is not in the watched corpus, so that row draws no finding here.
