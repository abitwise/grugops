# grugops

## What This Is

grugops is a file-based **agent factory** for software delivery: a small kit of markdown — role prompts, workflows, a **shared verified context**, checklists, a config dial, a visible Kanban/Sprint board, a lock-free task queue, and a traceability trail — plus per-tool installers, that drops on top of a coding-agent CLI you already use (Claude Code, Codex CLI, Gemini CLI, OpenCode, GitHub Copilot CLI). One Orchestrator (the "head grug") **decomposes** work across the full software-delivery lifecycle — business analysis → product → system analysis → architecture → engineering → QE/E2E → security/NFR/compliance → UAT → release — into queued subtasks that single-job "grug" agents claim and execute within hard limits, in parallel on Claude Code and sequentially on the other four CLIs, over the same files.

It is lean by default and scales to enterprise governance on a single config flag. It is for solo builders who want just-enough discipline and for regulated teams who need auditable, gated, release-controlled agentic delivery. It is **not** a platform, runtime, database, queue service, or hosted service — the intelligence lives in the host coding agent; grugops only supplies role, guardrail, memory, state, dial, proof, and gates.

## Core Value

A user installs grugops on top of the coding-agent CLI they already run, types `/grug`, and gets a disciplined delivery team — a visible board, a shared context where nothing is written until it is *verified*, and an auditable requirement→code→test→release trail — entirely as readable markdown, with humans always holding merge and deploy. **The role is the intelligence. The workflow is the guardrail. The verified context is the memory. The board is the state. The gate is the backpressure. Humans decide; agents execute.**

The v2.0 differentiator is strict and mechanical: **"verified" means passed the §14 behavior gate**, recorded as an auditable `verified_by` stamp that the writing agent cannot forge or self-set — never a black-box blackboard.

## Most Recent Milestone: v2.0 Decentralized Factory — Shared Verified Context (shipped 2026-07-28)

**Goal:** Re-architect grugops from a centralized Orchestrator + static handoff packets into a *decentralized* multi-agent factory where parallel agents (Claude Code primary) claim work from a queue and build on a **shared, verified, auditable context** that replaces handoffs entirely — targeting higher task success and ~50% lower token cost (per DeLM), while the four non-spawning host CLIs degrade gracefully to a sequential mode over the same shared context.

This is a **major architecture pivot** (hence the v2.0 milestone label; artifact SemVer stays 0.1.0 per D-28). It is grounded in **DeLM — *Decentralized Multi-Agent Systems with Shared Context*** (Mao & Mirhoseini, 2026; arXiv 2606.10662), whose thesis is that a central controller becomes a communication/integration bottleneck as subtasks grow, and whose remedy is three primitives: a **shared verified context** (typed notes read-before-act, written-after-verify), a **task queue** (agents asynchronously claim work), and **parallel agents** that build on one another's verified progress without routing through a central head. grugops extracts the best parts and differentiates on its own ground: the verified context is **auditable and human-gated**, leaning on grugops's existing §14 quality gate + no-fabrication discipline as the verifier.

**Target features (refined into requirements below):**
- **Shared verified context substrate** — typed notes/lessons; read-before-act, write-after-verify; *replaces* the static handoff packets
- **Verify-before-write mechanism** — built on the §14 gate + no-fabrication / `UNKNOWN - verify` discipline (the novelty: auditable, human-gated verified context, not a black-box blackboard)
- **Memory/trajectory compaction** — "compact verified updates," the token-economy win (aligns with caveman = token economy)
- **Task queue + async claim protocol** — atomic writes, duplicate-work/conflict prevention without central locking
- **Parallel agents on Claude Code** — re-introduces sub-agent spawning for the primary target; the other 4 CLIs degrade to sequential over the same context
- **Clean removal of static handoff packets** — rewire every role/workflow to the shared context; honestly retires the waived A3/DOG-02 dual-path handoff-parity concern (the test becomes moot once handoffs are gone)
- **Orchestrator redefinition** — shrinks from sole router/bottleneck to bootstrap/decompose + human-gate holder
- **Hard limits unchanged** — humans hold merge/deploy, enforced mechanically (the prod-deploy hook is untouched)

**Deliberate constraint changes (logged as Key Decisions below):** strict 5-tool capability parity is retired (Claude Code becomes primary; the other four degrade, never break); the prior single-window sequential / no-spawn decision is reversed for Claude Code only. Single-source role text (adapters as thin pointers) and the markdown-only kit ethos are preserved.

**Delivered (all 7 phases, 44 plans, 339 commits, +52,976/−2,775 across 460 files; 2026-06-16 → 2026-07-28):**

Code review caught two field-injection BLOCKERs (provenance forgery, queue-lock DoS), both fixed under TDD before sign-off.

A non-green gate run emits no verdict, so a refused finding degrades honestly to `UNKNOWN - verify`. Workflow 16 is the single-source protocol all roles reference and none restate.
- **Phase 22 — Memory & Trajectory Compaction** (9 plans): two-tier memory + the `context.compaction` dial + the load-bearing-field carve-out. Took 8 rounds and 7 distinct bypasses of one silent-absorb class to close; the fix that held was structural — a single exported frontmatter grammar shared by `parseNote` and `splitNotes` so the two cannot drift.

## Constraints

- **Tech stack**: Markdown for everything except the tooling layer, which is **TypeScript** (ratified 2026-06-13, D-13). The tooling scripts (the single installer, the structure validator, the ASVS generator, the foundation guards, and the prod-deploy hook) are authored in TypeScript, compiled with `tsc` to committed `.js`, and freshness-checked so the committed output cannot drift from its source. A single Node-required `install.ts` (compiled `install.js`) replaces the former dual POSIX/Node installer; **Node 22+ is a hard install prerequisite**. Dev/build deps are `{typescript, vitest}` (plus type-only `@types/node`), dev/CI-only and never shipped to hosts; host machines run the committed `.js` with **zero runtime dependencies installed** (the spirit of the former no-npm-deps rule is preserved). — Why: boring on purpose; the host coding agent is the runtime, and the committed `.js` runs cross-platform — including Windows, where POSIX shell cannot
- **Safety (hard)**: Agents never merge a protected branch and never deploy to production without named human confirmation; prefer enforcing this *mechanically* (e.g. a Claude Code PreToolUse hook) not just by prompt — Why: "humans decide, agents execute" must be more than words; an agent cannot be held accountable
- **Verify-before-write (hard, v2.0)**: Nothing enters the shared context without a real, non-self verification stamp — a §14-gate verdict, a passing test, or a named human. `self`, missing, or self-authored stamps are a structural FAIL. This floor is **un-dialable**; the governance dials add friction above it, never remove it — Why: the shared context replaced handoffs as the sole inter-role memory, so an unverified note is not a bad note, it is corrupted memory that every downstream agent then builds on
- **Structural closure for safety invariants (v2.0, emergent)**: A guard, oracle, or invariant is not closed by a green suite. Closure needs a structural fix (one authority per predicate, no second grammar), plus independent adversarial red-teaming, plus reproduction of the bypass — Why: 13 documented times in v2.0, a fully green suite still admitted a bypass; every heuristic detector that was narrower than the real format made the format the attack surface
- **Single-source**: Role text lives once; per-tool adapters are thin pointers, never copies — Why: avoid drift across five tools
- **Zero-config first**: Every role must honor `factory.config.json` when present and run lean with sensible defaults when absent — Why: don't tax solo users; don't let enterprise users skip a gate
- **Voice discipline**: Caveman voice in every role prompt; clear voice in security findings, compliance, money, and disclaimers — Why: the joke earns trust, it never replaces the explanation or muddies a safety topic
- **Installers**: Idempotent, additive, dry-run-capable, reversible; never overwrite or delete user content — Why: installing must be safe to re-run and undo
- **No fabrication**: Unknown commands are marked `UNKNOWN - verify`; never fake a passing gate, a test result, or a citation — Why: the trace is the proof
- **Minimal AGENTS.md**: Keep the substrate short and high-signal; push detail into the files it points to — Why: long machine-written context files measurably lower agent success and raise cost
- **Brand**: Always lowercase `grugops`; `/grug` command shape; original art only; keep grugbrain.dev attribution and the non-affiliation disclaimer visible — Why: brand consistency + IP safety
