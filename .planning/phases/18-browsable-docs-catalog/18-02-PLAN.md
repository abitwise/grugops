## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gate → temp mirror | The gate `cpSync`s the generator `.js` + the project's own kit source dirs into a `mkdtempSync` temp tree and spawns the generator there. No network, no untrusted input. |
| temp regeneration → byte-compare | `Buffer.equals` of the committed catalog vs the temp regeneration; no write to the real tree. |
| gate → exit code | Exit code is the build signal; a stale or unbuildable catalog fails the build red. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-06 | Tampering / repudiation | fail-open: broken generator reports "fresh" | mitigate | Mirror freshness.ts: a non-zero regen `spawnSync` (or throw) ⇒ print finding + `exit(1)`, NEVER fall through to "fresh" (D-07). Proven by the fail-closed-RED test. |
| T-18-07 | Tampering | gate read/write paths | mitigate | `ROOT = join(import.meta.dirname, "..")`; committed/rebuilt paths are fixed literals; the generator's OUT stays a fixed literal (the gate arranges the temp mirror, never overriding OUT) — no path traversal. |
| T-18-08 | DoS (minor) | temp-dir leak / collision | mitigate | `mkdtempSync(join(tmpdir(), "grugops-catalog-fresh-"))` unique per run + `cleanup()` (`rmSync` recursive+force) before every `process.exit` (success AND failure), mirroring freshness.ts. |
| T-18-09 | DoS (negligible) | oversized/malicious kit file | accept | Inputs are the project's own committed, byte-ceiling-guarded kit files; no external input. Out of proportionate scope. |
