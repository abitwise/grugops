<objective>
Fix the largest Windows failure class at the boundary that publishes it, not at the boundary that
compares it.

Two classes account for 94 of the 198 Windows failures, and RESEARCH establishes they are the same
defect at two registers: a path built with the host separator reaches a published row, a refusal
message or — worst — a dedupe KEY, where it silently fails to collide with the forward-slash key
another derivation supplies. That is why the banned-claim scan derives 118, 119 or 121 documents
against a pin of 120 and why its one named exemption region is found zero times in one case and
twice in another.

D-15 fixes this in the module that emits, and explicitly rejects normalizing in the tests: a
test-side fix leaves host-specific bytes published. RESEARCH Pitfall 3 bounds the same decision from
the other side — a path that is never published is a test-internal comparison and belongs to plan
33-04, not here. This plan writes that partition down so a reviewer can check it.

Purpose: one authority per published path spelling, provable on any host.
Output: a separator-parameterized normalizer applied at each measured publishing boundary, and a
banned-claim scan whose cardinality no longer depends on which separator its parts were spelled with.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host filesystem paths -> published rows, keys and messages | A host-shaped string crosses into an artifact other gates and humans read |
| one derivation's keys -> another derivation's Set | Two independently built key sets must collide or the dedupe silently under- or over-counts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-33-13 | Tampering | the banned-claim dedupe key | high | mitigate | Normalize at key formation so both derivations collide; prove it with a mixed-spelling synthetic part that reds when the normalization is deleted (Task 3). |
| T-33-14 | Repudiation | the exemption-region locator | high | mitigate | Assert the region is located exactly once for a backslash-spelled member; a two-sided miss (zero or twice) is the measured Windows behavior and must be closed in both directions. |
| T-33-15 | Information disclosure | published refusal messages | low | mitigate | Messages render forward slashes only, so a published artifact never carries a host-specific spelling of an operator path. |
| T-33-16 | Tampering | over-application of the normalizer | medium | mitigate | The census partitions published from internal sites and records both counts; an internal comparison site normalized here would be a defect, and the POSIX-host no-op check would not catch it — the written partition is the control. |
| T-33-17 | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed; RESEARCH § Package Legitimacy Audit records zero installs for this phase. |
