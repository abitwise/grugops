PART 2 — EVERY EARLY RETURN OF `arm`, AND THE SUCCESS PATH
================================================================================================

`arm` has four early returns and a success path with a catch. The recorded lesson is that a rule
applied in the arm it was written for is wrong in the arm beside it, and this function is where
that lesson has been paid for twice. Each row drives the loop into one branch and asks whether
the directory's watch record survives it.

  BRANCH                                    | HOW IT IS REACHED                  | RECORD AFTER
  ------------------------------------------+------------------------------------+-------------
  1  no read has resolved a root            | armAll() before any seed           | PRESENT (watch)
     (and the record it wrote says so)      | message                            | "the watch on .grugops/context was not armed:…"
  2  the directory is refused               | a genuine failure, then a refusal  | ABSENT  (was PRESENT (watch))
  3  already armed                          | three armAll() in a row            | ABSENT  (handles: 1)
  4  the directory is not there             | a failure, then the dir removed    | ABSENT  (was PRESENT (watch))
  5  SUCCESS: the handle opens              | a failure, then a clean re-arm     | ABSENT  (was PRESENT (watch))
  6  watch() throws (the catch)             | armFailures on the directory       | PRESENT (watch)

READ THE TABLE AS A RULE: exactly two branches leave a record standing — the one that has no root
to work with, and the one where the watch genuinely failed. Every branch that decides NOT to
watch this directory, for a reason that is not a watch failure, clears it. Before this plan the
containment branch was the one exception, and it was the only one of the four whose comment did
not say what it did with the record.

PART 3 — THE NEIGHBOUR-VARIATION QUESTIONS, ANSWERED
================================================================================================

V1  A refusal whose path is the watched DIRECTORY itself, a CHILD of it, a GRANDCHILD of it.
      the DIRECTORY itself links out  → plans/tickets armed = false  (armed 5)
      a CHILD entry links out         → plans/tickets armed = true  (armed 6)
      a GRANDCHILD entry links out    → queue/claimed armed = true  (armed 6)
      → only the first un-arms. A refusal at or above the watched path condemns it; one below it
        is a finding about an entry.

V2  A refusal arriving while the directory is ALREADY ARMED, and one arriving BEFORE it ever is.
      already armed  → the handle opened earlier is closed = true; armed now = [plans]
      never armed    → handles opened = 1; armed now = [plans]; record = ABSENT
      → the refusal check runs BEFORE the already-armed return, which is the only ordering that
        closes a handle a tree acquired a symlink under.

V3  TWO directories refused in ONE read, one of them an ancestor of the other.
      armed = [.grugops/context, .grugops/queue/claimed, .grugops/queue/done, .grugops/queue/pending]
      → four; neither `plans` nor `plans/tickets`. The two refusals cannot interact: `arm` asks
        the authority about each directory independently, on every tick.

V4  The repository ROOT moving between reads while a refusal is standing.
      armed before the move = [plans] (1 open handle(s))
      after the root moves  = []; every old handle closed = true; records = 0
      → the root change closes every handle and clears every record, because each named a
        directory under a root this loop has stopped reading. The standing refusal is not
        carried across either: it was never state, so there is nothing to carry.

V5  A refusal for a directory that DOES NOT EXIST.
      armed = []; record for plans = ABSENT; handles = 0
      → the containment return fires FIRST and leaves nothing, so an absent-and-refused
        directory is reported exactly as many times as an absent one: zero. The reader is the
        one channel that names the refusal, and it does so once.

V6  A directory whose refusal CLEARS in the same tick in which a NEW watch failure is recorded.
      during the refusal → armed [plans], records 0
      refusal lifts + watch throws → armed [plans], record = PRESENT (watch)
      the record's own sentence: "the watch on plans/tickets failed (ENOSPC: arrives as the re…"
      → the two conditions do not race: the containment return is taken or it is not, and the
        record the catch writes is written after it, about the failure that just happened.

V7  A refusal whose SPELLED path is absolute versus one already repo-relative.
      → THE QUESTION DOES NOT ARISE, and that is the answer rather than a dodge. The loop
        consumes NO path from the reader's error list. It composes `join(root, rel)` from
        `WATCH_DIRS` — the same string it hands `deps.watch` — and asks the authority about
        that. Whether a refusal spelled its path absolutely (`childPath`'s `target`, which is
        `resolve`d) or relatively cannot change the armed set, because no code reads it.
      MEASURED ANYWAY, so the claim is not just an argument: the tickets reader's refusals
        carry absolute `target` paths and the queue reader's `unsafe-task-name` carries its
        STAGE directory; V1's three rows above contain both shapes and the armed set tracks
        the directory in every one of them.

§ 6 — REACHABILITY: WHICH INPUT REACHES EACH BRANCH, FROM WHERE, UNDER WHICH COMMAND
================================================================================================

THE ANCESTOR RULE. There is no separate ancestor branch to reach — that is the point of the shape
chosen. `arm` calls `deps.contained(root, join(root, rel))`; in production that is
`insideRoot(root, dir, "the watched directory")` in `scripts/board-read.ts`, whose first statement is
`realpathSync(target)`. `realpathSync` resolves every component of the path, so the ancestor question
is answered by the same call as the leaf question, inside the module that owns containment. The INPUT
that exercises it is a symlink at any directory ABOVE a watched directory and inside the repository —
`plans`, or `.grugops`, or `.grugops/queue`. Any agent this kit runs can plant one; the threat model
row is T-32-34-03. FROM WHICH CALL SITE: `armAll()` → `arm(entry)` for each of the six `WATCH_DIRS`,
called from `run`'s initial arm and from every poll tick in `start`. UNDER WHICH COMMAND:

    node scripts/board-dashboard.js <root> --watch            (and --json --watch)

with `<root>` a tree in which `plans` is a symlink out of itself. `scripts/board-watch.test.ts`'s
case "un-arms a DESCENDANT of a refused ancestor" plants exactly that and asserts the armed set,
including the PREMISE that the authority never spelled `plans` itself — without which the case would
also pass under a mechanism that never reaches this rule.

THE RECORD DELETE. `arm`'s containment early return, reached when `deps.contained` answers false for
a directory that is currently carrying a `watchErrorsByDir` entry. Two INPUTS in sequence are needed
and neither alone reaches it: first a genuine watch failure (an `fs.watch` throw — ENOSPC or EMFILE
in production, the `GRUGOPS_BOARD_FORCE_WATCH_ERROR` seam or an injected `armFailures` entry in the
suite), then a containment refusal for the SAME directory. FROM WHICH CALL SITE: the same
`armAll()` → `arm(entry)`, on the tick after the symlink appears. UNDER WHICH COMMAND: the same
`--watch` invocation, with the watch failing once and a symlink planted at the watched directory
before the next poll tick. In the suite: `scripts/board-watch.test.ts`, "drops a watch record the
moment the SAME directory becomes refused", which asserts the record is PRESENT first — so it cannot
pass by describing a loop that never had one.

WHY THE BRANCH MATTERS AT ALL, since a refused directory is not watched either way: `emit` merges
`currentWatchErrors()` into the published `readErrors`, so every stderr frame and every `--json`
document carried the record's sentence — "it is closed and will be re-armed on the next poll tick" —
about a re-arm the early return guarantees cannot happen. Under CLAUDE.md's no-fabrication rule that
is a false statement on the trace surface, not noise.
