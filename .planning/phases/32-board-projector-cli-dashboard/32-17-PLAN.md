<objective>
Close the four reader-and-join findings that decide WHAT the snapshot contains, as opposed to what it
says about what it could not read.

Gap mapping for this plan (from `32-REVIEW.md`):

| Finding | What is wrong | Task |
|---------|---------------|------|
| WR-09 | `listDirectoryBounded` slices the raw `readdirSync` order and the callers sort afterwards, so the ORDER is deterministic and the MEMBERSHIP is not: once the bound bites, which entries survive is a function of the filesystem. The comment at the tickets walk says two runs over one directory agree, which is true of the order and false of the set. | Task 1 |
| IN-02 | The queue reader's docblock says it reports every skip, and two of its skips are silent: a claimed task directory with no `claim.md`, and a claim record carrying no `at:` line — the second being the same malformed-record class the `at:`-count rule reports as tampered. | Task 1 |
| WR-08 | Two ticket files claiming one `id`: the second is discarded with no record anywhere, while the status arm and the unplaced arm still iterate the RAW list, so the same duplicate produces two identical conflicts that survive the total order. The contract promises the projector reports every conflict and resolves none. | Task 2 |
| IN-03 | `splitRow` finds the last two spaces of a run, so a wider gap leaves a trailing space on the title, which lands verbatim in the published document — two boards differing only in whitespace produce different `schemaVersion: 1` payloads. | Task 3 |

ways those claims are not true today.
