  enumeration could not have.

§ 3 — THE BOUNDARY, ADJACENCY, EMPTY-INPUT AND ORDERING PROBES, NOW CASES
════════════════════════════════════════════════════════════════════════════════════════════════

  BOUNDARY   `carrierVerdict(n)` is the instrument, and the live tree is judged through it rather
             than by a bare equality. `CARRIER_BOUNDARY_ROWS` drives three real inputs:
               0 carriers  (the eight exempt files alone)   -> "vanished-authority"    RED
               1 carrier   (board-model.ts alone)           -> "exactly-one-authority" the live tree
               2 carriers  (board-model.ts + the control)   -> "second-authority"      RED
             and the case asserts explicitly that neither neighbour reads as one authority — zero
             is a census whose subject vanished, not a satisfied upper bound.

  ADJACENCY  Two readers identical except `^column:` vs `^column[:]` (two spellings `skeleton`
             normalizes to one) -> 3 carriers, listed by name. A duplicate cannot hide behind a
             sibling.

  EMPTY      A zero-file scanned set -> 0 carriers, verdict "vanished-authority". A one-file
             scanned set is asked the same question and answers "exactly-one-authority". The
             pre-existing non-vacuity premise case (glob non-empty, floored against `git ls-files`)
             is unchanged.

  ORDERING   BEFORE: the carrier list came out in the order the scanned set arrived in —
               sorted input   [board-model.ts, dup-1.ts, dup-2.ts]
               shuffled input [dup-2.ts, board-model.ts, dup-1.ts]      identical: false
             AFTER: `censusOver` sorts its rows by name before anything else, so the two runs over
             the same planted tree return the same LIST. The case runs the census forwards and
             reversed and compares, asserts the list equals its own sort, asserts the list has more
             than one member (an ordering probe over one element proves nothing), and asserts
             `SCANNED` is sorted.

  PRECISION  Unchanged and re-stated: every number here is `Array.prototype.length` over an array,
             compared with `toBe` against a small integer. No arithmetic, no rounding, no tie-break
             and no floating-point step occurs in either derivation. (Backstop marker.)
