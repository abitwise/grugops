Fourteen variations, fourteen refusals, fourteen with the write-detection mechanism among them. The
answers worth stating in words:

  * DEPTH COSTS NOTHING (N02, N03). The binding map is built in source order against itself, so a
    binding of a binding of a binding resolves by construction. A rule that COUNTED links would have
    a next link; this one does not count.
  * THE DECLARATION KEYWORD IS NOT PART OF THE RULE (N04, N05). `const`, `let` and `var` are the same
    node kind to this pass, and the measurement says so rather than the reader assuming it.
  * SCOPE IS NOT PART OF THE RULE EITHER (N07, N08). The pass is name-scoped, as the root-level rule
    above it already is, and the imprecision runs toward REFUSAL — the only direction a safety guard
    may be imprecise in.
  * A COMPUTED KEY DOES NOT HIDE THE CAPABILITY (N09, N10). `process["report"]` normalizes to
    `process.report`; `process[["rep","ort"].join("")]` normalizes to `process.[computed]`, which is
    admitted by neither set and is therefore refused. A key this pass cannot read is a key it refuses.
  * PASSING THE ALIAS ON DOES NOT HELP (N11). The refusal already fired at the BINDING, before the
    value travelled anywhere, so where it is called is irrelevant.
  * REASSIGNING TO SOMETHING HARMLESS DOES NOT LAUNDER IT (N12). Two value-writes to one name is an
    unprovable binding, refused by name with the path it would have carried.
  * THE ROUND'S OWN CONTRAST NOW AGREES WITH ITS SIBLING (N13 vs N01). Before the fix these two
    disagreed — the ROOT binding red the mechanism and the MEMBER binding did not, and that
    disagreement WAS the finding. They now produce the same verdict.

§ 5 — REACHABILITY: which call site evaluates these rules, on what input, under which command
-----------------------------------------------------------------------------------------------

A branch nothing reaches is a branch that passes by not running, and this repository added
`check-foundation-guards` because it once shipped a gate invoked by nothing.

Both new rules live inside `analyzeModule` in `scripts/board-readonly.test.ts`, and `analyzeModule` is
called by `analyzeClosure(root, entry)` once per module of the walked closure. `capabilityBindings` is
populated by the `establishBindings` pre-pass, which runs to completion over the module's whole AST
before `collectAcquisitions` is invoked — the ordering matters, because `globalMemberPathOf` reads
that map and `collectAcquisitions` calls `globalMemberPathOf`. `isAdmittedMemberPathPosition` is
evaluated by `collectAcquisitions` arm 3 at every PropertyAccessExpression and ElementAccessExpression
whose maximal path is rooted at a capability-bearing global or at a name carrying one. The INPUT is
the bytes of the committed `.js` files the walker returns for
`jsImportClosure(ROOT, "scripts/board-dashboard.js")` — five modules on the live tree — read with
`readFileSync` and parsed with `ts.createSourceFile`; the mirrors in the discrimination cases are
copies of those same live files with one plant appended. The COMMAND is
`npx vitest run scripts/board-readonly.test.ts`, which is `npm run check:dashboard-readonly`
(`package.json:25`); the file is also in the default suite, so the same code path runs under
`npx vitest run --exclude '**/scripts/e2e/**'`, which CI invokes at `.github/workflows/ci.yml:174`.
Every measurement in this document was produced by running that command against the committed `.js` —
not by calling the predicates directly — so what is recorded here is what a host running the gate
gets.

§ 8 — RESIDUALS, NAMED RATHER THAN IMPLIED
--------------------------------------------

  1. A CAPABILITY HANDED INTO AN OBJECT LITERAL AND REACHED THROUGH A PROPERTY OF IT is not tracked.
     `capabilityBindings` maps NAMES, so `const io = { s: process.report }; io.s.writeReport(p)` is
     seen as far as the object-property-value read of `process.report` — which IS refused by the
     position rule, so the escape does not open — but the path `process.report.writeReport` is not
     censused for it. The refusal holds; the ATTRIBUTION is shorter. Widening the map to object
     properties is a decision with its own converse cost (the shipped `defaultIo()` builds exactly
     such an object out of admitted paths) and is not taken here.
  2. A CAPABILITY RETURNED FROM A FUNCTION AND BOUND AT THE CALL SITE is likewise not tracked as a
     path. The same reasoning applies: the read inside the function is refused at its own position.
  3. THE PASS REMAINS NAME-SCOPED, not binding-scoped — inherited from 32-20 and unchanged. A local
     that shadows a tracked name is treated as the tracked name, which runs toward refusal.
  4. `require()` SPECIFIERS are censused by this guard but not followed by the closure walker — the
     residual 32-31 recorded in its own proof § 4. Unchanged by this plan, restated so it is not lost.
