3. FIVE MUTATIONS, AND WHAT EACH ONE PROVES
═══════════════════════════════════════════════════════════════════════════════════════════════════

Every mutation was applied to `scripts/board-dashboard.ts`, REBUILT, and the emitted
`scripts/board-dashboard.js` READ BACK before the suite was believed. `noEmitOnError` makes a
mutation that does not compile indistinguishable from one that has no effect — the third consecutive
plan in this phase to need that step, and the first run of M1 below was caught by it.

Baseline for every row: `npx vitest run --exclude '**/scripts/e2e/**' scripts/board-dashboard.test.ts`

── M1 — REMOVE THE SCRUB, KEEP THE POST-SERIALIZATION PASS ──────────────────────────────────────

    emitted read-back   :310  io.stdout.write(`${sanitizeCell(JSON.stringify(value))}\n`);
    result              2 failed | 65 passed
    red cases           • yields ZERO control code points from ONE parse — every string VALUE and
                          every KEY, at every depth
                        • removes the code points and NOT the content

    FIRST ATTEMPT WAS CAUGHT BY THE READ-BACK. Removing the call alone left `scrub` unreferenced,
    `tsc` refused with TS6133 and emitted nothing, and the suite came back 67 passed — green over
    the UNMUTATED artifact. The mutation was re-spelled to keep the reference and re-run. A run
    whose emitted artifact is not inspected is a run that can report the wrong answer twice.

── M2a — REMOVE ONLY THE POST-SERIALIZATION PASS, KEEP THE SCRUB ────────────────────────────────

    emitted read-back   :309  io.stdout.write(`${JSON.stringify(scrub(value))}\n`);
    result              67 passed — NOTHING RED

    THIS IS RECORDED BECAUSE IT IS TRUE, NOT BECAUSE IT IS CONVENIENT. The plan expected the
    line-boundary case to red here. It does not, and the reason is worth more than the expected
    result would have been: with `scrub` correct there is nothing left raw in the serialized text
    for this pass to remove, and the newline specifically has a SECOND, independent guarantor that
    is not this module's — `JSON.stringify` escapes U+000A inside every string it writes. The pass
    is REDUNDANT today. It is retained anyway, and M2b/M2c below are what justify retaining it.

── M2b — NARROW `scrub` BY ONE BRANCH (no descent into object values), PASS RETAINED ────────────

── M2c — THE SAME DEFECT WITH THE PASS ALSO REMOVED ─────────────────────────────────────────────

    emitted read-back   :310  io.stdout.write(`${JSON.stringify(value)}\n`);

    what a backstop is: invisible while the thing in front of it works, and the difference between
    a reported defect and a raw control byte on an operator's terminal when it does not.
