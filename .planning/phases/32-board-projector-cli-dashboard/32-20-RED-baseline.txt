WHY EACH ROW IS DANGEROUS, AND WHICH PREDICATE MISSED IT

  P1 node:v8         `writeHeapSnapshot(p)` creates and writes an arbitrary path. No fs symbol is
                     named anywhere, so the symbol intersection is empty; `v8` is not one of the
                     fifteen hand-typed banned names, so the deny-list admits it. ZERO obfuscation.
  P2 node:sqlite     `new DatabaseSync(p)` creates and writes a database file. Same two misses.
  P3 process.report  `process.report.writeReport(p)` writes a JSON report to a path, with NO import
                     ANYWHERE. Module-identity rules cannot see it by construction; it is reached
                     through a global.
  P4 node:vm         `runInNewContext(s)` executes attacker-supplied source. Same two misses as P1.
  P5 assembled id    `process.getBuiltinModule("node:" + "fs")` yields the real node:fs. The
                     namespace rule fires on an identifier bound to a LITERAL specifier, and an
                     assembled string is not one — the residual 32-11 named, F-03 measured, and the
                     verifier re-confirmed.
  P6 dynamic import  `await import("node:v8")` — the dynamic-import arm noted the specifier and
                     refused nothing, because refusal was reserved for fs identities.
  P7 unresolved      `__acquire("node:v8")` — a callee bound to nothing this pass can name. An
                     unprovable identity was silently treated as a safe one.
  P8 un-prefixed     `from "v8"` — the same module as `node:v8` under another spelling.
  P9 shadowed global A local parameter named `process` still reaches the real global at every call
                     site the pass does not resolve; nothing collected the member path at all.

WHAT CLOSES EACH (see 32-20-GREEN-proof.txt for the after side):
  P1 P2 P4 P6 P8 — Task 1, `ALLOWED_BUILTIN_SPECIFIERS` equality (module identity as an allow-list).
  P3 P5 P9       — Task 2, `EXPECTED_GLOBAL_MEMBER_PATHS` (the global member-path census).
  P5 P6 P7       — Task 2, `acquisitions` (one admitted way to acquire a module).
