## The adversarial re-run — the same defect one register down, found and closed

The recorded lesson in this repository is that the fix creates the next bypass, so the verifier's
own reproduction was re-run against the fix with ONE variable moved: the DIRECTORY readable, and one
ticket FILE at mode 000.

    tickets source : ok
    overall        : ok
    readErrors     : [{"source":"tickets","code":"EACCES"}]
    conflicts      : ["row-without-file ABC-101 — no ticket file carries that identifier"]

The defect was intact. `readTicketsSource` pushed the per-file error and left the source `ok`, so
the presence gate — which reads the SOURCE STATE — never fired. Closed by giving `SourceOutcome` a
`partial` arm and settling it in all three directory sources (tickets, queue, context), so the class
is closed rather than the instance. The same probe, re-run:

$ node probe-perfile.mjs   # after the fix
    tickets source : stale
    overall        : stale
    readErrors     : [{"source":"tickets","code":"EACCES"}]
    conflicts      : []

The discrimination is pinned by cases in `scripts/board-read.test.ts`: a REFUSED ticket document and
a TAMPERED claim record both leave their source `ok`, because those bytes were read and declined by
name — the contract's stated behaviour — and degrading a source for a refusal would badge every tree
carrying one malformed ticket and would move the committed golden.
