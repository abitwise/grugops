A1. THE BRANCH COUNT IS DERIVED FROM THE MODULE, NOT RECALLED
-------------------------------------------------------------

`scripts/board-model.ts` is parsed with the TypeScript compiler API — the same instrument
`scripts/validate.test.ts` uses for its reader census — `presenceActual` is located by name, and
every `return` site inside it is expanded into the set of strings it can produce, with each `${...}`
replaced by a hole. Concatenation is a cross product; a conditional is a union; an expression shape
the walk does not recognise THROWS rather than silently leaving the set.

  DERIVED BRANCH COUNT = 6

  [1] "<returns null — not a conflict>"
  [2] "plans/tickets/<>.md exists and declares the identifier <>, so it is joined under that
       identifier and not this one"
  [3] "plans/tickets/<>.md exists and declares the identifier <>, which no admitted document is
       joined under, so it is joined under no identifier"
  [4] "plans/tickets/<>.md exists and declares the identifier <>, which plans/tickets/<>.md
       claimed first, so it is joined under no identifier"
  [5] "plans/tickets/<>.md exists and the reader could not admit it (<>)"
  [6] "no ticket file carries that identifier"

The count is pinned as a NUMBER (`toBe(6)`), not as "greater than zero", so an EMPTY derived set and
a SILENTLY SHORT one both red. A separate `toBeGreaterThan(0)` PREMISE assertion distinguishes
"`presenceActual` was not found / produced nothing readable" from "the count moved".

A4. THE `joinedStem === undefined` BRANCH — WHICH OF THE TWO OUTCOMES WAS MEASURED
-----------------------------------------------------------------------------------

OUTCOME MEASURED: the branch is UNREACHABLE from any tree the reader can read, AND it is still
reachable through the exported `presenceOf`. It was therefore NOT deleted, and BOTH facts are
asserted.

  (i) UNREACHABLE FROM THE READER, measured rather than argued. A tree carrying every population at
      once — a self-declaring document, a contest winner, a contest loser, a lone mismatched
      document, a grammar-refused document, and the degenerate `.md` entry — read with
      `readTicketsSource` and indexed with `ticketPopulations`:

        records=4 unadmitted=2 byStem=4 byId=3
        byStem entries whose declared identifier is absent from byId: 0  []

      The suite asserts that emptiness as a derived invariant over the two maps, with two PREMISE
      guards (a non-trivial `byStem`, and at least one entry whose stem differs from its declared
      identifier) so the property cannot hold vacuously. The message names exactly what would make
      the branch reachable again: filling `byStem` from a second record list, guarding the
      `byId.set` on a condition the `byStem.set` does not share, or deleting from `byId` after the
      loop. Any of those makes the assertion red, and the branch then needs a reader-producible
      input row and a row in `agent-factory/contracts/board.md`'s presence table.

      WHY IT IS STRUCTURAL: `ticketPopulations` fills both maps in ONE loop over the SAME record
      list, so every `byStem` VALUE is some record's `id` and every record's `id` is a `byId` KEY —
      first-wins decides WHICH record a key holds, never WHETHER the key is present.

  (ii) REACHABLE BY DIRECT CONSTRUCTION, so the branch is not dead code. `TicketPopulations` is an
      exported type and `presenceOf` an exported function; a caller handing it
      `byStem {ABC-950 -> ABC-951}` with an empty `byId` reaches the arm and gets the sentence
      quoted in A3. The branch is the total handling of the declared
      `joinedStem: string | undefined` and is kept for that reason. It is NOT deleted on the
      strength of an argument — and it was not kept on the strength of one either: the failed
      attempt to reach it from the reader is written down above.

  CONSEQUENCE FOR THE CONTRACT (Part B): the presence table in
  `agent-factory/contracts/board.md` describes what the READER can produce, so its row count is
  pinned against the READER-PRODUCIBLE branches — the derived count minus the one branch this
  section proves unreachable. That partition is itself asserted (`exactly ONE audited branch is
  unreachable from any tree the reader can read`), so it cannot be widened by hand to make a
  count work out.
