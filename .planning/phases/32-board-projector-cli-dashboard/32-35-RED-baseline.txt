Everything ran on a copy of `scripts/fixtures/board-snapshot/` in the session scratchpad. The

Every code point was built with `String.fromCharCode(...)`, never typed as a literal byte.

| # | Site                                                     | Planted   | Route into the document        |
|---|----------------------------------------------------------|-----------|--------------------------------|
| 1 | `plans/board.md` — a BOARD ROW title                     | U+001B    | board grammar → row title      |
| 2 | `plans/tickets/ABC-101.md` — the TITLE field             | U+009B    | ticket grammar → ticket title  |
| 3 | `plans/board.md` — a COLUMN HEADING name (`In Review`)   | U+0007    | board grammar → column name    |
| 4 | `agent-factory/config/factory.config.json` — a WIP KEY   | U+001B    | dial → `config.wipLimits` KEY  |

TWO DEPARTURES FROM THE PLAN'S ASSUMED PLANT, BOTH MEASURED RATHER THAN ASSUMED:

  • THE PLAN PUTS THE BELL IN THE TICKET TITLE. The ticket grammar REFUSES it. Planting U+0007 in
    `title:` produced exit 0 with the ticket source degraded and this read error instead:

        tickets at <tree>/plans/tickets/ABC-101.md — control-character: line 3 carries a control
        character, which no terminal renders and no human wrote deliberately

    The ticket control class is C0 plus DEL (`agent-factory/contracts/board.md:107-108`), so no C0
    reaches the document by that route at all. The code point that DOES reach it through a ticket is
    one from the upper control range, which that class does not name — so site 2 carries U+009B and
    site 3 carries the bell instead. The plan's three code points are all still in play.

  • THE PLAN NAMES THREE SITES; THIS BASELINE PLANTS FOUR. Without site 4 the "every object KEY at
    every depth" half of the walk is vacuously green — a walk that visits keys and finds none to
    fail on proves nothing about keys. `config.wipLimits` is keyed by COLUMN NAME, which is content,
    and it is the one content-derived KEY the published document has.

    Site 4 is planted as the SIX-CHARACTER JSON ESCAPE inside the config file, not as a raw byte: a
    raw control byte in a JSON string is refused by `JSON.parse` itself
    (`PARSE: Bad control character in string literal in JSON at position 112`), so the dial never
    reads it. The escape is legal JSON, and `JSON.parse` turns it into a real control code point in
    the key — which is precisely the asymmetry this finding is about, one register over.

2. THE `--json` CHANNEL — RAW IS CLEAN, ONE PARSE IS NOT
═══════════════════════════════════════════════════════════════════════════════════════════════════

Command: `node scripts/board-dashboard.js <planted tree> --once --json`, exit 0.

    control code points in the RAW captured bytes .............. 0
    control code points recovered after ONE parse .............. 14
    lines the captured document occupies ....................... 1
    documents the capture parses as ............................ 1

The raw count is zero because the two existing mechanisms are EXACTLY COMPLEMENTARY:
`JSON.stringify` escapes every C0 into the six-character printable form, and the post-serialization
`sanitizeCell` removes what is left raw — which is the C1 range and DEL. Applied in that order, one
of them hides what the other would have removed.

THE WALK'S OWN SCOPE, STATED SO THE NUMBER CAN BE TRUSTED. `JSON.parse` once, then recurse: every
string leaf is inspected, every array index is descended, and for every object the KEY is inspected
before its value is descended. Nothing is decoded a second time. The counting class is
`[U+0000-U+001F, U+007F-U+009F]` — C0, DEL and C1 — spelled independently of the module's own.

U+009B — site 2, the ticket title — is ABSENT from the fourteen. It is not escaped by
`JSON.stringify`, so it reached the serialized text raw, and the post-serialization pass removed it.
That is the other half of the complementarity: the arm that survives one parse is exactly the arm
`JSON.stringify` escapes.

THIS IS THE FINDING, AND THE NUMBER IS THE POINT. The stdout write-site census
(`scripts/board-dashboard.test.ts:1779-1930`) exempts the header from the document chokepoint by
name, and what replaced the chokepoint there is a sanitizer hand-applied per field. A claim kept by
convention has a measurable number of exceptions, and until this line was written nobody had counted
them: six of nine. Two of those six — line 477's stale-badge join and line 456's `result.source` —
carry values that range over closed sets today, so there is no live bypass; the finding is that
nothing derives the claim, which is the same asymmetry this round has now found three times.

WHAT THE 2.15x MEANS. The 350 ms band has to contain a filesystem event, a 250 ms debounce, a
six-source re-read and a write, on whatever machine the shared CI suite step runs on. The
measurements above are an idle darwin box; the band is tight even there, and the file refuses to
skip on any platform by design. A red at this deadline arrives as a TIMEOUT, which prints no
latency — so it cannot say whether the watch was slow, whether the poll answered instead, or whether
the box was loaded. That is what Task 3 changes, and the three numbers above are what the widening
is measured against.
