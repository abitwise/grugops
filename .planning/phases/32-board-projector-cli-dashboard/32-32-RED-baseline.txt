THE CASES THAT RED, BY NAME:

    1. PREMISE: no closure module acquires a module by a route that is not a static literal import
    2. POSITIVE CONTROLS: the four capabilities the closure legitimately uses stay admitted

The PREMISE case — the write-detection mechanism — DID red here, because arm 4 treats any read of a
capability-bearing ROOT identifier outside a member access as an acquisition, and `const __g =
globalThis` is such a read.

    | plant                        | PREMISE case | refused acquisitions | census reds |
    |------------------------------|--------------|----------------------|-------------|
    | § 1, bind a MEMBER of a root | GREEN        | 0                    | 3           |
    | § 4, bind the ROOT           | RED          | 1                    | 0 (+1 ctl)  |

The difference between those two rows is the entire finding. It is not a census miss: the census saw
`process.report` and said so. It is that the POSITION rule stated at the root level (arm 4's
canonical sentence — the one admitted read of a capability-bearing root is as the object of a member
access) was never asked one level down, of a MEMBER path. A baseline recording only the failing half
could not show which arm is missing.
