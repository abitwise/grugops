WHAT THE NUMBERS IN THE PRINTED LINE MEAN
------------------------------------------------------------------------------------------

    board-readonly: mutating fs symbols 57 (stem-matched 60 minus 3 named exclusions) on node 24.12.0

  60  symbols the D-21 write-class stems matched across `node:fs` and `node:fs/promises` on
      THIS runtime. This number is a function of the Node version, not of the dashboard, so
      it is PRINTED and VERSION-LABELLED rather than pinned: CI runs Node 22 and will
      legitimately print a different one, and a pin that reds for that reason is a pin that
      gets loosened until it stops noticing.
   3  named exclusions subtracted: `openAsBlob`, `opendir`, `opendirSync` — all read-only,
      all caught only by sharing the `open` stem. `open` and `openSync` are deliberately NOT
      excluded: their write-ness depends on a flag literal a name-based derivation cannot
      read, so the guard refuses.
  57  the mutating set the closure is intersected against.

The BLOCKING pin is a different number, and it is asserted two-sided rather than printed:

    the dashboard closure's own node:fs symbol set = 6
    ["existsSync", "readFileSync", "readdirSync", "realpathSync", "statSync", "watch"]

Every member is a reader. That set is a function of this repository's code, so no Node
upgrade can move it, and a seventh symbol reds the guard on both the member case and the
count case.
