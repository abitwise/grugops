writer that does not exist. Both are `CLAUDE.md` "No fabrication" violations before they are bugs.

establish, and a recorded RED baseline plus GREEN proof for each.

THE FIX, in the order the bytes travel.

(1) Read raw. `readVerifyReread` reads the file with no encoding argument, producing a `Buffer`.
The agreement test compares `before.size`, `after.size` and the buffer's own `byteLength` — three
numbers that are all counts of bytes on disk, so they are comparable by construction. `mtimeMs`
equality stays exactly as it is; the docblock's measured argument for keeping both halves is
unchanged and must not be edited away.

(2) Decode after agreement, never before. Only once size and mtime agree does the function decode,
using `TextDecoder` constructed with `"utf-8"` and both `fatal: true` and `ignoreBOM: true`.
`fatal: true` is what turns an invalid sequence into a thrown error instead of a silent U+FFFD
substitution. `ignoreBOM: true` is load-bearing and its reason goes in the docblock: `TextDecoder`
strips a leading byte-order mark by default and Node's own utf8 file read does not, so without it
this change would silently alter the first line of any board a Windows editor saved — a behaviour
change nobody asked for, smuggled in under a bug fix. It was measured: zero files in
`scripts/fixtures/` and no `plans/board.md` in this tree carry a BOM today, which is exactly why the
regression would have shipped unnoticed.

the bytes will not become decodable on attempt two, and retrying costs a live screen three reads and
six stats per source per refresh forever — which is the second half of what made this defect
expensive. Do NOT let this throw fall into the outer errno `catch`: that path maps a missing `code`
property onto the literal `unreadable` and would report a decoding failure under a code that says
nothing.

under § Conflicts recording Task 1's gating rule: the projector does not raise a conflict that
