<objective>
TRACER for gap-closure round 3: prove ONE canonical-form cutover end-to-end, against the committed
`.js` that ships, before any other plan in this round expands.

The cutover is the smallest of the four the verifier, the reviewer and the round's own self-review
all independently recommend: **make the derivation's subject a total partition with a refusing third
bucket**. This plan applies it to module specifiers, wires it through both authorities that consume
one, rebuilds the committed twin, and measures the shipped gate command flipping from exit 0 to
exit 1 over a real writer.

Gap mapping (from `32-VERIFICATION.md` frontmatter `gaps:`, truth 4 — DASH-06):

| Gap item | Finding | Task |
|----------|---------|------|
| "The dashboard CANNOT write" is still false, route (a) | A writer imported through an ABSOLUTE-path specifier is in neither `isBareSpecifier`'s set (defined as not-`.` and not-`/`) nor the closure walker's relative set (follows `.` only), so it is neither censused nor walked. `npm run check:dashboard-readonly` exits 0 at 89/89 over a module that creates an arbitrary file. Survives `tsc`, `npm run build` and `check:build-parity` by construction. Independently reproduced by the verifier, by `32-REVIEW.md` WR-01, and by `32-23-ADVERSARIAL-REVIEW.md` F-04. | Tasks 1, 2, 3 |

Purpose: `CLAUDE.md` states the read-only rule as mechanical rather than prose, and D-21 states that
the guard's sets are derived rather than hand-listed. Today the derivation is honest but its SUBJECT
is a syntactic complement — "not `.` and not `/`" on one side, "starts with `.`" on the other — and
the `/` prefix is owned by neither. Three consecutive rounds of this phase have paid for a set
defined by a complement. This plan replaces the complement with a partition and gives it one owner.

Why this plan is FIRST rather than last, against round 2's ordering argument: round 2 ran the guard
plan at wave 6 so it was proved against the closure that ships. That argument is preserved two ways
rather than abandoned — every later plan in this round carries `npm run check:dashboard-readonly` in
its own `<verify>`, so the guard is re-proved on every commit that changes a closure module, and
plan `32-30` re-runs this plan's reproductions against the rebuilt committed `.js` at the end of the
round. Leading with the thinnest end-to-end slice is what tells us, after ONE commit rather than
after six, whether the canonical-form cutover actually holds against the artifact a host runs.

Output: one exported specifier-class authority; a total partition in the walker with a named refusal;
a two-sided specifier-class census in the guard; and a measured exit-code flip on the committed `.js`.

There is no `SPEC.md` for this phase, so there is no `## Edge Coverage` and no `## Prohibitions`
section to satisfy; the probe-report items this plan authors are in `must_haves.truths` above and the
round's full probe-item arithmetic is in `32-30-PLAN.md`.
