<objective>
Close the 5th distinct CMP-02 bypass (MULTI-NOTE THREAD FILE) by making the carve-out READ PATH
recover exactly the per-note set the WRITE PATH emitted. The production raw-thread representation is
a SINGLE `threads/<agent>.md` file (D-08, gitignored) that `writeThread`/`composeThreadNote`
(compactor.ts:517-564) builds by APPENDING each note as a `---…---` fence. But the read path
`readNoteDir` (compactor.ts:160-174) calls `readNoteFields`→`parseNote` ONCE per `.md` file, and
`parseNote`'s non-greedy fence regex (`/^---\n([\s\S]*?)\n---\n?([\s\S]*)$/`, context-io.ts:204)
matches only the FIRST fence — every note after the first is folded into note #1's `body` and is
invisible to BOTH round-5 gates, the byte-equal loop, AND the required-survival set. A §14-gate-
verified finding or an unconditionally-required failed-attempt buried as note #2+ is silently dropped
from the promoted set at exit 0 "carve-out intact".

This is the SAME family as rounds 1–5: a real on-disk byte present in the raw thread, projected or
truncated away by the read path before any survival decision keys on it. Round 6 closes the CLASS,
not the multi-note instance. The durable invariant to express and TEST: the carve-out read path must
recover EXACTLY the per-note set the write path emitted — same note count, same frozen ids, same
verbatim bytes — or fail closed.

The fix is READ-PATH-ONLY (the multi-note file is the intended D-08 representation; do NOT change the
writer), and consists of:
  1. A shared `splitNotes(text)` exported from context-io.ts that splits a multi-fence file into each
     note's VERBATIM byte string, using the SAME fence grammar `parseNote` recognizes — defined ONCE
     and shared (IN-02). A trailing non-blank, non-fence remainder is surfaced as `trailingMalformed`.
  2. `readNoteDir` iterates `splitNotes(fileText).notes`, keys each note by `<file>#<n>`, runs BOTH
     round-5 gates + the byte-equal/required-survival logic PER NOTE, and routes any `trailingMalformed`
     remainder into the existing `NoteDirResult.unparseable` fail-closed channel (WR-01 folds in: a
     fence-then-free-scratch file fails closed). Applied uniformly to raw and promoted sides.
  3. IN-01: export `noteId` from context-io.ts and have `composeThreadNote` reuse it, so a thread
     note's frozen id cannot drift from the promoted-counterpart id format the id-keyed match depends on.

Purpose: CMP-02 / SC2 is the un-cheatable mechanical floor of the body/frontmatter seam. A green unit
suite is necessary but NOT sufficient — proof is RED→GREEN reproduction against the COMMITTED .js, and
a CLASS-level round-trip invariant test, not just one multi-note fixture.
Output: a shared splitNotes + a per-note read path + an id-unified composeThreadNote, byte-fresh
committed .js, and a held-out RED-first multi-note + round-trip test corpus that pins the class, with
captured build+run evidence.

OUT OF SCOPE (deferred to follow-up rounds — do NOT plan or implement these here, so the executor and
verifier see the decision):

- WR-03 (readContext id/filename divergence signal + code/comment disagreement).
- IN-02 broader (unknown-key allowlist / typo-laundering class in validate()).
