<objective>
End the CMP-02 carve-out bypass cycle (ROUND 4) by treating the ROOT CAUSE, not the two named shapes.
The oracle in `scripts/compactor.ts` currently runs TWO enforcement schemes and a duplicated parser:

- a STRONG id-keyed exact-match + byte-equal path for durable notes (`promotedById`, `rawDurable`,
  the field loop at lines 328-346), and
- a WEAK token-keyed survival-only path for failed-attempts (rule 1, lines 181-211), which
  `continue`s past the byte-equal loop entirely (`promotedById` skip at line 247, `rawDurable` skip
  at line 270), plus
- a hand-rolled `readNoteFields` (lines 111-140) that is a near-copy of `context-io.parseNote`.

Every surviving bypass lives in the SEAM between these schemes. Round 4 collapses the seam.

Two independent, mechanically-reproduced bypasses both fail Truth 2 (CMP-02), and round 4 MUST close
BOTH or the cycle migrates to whichever is left open:

- **CR-03 (raw-side id collision):** `promotedById` is collision-guarded (compactor.ts:255), but the
  raw set (`rawDurable`/`rawRecords`, lines 268-283) has NO equivalent guard. Two durable RAW notes
  carrying one forged `id` both `.get(fields.id)` the SAME promoted note, both pass byte-equal (only
  `body` differs — the sanctioned D-01 compression latitude, not checked), so the second's drop is
  invisible → exit 0. This is a VERBATIM 22-04 must-have that was never implemented.
- **CR-01 (failed-attempt provenance exemption):** both `promotedById` (line 247) and `rawDurable`
  (line 270) `continue` on `kind === "failed-attempt"`, so the byte-equal field loop NEVER runs for an
  FA. The ONLY thing checked is rule-1 FA-token survival, so `by`/`at`/`verified_by`/`supersedes` are
  launderable on an FA at exit 0 as long as the FA-token survives — authorship laundering.

The fix is the **ORACLE UNIFICATION** (the user-locked architectural choice, not surgical
point-fixes). Failed-attempts flow through the SAME id-keyed exact-match + byte-equal field loop as
durable notes — FAs are MORE load-bearing (unconditionally required to survive), so they are checked
at least as strictly. Compounding FA-path warnings are closed in the SAME round so CR-01 cannot recur
in a new shape: WR-01 (FA survival keyed on the frozen `id`, not the forgeable body token), WR-02
(fail closed on an unparseable raw `.md`), WR-03 (validate `kind ∈ NOTE_KINDS` for every note),
WR-04 (held-out + GENERALIZED adversarial cases mutating every load-bearing field on a failed-attempt),
IN-01 (the docstring becomes true — affirm it), IN-02 (ONE shared exported frontmatter parser so the
read path cannot drift from the write path).

This is a SAFETY ORACLE. A green unit suite is NECESSARY but NOT SUFFICIENT — rounds 1, 2, and 3 EACH
passed a fully green held-out suite and were EACH still bypassable. The proof of closure is the
RED→GREEN transition of the two named reproductions AND a generalized mutation sweep run against the
COMMITTED `.js`, not merely a passing suite.

Purpose: make CMP-02 genuinely un-cheatable before Phase 23's parallel fan-out makes the token tax —
and the laundering surface — real. Output: a single exported frontmatter parser in `context-io.ts`,
a unified `scripts/compactor.ts` (FA path folded into the durable byte-equal pass + raw-side collision
guard + kind validation + unparseable fail-closed), byte-fresh `compactor.js` + `context-io.js`, and a
`scripts/compactor.test.ts` that pins the bypass CLASS with named reproductions PLUS a generalized
parameterized (field × kind) mutation sweep, all RED-first against the committed pre-fix `.js`.

CMP-01 and CMP-03 are already SATISFIED (plans 22-01 / 22-02) — this plan touches NEITHER and
re-covers NEITHER; it keeps only CMP-02 in scope.
