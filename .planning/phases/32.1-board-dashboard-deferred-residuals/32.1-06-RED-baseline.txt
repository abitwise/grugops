  DECISION, WITH ITS MEASUREMENT. Both are deleted. `scanSource` exists only to feed the
  regular-expression extractor: once the extractor is a real tokenizer the blanking pass has no
  consumer, because a tokenizer decides for itself what is prose. `stripNonCode` is a view over it
  with ZERO call sites — the measurement above, not the assumption A4 warns about — so deleting it
  removes an export nobody reads rather than a contract somebody depends on. The three
  behavioural cases whose prose names it (a specifier written only in a comment, only in a template
  literal, and one written inside a template SUBSTITUTION that must survive) assert properties of
  `moduleSpecifiers`, not of `stripNonCode`; they are KEPT and re-homed onto the tokenizer, because
  the property each one decides is still a property worth deciding. Deleting them would trade a
  false claim for a real hole.


§ 2 — THE THREE FINDINGS, REPRODUCED AGAINST THE PRE-TASK-1 COMMITTED BUILD OUTPUT
-----------------------------------------------------------------------------------

Each case below imports `moduleSpecifiers` from the COMMITTED `scripts/js-import-closure.js` at
06cd9d5a — the artifact the six production consumers actually load — and compares it with a real
`ts.createSourceFile(…, ts.ScriptKind.JS)` parse using `ts.isStringLiteralLike` for the value.

  $ node <the harness described above>

── F-16 / WR-02 — a regex literal carrying an import-shaped string, beside one real import
src      : "const re = /from \"x/; import y from \"./real.js\";\nexport const use = () => re.test(y);"
scanned  : ["x/; import y from :bare"]
ts-parse : ["./real.js"]

  BOTH DIRECTIONS FAIL AT ONCE. The scanner FABRICATES `x/; import y from ` (classified `bare`, so
  `jsImportClosureFacts` skips it silently) and SWALLOWS the real `./real.js`. That is WR-02's
  finding exactly: the walk hands back a closure missing a module, with no throw and no diagnostic.

── F-16 (path-shaped variant) — a regex literal whose interior spells a relative specifier
src      : "const re = /from \"\\.\\/evil\\.js\"/;\nimport y from \"./real.js\";\nexport const use = () => re.test(y);"
scanned  : ["\\.\\/evil\\.js:foreign","./real.js:relative"]
ts-parse : ["./real.js"]

  F-16's own listing: a FOREIGN row manufactured out of a regular-expression interior. `foreign` is
  a hard refusal in `jsImportClosure`, so this shape makes a gate that cannot start — CR-01's exact
  shape, one literal kind over.

── WR-03 — an import specifier carrying an escape sequence
src      : "import a from \"./mod\\u002ejs\";\nexport const use = () => a;"
scanned  : ["./mod\\u002ejs:relative"]
ts-parse : ["./mod.js"]

  The recovery table stored the RAW BYTES between the quotes. `jsImportClosureFacts` then resolves
  `./mod.js` as a path, finds no file, and throws `ImportClosureError` over a module that
  exists.

── F-17 — a dynamic import whose argument is a no-substitution template literal
src      : "export const load = async () => (await import(`./tpl.js`)).name;"
scanned  : []
ts-parse : ["./tpl.js"]

  The specifier pattern list accepts only `["']`, so the edge is invisible. Node resolves and runs
  it (F-17's own listing records `TEMPLATE-DYNAMIC-IMPORT-OK function`). A mirror built from this
  closure is short by exactly `./tpl.js`.

  All four reproductions are RED before Task 1 — three of them in the SILENT direction (a fabricated
  `bare` row is skipped, a swallowed real import is never reported, a missed template edge is never
  reported). § 3 of `32.1-06-GREEN-proof.txt` records the same four cases after the cutover.
