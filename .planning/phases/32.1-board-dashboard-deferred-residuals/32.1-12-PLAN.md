<objective>
Reproduce, then close on one path, the defect the verifier recorded as this phase's single failed
must-have: a C1 code point in a directory entry name survives `childPath`'s segment check, is joined
into a composed path, and is quoted into a published claim-record sentence outside the builder — so
the renderer DELETES it and the sentence names a file that does not exist on the tree.

This plan is the tracer. It drives ONE path all the way through — a claimed-queue directory whose
name carries U+0085, through the read seam, into the `no-at` and `tampered` sentences, out through
the stderr frame and the JSON document — proves it RED first, closes that one path, and files the
mechanically derived work list for the rest.

Per D-07 the remedy is that the sentence SPELLS the byte, never that fewer bytes are admitted. The
carve-out that excused these sites reasoned that the entry name "is itself content-derived and
escaped above"; traced through the reader, the claim-record sentences carry the composed path and
nothing else, so that premise does not hold there. This plan does not narrow the carve-out's prose —
plan 32.1-13 deletes the class it belongs to.

Purpose: the phase's own central claim for F-14 was that the builder owns every content-derived
interpolation across all three board modules. It does not. Either that becomes true or the claim
comes down; this plan starts making it true, from a measurement rather than from a citation.
Output: one failing-then-passing end-to-end case, one derived site census filed as the expansion's
work list, the claim-record sentences built through the builder, the pinned counts re-derived, and
the gap recorded OPEN in the residual register with a named owner.
</objective>
