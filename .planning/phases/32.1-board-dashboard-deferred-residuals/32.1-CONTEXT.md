### Proof enumerations → canonical form (F-14, F-15, F-19, F-21, WR-04, rows 207, 210)

- **D-01: One shared symbol-resolving instrument.** A `ts.Program` with a type checker is built once
  over the scanned `scripts/` sources and both enumeration-shaped rules ask the checker which
  *declaration* a name resolves to: the split-reader census (F-15 / WR-04) resolves every key-table
  reference to its declaration symbol, so named, renamed, namespace and re-exported imports all land
  on the same declaration; the IN-03 one-authority rule (F-19) matches register reads by resolved
  symbol, never by identifier text. The split-reader join is asked in **both** directions (WR-04's
  converse). Precedent on the tree: `scripts/context-io.test.ts` already builds a checker.
  — **Reversibility:** costly — two guard rules and the exemption registry (D-04) are re-derived
  from this instrument; going back means re-typing the enumerations the phase exists to delete.
- **D-02: The instrument is a test-only helper, not a production module.** It lives in a
  `scripts/*.test-support.ts`-style file that `tsconfig.json`'s `**/*.test.ts` exclusion pattern (or
  an added pattern) keeps out of `tsc` emit: no committed `.js` twin, no freshness row, never ships.
  `typescript` stays a dev/CI-only concern for this instrument, as CLAUDE.md requires.
- **D-03: The program's file set is tracked files only, floored against the walk.** The program is
  built over `git ls-files 'scripts/**/*.ts'`; a test asserts every `.ts` the `readdirSync`
  walk finds is either in the tracked set or explicitly reported as untracked, so nothing is silently
  skipped and a local scratch file (review IN-05) cannot red or hide the suite.
- **D-04: `NOT_A_SECOND_AUTHORITY` is re-derived under the checker.** Run the checker-based census;
  every entry that no longer trips it is deleted with a deletion note; whatever remains must carry a
  reason stated in terms the checker reads. The count is re-pinned two-sided from the derived set,
  never typed. Row 210 (`board-tracer.test.ts`, the ninth entry) closes when it resolves cleanly.
- **D-05: A declared canonical `check:*` command shape replaces the separator-alphabet counter
  (F-21, row 207).** Every `check:*` entry in `package.json` must match one of a small set of exact
  declared shapes (the `tsc --outDir .tmp-build && node scripts/<x>.js` form and the
  `npx vitest run <file>` form, or as the planner derives from the live manifest). Anything outside
  the declared shape is a **refusal naming the entry**, not an undercount. The step count is derived
  from the shape match.
  — **Reversibility:** reversible — the manifest is small and the shape is data.
- **D-06: `check:build-parity`'s inline `node -e` moves into a script file; the shape has zero
  exemptions.** The failure-message JavaScript becomes a committed script (or the whole check
  becomes one script) so the declared shape carries no named exception at all.
- **D-07: One refusal-sentence builder escapes by construction (F-14).** Every interpolation into a
  published sentence — conflict `actual`/`expected`, `readErrors` message, watch-record message,
  stderr frame — goes through one builder that applies `visible()` to each interpolated value. A
  test asserts that no raw template interpolation of a content-derived value exists outside the
  builder, across **all three** board modules (`scripts/board-read.ts`, `scripts/board-model.ts`,
  `scripts/board-dashboard.ts`). The site-list derivation is retired. `TICKET_CONTROL` is **not**
  widened to C1 in this phase (that would change what tickets are admitted, touching D-01/DASH-01).

### The regex import scanner (F-16, F-17, F-18, WR-02, WR-03, row 208)

- **D-08: The regex scanner is retired; the TypeScript parse is the one authority.**
  `moduleSpecifiers` in `scripts/js-import-closure.ts` is rewritten over `ts.createSourceFile`. Regex
  literals, template literals and escaped specifiers fall out of a real tokenizer; the second grammar
  is deleted, not patched. `typescript` becomes a **stated dev/CI requirement of the gate scripts**
  that import the scanner (`context-freshness`, `now-running-freshness`, `guarantees-freshness`,
  `trace-freshness`, `generate-hook-manifest`); a test asserts nothing under `install/` or `hooks/`
  imports the scanner, so the host zero-runtime-dependency rule is untouched (verified on the tree:
  `hooks/hook-entry.ts` names it only in a comment).
  — **Reversibility:** one-way — the freshness gates and the DASH-06 guard are asserted against
  this parser's output; the regex arm and its recovery table are deleted with their tests.
- **D-09: The independent second side of the closure oracle is Node's own loader.** A
  `module.register()` hook records every specifier Node actually resolves when the fixture corpus is
  loaded; the recorded set is asserted equal, per entry, to the static closure. This is runtime truth
  independent of any parser (F-17's oracle shared the scanner's blind spot). The same instrument is
  the runtime probe row 208 says it needs. The planner must ensure the corpus load cannot execute a
  real writer (a loader hook that records and refuses to evaluate, or a corpus of inert modules).
- **D-10: F-18 — restore two independent predicates.** The acquisitions PREMISE case must fire for a
  bare specifier that names a writer, in addition to the `ALLOWED_BUILTIN_SPECIFIERS` equality; each
  is mutation-proven to fail alone.
- **D-11: Dynamic-import canonical form: string literal only.** In the dashboard closure, an
  `import()` whose argument is anything but a plain string literal (template literal, identifier,
  call, concatenation) is a named refusal carrying the node kind in the message. No admitted
  alternative spellings.

## Specific Ideas

- The whole phase is an instance of the P27 lesson: when a predicate has been widened N times, define
  the canonical form and refuse everything outside it; delete the second grammar rather than patch it.
- F-15, F-19, F-21 are literally the same shape and must be closed by the same *kind* of move
  (resolve by symbol / declare the shape), so a reader can see one remedy applied three times.
- The loader oracle is deliberately a *different library* from the parser it checks; an oracle that
  asks the same question as the subject proved nothing in round 4.
- The e2e run (D-13) is a human-gated spend; the plan must not start it without the named go.

</specifics>
