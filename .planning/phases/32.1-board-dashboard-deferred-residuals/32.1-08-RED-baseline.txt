32.1-08 RED BASELINE
====================

Phase 32.1, plan 08. Two subjects: F-18 (D-10, two independent write-detection
predicates) and D-11 (one register for the dynamic-import question, with a
refusal that carries the node kind).

Every transcript below was produced on this box, on this tree, by running the
guard for real. Nothing here is quoted from another phase's document without
being re-measured: a finding quoted rather than re-run is a recollection.

Machine: darwin 25.5.0, node 24.12.0, vitest 4.1.8.
Tree at the start of this plan: 2f791a81 ("docs(32.1-07): complete the
sentence-builder plan").

Command under measurement (§§ 1-4):
    npx vitest run scripts/board-readonly.test.ts
which is byte-for-byte what `npm run check:dashboard-readonly` runs.

The plant is appended to the committed build output `scripts/board-read.js` --
a module inside the dashboard closure -- exactly as Phase 32's round-4 red team
planted S7 and S9. Every run restores both `scripts/board-read.js` and
`scripts/board-readonly.test.ts` from a byte copy taken before the run, and
every transcript carries its own `git status --porcelain -- scripts/` line so
the restoration is evidence rather than an intention.

"MECHANISM red" means the case

    PREMISE: no closure module acquires a module by a route that is not a
    static literal import

appears as a `FAIL` line in the reporter -- matched against the FAIL lines
only, never against the run's whole output. That distinction is load-bearing:
the string also occurs inside the failure MESSAGE of the new F-18 cases, so a
whole-output grep answers YES for a run in which the premise case passed. The
first pass of this measurement did exactly that and had to be re-taken.

"CENSUS red" means the two allow-list cases

    the closure's normalized builtin identities have exactly the allowed MEMBERS
    the closure's normalized builtin identity set has the expected COUNT

appear as FAIL lines, under the same rule.

Both are BARE by `classifySpecifier` -- S7 because npm permits a leading digit,

which predicate REFUSES them, not whether they deliver.

Sections 3 and 4 together are what makes "two predicates" a measurement. Each
one is watched refusing both plants with the other disabled, in both
directions, and neither mutant's unplanted control is silent -- the new F-18
cases red under BOTH mutations, so the pair cannot be quietly halved again
without a named case failing.

THE PINNED COUNT DID NOT MOVE. `ALLOWED_BUILTIN_SPECIFIER_COUNT` is 3 before
and after this plan (scripts/board-readonly.test.ts:3280). The plants are
writers arriving from outside, not new admitted builtins; a plan that moved
that number would have changed what the closure is ALLOWED to acquire rather
than what the guard detects.
