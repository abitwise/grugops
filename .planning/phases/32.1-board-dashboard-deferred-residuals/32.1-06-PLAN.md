<objective>
Retire the second grammar (D-08). `moduleSpecifiers` in `scripts/js-import-closure.ts` is a
hand-written scanner with a pattern list and a literal recovery table, and round 4 measured three
separate ways it disagrees with a real tokenizer: a regular-expression literal's interior is never
blanked so an import-shaped string inside one fabricates an edge (F-16, WR-02); the recovery table
stores a literal's raw source text so an escaped specifier resolves on its spelling rather than its
value (WR-03); and a template-literal dynamic import is invisible to it (F-17). Each of those is a
counter-example, and this repository's recorded answer to the fourth counter-example is to define the
canonical form and delete the second grammar rather than to add a fourth arm.

**This cutover is one-way** and carries a decision checkpoint before the deletion: the freshness
gates and the read-only guard are asserted against the new parser's output, and the regex arm goes
with its tests. D-20 already fixed the route — the parser is acquired lazily through a Node builtin
and never statically imported — so the checkpoint confirms the cutover, not the route.

Purpose: six production gate scripts consume this function, one of them on every CI leg including
Windows, and their correctness is what DASH-06's read-only proof rests on. A scanner that can miss a
real import makes a mirror short by exactly the file the walk could not see.
Output: a tokenizer-based extractor with a stated node set, three deletion notes, the corpus cases
that reproduce all three findings, and a shipped-surface rule that is scoped to what actually ships.
</objective>
