--- 1.2  THE SURVIVING PIN: BEFORE, AFTER, AND WHAT MOVED IT ---------------------------------------

  PUBLISHED_SUBSTITUTION_COUNT   before 86   after 86   UNMOVED

WHAT MOVED IT: nothing, and that is the measurement rather than an expectation. This plan added no
sentence and removed none; it added a TAG to 42 existing templates, and a tag is not a sentence. The
denominator counts substitutions written into a position a human reads as a finding, so it can only
move when such a position lands or leaves. If this number HAD moved, the cutover would have changed
what is published rather than how it is built, and that is the failure the pin exists to catch.

THE TWO PINS THAT WERE DELETED RATHER THAN RE-DERIVED:

  CONTENT_SUBSTITUTION_COUNT   was 26   DELETED — it counted the members of a classification table
                                        that no longer exists. Re-deriving it would have preserved
                                        the enumeration under a new name.
  OWNED_SUBSTITUTION_COUNT     was 44   DELETED — it is now a DERIVED side of the equality
                                        (`published.length`), so pinning it would be a second number
                                        to bump beside the one that derives it. The mutation
                                        controls measure their movement against a live derived count
                                        instead.

SECTION 2 — THE MUTATION PROOF: ONE SEEDED REMOVAL PER MODULE
===================================================================================================

The mirror re-runs the WHOLE pipeline — program, type checker, declaration resolution — over a
source served from mutated text at the compiler host's `getSourceFile`. Nothing on disk is touched.
Each seed is asserted UNIQUE in its module (the mirror refuses on any count other than one, because
`String.replace` with a string pattern rewrites only the first match).

  LIVE (unmutated): published=86 owned=86 unowned=0

  SEED board-model.ts     published=86  owned=85  offenders=1
    refusal: board-model.ts:1694 `t.id` (board-model.ts#id)
  SEED board-read.ts      published=86  owned=85  offenders=1
    refusal: board-read.ts:1609 `claimMd` (board-read.ts#claimMd)
  SEED board-dashboard.ts published=86  owned=85  offenders=1
    refusal: board-dashboard.ts:1471 `oneLine(e)` (board-dashboard.ts#oneLine)

FOR EACH OF THE THREE, ALL FOUR ASSERTIONS HOLD:
  • the owned count moves by EXACTLY ONE (86 → 85), so the number is a function of the seeded change
    rather than of a derivation that broke and started reporting something else;
  • DIRECTION ONE of the equality reds — exactly one offender;
  • DIRECTION TWO of the equality reds — owned (85) no longer equals published (86);
  • the refusal names the MODULE, the EXPRESSION and the resolved DECLARATION, so a reader can open
    the file and see the site without re-deriving anything;
  • the published DENOMINATOR is UNMOVED at 86 under a mutation that only removed a tag.

A PREMISE CASE ASSERTS THE SEED SET ITSELF: the three seeded modules are derived-equal to the three
modules the census walks. A control exercised in a subset of the modules says nothing about the ones
it skipped, and this plan's cutover landed in all three — 10 of the 42 sites are in the module that
had never been seeded before this plan.

--- 3.2  IDEMPOTENCE AT THE NESTED SITE ------------------------------------------------------------

`board-dashboard.ts`'s `emit()` applies the builder to a `readError.message` that a board module
already built through the builder, and after this cutover that nesting is the common case rather
than the exception. Two new cases in `scripts/board-model.test.ts` prove the property instead of
arguing it:

  • a sentence already carrying an escape spelling passes a SECOND application of the builder
    unchanged — asserted as byte equality, not as a containment;
  • the escape notation itself carries no byte the builder would escape again: `visible("<one C1
    point>")` is `<U+0085>`, and `visible("<U+0085>")` is `<U+0085>`.

  RESULT: both pass. A doubled escape would have been its own F-14 — a sentence stating
  `<U+003C>U+0085<U+003E>` about a path whose name carries one code point.
