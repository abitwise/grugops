## Accomplishments

- **One authority over symbol resolution (D-01).** `scripts/ts-symbols.test-support.ts` builds a fault-boundaried `ts.Program` with `noEmit` set explicitly, a per-file parse-fault boundary around `host.getSourceFile`, and `rootNames` as a **union** of the config's file list with the tracked sources. - **One authority over the file set, with the floor that makes the failure loud (D-03).** `trackedScriptSources` uses `git ls-files -- 'scripts/*.ts'`. The intuitive `scripts/**/*.ts` returns **26 of 153** on this tree, because git's default matching has no `WM_PATHNAME` and a bare `*` crosses `/`. The greater-than-100 floor turns that from a quiet narrowing into a named failure at 26 — recorded as a plant.

The tree's own analog spelling, `*.testkit.ts`, was refused after measuring that its `.js` twin is tracked: excluding that pattern would have turned a committed output into an ORPHANED COMMITTED OUTPUT and reddened `npm run freshness` for a file nobody touched.

- **The inertness argument turned into evidence.** `git status --porcelain` is captured immediately before and immediately after the corpus load and asserted equal. That is also the DASH-04 / DASH-08 concurrency edge: an interrupted or parallel oracle run mutates nothing, and what says so is the measured equality rather than a claim about the corpus's shape.
- **A depth-one blind spot removed from inside the guard meant to close it (D-03).** The walker-importer derivation was a depth-one `readdirSync` over exactly `["scripts","hooks"]`; a consumer under `scripts/runnable-ref/` would build a mirror no `CLOSURE_BASELINES` row pins and never move the count. It is now git-derived and recursive by construction, and the plant proves it: the new derivation moves to 13 and names the planted file, while the old one, run against the same planted tree, reports 12 and does not contain it.
- **The six-versus-seven question settled, and pinned.** This repository's own prose claimed in two places that a refusal reaches "seven production callers". Measured over the tracked set it reaches **six**. Both sentences are corrected and both now cite `WALKER_PRODUCTION_IMPORTER_COUNT = 6`, derived from the same set and asserted — because a corrected sentence with nothing deciding over it is the same defect with a better number in it.

## Decisions Made

See `key-decisions` in the frontmatter. The two that a later plan most needs to know:

1. **The loader oracle cannot be registered inside a vitest file.** Measured: zero resolve events, because Vite's transform rewrites dynamic `import()` into vitest's own module runner. It runs in a child `node` process — and that child must be a real script file, not `node -e`, because `-e` leaves `process.argv[1]` pointing at the entry we pass, which makes `is-entry` run the dashboard's main.
2. **Widen the matcher with the set, or the blind spot only moves.** Task 3's first run returned 11 instead of 12: the set had been widened to all tracked files while the pattern still enumerated the two relative prefixes a top-level file can write, so `hooks/guard.test.ts` (`../scripts/js-import-closure.js`) fell out.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The loader oracle had to move into a child process**

- **Found during:** Task 2
- **Issue:** The plan (following CONTEXT.md D-09 and the research's probe 3) has the helper "register a synchronous in-process loader hook with `registerHooks` from `node:module`" and record while the corpus loads. Measured on this tree: a hook registered inside a `*.test.ts` and awaiting `import(pathToFileURL(...).href)` of `scripts/board-dashboard.js` records **zero** events. `module.registerHooks` observes Node's own ESM loader; vitest rewrites the test file's dynamic import into Vite's module runner, which never reaches it. The research names this caveat and then assumes the explicit `import()` goes through Node — it does not. The plan's own PREMISE floor (`> 5`) would have reddened immediately.
- **Fix:** `recordRuntimeAcquisitions` writes a small oracle script into an OS temp directory (outside the repository, so it can never appear in the working-tree snapshots it exists to compare), spawns `node <script> <entry> <out>`, and parses the recorded events back. The hook is still `registerHooks`, still synchronous, still in-process — in the process where Node's resolver is the only resolver there is. A second measurement ruled out the cheaper `node --input-type=module -e` shaping: with `-e` there is no script path, so `process.argv[1]` becomes the entry path, `is-entry` concludes the dashboard IS the entry, and its `main` runs (the board rendered to stdout).
- **Files modified:** `scripts/loader-oracle.test-support.ts`
- **Verification:** 13 resolve events, 5 modules, 3 builtins, working tree byte-identical across the load; plant 2.1 in the RED baseline reproduces the truncating shaping at 1 event.
- **Committed in:** `6cf26ec8`

**2. [Rule 3 - Blocking] `trackedSourcesUnder` added to the Task-1 module so Task 3 need not type a second pathspec**

- **Found during:** Task 3
- **Issue:** Task 3's files list names only `scripts/board-readonly.test.ts`, but the derivation must cover `hooks/` as well as `scripts/`, and `trackedScriptSources` is `scripts/`-only. Letting the test write its own `git ls-files` call would put a second copy of the exact spelling that returns 26-of-153 when written wrong into the tree — a second authority over the one line this phase exists to make singular, and a direct hit on the plan's own prohibition against another arm where a canonical form is called for.
- **Fix:** `trackedScriptSources(root)` now delegates to a new `trackedSourcesUnder(root, dir)`, which refuses any `dir` that is not a plain top-level name (so a pathspec cannot be assembled out of a separator, a wildcard or a `..`). The consumer asks for `"hooks"`.
- **Files modified:** `scripts/ts-symbols.test-support.ts`, `scripts/board-readonly.test.ts`
- **Verification:** 12 importers derived including `hooks/guard.test.ts`; `npm run typecheck` exit 0.
- **Committed in:** `c6a1d2cf`

Widening the set while leaving the matcher enumerated moves a blind spot rather than closing one — the same defect this task addresses, one register over.
