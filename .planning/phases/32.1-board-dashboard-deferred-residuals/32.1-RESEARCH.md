## Summary

This phase has **no new technology** to choose. Every instrument it needs already exists on this tree
in a working, tested form; the research task was to find where, measure the exact shapes, and find the
places where CONTEXT.md's own citations do not match what is on disk. Nine such mismatches were found
and every one is recorded below as `UNKNOWN - verify` with what was actually measured, never silently
fixed.

Three findings change the shape of the plan materially. **First**, D-01's stated precedent is wrong:
`scripts/context-io.test.ts` does not build a `ts.Program`; the only real `ts.Program` + checker on
this tree is `scripts/runnable-ref/uat-spec-integrity.ts:1308` (`createProgramForTarget`), and
`context-io.test.ts:15409-15413` is a residual observation whose *expected value is literally*
`type-checker=false`. Building the instrument the way D-01 describes is right; the template to copy is
a different file, and the phase must not accidentally red `R-31-21-04`. **Second**, D-03's literal
command `git ls-files 'scripts/**/*.ts'` returns **26** of the **151** tracked `.ts` files under
`scripts/` on this tree, because git's default pathspec `*` crosses `/`; the correct spellings are
`git ls-files 'scripts/*.ts'` or `git ls-files ':(glob)scripts/**/*.ts'`, both of which return 151 and
exactly equal the `readdirSync` walk. A plan that copies the CONTEXT.md spelling verbatim builds its
"one authority" instrument over one sixth of the corpus and passes vacuously. **Third**, D-09's
runtime oracle was **built and run here** and it works: `module.registerHooks` records all 13
resolution events for `scripts/board-dashboard.js`, yielding exactly the 5-module static closure and
exactly the 3 builtins `{fs, path, url}` that `ALLOWED_BUILTIN_SPECIFIERS` pins — with the tree clean
afterwards and no writer executed. But the obvious "record and refuse" `load`-hook shaping is a
**vacuity trap**: a hook that short-circuits with `export {};` stops the walk after the first module
and records one edge. The probe that proves this is below.

Two decisions cost less than CONTEXT.md implies and two cost more. D-14 costs almost nothing: the
`waived` status is **already fully implemented** by `gsd-tools windows waive <id> "<reason>"`
(`~/.claude/gsd-core/bin/lib/broken-windows.cjs:466` declares the enum `['open','waived','fixed']`,
:532-540 cross-checks the recomputed counters, :277-287 refuses an empty reason) — the plan must
*call the verb*, not implement a representation. D-12's gate output is fully derived and stable at
**78 findings over 39 elements**, of which exactly **3** are frozen and need a `companion` cell of
**8** normalized words or more (`COMPANION_MIN_WORDS = 2 * CLAUSE_MIN_WORDS`, and `CLAUSE_MIN_WORDS`
is 4). Against that, **D-06 has a ripple CONTEXT.md does not mention**: collapsing
`check:build-parity` into one script moves it out of the `toolchain` class, which empties
`TOOLCHAIN_CHECK_SCRIPTS` — the register that F-19's whole one-authority rule is *about* — and moves
the pinned class counts `{gate-module: 9, suite-test-file: 1, toolchain: 1}`. And **D-15's remedy as
written cannot be executed**: the census sees *string literals*, not comments, and
`check-diff-disposition.ts` is tripped by exactly two literals, one of which is the git subcommand
`"status"` inside `git(["status", "--porcelain"])` and cannot be reworded away. The honest route —
measured here — is to reword only the `column` literal at `:1630`, because `namesBothKeys` requires
**both** keys, so dropping one is sufficient to retire the exemption.

**Primary recommendation:** sequence D-19 as written, but land **three** instruments in wave 0, not
two — the checker helper (D-01/D-02/D-03), the loader oracle (D-09), **and** the corrected
tracked-file-set derivation with its floor — because the file-set derivation is what makes the other
two non-vacuous, and it is the single highest-risk line in the whole phase.

## Common Pitfalls

### Pitfall 1: the vacuous file set (HIGHEST RISK)
**What goes wrong:** the checker program is built over `git ls-files 'scripts/**/*.ts'` and covers 26
of 151 files; every census over it passes.
**Why it happens:** git's default pathspec `*` crosses `/`, so `**/` demands an extra directory level.
**How to avoid:** use `git ls-files -- 'scripts/*.ts'` or `':(glob)scripts/**/*.ts'`; assert the count
against the `readdirSync` walk **and** assert the count is greater than 100.
**Warning signs:** a census whose carrier list is empty and whose PREMISE floor is absent or low.

### Pitfall 2: the record-and-refuse loader oracle that records one edge
**What goes wrong:** a `load` hook returning `export {};` prevents writers and truncates the walk; the
oracle agrees with a closure of size 1.
**Why it happens:** replacing a module body removes its import statements.
**How to avoid:** the shaping in probe 3 — let the inert corpus load for real, record on `resolve`,
assert the tree clean before and after, and pin the resolve-event count (13 today).
**Warning signs:** `RECORDED` has exactly one element; the equality passes with the static closure stubbed.

### Pitfall 3: emptying `TOOLCHAIN_CHECK_SCRIPTS` while rewriting the rule that reads it
**What goes wrong:** D-06 moves `check:build-parity` out of the toolchain class, the register becomes
`{}`, and F-19's cutover lands against an empty set that satisfies every assertion.
**Why it happens:** the two decisions are in different sections of CONTEXT.md and read as independent.
**How to avoid:** sequence F-19's rewrite **before** D-06, or plan them as one wave with the class
counts `{9,1,1}` moved deliberately.
**Warning signs:** `CHECK_SCRIPT_CLASSES.toolchain.targets` is 0 and nothing named it a decision.

### Pitfall 4: the `git(["status", …])` literal
**What goes wrong:** a plan reads D-15's "prose" literally and tries to delete a git subcommand.
**How to avoid:** reword only `scripts/check-diff-disposition.ts:1630`'s `column`; `namesBothKeys`
needs `every` key, so one is enough.
**Warning signs:** a diff touching `:1058`.

### Pitfall 5: tripping `R-31-21-04`
**What goes wrong:** the new checker helper is imported into — or its name is merely *mentioned* in —
`scripts/context-io-writer-set.test.ts`, and the residual whose expected value is `type-checker=false`
reds.
**Why it happens:** the residual is a **text** match (`text.match(/createProgram\(/g)`), not a semantic one.
**How to avoid:** a plan prohibition. `git diff --exit-code -- scripts/context-io-writer-set.test.ts`
after every cutover.

### Pitfall 6: a new dependency on the shipped side
**What goes wrong:** `import ts from "typescript"` lands in `scripts/js-import-closure.ts`, a
production compiled module, contradicting CLAUDE.md C2 and a written in-repo ruling.
**How to avoid:** route 1 in §D-08, or a named human decision.
**Warning signs:** a committed `.js` under `scripts/` whose import list is not builtins + relative.

### Pitfall 7: raw control bytes in the phase's own documents
**What goes wrong:** `check:nul-bytes` goes red on a REVIEW/RESEARCH/SUMMARY file, and BSD `grep`
silently reports zero matches for strings that are present.
**How to avoid:** spell every control character as escape TEXT. Precedent: user commit `888a1302`
("fix(phase-32): replace literal ESC byte in 32-REVIEW.md with printable \x1b") exists because this
already happened once.
**Warning signs:** `npm run check:nul-bytes` exits 1 naming a `.planning/` file.

### Pitfall 8: 78 disposition rows is a content job, not a code job
**What goes wrong:** a plan budgets one task for D-12 and produces placeholder `companion` cells.
**How to avoid:** the placeholder class is refused **by construction** (8-word floor, every placeholder
spelling normalizes to at most one word). Split across plans; one file per plan.
