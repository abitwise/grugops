## Decisions Made

See `key-decisions` in the frontmatter. The two that a later reader is most likely to need:

1. **Direction two is a binding-level rule, not the module-level one WR-04 sketched.** The review's fix sketch fired whenever a key-naming file imported anything from a scanning module. That would have redded the CORRECT shape — a file that names both keys and calls the one authority's own `parseTicketDocument`. The committed rule asks whether the imported DECLARATION itself reaches a text-scanning primitive, which is the exact symmetric twin of direction one's "is this binding a key table". Measured on the live tree: both forms give zero offenders today, so the tighter one was taken.
2. **Row 194's remedy is a string literal, not prose.** CONTEXT.md D-15 and the ledger row both say "stop writing the two ticket key words into that module's prose". The census resolves string literals and cannot see comments at all, and one of the module's two key literals is the `status` argument inside `git(["status", "--porcelain"])`. Following the prose framing literally leads a reader straight at a git subcommand. The deletion note in `scripts/validate.test.ts` records the correction so the next reader does not repeat it.

## Issues Encountered

- **The plant program could not be built through `createScriptsProgram`.** That function derives its file set from `git ls-files` inside the supplied root, and a temp mirror is not a git repository, so it returns `ok: false` by design. Resolved by building the plant program locally with explicit NodeNext options while still routing every resolution through `declarationOf` — so the one authority over "which declaration is this name" answers for plants and for the live tree alike.
- **The row-194 plant's first search string matched nothing.** The reworded sentence lives inside a template literal with escaped backticks, so the replacement text needed them escaped too. The case's own PREMISE assertion ("the reworded sentence was not found in the live module, so the plant planted nothing") is what caught it rather than a silently-passing test — the failure mode this repository has recorded six times.
