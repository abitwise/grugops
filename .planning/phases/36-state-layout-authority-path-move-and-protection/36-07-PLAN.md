<objective>
Make a repository still on the pre-v3 layout keep working after a kit update, and make install say so instead of
forking its state (D-13 step 3; LAYOUT-04).

Layout is decided by board presence (D-01). A plain install on a pre-v3 repository refuses the whole run before any
write, prints the --migrate command and exits 1, the installer's refusal convention (D-05); the wording is final now
although the state-moving migrate arm lands in Phase 38 (D-06). A repository with both boards proceeds on the new layout
with one stale note (D-02). The --migrate fall-through into the install run must not seed a new board beside a pre-v3 one
(research Pattern 4). The doctor reports the layout, WARN and never FAIL on pre-v3 (D-07). One named fixture serves the
refusal, doctor and fallback tests (D-08). The fallback's end in v4.0 is recorded as a decision and published (D-04).
The agent-side fallback text already reaches the kit-home Orchestrator (plans 36-05 and 36-06); this plan proves an
unmigrated repository reads it after --update.

Purpose: a kit update never breaks or forks an unmigrated repository's state.
Output: the probe, refusal, seed skip, both note and doctor line; the fixture and its tests; the D-04 record and docs.
</objective>
