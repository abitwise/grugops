<objective>
Delete the second grammar for "does this file grant spawn".

The spawn-grant guard tests two regular expressions against each physical line of a fence-stripped
body. One of them requires the tools key and the spawn token on the same line; the other requires a
leading dash. Neither survives a valid YAML folded scalar, where the key line carries only the fold
indicator and the value arrives on an indented continuation line that begins with neither. That was
reproduced twice on hermetic mirrors — once on a non-coordinator role adapter and once on a skill
file — and both runs reported all checks passed. The same file already reads a whitespace-collapsed
body elsewhere precisely so a hard wrap cannot change a verdict; the grant half was left line-anchored,
and that asymmetry is the bypass.

The oracle's grant-closure extraction shares the defect, because it filters lines with the same two
expressions before pulling the enumerated names out. So the guard and the oracle are two consumers of
one broken grammar, which is the shape this project's own doctrine names: one format-aware authority
per predicate, and the duplicate grammar deleted.

The fix is a real frontmatter-value reconstruction — a flattener that reads the frontmatter block and
returns each key mapped to its value with continuations, fold and literal indicators, quoting, flow
sequences and block sequences all resolved into one string — consumed identically by the guard and by
the oracle. It is proved by a parser oracle rather than by a handful of examples: every scalar form is
generated from a known semantic value, and the parser must recover the token predicate and the
enumerated names for every one of them.

Purpose: make the spawn-grant property hold against forms nobody imagined, not only against the forms
the original author did.
Output: one parser module, two repointed consumers, two deleted regular expressions, and fuzz.
</objective>

## Flagged Assumptions (probe-unresolved)

**SPAWN-04 — probe row `unclassified`, status `unresolved`.** The deterministic edge probe classified
this requirement's single item as unclassified, so no boundary, adjacency, emptiness, ordering,
encoding or precision predicate was derived automatically for the no-spawn-token property. It is
surfaced here rather than dropped or auto-backstopped. The identical row was surfaced in plan 27-08
with an explicit note that a tools value spanning multiple physical lines might evade the
line-anchored patterns; that assumption has since been confirmed as a real defect and is what this
plan closes.

What this plan does assert: the grant is read from a reconstructed value across thirteen scalar forms
at two indentation widths; the predicate is scoped to the tools keys in both directions; a parse
failure is a distinct result from a no-grant result; and both reproduced bypasses fail red.

An edge not covered here: a frontmatter value expressing the grant through a YAML anchor, alias or
merge key. No shipped adapter or skill uses one, the generator cannot emit one, and resolving aliases
would mean writing a YAML engine rather than a value flattener — which would be a second grammar with
more surface, not less. If an anchor form is ever needed, the flattener's parse-failure arm is the
place it must land rather than a silent no-grant.
