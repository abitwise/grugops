### WR-02 — indentation is invisible to the payload test and reappears only as a refusal

| # | document shape | guard today | platform (libyaml) |
|---|---|---|---|
| W2-a | `description: \|` / `  intro` / `  ---` / `  outro` | REFUSE — *"the closing delimiter position carries `  ---` … its leading residue renders no glyph of its own"* | `{"description"=>"intro\n---\noutro\n"}` |
| W2-b | `description: Read the docs` / `  ...and then some` | REFUSE — *"the closing delimiter position carries `  ...and then some`"* | `{"description"=>"Read the docs ...and then some"}` |
| W2-c | `description: >` / `  intro` / `  ...` / `  outro` | REFUSE — same clause on the `...` payload | loads cleanly |
| control | `description: \|` / `  intro` / `  --` / `  outro` | parses; `description` = `intro -- outro` | loads cleanly |
| control | a legal `---` close at column 0 | parses with its keys | — |

**W2-b is the cheap one.** An author wrapping a long `description:` whose continuation happens to start
with an ellipsis turns the whole foundation gate red on a file the platform loads fine, and the only
route back to green is deleting correct documentation.

**Why it happens, precisely.** `leadingInvisibleRun` (`scripts/frontmatter.ts:805-812`) counts the
leading run of code points that render no glyph — and space and tab render no glyph, so they are in the
run. The classifier then slices them off before asking *"does `rest` begin with a payload"*, so an
indented `---` answers **yes**, and the indentation reappears only as the `run !== 0` clause, which is a
**refusal**. But indentation is exactly what distinguishes a delimiter from content: in YAML and in
every markdown frontmatter reader the delimiter is at column 0, and an indented `---` inside a block
scalar or a wrapped value is content.

### IN-02 — the quoting rule applied where YAML gives the construct no quoting

| # | document shape | guard today | platform (libyaml) |
|---|---|---|---|
| I2-a | `tools: \|` / `  Read, "Agent(x\q)"` | REFUSE — *"carries the backslash sequence `\q` inside a double-quoted scalar"* | `{"tools"=>"Read, \"Agent(x\\q)\"\n"}` — no escape, nothing to refuse |
| I2-b | `description: \|` / `  "alpha"` | parses; `description` = `alpha` — the quotes are STRIPPED | `{"description"=>"\"alpha\"\n"}` |
| I2-c | `coordinator: \|` / `  "true"` | parses; `coordinator` = `true`, and `keyHasValue(keys, "coordinator", "true")` returns **`true`** | `{"coordinator"=>"\"true\"\n"}` |
| control | the same `\q` value OUTSIDE a block scalar | REFUSE — correct, and must stay | — |

**I2-c stated honestly, with its masking.** A non-coordinator file can claim the coordinator marker
through a construct the platform reads as the literal text `"true"`. On today's tree it is **masked** by
`guard_wr05`'s exactly-one-coordinator cardinality check, which would then see two coordinators and fail
— defence in depth, not a property of the parser. The mask would evaporate for any consumer of
`keyHasValue` that does not also count coordinators. It is recorded at Info weight, fixed by the same
one-line exemption, and pinned by a case.

## The rule, stated once — apply a rule only where the format gives the construct that meaning

```
leading run  = the leading run of code points that render no glyph of their own   (unchanged)
  ├─ indentation : the run consists ENTIRELY of the declared whitespace class
  └─ residue     : the run contains any other non-glyph code point                (unchanged behaviour)

closing position + indentation + payload  -> not-a-delimiter  ("keep scanning"; the fallback when no
                                             legal close is ever found is the EXISTING unterminated-block
                                             REFUSAL, so no silent success is created)
opening position + indentation + payload  -> refuse            (unchanged; here `not-a-delimiter` means
                                             the keyless SUCCESS arm, so indentation must not route there)
residue anywhere                          -> refuse            (unchanged, byte for byte)

flush, cur.block === true   -> the joined value is returned as-is; no quote pair is removed and no
                               escape is resolved, because a block scalar has neither
flush, cur.block === false  -> exactly today's behaviour, byte for byte
```

This adds **one label**, not one predicate. The classifier stays a single total function returning three
verdicts, and it already takes `position` as an argument — so the position-sensitivity is a branch inside
the one function, never a second function beside it.

<assumption_delta_decision>
**Detector reading:** `pluralization` — a second *kind of leading run* is introduced where there was one.
The classifier previously had exactly one leading-run fact (its length); this plan gives that same run a
second fact (what it is made of).

**The noun that is now primary:** the **leading run's composition** — indentation versus residue —
replacing the **leading run's length** as the thing the classifier reasons about when it decides whether
a payload line is a delimiter at all.

**Decision: `promote`.** Composition becomes primary and length is demoted to a detail used only for
slicing. No task may keep a length-only test beside the composition test "as a second opinion": two
answers to "is this line indented" is precisely the pair-of-predicates shape D-44 deleted from this exact
function after its union shipped a live bypass.

**Rationale:** the length test and a composition test can disagree — a run of length 2 is indentation or
residue depending on what those two code points are — and the disagreement is invisible to a reader
checking either in isolation. One scan, one labelled result, consumed once.
</assumption_delta_decision>
