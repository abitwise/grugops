<objective>
Close **WR-01**, **WR-02** and **IN-01** together, because they are one root cause seen from three
sides: the block-scalar machinery D-57 added decides a scalar's extent and a scalar's joins from facts
that are not the ones YAML uses.

**WR-01 — the end condition is the wrong threshold.** The content branch keeps a line inside the
scalar while it is more indented than the *header line*. YAML auto-detects the scalar's content
indentation from its *first non-empty content line* and ends the scalar at the first line less
indented than **that**. Where the first content line is more indented than the minimum, the two rules
diverge and the module over-includes. Measured on the committed build this session:

```
tools:                 module: GRANT, names ["grugops-orchestrator"]
  nested: >-           libyaml: {"nested"=>"Read,"}  -> no grant
        Read,
    # x, Agent(grugops-orchestrator)
```

That is a module grant the loader does not have — the direction the module's own doc block names as
**never exemptible**, shipped by the change that stated it. It is a false RED rather than a hole,
which is why it is a warning and not a critical, but it is a stated invariant violated.

**WR-02 / IN-01 — the line-break derivation reached the indicator and not the blank line.** D-57
correctly derived the join from the indicator because a space join was inventing enumerable names
where the loader's line break would be refused. The identical mechanism survives on the blank-line
axis: YAML folds a blank line inside a folded scalar to a line break, and this module drops the blank
line at the paragraph-break skip and then joins with a space. Measured:

```
tools: >                module names: ["alpha","ga mma"]
  Agent(alpha, ga       libyaml:      "Agent(alpha, ga\nmma)\n"
                                       the enumeration alphabet REFUSES a line break
  mma)
```

So the module enumerates two names, one invented, for a value the loader-faithful reading sends to
the loud refusal arm. IN-01 is the literal spelling of the same drop; the review's own disposition is
that fixing WR-02 fixes it, with a control row tying the two axes together.

Purpose: both are the KIT-03 / D-09 direction — a name invented or a value over-included in the set
equality the oracle promises is exact. They land in one plan because they are two facts about the same
construct, and this phase's record is that a warning deferred returns one abstraction level down.

Output: the end condition derived from the scalar's own detected content indentation, the blank line
treated as content inside an open scalar, the literal value equality pinned beside the folded one, the
boundary measured on both sides, mutation controls, and D-62 recorded.

Implements D-57 point 2 (the end condition is YAML's own rule, derived, never guessed) at the
threshold D-57 got wrong, D-09 / KIT-03, D-50 (a rule is applied only where the format gives the
construct that meaning), and D-19.
</objective>
