<objective>
Make the installer and uninstaller self-deriving so that the 17 adapters landing in plan `27-07`
require no installer edit, and so that an uninstall after that phase does not orphan sixteen files.

Per D-18 the installer **self-derives by `readdirSync`** of the source `.claude/agents` and
`.claude/skills` directories and installs what is there; `uninstall.ts` mirrors the same derivation.
It deliberately does **not** import `scripts/kit-model.ts` — the single-file installer stays
self-contained and decoupled from the `scripts/` layout, and no manifest artifact is introduced that
would need its own freshness gate. The separation of duty is explicit: the installer faithfully
installs whatever exists, while `kit-model` and the KIT-03 oracle guarantee at CI time that what
exists is correct.

Per D-06 every one of the 17 adapters is a self-sufficient resolver, so the materialization loop must
cover all of them rather than the current two hand-named call sites. The routing decision — materialize
versus plain copy — is taken from the presence of the resolver slot line in the source body, which
removes the last name literal from the code path.

This plan sits outside the phase's load-bearing ordering chain (kit-set authority, then the
`orchestrator.md` trim, then the adapters) because it touches neither the kit sets nor the adapter
content, so it runs in wave 1 alongside plan `27-01`.

Purpose: an already-installed repo carries the old single-adapter layout, so this is an install-time
data migration, not only a code edit.
Output: a derived install path, a derived and target-intersected uninstall path, and regression tests
for both the 17-adapter update and the user-content-survival contract.
</objective>

    `install.ts` would leave the uninstaller removing exactly one adapter and orphaning sixteen.

    source — at the very top of the removal sequence, **before** anything is removed, because the

    intersect that derived set with what actually exists in the target and remove only the intersection.

    the user's own agent files, which is a data-loss bug against the hard constraint that installers
    never delete user content.

    directory and do not silently remove nothing: report the condition and skip adapter removal, leaving
    the user to remove files by hand. Failing loud and leaving files is the correct trade in a tool
    whose contract is never to delete user content.

    Keep the existing safety posture unchanged: the `isProtected` denylist is still consulted before
    every removal, and `rmdirIfEmpty` is still used for `.claude/agents`, `.claude/skills/<name>` and
    `.claude` so that a directory holding a user's own files survives.
