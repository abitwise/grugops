## What is wrong, stated as three sentences

1. `AXIS_KEY_LINE` carries no block-mapping shape, no compact-nested-sequence shape, no block-explicit-key
   shape and no JSON-adjacent flow mapping; its flow-mapping opener is the space-separated spelling only.
   The cell builder emits the key line plus exactly two continuation lines.
2. The mid-line sweep's case title asserts that NO mid-line node start YAML defines returns the silent
   no-grant arm, and its evidence is a hand-written array with no derivation, no cardinality pin and no
   statement of what set it enumerates. Two families the review measured are counterexamples.
3. Each exemption's bound is the full cross-product its shape can produce and each match rule is a pure
   function of the same axis flags, so `matched <= bound` holds for every possible corpus. The only
   assertion in that region doing work is the liveness check — and the equality beside it turns red when
   an exempt cell agrees, whose cheapest repair is narrowing the exemption.

## Why the expressibility floor is read from the ledger

A comment saying "this corpus covers the families the module has failed on" is the thing that failed
nine times. The ledger in `scripts/frontmatter.ts`'s header is the module's own list of those families,
it grows by one entry per round, and it is the only list in the repository that a reviewer maintains
deliberately. Reading it at run time and asserting each entry is expressible by the generator turns
"this corpus is complete enough" from a claim into a mechanism — and it fails red the moment a tenth
entry is written without a corpus shape to match it. The ledger's entry count is DERIVED from the header
and asserted two-sided, so the floor cannot pass by finding zero entries.
