<objective>
Close CR-03 and the deferred `walkFilesRelative` cycle defect together, as D-29 requires, because they
are the same predicate — *have I already walked this real path?* — and CR-03 proves that answering it
in two places produces two different wrong answers.

`install/install.ts`'s nested walk (moved into `install/kit-source.ts` by plan 27-25) records the real
path of every directory it walks in a **global** visited set and returns nothing on a repeat. That is
false for this walk's purpose: members are reported at their **relative** paths, and one physical
directory reached by two paths yields two different relative paths, each of which the authority counts
as a distinct member. Reproduced: the authority sees `alias/x.md` and `real/x.md`; the installer
refuses one and silently drops the other, with which one dropped decided by `readdir` order. That
directly violates the invariant written fifteen lines above it in the same file.

`scripts/kit-model.ts`'s `walkFilesRelative()` has the opposite defect: it follows symlinks by design
and keeps no visited set at all, so a cycle re-walks the same real directory once per level. Measured
on this repository's host before any edit, with one cycle link planted under a one-adapter fixture,
`listAgentAdapters()` returned **32 members** for a directory holding one — aliased copies, terminated
by the operating system's symlink-resolution limit rather than by the walk. With two cycle links it
threw `Maximum call stack size exceeded`. Both are wrong sets from a walk that does not know where it
has been; neither is a clean refusal; and the *manner* of termination is the host's accident, not the
walk's contract. The deferred entry describes this as an unbounded hang — the executor must record
what actually happens on the machine the work is done on rather than restating that description.

One treatment, at both sites: a per-path **ancestor stack**. It bounds recursion, which is all a cycle
guard is for, without deleting a distinct relative-path member — the exact property a global visited
set destroys and the exact property `kit-model.test.ts` already asserts for the nesting case. The two
sites receive the same shape and each names the other; they do NOT receive a shared import, because
D-18 and D-28 keep `install/` off `scripts/`.

Purpose: one answer to "have I been here", correct in both directions.
Output: an ancestor stack at both walk sites, a case proving a two-path member survives, and a case
proving a real cycle terminates by contract.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a user-controlled or drifted kit tree -> the recursive walks | the walks follow symlinks by design, so the tree's shape decides the recursion, and the tree is not the walk's to trust |
| the authority's member set -> the installer's refusal set | a member the authority sees and the installer does not is a member that cannot be refused by name |
| the walk's termination -> CI and any host running the guards | a walk that terminates only by an operating-system limit terminates differently on different hosts |
