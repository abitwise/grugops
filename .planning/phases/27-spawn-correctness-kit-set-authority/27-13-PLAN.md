<objective>
Close the three installer-side findings that share one shape: a derivation whose failure mode is
silence.

The installer and the uninstaller answer the same question — what adapters and skills exist in the
source kit — and they answer it with the same code shape but opposite contracts. The uninstaller
returns a null on an unreadable source directory, reports it, and skips that removal class rather
than falling back to guessing. The installer returns an empty list, its loops then do not execute,
and the run prints a completion banner having installed nothing. A tarball that dropped dot
directories, a partial checkout or a permissions problem therefore produces a silent no-op install.
Two files disagree about the fail-loud contract for one derivation.

The same file also carries a literal control byte inside a fail-safe sentinel, which makes a
byte-oriented search classify the installer as binary and suppress its output — a verification
technique that degrades silently, and one that already forced two acceptance criteria in this phase
to be checked another way. It is fixed first, because the criteria in this plan depend on searching
that file.

And the installer writes a pair of runnable helpers into the user's repository that the uninstaller
never mentions, so those files are installed and never removed. That is a reversibility gap against
the installer's own stated constraint, and it is the same asymmetry as the first finding wearing a
different hat.

The installer deliberately does not import the scripts-layer authority — that separation is a locked
decision, so the installer keeps its own derivation and the agreement between the two is asserted by
a test instead of bought by coupling.

Purpose: make every installer derivation fail loudly and every installed file removable.
Output: a printable sentinel, a symmetric fail-loud contract, a nested-source refusal, a runnable
removal pass, and a conformance assertion against the shared authority.
</objective>

## Flagged Assumptions (probe-unresolved)

None specific to this plan. KIT-02's three classified probe items — adjacency, emptiness and ordering
— are authored as `must_haves.truths` in plan 27-10, where the authority they describe is created;
this plan carries the installer-side consequences of the same policy and asserts agreement with it by
test rather than restating the edges.

One planner assumption is recorded explicitly rather than buried: the locked decision that the
installer does not import the scripts-layer authority is honored, so two implementations of the
adapter rule continue to exist. That is a deliberate exception to the one-authority-per-predicate
doctrine, bought back with a conformance assertion that fails when the two disagree. If a future
phase revisits the locked decision, the conformance case is the thing to delete along with the
duplicate.
