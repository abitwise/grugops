<objective>
Make the adapter freshness gate a gate.

`scripts/adapters-freshness.ts` is correct: run by hand it compares seventeen adapters against a
fresh regeneration and reports zero byte differences. It is also invoked by nothing. The npm script
exists, but the continuous-integration workflow's gate block names its three siblings and not this
one, and it is the only freshness gate in the tree without a test file — every other one has a test
that spawns it, so the vitest lane covers them even where the workflow does not name them. The
consequence is concrete rather than theoretical: it is the single gate that would have caught either
of the two reproduced hand-edit bypasses, and it is also the only thing that notices when a role's
first sentence changes and the shipped adapter's routing description goes stale. Today a committed
hand-edit to an adapter passes every gate.

This plan wires it at both ends — the workflow step and the test file — because the workflow is not a
reviewed artifact of this phase and the test file is what makes the gate survive a workflow
refactor. It also finishes the KIT-02 repoint for the two consumers outside the foundation guards,
so the adapter set has one derivation across `scripts/` rather than one plus two.

Purpose: move the drift gate from "passes when someone remembers to run it" to "the build goes red".
Output: a hermetic-root option on the gate, a five-case test file, one workflow step, and two more
deleted duplicate derivations.
</objective>

## Flagged Assumptions (probe-unresolved)

**SPAWN-02 — probe row `unclassified`, status `unresolved`.** The deterministic edge probe classified
this requirement's single item as unclassified, so no boundary, adjacency, emptiness, ordering,
encoding or precision predicate was derived automatically for the byte-freshness property. It is
surfaced here rather than dropped or auto-backstopped.

What this plan does assert: the gate is invoked by two independent lanes; a byte edit, a top-level
orphan, a nested orphan and a broken regeneration each make it exit non-zero; a comparison over zero
adapters is reported as the anomaly; and the set half compares full relative paths so two entries
sharing a basename are distinct.

An edge not covered here: whether a byte difference confined entirely to line endings — a checkout
that normalized them, or an editor that rewrote them — would be reported as drift with a message a
reader can act on, or merely as an opaque byte difference. The comparison is a whole-buffer equality,
so such a difference does fail closed, which is the safe direction; the open question is only the
quality of the message.
