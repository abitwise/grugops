<assumption_delta_decision>
**Detector reading:** `pluralization` — a list that could carry a key more than once becomes a list that
carries it at most once.

**The noun that is now primary:** **the key**, reported once per claim-set membership fact, rather than
**the claim occurrence**, reported once per bucket that made it.

**Decision: `promote`.** The de-duplicated key is primary and the per-bucket multiplicity is dropped from
the foreign arm, matching the discipline the double-claimed arm already has. The multiplicity is not
preserved in a second field "so the message can still show it": two statements of how many buckets
claimed a key is the two-independent-facts shape this round has already deleted twice.

**Rationale:** the arm's consumer is a human reading a failure message, and a key printed twice reads as
two findings. The sibling arm already answers the membership question once; making both arms answer it
the same way is one discipline rather than two.

**Suggested invariant test:** a case asserting both arms report each key at most once, over a claim set
constructed with deliberate multiplicity in each. It goes red if a future edit reintroduces
claim-multiplicity into either arm.
</assumption_delta_decision>
