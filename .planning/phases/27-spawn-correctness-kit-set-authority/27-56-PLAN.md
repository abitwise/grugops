<objective>
Close **CR-03** by deleting a second grammar rather than extending one. The block-scalar header
recogniser asks its second introduction — the implicit block-mapping key `key: <header>` — using
`KEY_LINE`, which is the deliberately narrow grammar for the **top-level** keys a frontmatter block
may declare. Reusing it silently transfers that narrowness to **nested** mapping keys, where YAML
allows any scalar. Every nested key that is quoted, contains a dot, starts with a digit or contains a
space therefore fails to introduce a header, the block flag stays false, and the scalar's literal
content is handed to the comment scanner where a leading hash deletes the rest of the line.

Measured on the committed build this session — all four return `{"ok":true,"value":false}` while the
loader reads the grant plainly:

| nested key | module | `/usr/bin/ruby -ryaml` |
|---|---|---|
| `"a b": >-` | no grant | `{"a b"=>"Read, # x, Agent(grugops-orchestrator)"}` |
| `a.b: >-` | no grant | `{"a.b"=>"Read, # x, Agent(grugops-orchestrator)"}` |
| `1a: >-` | no grant | `{"1a"=>"Read, # x, Agent(grugops-orchestrator)"}` |
| `a b: >-` | no grant | `{"a b"=>"Read, # x, Agent(grugops-orchestrator)"}` |

Purpose: the module's own comment says the recogniser "CALLS the one constant rather than restating
it … nothing here decides what a header LOOKS like." That is true of the *indicator* and false of the
*position*: choosing the top-level key charset is a decision about which nested keys can carry a
header, and it is the wrong grammar for that question. This is one grammar doing two jobs — the
weaker-duplicate shape this module deletes on sight — so the fix is to give the nested question its
own production derived from YAML's own rule, and leave the top-level grammar alone where its
narrowness is the intended refusal.

Output: a nested block-mapping entry production, the four spellings closed, a derived key-spelling
axis adjudicated by the loader, a gate-level plant flipping exit 0 to non-zero, a mutation control
proving the new pin can fail, and D-60 recorded.

Implements the round's structural mandate (delete the second grammar), D-30 (ask which set the
predicate enumerates — here, which nested keys it admits), D-52 / D-56 item 1 (the pin is a derived
axis, never a hand-listed row table), D-09 / KIT-03, D-40 and D-19.
</objective>
