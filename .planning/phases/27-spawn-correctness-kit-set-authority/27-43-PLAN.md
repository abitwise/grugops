## Why the two families are ONE fact

```
family (a)   the key line carries NO value, so the CONTINUATION line is the node start.
             nodeOnKeyLine is false -> startsNode is TRUE, but inScalar is false, so the
             carry is skipped and the quote's state dies at the boundary.

family (b)   the quoted scalar opens MID-LINE inside a flow collection.
             nodeOnKeyLine is already true -> startsNode is FALSE and inScalar is false,
             so the carry is skipped for the second time, by a different route.

one fact     "may a node begin at THIS OFFSET" is a property of the position, and the only
             place the position is known is inside the walk that visits it.
```

## The rule, stated once

```
the scanner is TOLD           whether offset 0 of the line it is handed is a node start
the scanner TRACKS            unclosed [ and { seen outside quotes, and whether a node may
                              begin at the position it has reached (true after an opener,
                              after a comma, and after a `: ` separator inside a collection;
                              false once a content character of a node has been consumed)
the scanner RETURNS           the exiting state, with the open quote ALREADY GATED — non-null
                              only when the quote that is still open was opened where a node
                              may begin
the three sites DO            one assignment: store the returned state. Nothing else.
the deleted predicate         the separate node-start-quote helper, removed rather than kept
                              beside the walk
```

`stripComment`'s within-line behaviour — the quote toggles, the backslash skip inside double quotes,
and the condition under which a `#` starts a comment — is byte-unchanged. The gate decides only what
survives the boundary.

<assumption_delta_decision>
**Detector reading:** `pluralization`. The detector's snippets are this phase's own prose about
*deleting* second grammars rather than a second case being introduced, so the honest record is the
generalization, not the plural.

**The noun that is now primary:** **the quote state a scalar leaves open at a line boundary** — one
fact, decided once, inside the walk that visits the position where the quote opens.

**Decision: `promote`.** D-51 promotes that state into the single scanner walk and demotes the three
seeding sites to consumers that store what the walk returned. The per-site derivation of "may this
state cross" is deleted rather than parameterized.

**Rationale:** the three sites were three derivations of one fact, and their union was not the set of
node starts. A fact derived per consumer drifts the moment one consumer is edited alone; a fact
returned by the one walk that can observe it cannot.

**Suggested invariant test:** a source-inspection case asserting the module declares exactly one
crossing gate and that no call site of the scanner conditions the stored state on any expression. It
goes red if a future phase reintroduces a per-site derivation.
</assumption_delta_decision>
