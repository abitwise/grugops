**Why these choices.**
- The heading `## The 5 steps` is pinned by scripts/flow-guidance-text.test.ts (`section(ROLE_SWITCH, "The 5 steps")`), so the line goes under step 2, where a role learns its skills, never as a sixth step (Pitfall 6).
- The AGENTS.md line sits under its own blank line so it is outside every claim anchor's contiguous region (C-28-014 covers line 26 only); `check-claim-anchors` compares anchored regions byte for byte.
- Research Open Question 6 suggested registering the line as a claim. It is an imperative to the agent, which the registry's own `## Adjudicated as NOT a claim` table already excludes (the AGENTS.md coding rules row), so it gets an adjudication row instead, with that reason.
- An install never writes over a user's own AGENTS.md (install/install.ts, the AGENTS.md write rule), so in such a repository this line is absent. Plan 42-07 states that limit in docs/skills.md; the protocol's pointer still names the file, the same way `frontend-ui.md` points to the coding rules in AGENTS.md.
- Protocol sentences are procedural: 20 words at most each, no modal, one instruction each (agent-factory/writing-profile.md WP-02, WP-05).

**Why this plan runs beside 42-01 and 42-02.** It is the wave's only plan that edits the watched kit text, so
`check-diff-disposition` sees no sibling's unfinished edit; it edits no `.ts` source that compiles to a committed `.js`.
