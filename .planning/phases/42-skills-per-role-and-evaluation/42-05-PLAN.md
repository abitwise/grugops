**Decisions taken here (Claude's discretion under D-27).**
- `spawnSync("claude", ["--version"], { encoding: "utf8", timeout: 5000, shell: false, stdio: ["ignore", "pipe", "pipe"], windowsHide: true, maxBuffer: 65536 })`.
  This is the installer's first PATH-resolved exec: every other spawn uses `process.execPath`. It runs whatever `claude` is first on
  PATH, which is why it runs only when Claude Code is an installed host and why the README says so.
- Parse only the first line of stdout with the anchored pattern `^(\d+)\.(\d+)\.(\d+)\b`; observed output is `2.1.325 (Claude Code)`.
  Compare the three integers with those of `CLAUDE_CODE_LEVEL_FLOOR = "2.1.293"`.
- Lines (no planning IDs; install/message-references.test.ts refuses them, and a named README section must exist):
  below: label `advisory`, `Claude Code <x.y.z> is below v2.1.293, the version the junior engineer level needs; see install/README.md "The engineer level adapters (Claude Code only)"`;
  at or above: label `ok`, `Claude Code <x.y.z> meets the v2.1.293 floor for the junior engineer level`;
  cannot check: label `advisory`, `the Claude Code version was not checked: <reason>`, where the reason is one of
  "`claude` was not found on PATH" (ENOENT or EINVAL), "`claude --version` did not finish within 5 seconds",
  "`claude --version` exited <status>", or "its first line does not start with a version number".
- On Windows an npm-installed `claude` is usually a `.cmd` shim, which Node refuses to spawn without a shell (research A3, `[ASSUMED]`).
  The doctor never uses a shell, so there the result is "not checked", never a wrong verdict.
