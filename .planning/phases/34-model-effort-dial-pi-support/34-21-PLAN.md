## Diagnosis (brief §2.1), from source at planning HEAD b8845443

- Compare side: install/uninstall.ts:901, in removeOwnedEmptyFile, runs
  `recordMatches(own.entry.content, result.before, result.beforeMode)`. `beforeMode` is the mode read
  before this run's block removal (:829, :833).
- Why no row reaches it: install/record-truth.test.ts:356-369 (the L1 rows) make the edit with
  userModeEdit, which clears the write bits (installer-paths.test-support.ts:290). For the two pointer
  files the block removal writes first, and a read-only file fails that write, so the row passes
  through the write-failure path (exit 3 accepted). The test says so at :333-335. The direct case
  (:336-354) tests modeMatches and recordMatches alone and cannot see what removeOwnedEmptyFile passes.
- Write side of the fix: a writable mode change is a POSIX-bits change. Windows keeps only the
  read-only attribute of a file (WIN-2), so on Windows the act cannot be staged. The row asks the
  measured capability "POSIX permission bits beyond read-only" (scripts/check-platform-shapes.ts:683)
  and prints its skip there, the IN-03 pattern (install/installer-prune.test.ts:210-213, WINDOWS.md
  row 318).
