## Diagnosis (brief §2.1), from source at planning HEAD b8845443

- What is read: install/install.ts:5009 reads both dials off `transformed.text` only
  (`readRenderedDials`); :5021-5022 store each member's alias and level in `aliasOf` and `effortOf`.
- How it is compared: :5056-5068 compare only the SET of distinct levels with
  `announced.effort.levels`. The effort floor is "zero or one" (:3359) and zero lines reads as
  `inherit` (:3371), so a dropped line that leaves the set unchanged passes.
- What the generator announces: scripts/generate-role-adapters.ts:630 announces the distinct levels of
  its resolution map `efforts`; :570 writes the `effort:` line. The announcement does not come from
  the bytes.
- A line can be lost in two places:
  - (A) Between the render and the write. `transformAdapter` (install.ts:3414-3454) drops every
    terminated sentinel block, so a line inside one never reaches the target. The per-member
    render-versus-written comparison D-22 chooses refuses this.
  - (B) Inside the generator. The render itself lacks the line while the announcement comes from the
    map. The render and the written text then agree, so the D-22 comparison cannot see it, and the
    set check sees it only when the set moves. The verifier's reproduction (Gap 2) staged (B) with a
    patched generator. Closing (B) needs a per-member expectation that does not come from the bytes:
    a per-role announcement (the review's alternative) or an independent per-role resolution in the
    installer's probe. D-22 chose neither. Using the render-versus-written check per user decision
    D-22 (the verifier's reproduction suggested the per-role map). (B) is a named residual: stated in
    the code comments (DOC-1), recorded in deferred-items.md by plan 34-23, threat T-34-52, and
    measured once in this plan's SUMMARY (a throwaway run, never a committed test).
- IN-07: install.ts:3221-3236 checks the model announcement with `typeof v.roles !== "number"` and
  the effort announcement with `isCount`, so the two dials have two shape checks. The mirrored
  readers in scripts/model-tiers.ts (:654 and :861) already refuse a non-integer count, so the
  installer's check is reached only when those readers are bypassed; the shape rows below bypass them
  in a synthetic twin.
