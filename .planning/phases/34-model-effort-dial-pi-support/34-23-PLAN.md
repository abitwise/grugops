## Diagnosis (brief §2.1), from source and 34-VALIDATION.md "The two reds the prediction marked green"

- Fixture: install/ledger.test.ts:453 and :637 link to the literal `/some/where`, and :454 and :638
  expect `linkRecord("/some/where")`.
- Producer: treeRecord (install/user-file.ts:454) and backupContentRecord record a link as
  `link:` plus the readlink result, the target as the platform reports it.
- Platform (printed by run 37733716975: `expected 'link:D:\some\where' to be 'link:/some/where'`): on
  Windows Node passes an absolute symlink target through `path.toNamespacedPath`, which resolves a
  drive-less rooted path against the current drive (D: on the leg). Read from local Node v24.12.0 with
  `--expose-internals`; the leg's Node v22.23.3 copy is `UNKNOWN - verify`.
- Fix: an absolute target built with the host's own `join` under the test's scratch directory. Under
  the same reading it is already resolved, so namespacing only adds the `\\?\` prefix that readlink
  removes again, and the readback should equal the input byte for byte. That is a prediction for the
  deferred run (D-21), not a measurement. Not canonicalPathSpelling or realTargetPath: their Windows
  spelling has forward slashes, which Node converts for a link target, so the readback would differ.
