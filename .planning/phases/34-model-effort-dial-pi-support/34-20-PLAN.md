## Design decision: isOwnLink compares through sameRecordedPath (decided from source)

1. Under the posix flavor canonicalPathSpelling is the identity, so no POSIX behaviour changes.
2. Under win32 it folds only spellings that Windows itself treats as one path (separators, the `\\?\`
   prefix, drive-letter case). A link is never owned unless it points at the recorded source.
3. It still fails closed: a relative target, another directory, a non-link, and any lstat or readlink
   error all answer false.
4. Ownership still needs the install record: install-marker.ts:520 owns a `link:` entry only through
   isOwnLink, and uninstall.ts:456 asks it only for a recorded link. Nothing is deleted by presence
   (DC-2).
5. The write side keeps the exact string handed to symlinkSync, so no ledger record changes. The
   comparison spells both sides, so a record in either spelling binds (sameRecordedPath's contract).
