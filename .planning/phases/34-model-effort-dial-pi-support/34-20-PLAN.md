## Diagnosis (brief §2.1), from source at planning HEAD 717eb29b

- What is read: install/install.ts:5009 reads both dials off `transformed.text` only. :5021-5022 keep
  each member's values, and they are used only as SETS (:5039-5068).
- Case (A): `transformAdapter` (:3414-3454) drops a terminated sentinel block, so a line inside one
  reaches neither the target nor any read of the render.
- Case (B): the generator's render() writes a value other than its resolution. Render and written
  text then agree, and only an expectation independent of the bytes can see it. Plan 34-19 provides
  that expectation: the per-adapter map in both announcements.
- With the map, comparing the rendered value and the written value each with the announced value
  covers both cases. If both equal the announced value they equal each other; if they differ, at
  least one differs from the announced value. D-22's direct rendered-versus-written comparison is
  therefore subsumed. The refusal still says which text differs.
- The set checks (:5036-5068) are subsumed as well: the validator proves each announced list equals
  its map's values, and the loop proves each member equals its map value. They are removed. The
  role-count checks (:4909-4932) stay, because they fire before any read and name both numbers.
- IN-07: :3221-3236 checks the model announcement with `typeof` and the effort announcement with
  `isCount`.
