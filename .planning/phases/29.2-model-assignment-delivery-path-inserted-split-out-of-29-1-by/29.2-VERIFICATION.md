verification. Per this project's established rule that a green test suite is not proof of a
safety invariant, this defect is treated as a phase-blocking gap rather than a note for later.

### Gaps Summary

The phase's stated goal — a `models` block written into a target repo changes the adapters that
repo's session loads — **is achieved and independently reproduced** across every documented
decision (D-01 through D-16): fresh delivery, idempotent re-run, staleness detection, illegal-block
refusal, hand-edit ownership, the target-true banner, the rewritten kit prose, the `--update`
boundary, and the changelog entry all hold exactly as designed.

The phase does not, however, meet the bar for "complete" under this project's own standing rule
that a green test suite is not proof of a safety invariant. `29.2-REVIEW.md`'s CR-01 finding — a
live symlinked target-adapter destination is written through, silently destroying whatever file it
points at (which can be entirely outside the target repository) — was independently reproduced in
this verification, not merely trusted from the review report. It directly violates CLAUDE.md's
project-wide installer constraint ("never overwrite or delete user content") and D-13's own stated
rationale for why unconditional rewrite is safe ("CLAUDE.md's never-overwrite rule protects USER
content, which a generated file marked 'do not hand-edit' is not" — a claim that is false exactly
when the "generated file" is actually a symlink to something else). The defect predates this phase,
but this phase is what turned the ordinary re-run into the *documented, routine* delivery mechanism
for a `models` edit (D-07/D-15), which is what promotes it from a latent residual to a release
blocker, per the review's own reasoning. It remains unfixed as of the latest commit on the tree.

Two of REVIEW.md's five warnings (WR-01 dry-run/real-run disagreement, WR-02 a stale "where config
is read from" claim in `factory.config.md`) are also real, independently significant, and left
open, but neither causes data loss or misrepresents the phase's core delivery claim — they are
recorded here as warnings, not additional blocking gaps.

**Recommended next step:** close CR-01 (the fix REVIEW.md proposes is a small, well-scoped
`isSymlink(dest)` guard mirroring `linkOrCopy()`'s existing pattern, plus the matching guard in the
`--check` doctor's read path and a regression test) before this phase is marked complete.
