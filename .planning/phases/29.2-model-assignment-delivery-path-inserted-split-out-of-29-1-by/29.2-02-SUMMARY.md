## Accomplishments

### Task 1 — the second slot and the skip-if-identical write (`8283755`)

- **`transformAdapter(srcText) -> { text, banners }`** — the pure half of materialization, extracted from `materializeAdapter`. ONE state machine over BOTH slots: either open sentinel starts a buffered block, the matching close drops it, the kit slot line injects the kit block above itself, and a line equal to the generator banner is replaced by the banner block and counted. Whole-line equality throughout, never a pattern, matching `srcCarriesSlot`'s routing test exactly. CR-01's bounded removal now covers the second slot **because there is only one loop to give it**.
- **`materializeAdapter` is build-then-compare-then-write (D-11).** It builds the FINAL text, reads the destination's current text, and writes only on difference — reporting `skipped … (identical copy present)`, the wording `linkOrCopy` already prints, when they match. `mkdirp` moved below the comparison so an identical case touches nothing at all.
- **The target-true banner (D-14).** `KIT_BANNER` (byte-equal to the generator's `PROVENANCE`), the `BAN_OPEN`/`BAN_CLOSE` pair, and `TARGET_BANNER` are declared beside the existing materialization sentinels. The replacement names the install re-run **and where it is run from**, and names `.grugops/factory.config.json` as the model source. It names no preset, no alias and no cost.
- **The banner count floor**, asserted in the agents loop's existing pre-write pass — the one that already reads every rendered file's bytes for `readRenderedAlias` — so a bad count refuses **before the first write** and the render's all-or-nothing posture is preserved. Its comment states what bounds its input: bytes this run rendered for an AGENT adapter, never the slot-carrying skill, which legitimately carries zero.
- **D-13 ownership recorded in the writer's own comment**, including *why* it is not `materializeRunnable`'s never-overwrite contract: under never-overwrite a models edit could never reach an adapter someone had once touched, and the doctor would warn about it forever.

## Decisions Made

- **The transform is a pure function with three callers, not a flag on the writer.** The writer, the pre-write banner floor and the read-only doctor all reach one authority. A doctor that recomputed "what would be written here" its own way would be a second grammar over the same bytes — which is the class D-09 exists to avoid.
- **The banner count floor lives at the agents call site, not inside the transform.** The transform serves the skills loop too, and the one slot-carrying skill legitimately carries zero banner lines. The predicate is asked only where the caller knows what it is looking at, and the bound is written down beside it.
- **The doctor does not restate the twins pre-check.** `renderAdaptersInMirror` already refuses a partial checkout by name and counts the absent members. The doctor adds the severity and the sentence. A second implementation of one predicate inside the doctor is the duplicate-authority class this repository keeps deleting; what the doctor owns is the tier, not the test.
- **`--dry-run` does not print the staleness verdict.** The verdict lives only inside `doctor()`, so no crossover exists to suppress; plan 01's resolution report remains the dry-run surface.

## Deviations from Plan

### 1. [Rule 3 — Blocking] The mirror's input constants had to move above the doctor

- **Found during:** Task 2, before the doctor could call the render at all.
- **Issue:** Plan 01's summary recorded that `renderAdaptersInMirror` is a hoisted `function` and therefore reachable from the doctor "with no temporal-dead-zone hazard". That is true of the *function*, and false of what its body reads. `GENERATOR_TWINS`, `GENERATOR_KIT_SOURCES`, `MIRROR_PACKAGE_JSON`, `RESOLUTION_PROBE_REL` and `RESOLUTION_PROBE_SOURCE` are `const` bindings declared roughly six hundred lines *below* the `if (CHECK) process.exit(doctor())` branch. A `const` is in its temporal dead zone until the module reaches it, so the first `--check` run that tried to render would have thrown `Cannot access 'GENERATOR_TWINS' before initialization` — a crash, at the exact moment the feature first mattered.
- **Fix:** the five constants and their comment block moved to sit beside the materialization sentinels, above the doctor. **This is the file's own established remedy, not a new one:** the `MAT_OPEN`/`MAT_CLOSE`/`MAT_SLOT` block already carries a comment saying it is "Declared HERE (before the doctor) so the doctor's adapter `KIT=` parser can reference them under `--check`", and `report`/`mkdirp`/`sameContent` carry the same note. The moved block now carries its own paragraph saying why it moved, and a note at the old site points to it. The function and its interfaces did not move.
- **Verification that the move is behaviour-neutral:** `npm run typecheck`, `npm run build` and the full `install/install.test.ts` suite (101 passed at that point) were run immediately after the relocation and before any doctor code was written. Nothing changed.
- **Committed in:** `b3ea90a`.

### 2. [Rule 2 — Missing critical] The doctor's no-verdict relay, and the twins pre-check not restated

- **Found during:** Task 2.
- **Issue:** the plan's action text says "Before building the mirror, check the presence of the four generator modules under `GRUGOPS_SRC`." Implemented literally, that is a *second* implementation of a predicate `renderAdaptersInMirror` already owns — the set-literal / duplicate-authority failure class this repository's memory names twice over.
- **Fix:** the doctor branches on the helper's own `ok: false` result and relays its reason (re-indented to align under the padded report label), prefixed with the sentence that makes an absent verdict legible as one. The observable behaviour the plan asked for is unchanged: the finding names how many of the four are absent and which, names the checkout, says no adapter was compared, gives the re-run remedy, is a WARN, and escalates under `--strict`. All of that is asserted, per twin in turn.
- **Discrimination measured:** deleting the relay (`if (!res.ok) { return; }`) makes a partial checkout produce **no line at all** — the silent-clean shape — and the case reds on `named=false`. Recorded as mutation B2 below.
- **Committed in:** `b3ea90a`.

### 3. [Rule 1 — Bug] The plan's first mutation for task 1 is unreachable as written, and was replaced by one that is

- **Found during:** Task 1's mutation round.
- **Issue:** the plan asks for "delete the banner strip pass and confirm the idempotence case reds naming the doubled block." A doubled block is **not reachable on the agents path**: an agent adapter's bytes come from a fresh mirror render, which emits exactly one generator banner and no prior sentinel block, so deleting the strip pass changes nothing there.
- **Fix:** the strip pass is exercised where source bytes still reach the transform — the resolver **skill**, which is materialized straight from `$GRUGOPS_SRC`. This is precisely the relocation plan 01 already made for the CR-01 kit-block case, and for the same reason, which is recorded in that case's own comment and now in this one's. A planted prior banner block must be dropped; a planted *unterminated* one must restore every line it buffered, in order.
- **Measured:** with the strip pass deleted, the planted block survives into the target and the case reds. Recorded as mutation 1 below.
- **Committed in:** `8283755`.

### 4. [Rule 2 — Missing critical] The banner count floor had no behavioural fixture

- **Found during:** post-Task-1 review of the count floor.
- **Issue:** the floor is the mechanism that makes the hand-synced banner literal safe, and its dangerous direction is silent (recogniser matches nothing → every target keeps a banner naming a command it cannot run → suite stays green). The anchor for the patch is derived from `provenanceLiteral()`, so the case does not spell the literal a second time, and `patchSyntheticGenerator` throws if the anchor is absent, which is the case's premise assertion.
- **Committed in:** `8283755`.
