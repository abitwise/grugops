## Flagged assumptions

- A sibling that is absent is no finding: a host may run state-check alone, and the existing host-emulation tests copy it
  alone. Only a present sibling can disagree.
- The stamp is a version marker between programs, not a security boundary: a contributor who can edit tools/grugops/ can
  edit the stamp too (T-37-54, accepted).
- Reversibility: costly (flagged on Task 1). The stamp line's shape (`export const RUNNABLE_SET_STAMP = "sha256:<64 hex>";`
  plus RUNNABLE_SET and RUNNABLE_SELF) becomes a contract between programs on every host from the next release; a later
  change to it must keep reading this shape. The shape is owned by one module so that a change is one edit. This is a
  planner assumption, not a CONTEXT.md decision (decisions there are the human's): the SUMMARY names it under
  `For the human` so the orchestrator can raise it before the release that ships it.
