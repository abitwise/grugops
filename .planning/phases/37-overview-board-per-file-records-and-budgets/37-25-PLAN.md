## Flagged assumptions

- V8 reports a call's frame at the line of the called name, also for a method call split over lines (checked during
  planning on Node 26.11.1); a site's line is therefore the line of its callee name token. The fired-fault count of each
  row is the check that this held for every site.
- The same rule decides a via line. While a function runs, the frame of the scope that entered it sits at the call that
  is executing in that scope: for a direct call, the callee name token of that call; for a function handed on as an
  argument value (directly, or as a property of an object literal argument, as trace-render does with
  `collectTraceNotes(present, { listTasks, readTask })` and `compareTraceTree(plan, root, { readText, listDir }, ...)`),
  the callee name token of the outer call that receives it. A bare identifier reference elsewhere (the first mention of
  the name, a stored or returned function) is not a frame line, so callingSites derives via lines from call expressions
  only and throws on any other reference shape, naming its line, so a new indirection is added to the derivation rather
  than dropped.
- The preload captures each stack with no depth limit (plan 37-20), so a via frame deep in a call chain is still matched.
