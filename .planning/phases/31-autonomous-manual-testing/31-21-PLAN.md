<objective>
Close **CR-12** and **WR-22** of `31-REVIEW.md`, both independently reproduced by `31-VERIFICATION.md`
round 5 against the committed `scripts/context-io.js`.

Round 4's `31-18` closed CR-11 — a caller-forged note silently overwriting an already-admitted
destination note — by putting a destination READ at `writeNoteFile`, the module's single note-write
chokepoint. That closure is real and is independently re-verified (verification rows 5 and 6). What it
cost is CR-12: the read is an unguarded `readFileSync`, and `readFileSync` on a path that is not a
regular file BLOCKS at `open(2)` with no timeout. A FIFO planted at a note path therefore wedges
**every writer in the module** — `appendNote`, `appendPreAdmittedNote`, `admitAndAppend`,
`promoteAdmitted`, `emitTrusted`, `emitVerdict`, `emitCheckpointNote` all end on that line — silently,
on both streams. Measured: `timeout 10 node …` → exit 124, zero bytes of stdout, zero bytes of stderr.

This is not a novel hazard in this repository. It is finding `RA1-2` of plan 30-11 round 2, measured
on the committed guards at 20 seconds, and this same file's `readGovernanceConfigCandidate` carries a
25-line header explaining it and a reader that refuses it — 2,400 lines below the new unguarded read.
One allowed `mkfifo` turned BOTH guards off then; it wedges every note write now.

WR-22 is the same write path's second defect. `promoteAdmitted` writes the note FIRST and appends the
GOV-02 ledger event SECOND, and `ledgerRecordsId` fails OPEN on an unreadable ledger. So the sentence
`agent-factory/workflows/18-context-compaction.md:83` added last round — "the destination never holds a
human-disposed finding with no ledger line" — is an assertion, not a property: the review MEASURED the
converse with a FIFO at the ledger path (`timeout 15` → exit 124, the note already written), and an
unreadable ledger silently produces the duplicate event D-19 (4) exists to prevent.

Purpose: make the destination read bounded and fail-closed through the authority this module already
owns, and make the ledger-before-note ordering a property rather than a sentence.

Output: one module-private non-blocking regular-file reader consumed by `writeNoteFile`,
`ledgerRecordsId` and `readGovernanceConfigCandidate`; a named refusal for a note path that is not a
regular file; an inverted, fail-closed ledger step in `promoteAdmitted` with a new decline clause; two
new DERIVED axes in `scripts/context-io-writer-set.test.ts` (unguarded read sites, and the write ORDER)
each with a two-sided count and a watched-fail mirror; a corrected, retention-scoped workflow sentence;
and decision **D-24** appended to `31-CONTEXT.md`.
