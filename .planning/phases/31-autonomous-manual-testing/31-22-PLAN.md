<objective>
Close **CR-16** and **WR-25** of `31-REVIEW.md`, both independently reproduced by `31-VERIFICATION.md`
round 5, and make `agent-factory/workflows/18-context-compaction.md` true of the mechanism.

Round 4's `31-18` closed WR-17 — a proof whose left operand the benefiting caller supplies — by
constraining the origin. That closure holds for an origin OUTSIDE the repository. It does not hold for
the case that matters: the agent calling `promoteAdmitted` runs INSIDE the repository, so every
directory it can create sits under `trustedRepoRoot()` and satisfies the second arm
`resolvedFrom.startsWith(trusted + sep)`. The verifier measured it directly — legitimately-obtained,
human-disposed bytes copied into an ordinary directory the caller made under the repository root, with
no `.grugops/context` shape anywhere on the path, promoted into a fresh destination id: `promotedId`
returned, `threw` was `null`, the destination holds the file. That is verbatim the action the workflow
tells the agent is "mechanically refused".

WR-25 is the same route's answer being misdirected. The measured clause order puts
`human-stamp-not-gated-at-destination` ahead of `origin-outside-trusted-store`, so under `off` or an
absent configuration — the lean posture most repositories run — a caller naming a forged origin is told
the destination's DIAL is the problem, and the workflow's remedy for that clause is to set the dial. A
caller following the message widens a gate in response to an origin fault. The safety consequence is nil
(all four dial values refuse) but the register's entire reason for existing is that the caller is told
WHICH clause failed.

Purpose: give the origin check ONE canonical form and refuse everything outside it by name, and make the
clause a caller sees the one that actually describes its input.

Output: a single-arm `originIsTrusted`; a rewritten `T-31-18-01` residual true of the narrowed
mechanism; a decided disposition for the `to` argument (constrained or named); the clause order inverted
and made a DERIVED axis with a transposed watched-fail mirror; corrected workflow sentences at `:56` and
`:75`; and decision **D-25** appended to `31-CONTEXT.md`.

**Ordering note:** wave 2, `depends_on: ["31-21"]`. This plan and `31-21` both modify
`scripts/context-io.ts`, `scripts/context-io.js`, `scripts/context-io-writer-set.test.ts`,
`hooks/hook-entry.ts`, `hooks/hook-entry.js`, `agent-factory/workflows/18-context-compaction.md` and
`31-CONTEXT.md`, and both edit the SAME function body (`promoteAdmitted`). Sequencing removes the
conflict and means this plan's clause-order derivation runs against a body whose ledger step has already
moved, so the derived order is measured once against its final shape rather than twice against two.

**Assumption delta:** `no-change`. Both detector hits are already decided in `31-CONTEXT.md` (D-14,
D-21); no identity-model question is open for this plan.
