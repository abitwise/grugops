Round 4's `31-19` closed WR-21 — an unbounded upward governance-root walk that adopted a
home-directory-shaped ancestor — by halting the search at the user's home directory. That closure is
real and is independently re-verified. What it cost is CR-13: the halt is asked BEFORE the directory is
inspected, at every step. So a repository whose root IS the home directory has its own `.git` and its
own `.grugops/factory.config.json` skipped entirely, and `trustedRepoRoot()` falls through to the kit,
whose shipped dial is lean. Measured: with `HOME` set to a planted repository root carrying `.git` and
`human_admission: high-severity`, the resolution returned the kit and the dial read `off`; the identical
tree one level below the real home read `high-severity`. The two runs differ in nothing but whether the
repository root is the home directory.

That is the WR-15 verdict direction exactly — **a configuration moving from refused to admitted** — and
this same file already rejects `.grugops` as a boundary marker on precisely that ground. On the four
hosts D-12 names as having no attended lane, the in-script refusal is the only tier there is.

**The review's fix sketch is not adopted verbatim, and this plan states the reason in the source.** The
sketch assigns `nearest = dir` before asking whether `dir` is home and then returns `nearest`, so a home
directory carrying only `~/.grugops/factory.config.json` — the exact tree `install/install.ts` creates
under the shipped shared-install model — would be adopted. That is WR-21's own hole, restored. The
adopted rule is strictly narrower: at the home directory the walk demands a version-control boundary
marker as well as a configuration, and home never becomes `nearest`.

Purpose: make the bound bound ASCENT rather than OBSERVATION, without reopening the hole the bound was
added to close.
