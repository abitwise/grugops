<objective>
Give the UAT-spec runnable's own coverage gate an oracle that does not move under it, and stop the
walk's input boundary from narrowing a host's denominator in silence.

Three items land here, all in one file family, all about a claim that outran its mechanism:

1. **The suite-RED regression** (`31-VERIFICATION.md` round 7, frontmatter `regressions`, spot-check
   row 7; `31-REVIEW.md` Anti-Patterns row 5). The self-check derives its expected finding-id set by
   walking `31-REVIEW.md`'s current `###` headings and compares it against `CORPUS_COVERAGE`, a
   hand-typed literal. This project fully REPLACES `31-REVIEW.md` every round, so committing a review
   turns the suite red with zero source change. It is red at the round base.
2. **WR-35** — `.temp` in `SKIPPED_DIRECTORIES` bakes this repository's scratch convention into a
   runnable the installer materializes into every host at `tools/grugops/uat-spec-integrity.js`, and
   the narrowing is invisible because `expected` and `visited` shrink together.
3. **IN-16 / IN-17** — `TEST_INFO_CANONICAL_HEAD` outlived the mechanism D-30 (5) deleted, and a doc
   block in `deriveDeclaredBindings` is spliced mid-clause.

This plan is FIRST in the round for a mechanical reason: plans `31-34` and `31-35` both verify against
`scripts/runnable-ref/uat-spec-integrity.test.ts`, and a harness that is red at the base cannot tell
them whether their own fix worked.

Purpose: a round that measures itself needs a measuring instrument whose reading does not depend on
which document was committed last.
Output: a frozen, committed corpus manifest; a two-sided derived coverage equality; a disclosed input
boundary; a dead export and a spliced sentence removed; decision `D-33` recorded.
</objective>
