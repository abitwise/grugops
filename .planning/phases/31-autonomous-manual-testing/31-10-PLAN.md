<objective>
Close the second `missing:` item of gap 1 in `31-VERIFICATION.md` round 2: extend
`scripts/context-io-writer-set.test.ts` from one refusal-family question to one per refusal family
`admit()` implements, so a writer that reaches only one family cannot read as closed.

Purpose: this is the anti-recurrence half of CR-05, and it is the item the round-2 verifier singled
out as the reason the shipped suite could not see the defect. 31-05 derived the WRITER set by AST and
asserted its cardinality — correct — and then asked every member exactly one question, `"refuses the
fabricated artifact-ref"`. The set that was derived was the writers; the set that was enumerated by
hand had one member. The project's own doctrine for this round is "derive BOTH axes and check the
converse": this plan derives the second axis from `admit()`'s own source, exercises the full cross
product, and proves the probe set discriminates before it is trusted.

Output: a `scripts/context-io-writer-set.test.ts` whose refusal-family set is read off `admit()`'s
parsed body, whose exercise table is a (writer x family) matrix asserted equal to the cross product
of two derived sets, whose probes are proven to trip every derived site, whose converse is tested,
and whose derivation and refusals have both been watched failing.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the contract test -> the module it measures | The test derives its expectations from the module's source; a derivation that silently measures nothing produces a green result that means nothing. |
| a future writer or refusal site -> the shipped contract | Anything added to the module later must move a derived set, or it lands outside the contract exactly as CR-05 did. |
| the committed `.js` -> the TypeScript source | A host runs the `.js`; a test that only drives the `.ts` measures something no host executes. |
