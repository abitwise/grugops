without a lowered safety floor. Today the gate refuses `dropped` on an `architecture` row and a dropped row must keep its anchor.

**The retired arm, as D-25 states it.** A retired row stays in the registry with its id, a reason and the commit; its text leaves the
file; the gate checks the retired text is ABSENT from the named file. Copy the unanchorable PRESENCE loop in
scripts/check-claim-anchors.ts (about lines 422-460) and invert it: fail when `bytes.includes(Buffer.from(claim.verbatim, "utf8"))` is
true, and fail when the file still carries the canonical anchor line for the id. Retired rows are removed from the input to
`anchoredDocs` (scripts/audit-model.ts about line 1935) or filtered at the caller, so a file whose only rows are retired is not scanned
for a bijection it no longer owes. The `dropped`-on-non-safety refusal (check-claim-anchors.ts about lines 305-318) stays as it is.

`retired` too: a retired claim is not a finding, it is a withdrawn sentence. Instead require the mechanism to carry the reason and
the last commit where the text stood, written as a backticked hex token of 7 to 40 characters. Write the reasoning above
CLAIM_STATUSES in the style of the existing comment block (about lines 101-130) that explains why `dropped` cannot launder `false`.

check-audit-register.ts. generate-guarantees reads safety rows only; retired is refused on safety rows, so the guarantees join is
untouched.
