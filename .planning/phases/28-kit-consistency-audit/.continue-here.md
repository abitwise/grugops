## The fix worklist — 4 blockers

Full detail, with reproductions, is in `28-REVIEW.md`. Summary:

**CR-01 — `scripts/check-uat-oracles.ts:334-335`** *(the most severe)*
`if (rows.length === 0) continue;` skips the 5-tool-table asymmetry assertion entirely when no rows match, **while still printing** `PASS  WR-05 wording: … the 5-tool-table flip is asymmetric`. Reproduced by deleting the Claude Code row from both `agent-factory/packaging/adapters.md` and `agent-factory/README.md` in a mirror → `ALL CHECKS PASSED`. The gate pins `rows.length > 1` but never `=== 0`. A PASS line asserting an unperformed check is a fabricated gate result, which `CLAUDE.md` forbids outright.

**CR-02 — `scripts/audit-model.ts:838-842`**
`readRegistry()` does `meta[m[1]] = m[2].trim()` with no duplicate-key detection — last wins, silently; unrecognised lines are dropped. A claim block carrying `- status: false` … `- status: true` parses as `"true"`, and `check-claim-anchors.ts:293` short-circuits on `status === "true"`, skipping every D-17 disposition / `finding_id` / `target_phase` obligation. Note the asymmetry: `readRegister()` refuses duplicate row keys and duplicate finding ids at `audit-model.ts:464`, and `context-io.parseNote` calls a duplicate key *"the on-disk signature of a field-injection forgery."* `readRegistry` is the only one of the three that is silent.

**CR-03 — `scripts/check-claim-anchors.ts:249-269`**
An empty verbatim fence yields `want = [""]`, compares against the blank line below the anchor, and passes: `1 verbatim comparison(s) performed, all byte-identical`. The gate already refuses a vacuous bijection at *document* level; the same argument is simply unapplied at *row* level.

**CR-04 — `scripts/check-audit-register.ts:113-119`**
`normalizeObservation("—")` returns `"—"` — neither blank nor bare — so it satisfies D-06's substantive-observation requirement. `audit-model.isBlank()` and `check-claim-anchors`' mechanism check both treat `—`/`-` as blank. This is the **third** definition of "blank" in one phase and the only one that disagrees — on the glyph that is the register's own unfilled marker, i.e. the one an author is most likely to type into an unread row.

**Three of the four are one shape:** a vacuity floor that exists at the collection level but not at the element level. Fixing them one at a time, four times, would repeat the mistake — consider whether one element-level vacuity rule belongs in `audit-model.ts` as the shared authority.
