<objective>
Read all 17 roles, plus the one protocol file that counting excludes and drift does not, and record a
verdict for each.

Per D-06 this is a real read under a mechanical pre-pass, not a pre-pass reported as a read. The
pre-pass emitted evidence rows for the greppable predicates in 28-03; this plan seeds those findings
into each file's read so the reader starts from evidence, and then requires a substantive observation
in every row. An agent reporting an absence of findings is narrating rather than demonstrating, which
is why the bare word is refused by the gate and why the register states the limit in plain text
instead of implying it away.

Per D-06's rationale these files are read inline rather than fanned across subagents. Fanning 17
files across subagents would make every verdict an unbacked agent claim — the green-proved-nothing
shape multiplied by 17, in a repository whose recorded lesson across a whole milestone is that a green
result is not evidence.

Per D-07 six named categories are applied to each file, and the sixth — would two agents reading this
step reach the same act — is record-only. Its findings are dispositioned deferred to Phase 29 by
default, which the parse authority enforces. That gives LANG-02 a located worklist and structurally
prevents this audit from becoming a style pass on prose Phase 29 is about to rewrite.

Per D-02 the underscore-prefixed protocol file is read once even though it does not count, because
`docs/design/shared-install.md` records its step 4 demanding a handoff file — making it one of the
likeliest drift carriers in the tree, and dropping it silently the exact failure shape this project
keeps hitting.

Per D-18 the `safety_surface` flag is captured now, while the reader is already in the file.

Purpose: turn 18 files from unread into recorded, with findings located and dispositioned.
Output: 18 filled register rows and their finding rows.
</objective>

## The rubric, restated so it is applied rather than recalled

Six categories. Every file gets all six asked of it. Every finding names the one it came from.

| # | Category | The question |
|---|---|---|
| 1 | Factual correctness | Does this file describe the architecture that ships — decompose rather than route, shared verified context rather than a handoff relay, the three spawn tiers? |
| 2 | Reference integrity | Does every path, role, workflow, checklist and config key it names resolve on disk? |
| 3 | Claim honesty | Is anything unproven stated as fact? Is `UNKNOWN - verify` present where something is genuinely unknown? |
| 4 | Internal consistency | Do its counts, versions, tier names and config keys agree with the schema and with sibling files? |
| 5 | Strangeness | Are there vestigial sections, contradictions, dead options, or text with no remaining reader? |
| 6 | Instruction determinism | Would two agents reading this step reach the same act? **RECORD-ONLY — deferred to Phase 29.** |
