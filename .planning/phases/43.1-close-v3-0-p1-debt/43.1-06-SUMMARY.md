# Phase 43.1 Plan 06: Kit-home overlap by device and inode (D739) Summary

**The kit-home overlap refusal now compares directory identity (dev:ino of the existing part of the real path, then the missing names) beside the real-path string, so a kit home spelled through a macOS firmlink under `/System/Volumes/Data` can no longer pass the check and replace the in-repo `agent-factory/`.**

## Accomplishments

- `pathNodes(p, stat?)` in install/user-file.ts gives the identity of a path that may not exist yet. It walks the real spelling from `realPathThroughExisting` (never the user's spelling), starting at `path.parse(real).root`. Each existing component gets `dev:ino` from a bigint stat, and each component after the first ENOENT gets its name only. It returns null when the real path cannot be read, when a stat fails with any code other than ENOENT, or when the root has no identity.
- `kitHomeOverlap` is a pure decision. `overlapBySpelling` is today's string rule, moved over unchanged. The identity test checks the same shapes over node lists: same directory, or one inside the other, found by locating one list's leaf anchor inside the other list. A hit by either test refuses.
- A degenerate guard: a node list in which an existing node reports its parent's `dev:ino` takes no part in the identity test. The string test then decides alone, which is the rule of scripts/context-io.ts's home-boundary builder.
- install/install.ts builds the node lists for the kit root, the kit home, the target and each kit entry, and calls `kitHomeOverlap` once. A null node list joins the existing could-not-be-read list with the same message. The overlap message, exit 1, empty stdout and the block's position are unchanged. A dated "Since plan 43.1-06" paragraph was added to the block comment.
- A 12-case D739 describe with injected identities covers the four REFUSAL_VARIANTS shapes (each one also a mutation proof), distinct identities, a missing tail refused and accepted, a real scratch directory, EACCES, and the degenerate platform.

## Decisions Made

- The string test stays first. When it hits, the reported entry is exactly what install reported before this plan; the identity test only answers when the string test does not.
- Nodes compare by identity where both have one, and by name otherwise. Where a kit home's missing component meets an existing target component of the same name, that counts as a match, so the check errs toward refusing.
- The degenerate guard lives in the pure decision rather than in `pathNodes`, so tests with injected node lists can reach it.
