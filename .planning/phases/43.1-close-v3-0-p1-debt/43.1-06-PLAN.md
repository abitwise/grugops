**Why a string test misses it.** A firmlink is not a symbolic link, so `realpathSync.native` keeps the spelling; on macOS the two
spellings of a firmlinked directory reach the same Data-volume inode (cited, not run here: RESEARCH A1). A symlink-based test proves
nothing about D739, because realpath already resolves links (Pitfall 9). Unprivileged bind mounts are blocked on this machine
(`unshare -Urm` gives EPERM; AppArmor restriction 1), so the pin injects identities: it is the only way to make a case that is red
on the string test and green on the identity test here. A real macOS run stays `UNKNOWN - verify` (43.1 CONTEXT, deferred).

**Design (RESEARCH Item 7).** Represent a path as a list of nodes, root to leaf: each existing component carries its name and
`dev:ino` (from `statSync(prefix, { bigint: true })`, since `ino` can exceed 2^53); after the first ENOENT every component carries
its name only. The walk runs over the REAL spelling from `realPathThroughExisting`, starting at the spelling's root
(`path.parse(real).root`, so a drive root works), never over the user's spelling. Same directory: both leaves exist and share
`dev:ino`, or both are missing with the same deepest existing `dev:ino` and the same missing names. Inside: the parent's leaf
anchor (its deepest existing `dev:ino` followed by its missing names) occurs in the child's list before the child's leaf. Compare
names only where a node has no identity. Degenerate guard: if any existing node reports the same `dev:ino` as its parent node while
the two spellings differ, the identity test answers "no overlap" for that path and the string test decides (copy the rule of
scripts/context-io.ts near line 5689).
