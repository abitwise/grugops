**Cause found and reproduced.** The test (`install/install.test.ts:6906-6915`) asserts two things. `[VERIFIED: CI log run 44074559757]`

**How existing installs are handled today** (read this session):

## Item 7: D739 — kit-home overlap by identity

**Where:** the overlap refusal is `install/install.ts:3666-3726` (the block after the self-checkout guard). It computes `realKit`, `realHome`, `realTarget` with `realPathThroughExisting` and compares strings: `k.realAt === realTarget || within(k.realAt, realTarget) || within(realTarget, k.realAt)` and `realHome === realTarget || within(realHome, realTarget)`, with `within = (child, parent) => child.startsWith(parent.endsWith("/") ? parent : \`${parent}/\`)` (line 3697) `[VERIFIED: read]`. `realPathThroughExisting` is `install/user-file.ts:404-424`: lstat up to the deepest existing ancestor, `realpathSync.native` on it, append the missing rest, spell canonically; null when unreadable (the caller then refuses).

**Why it misses a firmlink:** red-team B1 (33.1 deferred row, `deferred-items.md:55`) reproduced that a kit home spelled `/System/Volumes/Data<path>` passes and a re-install replaces the in-repo `agent-factory/` (against bdb4da27). Firmlinks are not symbolic links, so the real-path string keeps the spelling. On macOS "All items on the combined System and Data volumes (except /dev) have the same volume ID" `[CITED: eclecticlight.co/2023/09/20/navigating-boot-volumes-in-paths-and-inodes]`, and the two spellings of a firmlinked directory reach the same Data-volume inode `[ASSUMED: secondary sources; not run on macOS this session]`. So `(st_dev, st_ino)` identifies the directory where the string does not.

**Design (keeps every census rule):**

1. In `user-file.ts`, add an identity function built **on** `realPathThroughExisting` (census rule (a) allows exactly two `realpathSync.native` call sites: `realTargetPath` and `realPathThroughExisting`; `install/path-spelling-census.test.ts:407`). Take the real spelling, split it into components, walk prefixes from the root: for each prefix that exists, `statSync(prefix, { bigint: true })` → `{dev, ino}`; the first `ENOENT` ends the existing part; the rest are missing names. Return `null` on any other error (fail closed, as today).
2. Represent a path as a list of nodes root→leaf: existing nodes carry `dev:ino`, missing nodes carry their name. Two paths name the same directory when their leaf nodes are equal (both existing: same `dev:ino`; else same deepest-existing `dev:ino` and the same missing names). `child` lies inside `parent` when parent's node sequence (from its deepest existing node down) appears in child's sequence below the root and child is longer.
3. Walk ancestors of the **real** spelling, not of the user's spelling: a symlink in the user's spelling would otherwise put the link's parent in the chain and refuse a legitimate layout.
4. In `install.ts`, refuse when **either** the existing string test **or** the identity test reports an overlap (union, fail-safe; keeps current behavior on Windows, where `ino` reliability is out of scope and tracked in `.planning/WINDOWS.md`). Use `bigint: true`: `ino` can exceed 2^53.
5. The refusal text and exit code stay as they are (`installer-kit-home.test.ts:95-150` asserts `overlaps the target`, `Set GRUGOPS_HOME to a directory outside the repository`, `Nothing was written.`, stdout empty, zero bytes changed).

**Target not existing yet:** the identity must handle a missing path at any of the three inputs, as `realPathThroughExisting` already does (whether install refuses a missing target before this block was not checked: `UNKNOWN - verify`). The kit home and kit root often do not exist on a first install, which is why the missing-names tail is part of the identity.

**What goes wrong:** a test passes locally and fails on CI's Node 22 (Item 3 is exactly this).
**How to avoid:** for any test that spawns Node or reads Node warnings, run it once under the Node 22 binary too. The official tarball unpacked in a scratch dir works without installing anything system-wide.
**Warning signs:** assertions on stderr text Node itself prints.

### Pitfall 2: Re-point the constant, forget the compiled twin
`scripts/canonical-corpus.ts` is a module with a committed `.js`. `npm run freshness` fails if only the `.ts` changes.

### Pitfall 3: A re-install leaves the old runnable name in place
The ledger carries a held kit-false entry forward, so a dest-only rename without stale handling leaves `test-skip-integrity.js` installed and the host's `node --test` still red. Test the upgrade path, not only a fresh install: install at HEAD~ (old name), then install at HEAD, then run `node --test`.

### Pitfall 4: Editing anchored text without the registry row
Any byte change inside `<!-- claim: C-28-NNN -->` blocks fails `check:claim-anchors` unless the registry verbatim changes in the same commit; for a watched file it also needs the diff-disposition companion. Plan every registry-touching edit in one plan (P5) to avoid merge conflicts on `docs/audit/28-claim-registry.md`.

### Pitfall 5: Editing `audit-model.ts` without regenerating the hook manifest
`scripts/audit-model.js` is hash-frozen in `hooks/hook-entry.ts` `DECIDER_MANIFEST`. Phase 43 hit exactly this (43 deferred-items.md:5-19). Run `npm run generate:hook-manifest` and commit `hooks/hook-entry.ts`, `hooks/hook-entry.js` in the same commit.

### Pitfall 6: Hand-editing generated pages
`docs/GUARANTEES.md`, `docs/reference/**`, the guarantees pointer line in `agent-factory/README.md:67-68` (`<!-- generated: guarantees-pointer -->`) are generated. Change the generator and regenerate.

### Pitfall 7: Rewriting a released CHANGELOG entry
Keep a Changelog: add the D693 precondition and the D66 rename under `## [Unreleased]`; leave `## [2.2.0]` text as published.

### Pitfall 8: Suite comparison by count
Compare failures by test name against the baseline in this file; EDQUOT on the shared `/tmp` tmpfs moves counts between runs.

### Pitfall 9: A firmlink test that cannot fail
A symlink-based "alias" test passes with the old string comparison too (realpath resolves links), so it proves nothing about D739. The pin must be a case that is red on the string comparison and green on the identity comparison.

### Item 7 identity (shape; names are illustrative `[ASSUMED]`)
```typescript
// In install/user-file.ts, beside realPathThroughExisting (no new realpathSync.native call).
export type PathNode = { readonly id: string } | { readonly name: string };
export function pathNodes(p: string): PathNode[] | null {
  const real = realPathThroughExisting(p);
  if (real === null) return null;
  const parts = real.split("/").filter((s) => s !== "");
  const out: PathNode[] = [];
  let cur = "/";
  let missing = false;
  for (const part of ["", ...parts]) {
    if (part !== "") cur = join(cur, part);
    if (!missing) {
      try {
        const st = statSync(cur, { bigint: true });
        out.push({ id: `${st.dev}:${st.ino}` });
        continue;
      } catch (e) {
        if (codeOf(e) !== "ENOENT") return null;
        missing = true;
      }
    }
    out.push({ name: part });
  }
  return out;
}
```
POSIX-only as written; the Windows branch keeps the string comparison (out of scope).
