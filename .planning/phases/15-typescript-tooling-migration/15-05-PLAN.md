<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| grugops kit (dev tier) -> host repo committed path | The installer materializes a compiled `.js` into the host's `tools/grugops/`; it must be additive/never-overwrite and the path must be committed (not gitignored) so host CI sees it. |
| untrusted routine input file -> reference routine parse | The routine reads an input file; a missing/malformed input must yield exit 2 (error), never a crash or a false pass. |
| host CI (only Node) -> materialized routine | The routine must run with only bare Node — no node_modules, no ~/.grugops — or D-11's whole point (central kit absent in host CI) is defeated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-05-Tamper | Tampering | materialization overwriting a user-edited routine in tools/grugops/ | mitigate | `materializeRunnable` reuses the additive/idempotent/never-overwrite shape (skip-if-identical, never `>`-truncate); the install harness asserts a user-edited materialized file is NOT overwritten and a re-run is a no-op. |
| T-15-05-Tamper2 | Tampering / bypass | a kit-shipped routine pulling a host runtime dep so it fails in bare host CI | mitigate | Reference routine uses `node:` builtins only (asserted: no non-`node:` import); the Pitfall-3 host-emulation test runs the materialized `.js` from a temp dir with no node_modules and asserts it still works. |
| T-15-05-DoS | Denial of Service -> bypass | malformed/missing routine input crashing instead of returning a clean error | mitigate | Fail-closed input read (try/catch -> exit 2 error, distinguishable from a clean fail per D-12); the harness asserts the missing-input case exits 2. |
| T-15-05-Info | Information disclosure / availability | materialization path gitignored/uncommitted so host CI can't find the routine | mitigate | `tools/grugops/` is a committed, namespaced path (not `.grugops/` state, not `bin/`); the harness asserts the file lands at the committed path and runs from a checkout-equivalent fixture (Pitfall 5). |
| T-15-05-EoP | Elevation of Privilege | the new install action setting the deploy-approval var or touching protected dirs | mitigate | `materializeRunnable` writes only to `tools/grugops/`; the installer's never-set-deploy-var + never-touch-protected-dirs invariants are unchanged (asserted: no `GRUGOPS_PROD_DEPLOY_APPROVED=` write introduced). |
</threat_model>
