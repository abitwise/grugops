## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] tsconfig missing `types:["node"]` — tsc could not resolve `@types/node`**
- **Found during:** Task 2 (first `tsc --noEmit` of `freshness.ts`)
- **Issue:** With `@types/node` installed, `tsc` still reported TS2591 (`Cannot find name 'process'` / `node:fs` / `Buffer`) and TS2339 (`import.meta.dirname`) — the global/builtin types were not being pulled into the compilation. The plan's Pattern-1 tsconfig did not include a `types` field.
- **Fix:** Added `"types": ["node"]` to `compilerOptions`. This resolves the already-installed `@types/node` (no new dependency); a minimal, conventional tsconfig correctness fix.
- **Files modified:** `tsconfig.json`
- **Commit:** `abe2a87` (folded into the Task 2 GREEN commit since it is the enabling fix for the freshness type-check)

**2. [Rule 3 - Blocking] tsc emitted redundant test `.js` — excluded `**/*.test.ts` from emit**
- **Found during:** Task 2 (the `scripts/**/*.ts` include glob would emit `scripts/freshness.test.js`)
- **Issue:** Vitest transforms and runs `.test.ts` directly and never needs a committed `.test.js`; a `tsc`-emitted test `.js` would either pollute the tree as untracked or become a redundant committed build output the freshness gate then has to check.
- **Fix:** Added `**/*.test.ts` to tsconfig `exclude`. The build now emits only production routine `.js`. Verified `tsc` emits exactly `scripts/freshness.js` and no `freshness.test.js`.
- **Files modified:** `tsconfig.json`
- **Commit:** `abe2a87`

Note on npm's package.json rewrite: `npm install` reordered `devDependencies` alphabetically and rewrote the version specifiers (it wrote `^22.19.21` for @types/node); the specifiers were normalized back to the plan's pins (`~6.0.3`, `~4.1.8`, `~22`) and the lockfile reconciled, all resolving to the identical installed versions. Not a behavioral deviation.

## @types/node Justification (recorded per the plan's `<output>` requirement)

`@types/node` is the one dev-dep beyond D-05's literally-named `{typescript, vitest}`. It is **type-only** — its declarations are erased at compile time, it ships **zero runtime code**, and it never reaches a host machine. It is required for `tsc --strict` to resolve the `node:` builtin imports (`fs`, `path`, `os`, `child_process`) plus the `process`/`Buffer`/`import.meta.dirname` globals these tools use. This is in-bounds under D-05's "minimal + individually justified" reading (Assumption A1, confirmed). **Chosen @types/node major pin: `~22`** — tracks the D-03 Node-22 runtime floor so the types never describe APIs unavailable at the minimum supported Node (Open Question 1 resolution; resolved at 22.19.21).
