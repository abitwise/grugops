## Accomplishments

- **validate-agent-factory.mjs → .ts**: 1:1 behavior port. The C3 unset-kit guard (literal `(C3)` message + `process.exit(1)`, no `.`-fallback), the CR-03 fail-closed-on-null reject in BOTH `checkConfig` and `checkPackaging`, all six frozen name lists (WORKFLOWS 14, FROZEN_HANDOFFS 16, ROLES 16, CHECKLISTS 11, ROLE_SECTIONS, WORKFLOW_SECTIONS), the `production_requires_human_confirmation` safety invariant (presence-guarded, only explicit `false` rejected), the optional-enum recognition of the 8 v1.2 dial keys, `--strict` warning-promotion, and the `0`/`1` exit contract are all preserved verbatim. `import.meta.dirname` replaces `dirname(fileURLToPath(import.meta.url))`.
- **generate-asvs-checklist.mjs → .ts**: byte-reproducibility IS the contract and it is proven on three axes — the new `.js` output is byte-identical to (a) the old `.mjs` output and (b) the currently-committed `security-nfr-checklist.md` (`cmp -s` identical; `git status` shows no checklist change). The source pin (SHA + `EXPECTED_ROWS=345`), the fail-closed load chain (read → parse → non-object reject → missing-array reject → row-count must == 345 or refuse to write), and the deterministic `lines.join("\n")` + `writeFileSync` emit are byte-for-behavior identical.
- **check-foundation-guards.sh → .ts**: all SIX guards ported 1:1 — the `pass/fail/warn` spine where WARN never increments FAILS; the WR05 EREs + 4-file SCAN; the `guard_voice` fence-strip line-state loop (the `awk` fence machinery translated to an equivalent TS loop with the same `__UNCLOSED_CAVEMAN_FENCE__` sentinel + the 3 per-phrase neutralizations, anchor NOT re-engineered per D-10); `guard_caveman_preserved` (≥2 `^You` OR ≥1 idiom); the locked per-role `role_ceiling()` byte table (a `switch`, NOT live-computed); the 17-file `ROLE_FILES` + 3-file `SEC_VOICE_FILES` lists verbatim; and CR-01 missing-file-fails-red everywhere. **The full `.sh`-vs-`.js` output diff over the real tree is byte-identical** (same PASS/WARN/FAIL lines, same exit 0).
- **check-kit-refs.sh → .ts**: the `SCAN`/`GH_SCAN`/`MARKER_SITES` lists, the 16-template `ALLOW` ERE, the `MARKER` substring, and the 3 assertions + SC2 marker check ported verbatim. The `grep -rn` becomes a scoped recursive file-walk over ONLY the explicit SCAN paths (never repo-wide; no `process.cwd()`-rooted walk). The exclusion-by-not-listing design (`seed/` intentionally absent) is preserved by exact SCAN membership. **Full `.sh`-vs-`.js` output diff is byte-identical.**
- **Three Vitest harnesses (45 tests)** reproduce the RED-by-design parity oracles: `check-foundation-guards.test.ts` (21) plants exactly one violation per guard (both wr05 grant shapes, CR-01/CR-02 missing-file per guard, WR-03 unclosed fence, D-06 sand, WR-01 single-opener, D-05 refinement-accept) + smoke-green + config byte-identity; `validate.test.ts` (21) covers own-tree green bare/`--strict`, GOOD + 6 BAD fixtures, `--strict` promotion, the two-root split (good / missing-kit / **unset-kit C3**), CR-03 null-literal (config + plugin), optional-enum (asvs / test_integrity / prod-confirm) + absent-keys-pass; `generate-asvs-checklist.test.ts` (3) covers writes+exit-0, byte-reproducibility (regen twice identical), and the fail-closed truncated-source → exit 1 + no-partial-write (hermetic).

## Decisions Made

- **ASVS provenance header kept verbatim** (names `generate-asvs-checklist.mjs` as the re-run command) so the regenerated checklist stays byte-identical to the `.mjs` output. Changing it would have drifted the committed checklist a byte and broken the D-02 freshness + security-checklist provenance. Plan 06 retires the `.mjs` and repoints the header.
- **CHECK_ROOT env override added to both read-only checkers** (default = `import.meta.dirname/..`). The `.sh` harnesses ran the guard FROM inside a hermetic mirror so its hard-coded relative paths resolved there; the TS guard exposes a root override so the Vitest harness mirrors inputs into a temp dir and points `CHECK_ROOT` at it — same hermetic plant-and-run behavior, no path re-derivation. This is the only addition beyond the 1:1 port and it does not change any guard's logic or the real-tree behavior (default root is unchanged).
