Close the first half of Gap B in 33.1-VERIFICATION.md ("The installer contract … never overwrite or delete
user content … holds for the retirement's new reversal path"): re-review WR-05, where removeIfEmpty deletes
a whitespace-only `.github/copilot-instructions.md` with no ownership record and labels it
"grugops-created". This is gap-closure round 2 of the 4-round cap (D-06).

The fix is the mechanism plan 33.1-21 built for directories, extended to files. Install records in
`.grugops/install.json` which files it created (`createdFiles`, beside `createdDirs`, read through the one
reader in install/install-marker.ts), and uninstall deletes a file only on that record. The same rule then
covers CLAUDE.md, the other file ensureBlock creates when it is absent. Otherwise the ledger would record a
file uninstall never consults, which is the "recorded but ignored" shape IN-01 names. The interim rule from
VERIFICATION ("call removeIfEmpty only when this run's own removeSentinelBlock call actually found and
removed a block") becomes a permanent second condition, not a stopgap.

Two cheap findings on the same files are folded in. IN-04: the marker reader blocks forever on a FIFO, and
this is the module being extended. IN-01: the `left` wording overstates what the ledger knows.

The Gemini settings half of Gap B (re-review CR-03) is plan 33.1-26. The ownership axis of the fs census,
the DRY_RUN matrix and the published text are plan 33.1-27.

Purpose: uninstall never deletes a file it has no record of creating.
Output: the `createdFiles` ledger on both sides, the ownership-gated empty-file removal, the IN-04 and IN-01
fixes, and their tests.
