# Phase 33.1 Plan 12: Shared-context carried findings (WR-01, WR-02, IN-01) Summary

**What changed:**
- **WR-01:** all three note-plus-ledger routes now record an identical re-append once. Each asks `ledgerRecordsId` (fail closed) before its GOV-02 append, as `promoteAdmitted` already did.
- **IN-01:** `appendNote`'s pre-check refusals now name `appendNote`.
- **WR-02:** notes are published by an exclusive hard link that cannot replace an occupant. The one remaining over-record (a lost race after the ledger line) is written down as the accepted residual.

## Accomplishments

- **WR-01, appendNote (tracer):**
  - `admit()` gains a trailing `stored` flag. `appendNote` passes `destination.existing !== null`, which by that point can only mean identical bytes.
  - On the retained append, `admit()` asks `storedNoteAlreadyRecorded`, a fail-closed wrapper of `ledgerRecordsId`. It skips the line when the id is already recorded.
  - Every refusal family above the retention guard still runs.
- **WR-01, admitAndAppend:**
  - `noteDestinationRefusal` now returns `{ refusal }` or `{ refusal: null, stored }`.
  - The gated branch asks the ledger through the same wrapper, keyed on `actionOwner.root`. That is the same root its append uses, so roots are never mixed. An unreadable ledger comes back as a named finding.
  - The non-gated branch hands `occupied.stored` to `admit()`.
- **IN-01:** `decideNoteDestination(notesDir, id, text, who)` names the function it refuses under. `appendNote` passes `"appendNote"`, and its differing-occupant refusal is framed `context-io.appendNote: refusing to write — <occupant sentence>`.
- **WR-02:**
  - `publishNoteExclusive(tmpPath, finalPath)` is exported. It does `linkSync`, then removes the temp.
  - On `EEXIST` it compares the occupant and the temp through the one bounded reader. Identical bytes are a no-op. Different bytes are refused and the occupant is left untouched.
  - Any other link error is a named refusal. There is no rename fallback and no platform branch.
  - `writeNoteFile` creates its temp with `flag: "wx"` at a random-UUID name and publishes through `publishNoteExclusive`. `atomicWrite` now serves only the index artifacts and out-of-module callers.
- **Comments:**
  - `grep -c "true by construction" scripts/context-io.ts` went from **5 to 0**.
  - Each rewritten site now says one of two things. Either a refusal writes nothing "by the order of the code" (declines and the candidate-size check, which are not check-then-act), or it names the check-then-act and its residual (the destination read in `appendNote`, `promoteAdmitted` and `admitAndAppend`).
- **Ledger:** WINDOWS.md rows 303, 304 and 307 were marked `fixed` through `gsd-tools windows fixed` (open 243 → 240, fixed 39 → 42).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The ledger append lives inside byte-frozen `admit()`**
- **Found during:** Task 1.
- **Issue:** The plan says to ask `ledgerRecordsId` "before the ledger append" in `appendNote`. For `appendNote` that append runs inside `admit()`, which a freeze test pins by SHA-256. Doing the look in `appendNote` alone would need a second read of the retention dial, because under lean retention an unreadable ledger must not refuse. The alternative is reading an `admit()` refusal message back as a signal. Both are shapes this module has paid for before.
- **Fix:**
  - `admit()` gets a trailing `stored = false` parameter and one guarded call at its single append site.
  - The freeze is re-based (seventh re-base) and recorded in the test's comment block, the way the 30-03 and 31-01 re-bases were.
  - This is a plan-directed unfreeze. It is not a human-authorized one like 31-39 (D-39), and a human may want to review it.
- **Files modified:** `scripts/context-io.ts`, `scripts/context-io.test.ts`.
- **Commit:** `104c1d93`.

**2. [Rule 3 - Blocking] Derived pins in files outside `files_modified`**
- **Found during:** Tasks 1 and 3.
- **Issue:** `scripts/context-io-writer-set.test.ts` pins the authority-call mutation anchor, the fs import alphabet, the non-note-writer residual set and the blocking-site dispositions. All of these move with this plan's code.
- **Fix:** Each pin was re-derived from the source and classified in a comment. None was bumped without a reason.
- **Commits:** `104c1d93`, `04afbaa5`.

**3. [Rule 1 - Consistency] The IN-01 shape**
- **Found during:** Task 2.
- **Issue:** Wrapping `decideNoteDestination` in a try/catch inside `appendNote` broke the AST dominance test, which reads `const … = decideNoteDestination(…)`. It also left a doubled `writeNoteFile` prefix inside the message.
- **Fix:** Take the review's second option: parameterize the function name the shared decision refuses under. `appendNote` passes its own name.
- **Commit:** `d04e002d`.

**Total deviations:** 3 auto-fixed (2 blocking, 1 consistency).

**Impact:** No scope creep. The only behavioural change outside the plan's text is on `admit()`'s append site, and only when `stored` is true.
