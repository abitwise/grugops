# Phase 33.1 Plan 22: The one host reader (readFact + ACCEPT) and the floor census Summary

**Every host value that can make a git-host floor row `held` now goes through readFact(value, ACCEPT.<name>), with the table checked at module load. An absent bypass allowance, a garbage reviewer element, a garbage rule entry or an undocumented branch policy can only reach `unknown`. A type-checked AST census pins where state literals are produced and where host JSON is read.**

## Accomplishments

- **Re-review CR-01 closed.** classicBinding reads the allowance through `readFact(allowances, ACCEPT.bypassAllowances)`. That entry is held only when the key is present and users, teams and apps are all empty arrays. An absent key reads `unknown`, and the evidence says "classic protection carries no readable bypass_pull_request_allowances (absent or of an unexpected shape)". The case that pinned `protected` now pins `UNKNOWN - verify`.
- **D-30 by construction.** There are 12 ACCEPT entries: bypassAllowances, enforceAdmins, classicReviews, approvalCount, disabledFlag, ruleEntry, rulesetBypass, environmentPresent, reviewerList, preventSelfReview, canAdminsBypass and deploymentBranchPolicy. `assertAcceptTable()` iterates `Object.values(ACCEPT)` at load, so there is no second list to keep in step. Two entries carry an `absentFailedWhy`: classicReviews (absent means failed) and deploymentBranchPolicy (null means failed).
- **WR-01 closed.** A reviewer counts only as `{ type: "User"|"Team", reviewer: { id: <positive safe integer> } }`. Any invalid element makes the list `unknown`. The self-review row is `unknown` whenever the selected rule's reviewers are not readable.
- **Garbage in either list only lowers a row.** readRulesetArm keeps only `ruleEntry`-held entries. Any garbage entry makes the read `partial`, with the reason "an entry of the rule list is not a readable rule". reviewerRules returns `{ rules, partial }`, and `downgrade()` turns a would-be `failed` into `unknown`.
- **Policy pair and count.** deployment_branch_policy is held only as `{ protected_branches: true, custom_branch_policies: false }`. An approval count is held for a safe integer ≥ 1, failed for 0, and unknown for anything else (−1, 1.5, 2^60, a string, absent).
- **hostField is the one accessor.** It covers answered()'s message, readClassicArm's message, name and protected fields, readRulesetBinding's id, rulesOfType, rulesetOf, rulesetBindings and ruleBinding, environmentVerdict's environments and names, and the main flow's default_branch and name. The only exception is environmentName, the declared `config-json` read.
- **IN-05 fixed.** The opening sentence now names both output lines, and the tables sentence follows the list.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Plan inconsistency] The self-review row must account for unreadable reviewers**
- **Found during:** Task 2
- **Issue:** The plan's reviewerRule selection ("first rule whose reviewers read held, else the first required_reviewers rule") plus a plain prevent_self_review read leaves self-review `held` for `reviewers: [null]`. That contradicts the plan's own behaviour bullet: self-review is "not held".
- **Fix:** When the selected rule's reviewers read `unknown`, the self-review row is `unknown`.
- **Files modified:** scripts/runnable-ref/host-protection.ts
- **Verification:** The 10 WR-01 cases assert that self-review is not held. All are green.
- **Committed in:** 68b7e51f

**2. [Rule 3 - Blocking] A census position rule required a one-line refactor**
- **Found during:** Task 3
- **Issue:** `states.indexOf("held")` put the literal "held" in a call-argument position inside a row reader. The plan's position rule would count that as a producer outside the stated held scopes.
- **Fix:** It is now `states.findIndex((state) => state === "held")`, with no behaviour change (144/144 green).
- **Committed in:** da4544fd

**3. [Rule 1 - Census false positive] The key argument of hostField is non-producing**
- **Found during:** Task 3
- **Issue:** `hostField(br.body, "protected")` names the branch endpoint's `protected` field. It is not a verdict, but the census counted it as `readClassicArm:protected`.
- **Fix:** The census treats the second argument of a hostField call as non-producing. hostField returns the value under the key, never the key. This is documented in the file header.
- **Committed in:** a0a1b6f4

**4. [Rule 2 - Missing critical] Closing the census's own retyping blind spot**
- **Found during:** Task 3
- **Issue:** The HOST_READS census finds reads by the `Record<string, unknown>` type. A cast such as `as { enabled: boolean }`, or a type guard `v is { … }` over `unknown`, would move a host read to a type the census does not look for (DC-1 by another route).
- **Fix:** A 9th test refuses any cast or type predicate that gives an opaque value (unknown, any or host JSON) an object shape with named properties. The census also counts spread, `Reflect.*`, `Object.hasOwn` and `Object.getOwnPropertyDescriptor(s)`, and `JSON.stringify` as reads. ACCEPT may be referenced only as readFact's second argument or inside the self-check. Demonstrations 13 and 14 above prove the refusal.
- **Committed in:** a0a1b6f4

**5. [Rule 1 - Acceptance criterion] IN-05 rephrased rather than moved**
- **Found during:** Task 2
- **Issue:** Moving the tables sentence as the plan describes still leaves line 17 beginning `// and one summary line`, which the acceptance criterion forbids.
- **Fix:** The opening sentence now names both outputs ("One line per inspected target, and one summary line, `HOST-PROTECTION: …`. Each target line carries exactly one of three words:"), and the tables sentence follows the list.
- **Committed in:** 68b7e51f

**6. [Minor ordering] hostField introduced in Task 1**
- The plan places hostField in Task 2. Task 1 already needed it for the allowance read, so it landed in 9d50bbbd. The end state is the same.

**7. [Wording] Partial rule-list evidence**
- `… on the first page, but <why>` became `… in the entries read, but <why>`, because a partial read now also covers a garbage entry, not only pagination. No test asserted the old wording.
