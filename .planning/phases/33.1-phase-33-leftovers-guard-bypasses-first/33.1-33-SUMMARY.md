## Accomplishments

- **DC-2 class test, derived.** `install/installer-never-installed.test.ts` takes WRITE_PATHS from `deriveWritePaths()` (the union of the default, `--symlink`, `--migrate` and checkpoints-at-notify installs), prints it and pins WRITE_PATH_COUNT = 85. A round-trip check asserts that every path uninstall changes after a real install of each variant lies inside the set, so the set covers every path uninstall can touch. Variants, each real and DRY_RUN on identical copies, with the kit home snapshotted:
  - **FD:** a user file at every file path and every directory made.
  - **D:** every directory made empty.
  - **FI:** install's own bytes with no marker, one per variant (README §1's copy path).
  - **FM:** install's bytes under a user's JSON object at the marker path.
- **ownsMarker.** `installMarkerProblems` (install-marker.ts) names the install-owned fields a marker lacks. `ownsMarker()` (uninstall.ts) is true only for an `ok` read with none. A user's JSON object at `.grugops/install.json` is treated as an unusable marker for the whole run: a counted verify, no ledger in it is used, and it is left with `left .grugops/install.json (it does not read as a grugops install marker — no grugopsHome, no kitRoot, no installMode — ...)`. The derived test found this sibling, as the plan predicted: removeMarker deleted the file by name. It also found a second one. The object read as a legacy marker, so the kitFiles byte-identity fallback removed the 6 verbatim skills (variant FM).
- **The appendedBlocks ledger (carry items 4, 6, 11).** For each file ensureBlock writes to, install records `sha256:` of the exact bytes it wrote there, `\n<open>\n<body>\n<close>\n`. writeMarker writes the ledger back verbatim on a run that appends nothing (the plan-32 rule), overlays this run's appends, and writes a malformed ledger back raw with a verify. Uninstall's `ownsBlock` asks only the ledger. `removeSentinelBlock` removes exactly one span whose bytes hash to the record, and writes every other byte back as bytes, not as rebuilt lines. It removes nothing, and leaves the file with the reason, when:
  - there is no marker, or the marker has no ledger;
  - the ledger is malformed;
  - the ledger has no entry for the file;
  - the block was edited;
  - the close marker is missing;
  - two spans match.

  malformedLedgers() and updateKeptMarker know the ledger. A kept marker drops the blocks this run removed.
- **Named passes.** `removeGrugopsAgentsMd()` and `removeMaterializedRunnables()` are behaviour-preserving extractions. Uninstall stdout and the resulting tree were byte-identical in 16 scenario runs, and the install/ suite stayed green with no assertion changed.
- **Ownership axis** (installer-fs-census.test.ts). It works at two levels, each two-sided with counts:
  - `UNINSTALL_PATH_FILES` is derived from the imports: 6 modules.
  - `OWNERSHIP_SITES` has 4 rows (ledger, helper-gated, read-only).
  - `CALLER_OWNERSHIP` has 13 rows, covering 15 calls of unlinkPath, rewritePath and removeFile keyed by calling scope.

  The structural checks:
  - a ledger gate is named before the call it guards;
  - ownsKitFile is handed to removeFile, and removeFile calls `owns()` before its unlink;
  - ownsFileNow, plus sameFileBytes or isOwnLink, comes before a source-identical removal;
  - each gate's own definition names its record.

  The header names the brief §2.2 interim set. Carry items 12 and 13 are declared KNOWN_EXCEPTIONS.
