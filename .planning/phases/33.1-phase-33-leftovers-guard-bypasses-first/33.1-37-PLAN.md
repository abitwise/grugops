<objective>
Close CR-01 and its kit-home siblings, per D-33 (b). The review reproduced that `GRUGOPS_HOME=<target>` makes
install rename the user's in-repo `agent-factory/` aside and delete it recursively, exit 0, with no backup
and no warning, even under DRY_RUN. The §2.3 search (plan 33.1-36, rows D8-D12) found the same class one
register over: copyKit deletes whatever is at the kit root by presence, so a `GRUGOPS_HOME` pointing at any
directory holding someone's `agent-factory/` loses it. It also removes its temporary directory by name first.
Deferred row 31 ("the kit home is outside the target") is disproved, and this plan replaces that assumption
with a check.

1. Refusal: no install run, real or DRY_RUN, starts when the kit home and the target overlap.
2. Record: the kit home keeps a record of what install wrote there. A kit install recorded is replaced, as
   D-31 item 14 accepts. Anything else is renamed aside and recorded, never deleted.
3. Derivation (IN-06): the class tests cover the kit-home axis, so a fourth member of this kind would turn them
   red.

A judgement call for the human. D-31's kit-home decision of 2026-09-30 (with item 14) accepted that a re-install
overwrites edits in the shared kit home, and deferred a backup of kit-home edits. This plan keeps that acceptance
for a kit the new record says install wrote, and does something D-31 did not decide for everything else: an
unrecorded kit root is renamed aside to a recorded backup, never deleted. Every kit home written before this
release has no record, so its first re-install leaves one backup there. The alternative (replace an unrecorded kit
without a backup, as before) deletes user content whenever the kit root is not install's (CR-01's sibling). The
SUMMARY lists this under `## Decisions needed from the human`, and plan 33.1-43 collects it.

Purpose: the installer contract (never delete user content) has to hold for the kit home too, not only inside
the target.
Output: the refusal, the kit-home record, treeRecord, the refusal and kit-home variants, README/CHANGELOG,
and replay cases.
</objective>
