# Phase 33.1 Plan 29: Gemini settings ledger (geminiSettings) Summary

**Uninstall now changes `.gemini/settings.json` only as the install marker's `geminiSettings` record says. The record says whether install created the file or appended `"AGENTS.md"`, and what shape it found, with content records in the one sha256 grammar. A file with no record is left byte-identical. Install refuses shapes it cannot merge and reverse, with a counted verify. `readForWrite` refuses hard-linked files, so nothing is written through a second name.**

## Accomplishments

- **CR-03 closed, including red-team carry #1.** A never-installed target keeps its settings file byte-identical under a real run and DRY_RUN. Six bodies were tested:
  - the shape CLAUDE.md recommends, compact and in installer formatting;
  - the review's `{"context":{"fileName":"GEMINI.md"},"notes":"we also keep AGENTS.md"}`;
  - the red-team's user fileName with "see AGENTS.md" elsewhere in the file;
  - a user's own AGENTS.md entry beside another key;
  - unparseable text.

  The substring gate `raw.includes("AGENTS.md")` is gone. The decision comes from the ledger before the file is read.
- **Exact reversal.** Uninstall removes the last exact `"AGENTS.md"` element from an array fileName and restores the recorded shape: an absent fileName or context is removed again, and a string becomes the string again. It deletes a created file when it is unchanged, or when nothing is left in it after the entry is removed. A fileName that is no longer an array is left and reported. Six merge shapes, including an empty-string fileName and an empty array, round-trip to the exact bytes.
- **Install shape guard.** A counted verify with no crash for null, an array, `{"context":"x"}`, a null context, a number, null or mixed-type fileName, and invalid JSON. It used to throw a TypeError on `{"context":"x"}` (carry item). An empty-string fileName used to be dropped silently. It is now kept as a string and restored.
- **Record supersession.** The record always describes the most recent install that changed the file:
  - a run that creates or appends replaces the record;
  - a run that changes nothing carries the earlier record only while `context.fileName` still holds its record (`fileNameContent`);
  - otherwise the record claims nothing;
  - an absent record stays absent unless this run acted, or a fresh install observed AGENTS.md already listed.
- **Hard links (red-team carry #9) closed.** readForWrite refuses a regular file with more than one name. This covers CLAUDE.md, the Copilot file, the settings files and the kit files on install, every uninstall rewrite, and a hard-linked marker, which could otherwise be another repository's ledger.
- `malformedLedgers()` and uninstall's `updateKeptMarker` both handle `geminiSettings`. A kept marker's Gemini claim drops to "claims nothing" once the change is reversed.

## Residual risk

- **Uninstall without a re-install still trusts the record's flags, not the current content.** Suppose the user deletes the settings file install merged and writes their own with an `"AGENTS.md"` element at the end. Uninstall then removes that element. This follows the plan's rule ("created, then the user removes GEMINI.md, then uninstall removes AGENTS.md"), and removeAskRules has the same shape. A re-install in between drops the claim.
- **A claim is dropped when fileName changes.** A re-install after the user changes `context.fileName` (for example, reorders it) drops the claim, so uninstall leaves AGENTS.md in the file and reports it.
- **More verify findings on hard-linked files.** A hard-linked file in the target is now a verify even where install would only have skipped it: a seed file already present, an identical copy, or the `--migrate` legacy config. This is the conservative direction, it is rare, and the README states it.
- **Time-of-check to time-of-use.** A hard link made between readForWrite's lstat and the write is the existing disclosed window.
- **Not in scope, still open:** carry #3 (kit files by name, plan 30), #4 and #11 (sentinel blocks by presence, plan 33) and #6 (plan 33). They are unchanged by this plan.
