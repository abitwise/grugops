# Phase 33.1 Plan 29: Gemini settings ledger (geminiSettings) Summary

**Uninstall now changes `.gemini/settings.json` only as the install marker's `geminiSettings` record says. The record says whether install created the file or appended `"AGENTS.md"`, and what shape it found, with content records in the one sha256 grammar. A file with no record is left byte-identical. Install refuses shapes it cannot merge and reverse, with a counted verify. `readForWrite` refuses hard-linked files, so nothing is written through a second name.**

It deletes a created file when it is unchanged, or when nothing is left in it after the entry is removed. A fileName that is no longer an array is left and reported. - **Record supersession.** The record always describes the most recent install that changed the file:
  - a run that creates or appends replaces the record;
  - a run that changes nothing carries the earlier record only while `context.fileName` still holds its record (`fileNameContent`);
  - otherwise the record claims nothing;
  - an absent record stays absent unless this run acted, or a fresh install observed AGENTS.md already listed.
- **Hard links (red-team carry #9) closed.** readForWrite refuses a regular file with more than one name. This covers CLAUDE.md, the Copilot file, the settings files and the kit files on install, every uninstall rewrite, and a hard-linked marker, which could otherwise be another repository's ledger.
- `malformedLedgers()` and uninstall's `updateKeptMarker` both handle `geminiSettings`. A kept marker's Gemini claim drops to "claims nothing" once the change is reversed.

### Approach to B3: option (a), with option (b) as the refusal path

`install/json-text.ts` is a new module that imports nothing and does no I/O. It is now the one way install and uninstall edit a JSON file the user owns.

- **Tokenizer.** A strict recursive-descent tokenizer tracks string and escape state and keeps the UTF-16 span of every value and member. No regex runs over the raw JSON; the only regex is a sticky match on a number token.
- **Install only inserts.** It adds one of these:
  - an element after the last element, or just after the `[` of an empty array;
  - a member after the last member, or just after the `{` of an empty object;
  - for a string `fileName`, a `[` before the string and `, "AGENTS.md"]` after it.

  The new text copies the container's line end and indentation when the container has one item per line, and is compact otherwise.
- **Uninstall deletes exactly the span install inserted.** For an item after another item, the span starts at the end of the item before it. For the first item, it runs up to the next item. When every item goes, it runs from the bracket to the last item's end. Unwrapping puts back the kept element's own text. So install followed by uninstall gives back the same bytes. On a file the user has edited since, only the recorded item and its separator go.
- **Refused (option b).** The run reports a counted verify, writes nothing and leaves the file byte-identical when the file:
  - is not valid UTF-8 (a decode and re-encode would change the bytes);
  - is not strict JSON (a comment, a trailing comma, NaN, single quotes, text after the value);
  - is nested more than 256 levels deep;
  - has a duplicate key on the edited path: `context` or `context.fileName` for Gemini, `permissions` or `permissions.ask` for Claude.

  A leading BOM is kept, and a duplicate key off the edited path is kept byte for byte.
- **Oracle.** The spliced text is parsed again and must equal the value that the old parse-and-modify logic would produce (`sameJsonValue`); otherwise the run refuses.
