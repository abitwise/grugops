# Phase 33.1 Plan 27: installer DC-3 closed as a class Summary

**The install marker reader and every uninstall read now go through readUserFile, so a FIFO, directory or symlink to one at `.grugops/install.json` (IN-04), or at any file uninstall edits or compares, is never opened. The census derives its reader list from node:fs's own exports and holds every content read under install/ to readUserFile or a pinned kit-path source. One shared derivation of every path any install variant writes drives a FIFO-and-directory test over five run kinds.**

## Decisions Made

See key-decisions in the frontmatter. The plan's `stdin` class is an addition. A READ_SITES row has to be `kit-path` or `stdin`, and the `stdin` class is held by a structural check that the source is the literal descriptor 0. The alternative was to classify a read of descriptor 0 as a kit path, which would be false.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] uninstall crashed on a directory at a kit path or at the marker**
- **Found during:** Task 1 RED.
- **Issue:** `removeFile` and `removeMarker` called `rmSync(path, { force: true })` on whatever was present. On a directory that throws `ERR_FS_EISDIR` (exit 1, with a stack trace). On a FIFO it deletes the FIFO, so the special file does not survive uninstall.
- **Fix:** both remove only a path that lstats as a regular file or a link. Anything else is `left`, with its kind named. A link or non-directory on the way is a verify (removeFile), or `left` with the reason (removeMarker). The check runs before the DRY_RUN branch, so the preview and the real run name the same paths.
- **Files modified:** install/uninstall.ts/.js, install/user-file.ts/.js (`kindAt`).
- **Commit:** 05fe978b.

**2. [Rule 2 - Missing critical] No-follow semantics for uninstall's edits (per the dispatch note)**
- **Issue:** uninstall's `isFile` (lstat) guard skipped a link at the leaf silently with "no grugops block present". It did not guard a link on the way, and a rewrite would follow one.
- **Fix:** every uninstall edit asks `readForWrite(TARGET, f)`. A link at the path or on the way, a special file, or a non-directory where a directory should be is a counted verify, and the path is never written. `rmdirIfEmpty` skips a directory reached through a link.
- **Visible change:** a CLAUDE.md that is a symlink now gives `verify` (exit 3) on uninstall, where it used to give `skipped`. Install has refused to append through that link since the plan 33.1-26 red-team fixes, but an older install may have appended through it, so uninstall cannot say there is no block.
- **Commit:** 05fe978b.

**3. [Plan text] `--check`'s unreadable-marker finding is the doctor's "not installed" FAIL, and its exit code is 1**
- **Found during:** Task 1 RED.
- **Issue:** the doctor folds any unusable marker into `FAIL grugops not installed` (exit 1, the README's code-1 row for a doctor FAIL) before it reads anything else. It does not print the "could not be read as a JSON object" line install and uninstall print. The plan's allowed exit codes were {0, 2, 3}.
- **Fix:** the IN-04 test asserts the doctor's existing finding. The special-files test allows {0, 1, 2, 3} for `--check` only, and the comment cites the README row. Install and uninstall keep {0, 2, 3}.
- **Commits:** 8eeaa262, bc5a461e.

**4. [Rule 3 - Blocking] The AUTO-06 config-path pin in scripts/context-io.test.ts**
- **Found during:** the full regression after Task 3.
- **Issue:** the new test-support module spells `factory.config.json`, because it writes fixture configs for the notify and old-layout variants. The derived set of config-resolving sites went from 11 to 12.
- **Fix:** a documented CONFIG_PATH_SITES entry, and the count moved from 11 to 12 with the "is it a second governance reader?" answer (no: it writes fixtures and reads no dial).
- **Commit:** 6fc40a87.

**5. [Scope] Helpers moved and the write-set test refactored**
- **Issue:** the dispatch said installer-write-set.test.ts must consume the one derivation. It also said to remove the marker exclusion once the reader was routed. The plan moves the dry-run test's helpers into the shared module. Neither test file was in the plan's `files_modified`.
- **Fix:** installer-write-set.test.ts consumes `deriveWritePaths()`. It asserts that the union's untimestamped part equals the default variant's writes, and that there are 7 timestamped paths. It keeps its two independent cross-checks (the report lines and the createdDirs ledger). installer-dry-run.test.ts imports `snapshotTree`, the fixtures and `spawnBin`.
- **Commit:** bc5a461e.

## Residual risk

- **The doctor names a special marker "not installed".** It is a FAIL (exit 1) and fails closed, but the wording does not say the marker is a FIFO or a directory. This is a DC-1-adjacent wording gap, not a pass.
- **TOCTOU on uninstall rewrites.** `writeFileSync(f, ...)` and `unlinkSync` still open or remove the path by name after `readForWrite` asked. A same-user swap in that window could redirect them. This is the same residual plan 33.1-26 disclosed for install.
- **The class test detects hangs, not non-blocking opens.** `installer-special-files.test.ts` sees a blocking read through its timeout. A future `O_NONBLOCK` open of a FIFO would not hang, and would release a blocked writer. The census read axis refuses any content read outside readUserFile statically, and the per-site install.test.ts cases use blocked writers. The class test itself plants no writers.
- **The census's export set was measured on node v24.12.0.** CI runs Node 22. The 23 pattern-matched names are expected to be the same on 22, but that was not measured, because no Node 22 is installed here. If they differ, the census fails red on CI (fail-closed and visible), and the fix is to classify the name.
- **DC-2 remains for the next plans.** `removeFile` still removes a kit skill or adapter that is a regular file or link by presence (plan 33.1-30, kitFiles). `removeMarker` removes an unreadable but regular marker (plan 33.1-33, ownsMarker).
