3. **33.1-36 (key decision, a reading of D-33 (b)): one malformed entry makes the whole ledger malformed.**
   - **What the round did:** install writes the ledger back verbatim with one verify, and uninstall removes and edits nothing on it and keeps the marker verbatim. A marker that carries `ledger` next to a retired record is `unreadable` and left byte for byte.
   - **Alternative:** honour the well-formed entries and skip only the bad one.
   - **Cost:** a hand-edited or partly corrupt record would still drive deletions.
   - **Reversibility:** reversible.
4. **33.1-37: rename-aside of an unrecorded kit home on the first re-install or `--update` (D-31's kit-home decision of 2026-09-30, item 14; D-33 (b)).**
   - **What the round did:** copyKit renames anything at the kit root that the kit-home record does not name to a recorded `agent-factory.bak.<ISO>`. That includes every kit home written before this release, plus a link, a file, or a user's own `agent-factory/`. This goes beyond item 14, which accepted overwriting a kit and deferred kit-home backups.
   - **Alternative:** replace without a backup, as before.
   - **Cost:** the alternative deletes user content whenever the kit root is not install's (CR-01's sibling). The cost of this choice is one backup directory per pre-release kit home, which prune can remove (see item 14).
   - **Reversibility:** reversible.
5. **33.1-37 (a reading of D-33 (b)): where the overlap refusal runs.**
   - **What the round did:** the refusal runs on every install, DRY_RUN and `--allow-self` included. It does not run on `--check`, which writes nothing, or on `--update`, which has no target and is held by the kit-home record. It also does not run on `--prune-old-kit`, which acts only on records.
   - **Alternative:** also refuse `--update` when the kit home lies inside the current directory's repository.
   - **Cost:** a new notion of target for `--update`.
   - **Reversibility:** reversible.
6. **33.1-37 (deviation 2, narrowing the kit-home ledger of D-33 (c)): a kit-home `backup` entry must name copyKit's backup shape.**
   - **What the round did:** a kit-home `backup` entry whose path is not `agent-factory.bak.<ISO>` makes the record malformed. A malformed record is read as no record, which only ever renames aside.
   - **Alternative:** accept any path in the kit home.
   - **Cost:** a forged or hand-edited record could point a later prune at, for example, `Documents`.
   - **Reversibility:** reversible.
7. **33.1-38: links at recorded paths count as `verify`, exit 3 (D-33 (b)).**
   - **What the round did:** a link where install recorded a copied file, or a re-pointed `--symlink` link, is left, never followed, and counted. Before, such a link was `left` with exit 0 when it pointed into the uninstalling checkout.
   - **Alternative:** keep exit 0 for links into the kit source.
   - **Cost:** ownership would be read from the kit source again, which is WR-01's class.
   - **Reversibility:** reversible.
8. **33.1-38: a forged marker can name any in-repo path, `.git/` included (D-33 (b)).**
   - **What the round did:** the walk removes any recorded file inside the target whose record holds. `isProtected` covers agent-factory/, plans/, .planning/, .grugops/, docs/ and src/, but not `.git/`. So a bound, well-formed marker forged with `.git/HEAD`'s exact sha256 and mode has that file removed.
   - **Options:** add `.git/` to the protected list, or limit the walk to the path shapes install writes. Neither was done; the plan kept the guard text.
   - **Cost:** doing nothing leaves this path open. Either fix is small; limiting to write-path shapes needs a derived shape list.
   - **Reversibility:** reversible.
   - **Placement:** a later phase or backlog 999.1. Ledger row: Open.
9. **33.1-38 (key decisions, readings of D-33 (b)'s walk).**
   - **What the round did:**
     - The report-only kit pass also names the target's own grugops-shaped files (`.claude/agents/grugops*.md`, `.claude/skills/grugops*/SKILL.md`), read with readdir only, and never removes them.

   - **Reversibility:** reversible.
10. **33.1-39: directory and backup entries do not keep the marker, a narrowing of D-33 (b)'s "while any recorded entry is left".**
    - **What the round did:** file, block, gemini and ask-rules entries keep the marker; directory and backup entries do not. They are still reported, and a kept marker still lists the ones present.
    - **Side effect:** once uninstall removes the marker, recorded backups lose their record. `--prune-old-kit` can then no longer remove them, so README and CHANGELOG say to prune before uninstalling.
    - **Alternative:** backup entries keep the marker.
    - **Cost:** a marker stays after every uninstall where a handoffs or edited-kit-file backup exists, because prune never removes those.
    - **Reversibility:** reversible.
11. **33.1-39: pointer files count as `reversed` once their block is removed (D-33 (b), WR-02's "removed, reversed").**
    - **What the round did:** in a `CLAUDE.md` or Copilot file that install created, the file entry stops holding the marker once this run has removed the block and the user's lines remain.
    - **Alternative:** the file entry holds the marker.
    - **Cost:** every user who added lines to an install-created `CLAUDE.md` keeps a marker until they delete it by hand.
    - **Reversibility:** reversible.

    - **Alternative:** always delete a `{}` result, as the plan's wording said.
    - **Cost:** it breaks the plan 33.1-34 L1 rule, under which a chmod or whitespace edit is a user edit and keeps the file.
    - **Reversibility:** reversible.

14. **33.1-40: a kit-home backup of something that was not install's kit is prunable (D-33 (c)).**

    - **Alternative:** a separate origin for "not install's kit" that prune never removes.

    - **Reversibility:** reversible.

    - **Reversibility:** reversible.
