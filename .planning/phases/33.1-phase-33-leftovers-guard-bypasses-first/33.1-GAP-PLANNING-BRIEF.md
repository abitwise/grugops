# Phase 33.1 — Gap-Planning Brief (read before any `--gaps` planning, checking, executing, reviewing or verifying)

Written 2026-09-29 after gap round 2 was planned (plans 33.1-22..29). Rounds 0 and 1 both
verified at 6/8; the findings changed, but they stayed in two defect classes, and each fix
exposed the next member of the class next door. This brief turns that history into a rule for
every later round. It is guidance for agents, not a decision record: decisions stay in
`33.1-CONTEXT.md` (D-NN) and the D-31 checkpoint in plan 33.1-29.

## 1. The defect classes and their rules

A later finding that matches one of these is **the same class again**, not a new gap. Fix the
class, not the site.

| ID | Class | Rule that must hold everywhere | History |
|----|-------|--------------------------------|---------|
| DC-1 | Missing or unrelated evidence read as proof | The host check answers `protected`/`held` only on present, well-typed evidence that agrees with the rest of the same run. Absent, null, wrong-typed or garbage → `UNKNOWN - verify`, never `held` | R0 CR-01 → R1 CR-01 (absent `bypass_pull_request_allowances` = "binds") + CR-02 (branch_policy held with no protected branch) + WR-01 (`reviewers: [null]`) |
| DC-2 | Delete or edit by presence or shape, not by install record | Uninstall deletes or edits a path only when an install record says install created or changed it, and the content still matches. Everything else → `left` with a reason. A never-installed target is changed by zero bytes | R0 CR-02 (DRY_RUN rmdir) → R1 CR-03 (`.gemini/settings.json`) + WR-05 (blank copilot file) → R2 checker (kit skills/adapters by name) |
| DC-3 | Unbounded read of a user-controlled path | Every read the tooling makes on a user-controlled path is limited to regular files (or a symlink resolving to one). A FIFO, directory or device → skip or `left`, never a hang | R1 IN-04 (marker FIFO) → R2 checker (`sameFileBytes`, four callers) |

## 2. Required in every gap-round plan set

### 2.1 Tests that catch any member of the class, not the named sites
For each class a round touches, the plans must include one behavioural test that fails on
**any** member of the class. The class rule is tested by itself, with no list of the sites
already known:

- **DC-1:** start from a fully protected fixture and remove, null or garble every field, one at a
  time **and in pairs**, including cross-row cases (for example the branch-policy line alongside a
  branch that is not protected). Assert `protected`/`held` never appears unless the evidence is
  complete and consistent. Take the field list from the fixture itself, not a hand-typed list,
  and assert its count.
- **DC-2, never-installed target:** plant a user-authored file at **every** path install can
  write, taking that set from install's own write paths or its record, never typing it by hand,
  and assert the count. Run uninstall (real and DRY_RUN) and assert zero bytes changed.
- **DC-2, user edit:** install, edit each installed file in turn, uninstall. Assert every edit
  survives and is reported `left`.
- **DC-3:** put a FIFO and a directory at every path the tooling reads. Assert the run finishes
  within a timeout and the special file is untouched. Skip, with the reason printed, only where
  `mkfifo` is unavailable or on win32.

Each of these tests needs a mutation proof: break the rule, watch the test go red, and record it.

### 2.2 One authority per rule
- **DC-2:** one `owns(path)` authority over one install record. Uninstall asks only that check
  before any delete or edit. Round 2 adds four separate records (`createdDirs`, `createdFiles`,
  `geminiSettings`, `kitFiles`). A later round should merge them behind that one check rather
  than add a fifth.
- **DC-1:** the single `readFact`/`ACCEPT` reader from plan 33.1-22 is the only place host fields
  are read. A static census asserts no field is read outside it.
- **DC-3:** the regular-file guard lives inside the shared read helper, not at each call site.

### 2.3 Sibling search before execution
The planner and the checker must each list, for every class a round touches, **all** code sites
in that class, found by search or syntax tree and not taken from the review's list. For each
site, name the plan and test that covers it. The review's findings are examples of a class, not
its full set.

## 3. Required in every gap-round execution

- **Red-team each plan:** after each plan's executor finishes, a separate agent gets only this
  brief's class rules and the committed `.js`, and tries to break the rules the plan touched. It
  does not run the plan's own tests. Any break is fixed before the next plan starts. In earlier
  rounds, executors checking against their own tests never found a sibling.
- **Reproduce against the build:** use `node <committed .js>` in a scratch git repo, the way the
  verifier does, not only vitest.
- **Review snapshot:** before any re-review, snapshot `33.1-REVIEW.md`; `/gsd-code-review`
  overwrites that path.

## 4. Scope lever (for the D-31 checkpoint and after)

DC-1 keeps coming back partly because the check tries to prove the whole D-30 `floor-full` set
from partial API answers. If a later round finds DC-1 again, the checkpoint should offer to
narrow the scope. `protected` would be answered only for the published branch items, and every
other floor item would read `UNKNOWN - verify` by design, with that stated in README §5. A
smaller surface is cheaper than another round at the cap.

## 5. Round budget

Four-round cap (the standing rule from Phase 31). Round 2 is planned. If round 2's verification
finds a member of DC-1 or DC-2 again, treat that as a scope problem. Put §4 to the human before
planning round 3.
