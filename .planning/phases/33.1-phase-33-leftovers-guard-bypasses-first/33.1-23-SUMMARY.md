### Mapping disagreements and how each was resolved

The code never gave `held` for a fed row or `protected` for a fed target, so no code fix was needed. The plan's mapping predates plan 33.1-22's red-team round, and was wrong about which rows four groups of fields move. Each correction below keeps every fed row not held:

1. **Rule `ruleset_source` / `ruleset_source_type` (6 fields).** The plan listed them as INERT ("never read"). Since red-team case P they are read: a rule naming another source makes ruleset 1 bind nothing, so they feed **all five branch rows**. They are removed from INERT.
2. **Ruleset body `enforcement`, `target`, `source` and `source_type` (4 fields)** are not in the plan's mapping, because they were added by the red-team round. They are read before the bypass value and feed **all five branch rows**.
3. **Environment `reviewers`, `reviewers[0]`, `.type`, `.reviewer` and `.reviewer.id`.** The plan said they feed required_reviewer only. Under WR-01, a rule whose reviewers are not readable leaves the self-review row unreadable too, so they feed **required_reviewer and no_self_review**.
4. **Removing an array element.** "Absent" for an index is removing it, which leaves a shorter, well-formed list. A list read in full without the element can correctly read `failed`: removing the pull_request rule fails the review rows, and removing the only reviewer fails required_reviewer while prevent_self_review stays read, as plan 33.1-22 decided. For removal, the matrix asserts that some fed row stops being held, the fed target is not protected and the exit is not 0, rather than that every fed row is `unknown`. EXCEPTIONS was not widened.

INERT is 14 fields: environments `total_count`, the reviewer `login`, and the 12 descendants of the listed branch's classic body. EXCEPTIONS is the plan's two entries, unchanged.

## Residual Risk

- **Pairs.** This matrix mutates one field at a time. Plan 33.1-24 adds pairs, including cross-row pairs, reusing BASELINES, BODIES, LEAVES and runHostCheck.
- **Indexing the list.** `listed[0]` in readClassicProtectionEvidence (and `v[0]` in the predicate) is an element access on an `unknown[]`/`any[]`, which the HOST_READS census does not count. Any field read on that element outside hostField is caught: as an `any` access, or as a host-JSON read once narrowed. The index itself is not caught.
- **"Some branch" semantics.** Step (a) accepts a classic body on any branch this run read, including one whose other rows fail. The claim is only "classic branch protection exists on at least one branch", which is what makes "Protected branches only" restrictive. It does not claim that the branch that deploys is well protected; the branch rows cover that.
- **Rulesets.** Whether "Protected branches only" counts ruleset protection is not documented, so a ruleset-only repository reads `UNKNOWN - verify` for this line by design. README §5 wording is plan 33.1-25's.
- **Red-team (brief §3).** A separate agent should attack the committed `.js` against DC-1 before plan 33.1-24 starts. That is the orchestrator's step.
