Implement D-31's scope lever, Q4 `q4-narrow-scope` (the gap-planning brief's §4), which D-33 (a) puts in
this round, and close WR-04 and IN-04. All three change the same thing: what goes into the host check and
what comes out of it.

DC-1 (missing or unrelated evidence read as proof) came back in every round, partly because the check tried to
prove the whole floor-full set from partial API answers. The named human chose to narrow the scope. The check
answers `protected` only for the branch checklist. The production environment lines read `UNKNOWN - verify` by
design, and README §5 says so. That removes the largest DC-1 surface (environment lists, reviewer shapes, the
branch-policy evidence chain) instead of adding another round of fixes to it.

a slow pipe, because the tail exits at once. The installer fixed this class with `process.exitCode`.
IN-04: `--brnach release` is ignored and `--env -x` drops its value silently.

Purpose: a smaller, honest floor answer that reaches its reader whole and never runs on a misread command line.
Output: the narrowed check, its tests and matrix, the docs that point at README §5, and the replay cases.
