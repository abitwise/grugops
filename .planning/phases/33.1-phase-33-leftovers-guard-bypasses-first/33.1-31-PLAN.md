<objective>
Prove Gap B as a class, the way the gap-planning brief requires (§2.1, DC-2), and hold it with a static census.
This is gap-closure round 2 of the 4-round cap (D-06).

1. Behavioural, derived. The DC-2 rule is that a never-installed target is changed by zero bytes. The test
   plants a user file at every path install writes, taken from a real scratch install and not typed by hand,
   and asserts that uninstall, real and DRY_RUN, changes nothing. This is the test that would have caught
   CR-03 and WR-05 without anyone listing them. Run on the current tree it also finds a sibling nobody listed:
   removeMarker deletes `.grugops/install.json` by name. This plan closes that the same way as the others,
   with a record gate (`ownsMarker`: the file must read as install's own marker).
2. Static. The fs census from plan 33.1-18 classifies every mutating call site on one axis, DRY_RUN. That axis
   proved the Gemini and Copilot paths DRY_RUN-safe and said nothing about ownership, which is how Gap B
   survived round 1. This plan adds the ownership axis over exactly the modules uninstall runs, and checks each
   claimed gate's position in the syntax tree.

Sibling search (brief §2.3, DC-2), by reading uninstall.ts and install.ts, not the review's list. Every delete
or edit of a user path, the record that now gates it, and what proves it:
- Uninstall side:
  - rmdirIfEmpty: createdDirs (33.1-21); this plan's variant D.
  - removeOwnedEmptyFile: createdFiles (33.1-27); variant FD, and the user-edit test (33.1-32).
  - removeSentinelBlock: the exact sentinel lines, content-identifying; variant FD.
  - unmergeGemini: geminiSettings (33.1-28); variant FD and the user-edit test.
  - removeAskRules: claudeAskRules (33.1-03, 33.1-21); variant FD and the user-edit test.
  - removeFile through removeKitSkills and removeKitAdapters: kitFiles (33.1-29); variant FD and the user-edit test.
  - removeFile through the AGENTS.md block and the runnables loop: byte identity with the kit source (existing); variant FD and the user-edit test.
  - removeMarker: the marker's own shape (this plan, ownsMarker); variant FD.
- Install side:
  - The overwrite of an edited kit file: D-32's pre-flight (33.1-30) and its "kit re-install" cases.
  - ensureBlock, mergeGemini and writeAskRules: additive merges into the user's file, never a delete; bounded by readUserFile (33.1-26); the user-edit test.

The user-edit class test (edit every installed file in turn), the DRY_RUN file-subset checks and the published
text are plan 33.1-32.

Purpose: no delete or edit on the uninstall path can land without an ownership record, and a never-installed
repository is provably untouched.
Output: the derived never-installed test, the ownsMarker gate, the ownership axis and the named removal passes.
</objective>
