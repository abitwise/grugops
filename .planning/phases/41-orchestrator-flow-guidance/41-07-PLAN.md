<design_decisions>
Planner's choices within D-35. Each is flagged to the human in the plan's return.

- **`appendNote`, not `admitAndAppend`.** `admitAndAppend` trusts a `human:NAME` stamp on a gated note because the per-call hook has already checked it, so a shell tool on that route would let an agent self-authorize a high-severity finding. It also refuses `human:NAME` on a non-gated note (W3), which would refuse Workflow 04's `Confirmed:` finding at the default dial. `appendNote` runs `admit()`, the in-script tier Workflow 16 already names for hosts with no hook, and it never grants a high-severity admission.
- **No `--root`.** The 30-11 rule says an admission may not point governance at a root the caller chose. The store is the working directory's `.grugops/context/`, checked the way `claim.js` checks its root. The dial is `appendNote`'s default, `trustedRepoRoot()`.
- **No `--at`.** The program stamps `at` at write time, so this route cannot forge the time `done` compares.
- **`index.md` and `index.jsonl` are rendered after each note**, the way `claim.js` renders `now-running.md` after each change, because Workflow 16 `## Commit` names them as artifacts.
</design_decisions>
