# Phase 29.1 Plan 12: Close R2-CR-01 — the guard's verdict describes the run it performed Summary

`guard_model_assignment` no longer compiles an unvalidated `CHECK_ROOT` into an unanchored regex: the
root is `resolve()`d at its declaration and the rendering match must end on a path boundary declared
once at module scope, so the verdict and both refusal reasons name the same paths under every
documented invocation shape — proven by a byte-identity of two live CLI runs that is RED on the
pre-fix build and GREEN on the post-fix build, with each half separately mutation-proven.

  derived from it; `ROOT_PATH_BOUNDARY` is declared once and `ROOT_PATH_RE` is built from it. The
  boundary alternation exists in exactly one place (`grep -c ROOT_PATH_BOUNDARY` = 2: one declaration,

## `(o-prefix)`: behaviour axis, not source axis

`(o-prefix)` asserts on the **behaviour axis** — the plan's preferred option, and the fallback to a
source-text assertion was not needed. The reachability problem the review named (every path the guard
renders is *built from* the root, so a prefix sibling never arises) was solved by using the path the
guard **echoes** rather than one it constructs: an illegal `models.preset` is quoted back verbatim
into the refusal via `JSON.stringify`, and that value is an arbitrary caller string. The fixture
plants `{"models":{"preset":"<parent>/mirXTRA/deep"}}` into a mirror rooted at `<parent>/mir`, so the
rendered refusal contains a string that begins with the root but is not under it. Under a substring
match its leading characters are deleted and it becomes `mirXTRA/deep`; under the path-boundary match
it survives whole.

```
  // (PLAN 29.1-12, R2-CR-01) AND WHAT IT COULD PUT IN. The paragraph above argues only about what this
  // helper keeps OUT of the verdict, and that half-argument is how the helper shipped able to corrupt
  // the verdict it was written to protect. A root compiled into an UNANCHORED pattern rewrites text
  // that is not a path at all: taken verbatim from the environment, `CHECK_ROOT=.` escaped to `\.` and
  // matched ANY period followed by non-whitespace, so this guard published a green PASS line naming
  // `agent-factory/config/factoryconfig.json` — a file that has never existed — while exiting 0. That
  // is the WR-08 defect class, a verdict misdescribing the run it performed, reintroduced by the fix
  // that closed WR-08. It survived because every mirror root planted in the suite is absolute, so no
  // case in the repository could see it.
  //
  // TWO PROPERTIES NOW HOLD, AND THEY ARE ONE CONSTRUCTION RATHER THAN TWO HAND-KEPT COPIES. The root
  // is NORMALISED at its declaration, so what is compiled here is an absolute repository path whatever
  // the caller typed. And the match must END ON A PATH BOUNDARY, taken from the single module-scope
  // declaration of that boundary rather than restated here, so this is a path-PREFIX rewrite and not
  // an arbitrary substring rewrite. Two copies of a boundary rule is how a second grammar arrives.
  //
  // Everything downstream of the match is unchanged: the capture group runs to the first whitespace or
  // quoting byte, and the replacer's leading-separator strip and backslash normalisation apply only
  // inside what was matched, so nothing outside a path is rewritten.
  const ROOT_PATH_RE = new RegExp(
    `${ROOT.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")}${ROOT_PATH_BOUNDARY}([^\\s'"\`]*)`,
    "g",
  );
```

## Deviations from Plan

### 1. [Rule 2 — Missing critical functionality] The plan's half-one mutation discriminator does not discriminate

- **Found during:** Task 1, acceptance criterion "Mutation-proven discrimination, half one".
- **Issue.** The plan asserts that reverting **only** the `resolve()` normalisation, leaving the
  boundary in place, will red the byte-identity case `(o-rel)`. **Measured: it does not.** The
  mutation was applied, rebuilt, and both `(o-rel)` and the two live CLI runs stayed GREEN:

  ```
  $ /usr/bin/diff <(node scripts/check-foundation-guards.js 2>&1) <(CHECK_ROOT=. node scripts/check-foundation-guards.js 2>&1) ; echo $?
  0
  $ npx vitest run scripts/check-foundation-guards.test.ts -t 'renders the same verdict as the default root'
        Tests  1 passed | 256 skipped (257)
  ```

  **Why.** With `CHECK_ROOT=.` the escaped pattern is `\.`, and every period inside
  `factory.config.json` is followed by a **letter**. The boundary alternation alone already refuses
  those matches, so the boundary half independently prevents the exact corruption `(o-rel)` observes.
  Each half is individually sufficient for that one input; `(o-rel)` therefore only reds when **both**
  are absent — which is precisely the pre-fix build, and is the RED-first transcript recorded above.
  Confirmed with a standalone probe of the pattern:

  ```
  pattern: \.(?=[\\\\/]|[\\s'"`]|$)([^\s'"`]*)
  rewritten: agent-factory/config/factory.config.json     (unchanged)
  ```

  Left as written, the plan's `must_haves` truth "Neither half is load-bearing by assumption" would
  have been satisfied only in prose — the normalisation would have shipped with **no case in the
  repository able to see it**, which is the identical failure mode that let R2-CR-01 ship in the
  first place.
- **Fix.** Added case **`(o-rel-word)`**, which reaches the normalisation half on the axis where it
  genuinely bites: a relative override is an arbitrary caller **token**, and a short one collides with
  ordinary prose in the very sentences this helper rewrites. The fixture names the mirror directory
  `key` — a word the refusal sentence already contains — and runs from the parent with
  `CHECK_ROOT=key`. Without normalisation the pattern matches the bare word (a space satisfies the
  boundary) and replaces it with `.`; with normalisation the pattern is an absolute path and matches
  nothing but the path. The case asserts its own premise first: it derives the reference rendering
  from an absolute-root run and asserts the colliding word actually occurs in the prose followed by
  whitespace, so the fixture cannot pass by exercising nothing.
- **Files modified:** `scripts/check-foundation-guards.test.ts`
- **Verification:** RED under the half-one mutation (transcript above), GREEN restored.
- **Commit:** `8b64299`

- **Commit:** `4e497db` (removal), `8b64299` (landed with consumers)
