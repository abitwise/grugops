## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The set equality was not decidable in the documented-but-illegal direction**

- **Found during:** Task 3, while designing the extraction.
- **Issue:** As written by Task 2, the three closed-set declarations in `factory.config.md` used
  three different phrasings (`\`preset\` is exactly …`, `Allowed: exactly …`, `Allowed values:
  exactly …`). Any extractor over that would either need three parsers, or would have to intersect
  backticked spans with a candidate universe — and an intersection can only find an UNDOCUMENTED
  legal member. A documented-but-illegal member such as `turbo` is outside the universe, so it would
  pass. The plan requires both directions to fail separately.
- **Fix:** The three sites were unified onto one machine-readable grammar with a lowercase marker at
  every site (`preset allowed set:` / `alias allowed set:`), so one parser handles all of them
  without case folding, and the number of declaration sites is itself pinned two-sided.
- **Files modified:** `agent-factory/config/factory.config.md`
- **Commit:** `35a2259`

**2. [Rule 1 - Bug] The oracle's own vacuity floor was unreachable**

- **Found during:** Task 3, discrimination proof 6 — found by RUNNING the mutation rather than by
  reading the code.
- **Issue:** Three describe bodies read their surfaces eagerly at collection time. With the roster
  shortened to two, the first eager read threw `no surface registered under the role
  "hostGuidance"`, the file failed to collect, and vitest reported `Tests no tests`. The cardinality
  case that exists to catch a short roster never executed, and the failure named a missing role
  rather than the premise. This is the harness-premise failure class: the floor was proven only by
  the layer above it.
- **Fix:** `assertRosterPremise()` now runs at MODULE LOAD, before any surface is opened, and throws
  a message that names the premise, both readings of the cardinality, and the remedy. Every eager
  surface read moved inside its own case.
- **Files modified:** `scripts/model-dial-consistency.test.ts`
- **Commit:** `35a2259`

**3. [Rule 3 - Blocking] `TRIPWIRE_MODULES` fired on the added test module**

- **Found during:** Task 3, the full regression run.
- **Issue:** `scripts/check-foundation-guards.test.ts:8842` pins the exact number of test modules,
  by design, so that "a module added, removed or renamed out of this scan is a structural event, not
