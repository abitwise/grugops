# Phase 29.1: Per-Role Model Assignment - Context

**Gathered:** 2026-08-19
**Status:** Ready for planning

<domain>
## Phase Boundary

A `models` block on the config dial resolves a model alias per role, and
`scripts/generate-role-adapters.ts` emits that resolved value in place of its
hard-coded `model: inherit` across all 17 Claude Code sub-agent adapters. A repo
with no `models` block generates adapters **byte-identical to today's**.

In scope: the config field and its resolution, the generator change, the
`agent-factory/packaging/subagent.frontmatter.md` upstream update, one named
opt-in preset, alias validation, a derived emitted-equals-resolved guard, the
install-time delivery path, the `CLAUDE.md` "What NOT to Use" amendment, and the
MODEL-07 honesty floor.

Out of scope: per-checkpoint autonomy (Phase 30), any measured cost number, any
per-role model concept for the four non-Claude-Code host CLIs (they have none),
and reasoning-effort or any dial other than model alias.

</domain>

<decisions>
## Implementation Decisions

### Delivery path — how a config change reaches an adapter

**Scout finding that drove this area:** `install/install.ts` copies the kit's
**already-generated** adapters into the target (`linkOrCopy` at the adapter loop;
copy is the default per D-05, `--symlink` is opt-in). The generator never runs in
the target. So without a change here, a per-repo `models` block is inert — the
adapter a user's session loads carries whatever `model:` the kit shipped.

- **D-01:** Install performs **install-time generation**: it resolves the target's
  config and mirror-spawns the generator (cpSync the generator twin, the
  `kit-model` twin and the kit sources into a temp tree, spawn, read results out)
  rather than copying pre-generated adapters. This is the pattern
  `scripts/adapters-freshness.ts` already proves in-tree, and it keeps the
  generator's `OUT_DIR` a fixed literal with no output flag — the T-27-28
  path-traversal mitigation is untouched, not relaxed.
  — **Reversibility:** costly — reverting means install goes back to copying, and
  every repo installed under the new path holds adapters no longer reproducible
  by the old one; the `--check` assertion in D-02 and the `--symlink` arm in D-03
  both hang off this.
- **D-02:** A post-install config edit is caught by **re-running install**, and the
  existing `--check` doctor gains an assertion that each installed adapter's
  `model:` frontmatter value equals the target config's resolved value, naming
  stale adapters. Rejected: a target-side freshness gate (more machinery), and
  install-time-only with no detection (silent staleness — the failure mode
  `adapters-freshness.ts`'s own header was written against).
- **D-03:** `--symlink` install **plus** a non-default `models` block: install
  proceeds, materializing the **adapters as copies** because they are now
  per-repo derived artifacts, while everything else still symlinks. The
  divergence from the requested install mode is **reported by name**, never
  silent. Rejected: refusing the install outright, and dropping the models block.
- **D-04:** `scripts/adapters-freshness.ts` regenerates under an **explicit
  zero-config resolution**, not under whatever config happens to sit on the tree.
  Otherwise adding a `models` block to grugops's own config either turns CI red
  for a reason nobody expects, or ships tier-pinned adapters as the committed
  artifact. grugops's own repo therefore keeps no `models` block and its 17
  committed adapters stay `model: inherit`.

### Config shape and precedence

- **D-05:** The block is `{"models": {"preset": "<name>", "roles": {"<stem>": "<alias>"}}}`.
  `preset` resolves first against `kit-model.listRoles()`; `roles` is a **sparse
  override**, never a full map. An absent `models` block means `inherit` for every
  role. Role identity is the **role file stem** from `listRoles()` (e.g.
  `software-engineer.md` → adapter `grugops-software-engineer`), and the resolved
  map's cardinality is asserted against `ROLE_COUNT` so role #18 cannot arrive
  unassigned. Rejected: a per-role map with no preset — a hand-keyed 17-entry map
  in user config **is** the set-literal-drift class this milestone exists to
  eliminate.
  — **Reversibility:** one-way — `models` is a published config-dial contract; once
  users write it, changing the key shape needs a migration in `install --migrate`
  and breaks every repo already carrying the block.
- **D-06:** An unknown key in `roles` — a typo, or a role renamed or removed —
  is **refused, naming the key and the valid set**. A silently-ignored override is
  a tier the user believes they set and did not.
- **D-07:** The preset name is a **closed set** and **exactly one preset ships**.
  Values: `none` (the default; every role `inherit`) and the one shipped preset.
  Any other value is refused by name. Adding a second preset later is a visible
  source change, not a config-side surprise.

### Preset assignment and rationale

**MODEL-03 names three roles strong (orchestration, architecture, security/NFR)
and three cheap (engineering, QE/E2E, UAT), leaving 11 of 17 unassigned.** The
asserted-count clause means all 17 need a position and a reason.

- **D-08:** The preset is named **`tiered`**, not `cost`. `"preset": "cost"` is
  itself a cost claim, and MODEL-07 forbids shipping an unmeasured one. `tiered`
  names the mechanism without asserting the saving.
- **D-09:** The `tiered` preset assigns **`opus` to 4 roles and `sonnet` to the
  other 13. No role is assigned `haiku`.** The four: `orchestrator`,
  `architect-design`, `security-nfr`, `compliance-officer`.
  Rationale for the shape: every role in this kit either writes into the shared
  verified context or produces an artifact a human signs off on. The §14 gate
  catches correctness, not judgment — a thin-model UAT pack, ticket, or test plan
  degrades *past* the one mechanism that would have caught it rather than into it.
  Per-role reasons for the four: decomposition quality determines every downstream
  task; architectural boundaries are expensive to reverse; a missed vulnerability
  and a misclassified regulated-data field are both real-world harm rather than
  rework. Rejected: the literal MODEL-03 reading (`opus`×3 / `haiku`×3 /
  `sonnet`×11), which exercises all three aliases but puts the thin tier exactly
  where quality degradation is least visible.
  **Noted as genuinely arguable:** `incident-responder` — an incident is where
  time pressure and blast radius coincide — was considered for `opus` and left on
  `sonnet` because the role is procedural and hands to a named human. A later
  reader disputing this assignment is the intended use of D-10.
- **D-10:** The per-role rationale is a **required field in the exported tier
  table**, not a comment and not a separate prose doc. A role entry with no
  rationale **fails generation**. One mechanism therefore serves both MODEL-03's
  asserted count and MODEL-07's disputability, and the rationale cannot drift away
  from the assignment it explains.

### Refusal, degradation, and the guard

**MODEL-04 ("full model ids are refused") and MODEL-05 ("fail-closed to
`inherit`") are not contradictory — they describe different inputs.** MODEL-05's
"never to a *pinned tier*" implies a fallback path, and that path is a reader, not
the generator.

- **D-11:** Split by consumer. **Absent** value → `inherit` (the zero-config
  contract, not an error). **Present but illegal** — a full model id, a typo, a
  non-string — → the **generator refuses hard**: exit 1, naming the role, the
  offending value and the legal set, writing nothing. That is the generator's
  existing all-or-nothing posture (T-27-32), not a new behaviour. **Every other
  consumer** of a resolved model — the `--check` doctor, any runtime reader —
  **degrades to `inherit`**, never to a pinned tier.
  Legal aliases, closed set: `inherit` / `opus` / `sonnet` / `haiku`. Full model
  ids are refused because they rot into the hand-maintained stale literal this
  milestone exists to eliminate, and because an alias degrades gracefully for a
  user whose account lacks the stronger tier.
- **D-12:** A **new `guard_model_assignment`** in
  `scripts/check-foundation-guards.ts` reads each **committed** adapter's
  frontmatter through `scripts/frontmatter.ts` (the one authority) and compares it
  against a resolution computed **without re-running the generator**, with the
  member count asserted against `ROLE_COUNT`.
  **Why not extend `adapters-freshness`:** that gate regenerates and byte-compares,
  so both sides move together — it proves determinism, not that the resolution is
  correct. That is structurally the CR-01 defect Phase 29 spent rounds on
  (a check that "parses components out of the run and compares them to a tally over
  the same live document"). The guard must be an independent second opinion.
- **D-13:** MODEL-06's Claude-Code-only scope statement is **authored in
  `agent-factory/packaging/subagent.frontmatter.md`** — the single upstream source,
  which already documents the `model: inherit` choice and which MODEL-02 requires
  change in the same commit. `agent-factory/config/factory.config.md`'s `models`
  entry **points at it rather than restating it**. `CLAUDE.md`'s "What NOT to Use"
  entry against non-`inherit` wrappers is amended to name this mechanism as the
  documented reason. Rejected: two full statements held byte-identical by a claim-
  registry anchor (correct but adds a registry row for a claim with one authority).

### Honesty floor (MODEL-07)

- **D-14:** **No measurement is taken this phase and no cost claim ships.** The
  tier split is described as a plausible, unmeasured spend shift; every cost or
  limit-savings statement carries `UNKNOWN - verify`. `scripts/measure-cost.ts` is
  **untouched** — its standing `UNKNOWN - verify` (the `claude --output-format
  json` usage schema was never confirmed against a real authed capture, D-10/D-11)
  remains the honest answer. This matches how v2.0's ~50% figure was handled:
  grugops has never shipped an unmeasured cost claim, and a tier assignment is not
  evidence of a saving.
  Rejected: doing the authed capture this phase (pulls a deferred Tier-2 live-
  capture concern into a config phase), and wiring a measurement hook now
  (machinery with no consumer).

### Claude's Discretion
- The exact temp-tree layout and spawn mechanics of install-time generation —
  follow `scripts/adapters-freshness.ts`'s proven mirror-spawn shape.
- Where the tier table module lives (`scripts/kit-model.ts` vs a new sibling) and
  its exact exported type, provided the rationale field is required by the type
  and the count is asserted.
- Finding wording for every named refusal, following existing guard voice.

<code_context>
## Existing Code Insights

### Reusable Assets
- **Mirror-spawn harness** (`scripts/adapters-freshness.ts`): cpSync the generator
  twin + `kit-model` twin + kit sources into a temp tree, spawnSync the mirrored
  generator, read results out. Fifth instance of the pattern in this tree. D-01's
  install-time generation is a sixth use, not a new mechanism.
- **Two-location config resolution** (`readGovernanceConfig` in `context-io.ts`):
  `.grugops/factory.config.json` then `agent-factory/config/factory.config.json`,
  with present-but-degenerate shapes handled distinctly from genuinely absent ones.
- **`kit-model.listRoles()` + `ROLE_COUNT`**: the derive-and-assert pair every
  set in this tree is built on since Phase 27.
- **`scripts/frontmatter.ts`**: parses an adapter's frontmatter with the retain-
  every-occurrence discipline (a duplicate key is a refusal naming the count, not a
  last-wins silent pick).

### Established Patterns
- **Derive the set, assert the count.** The set-literal-drift class caused the
  Phase 23 spawn defect (7 granted names, 0 adapter files). Any 17-entry list
  written by hand — in source or in user config — reproduces it.
- **Delete the second authority rather than teach it a case.** The generator's own
  header records removing its duplicate `parseFrontmatter`; the resolution logic
  must not become a second config reader.
- **Named refusal over silent skip.** Every fail-closed arm in this tree prints a
  finding naming the offending member. D-03, D-06, D-07 and D-11 all follow it.
- **Zero-config byte-identity is asserted, not assumed.** SC1 says "byte-identical
  to today's", not "still works".
- **A green suite is not proof of a safety invariant.** D-12's independence
  requirement exists because a regenerate-and-compare check moves both sides
  together — the CR-01 shape from Phase 29.

### Integration Points
- `generate-role-adapters.ts` `render()` — the `model:` emit line.
- `install/install.ts` — the adapter loop (copy → mirror-spawn generation), the
  `--check` doctor (staleness assertion), and the `--symlink` arm.
- `adapters-freshness.ts` — pinned to an explicit zero-config resolution.
- `check-foundation-guards.ts` — new `guard_model_assignment` member.
- `agent-factory/config/factory.config.{json,md}` and the seed config — the new
  `models` field and its documentation.
- `subagent.frontmatter.md` and `CLAUDE.md` — the prose that must not disagree with
  the generator.

</code_context>

<specifics>
## Specific Ideas

- The preset value is spelled `tiered`. `cost` was explicitly rejected as a name
  because it asserts an economic outcome MODEL-07 requires be measured.
- The four `opus` roles are named exactly: `orchestrator`, `architect-design`,
  `security-nfr`, `compliance-officer`.
- `haiku` remains a legal alias a user may set; it is simply not used by the
  shipped preset.
- `incident-responder` is recorded as the arguable `sonnet` assignment, so a later
  reader disputing it has the reasoning in front of them.

</specifics>

<deferred>
## Deferred Ideas

- **A second preset** (e.g. a `quality` position, strong everywhere judgment
  plausibly matters). D-07 ships one preset; a second is a visible source change
  in a later phase.
- **The authed `claude --output-format json` usage capture** that would let
  `measure-cost.ts` report real numbers — deferred since v1.2 (D-10/D-11) and not
  pulled into this phase by D-14.
- **Per-role reasoning-effort or other per-agent dials** beyond model alias — out
  of scope; this phase ships the model alias only.
- **Wiring tier resolution into `measure-cost.ts`** so a future capture can
  attribute cost per role — rejected now as machinery with no consumer.
