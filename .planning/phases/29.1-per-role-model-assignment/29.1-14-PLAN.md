R2-WR-02: `scripts/check-foundation-guards.test.ts:10170-10185` locates the ubuntu gate block by its
step name and then takes everything to end of file. Today that slice is accidentally correct because
the block happens to be the last step in the workflow. The moment a step is appended after it, a
`npm run generate:adapters` occurring THERE satisfies the case while the ubuntu gate no longer runs
it. The probe also runs over raw text in a block that is roughly four-fifths comment, so a future
comment quoting a command keeps the case green with the command deleted. The case's own header
asserts the stronger property it does not hold — that a hit anywhere else in the workflow does not
put the command on the gated path. This is the exact defect plan 29.1-10 identified and fixed in the
sibling oracle four commits earlier, whose own comment records that a section reader searching to
end of file is not reading a section. The lesson was recorded in the same round and not applied here
— and `scripts/skill-twins-freshness.test.ts` Case 8 still carries the same unbounded reader, which
is why this plan closes the class rather than the instance.

R2-IN-05: `.github/workflows/ci.yml` asserts adapter cleanliness with a command that ignores
untracked files, beside a comment claiming it proves the committed adapters match the live
configuration. An adapter the generator creates that was never committed leaves that command empty.
In CI the gap is unreachable today; locally it is reachable, and the command reads as a stronger
guarantee than it gives.

Output: a pin bounded at both ends over commands rather than prose, the same discipline applied to
its sibling and the class counted, and a cleanliness assertion that can see what it claims to see.
