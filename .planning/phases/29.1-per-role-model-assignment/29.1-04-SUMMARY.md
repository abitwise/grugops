## Decisions Made

- **One TIERED-cardinality arm, three numbers.** `MODEL_TIERS_COUNT` is declared `= ROLE_COUNT`, so a second arm would be a branch no input can reach and the gate would print two sentences for one fact. ## Deviations from Plan

### 1. [Rule 1 — measured specification error] The plan's cases (c) and (d) do not reach the arms they name

- **Found during:** Task 1, before a line of the guard was written — the admission grammar was probed rather than assumed.
- **Issue:** The plan specifies case (c) as "duplicate the `model` key … assert the finding names the COUNT and both values" and case (d) as "set the value to the empty string … assert a finding naming emptiness". Measured against the committed `canonical-frontmatter.js`, **neither plant reaches the guard's arms**: a duplicate key is `[duplicate-key]` and every spelling of an empty value is `[dangling-empty-key]` / `[quoted-on-plain-only-key]` / `[scalar-padding]` / `[unrecognized-line]`. `admit()` refuses a duplicate rather than merging it — the structural difference from `frontmatter.ts`, whose value list length *was* the number of times a key appeared. The plan's wording was written against the older parser's behaviour.
