   — verified, the script appears in `package.json:25` and in no CI step.

surface is unreachable from the build. The user's ruling is to close BOTH halves, and this plan
does: the guard's advisory report becomes a failure, and the generator joins the ubuntu gate
block with a `git diff --exit-code` behind it that additionally proves the committed adapters
match the live configuration.

over the same file. WR-08: `sourceLabel` is initialised to a phrase meaning "there is no
configuration anywhere" and is only reassigned inside the success branch, so a degraded run
whose configuration file exists and was refused prints exactly the conflation this module's own
header spends a paragraph forbidding. IN-05 is the same defect one line up and is fixed the same
way — by deleting the initialisers so a future fourth path is a compile error. IN-02: the verdict
embeds an absolute path, which breaks this guard's own byte-identical-output commitment and
leaks a home directory into CI logs.

cardinality floor out of `resolveModels` was that it lives in `roleCorpusCardinalityRefusal` and
`tieredCorpusRefusals`; today it lives in their tests. This plan gives `tieredCorpusRefusals` a

names, because on this repository's own zero-config tree a tiered-path-only call would never
execute in CI, which is the very shape IN-01 reports.

Output: refusals that can fail a build, a verdict that describes the run it performed, and a
cardinality predicate with a consumer that actually runs.
