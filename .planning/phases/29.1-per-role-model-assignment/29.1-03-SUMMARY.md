## Decisions Made

- **No `resolvedPresetName(...)` accessor.** The plan offered it conditionally ("if the preset name is
  not already carried on the resolution result"). It is carried — on `ModelsConfig.preset`, which the
  generator holds and hands straight to `resolveModels`. What genuinely lacked a single authority was
  the **line's shape**, so the module gained `RESOLVED_PRESET_PREFIX` + `resolvedPresetLine` +
  `resolvedPresetsIn` instead. The generator announces `modelsConfig.preset` — the same object it
  resolved with, not a second derivation — so the announcement cannot describe a resolution the run
  did not perform.
- **The preset assertion runs before the byte comparison.** A configured regeneration also moves
  bytes. A gate that let the wrong preset fall through would produce a `STALE:` finding that looks
  entirely correct and says nothing about which resolution it compared. Case 10 pins this by
  asserting the output does **not** contain `STALE:`.
- **An ambiguous stdout is refused, not resolved.** The plan named three outcomes; a stream carrying
  two announcements is a fourth. Taking one of them would be a silent choice between two claims about
  the same run, so the gate names the count and the values and dies.
- **The verdict's announcement line carries no full stop.** It re-emits the same marker the generator
  uses so a reader of *this* gate's output can parse it with the same grammar; trailing punctuation
  becomes part of the parsed value. Measured — the first draft produced `none.` and failed its own
  case, which is recorded in a comment at the line.
