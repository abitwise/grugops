## Critical Issues

### CR-01: the round-4 suffix-traversal bypass is restored by inserting one declared terminator byte

**File:** `scripts/check-kit-refs.ts:234` (`CONFIG_REF_TERMINATOR`), `:252-265`
(`configReferencesIn`), `:363-367` (the claim this falsifies)
**Also:** `scripts/check-kit-refs.test.ts:494-535` (the SUFFIX case, which probes exactly one point
on this axis)

**What is wrong.** `configReferencesIn` truncates each record at the first byte in
`/[\s`'"()[\],;]/`, and membership is then decided over the **truncated prefix**. Round 4's CR-03 was
`agent-factory/config/factory.config.json/../../../../etc/passwd` — no terminator, so the whole path
is the record and it is correctly refused. Insert **any one** of the eight declared terminator bytes
between the admissible basename and the traversal, and the record collapses back to
`factory.config.json`, which **is** a member. This is the same "the capture was a prefix of a longer
path" defect the round deleted the regex for, wearing a different alphabet — and the code's own
comment at `:230-233` asserts the opposite (*"it cannot be the lever a future bypass reaches for: a
record that stops in the wrong place is simply a different string, and a different string is still
put to the same membership rule"*). A record that stops **early** is a SHORTER string that IS in the
set, so truncation admits what the full path would refuse.

**Concrete failing input** — reproduced on a hermetic `git archive HEAD` mirror against the
committed `scripts/check-kit-refs.js`. On `agent-factory/config/factory.config.md` line 138, replace
the first `agent-factory/config/factory.config.json` with
``agent-factory/config/factory.config.json`/../../../../etc/passwd`` (a single backtick inserted):

```
byte delta on line 138: +24
grep -o 'agent-factory/config/' count in file: 3   (UNMOVED)
grep -c 'etc/passwd':                          0 -> 1
records the gate extracts from line 138: ["factory.config.json","factory.config.json"]

  PASS  no agent-factory/config/ refs remain (3 counted self-reference mention(s) on 2 line(s) exempt ...)
  PASS  the config self-reference exemption is exactly 3 mention(s) on 2 line(s) in 1 file(s), as declared
ALL CHECKS PASSED
TRUE EXIT = 0
```

All three published cardinalities (files 1, lines 2, mentions 3) are exactly as declared, the
run-time unit-mismatch floor stays silent, and the shipped configuration reference — the document
this phase's single packaging authority points every reader at — now names a path four levels out of
the kit. The same result at TRUE exit 0 with `'`, `;` and `,` in place of the backtick
(measured: 4 for 4).

**Why the oracle is green over it.** `check-kit-refs.test.ts` calls
`respellFirstNamedPath(ref, CONFIG_SIBLING + SUFFIX_TRAVERSAL)` — the **no-delimiter** point. The
corpus carries no input in which a terminator sits between the member name and the suffix, which is
the entire difference between red and green.

**Direction.** FAIL-OPEN. D-08.1 is a zero-tolerance gate publishing a green verdict that
misdescribes its own run.

**Suggested direction.** Do not widen or narrow the terminator class — that moves the same
truncation somewhere else. Decide membership over the **whole named token the reader sees**, not
over a delimiter-truncated prefix: e.g. require that the record be a member AND that the byte
immediately after the record not be a path-continuation byte (`/`, `.`, `\`), so a truncation that
is followed by more path is a stray by the ONE rule rather than by a new special case. Then add a
RED case at the terminator-truncated suffix position, and state its premise in the unit the gate
decides in (the record VALUE), not only in the needle count — see WR-03, which explains why the two
count units cannot see this.

### WR-03: the oracle's "state every premise in BOTH units" discipline is satisfied by construction — the two units are the same number on every input

**File:** `scripts/check-kit-refs.test.ts:196-225` (`recordsIn` and its docstring),
`scripts/check-kit-refs.ts:459-464` (the run-time floor it mirrors)

`recordsIn` pushes exactly one record per occurrence of the needle and `mentionsIn` is a split count
of the same needle; `agent-factory/config/` has no proper prefix that is also a suffix, so the two
numbers are **equal for every possible input**. Every new RED case therefore states
`mentionsIn(after, …) === N` and `recordsIn(after, …).toHaveLength(N)`, which is one number asserted
twice. The docstring's stated bound is stronger than the mechanism: *"a drift between the two
classes reds the premise assertions that use it, naming both counts"* — a change to
`RECORD_TERMINATOR` moves record **values**, never record **counts**, so no count premise in the
file can see such a drift. Only two value assertions (`toContain("")` in the bare-directory case and
`toContain("factory.config.json" + SUFFIX_TRAVERSAL)` in the suffix case) would.

This matters because it is why CR-01 is invisible: the terminator-truncated bypass moves **no
count**, only a record value, and the corpus's premise discipline is written in counts.

**Fix:** assert premises over the record **VALUES** (`expect(recordsIn(after, …)).toEqual([...])`),
which is the unit membership is decided in; and either derive `RECORD_TERMINATOR` from the gate
module or delete it and assert the values directly.

`WR01_DEFECT_SPELLINGS` / `WR01_FIXED_SPELLINGS` are also hand-maintained two-element literals with

**Fix:** loop the scan over `["check-kit-refs.ts", "check-kit-refs.js"]` as `model-tiers.test.ts`
