### Blocker 1 — the kit-ref gate, third round running

The plan-22 fix is real. `configReferencesIn` emits one record per **needle occurrence**, so the count
the gate publishes and the set it adjudicates are the same set by construction, and all three round-4
spellings now red. In deleting the capture/occurrence mismatch it introduced a **truncation**
mismatch: a record stops at the first declared terminator, and membership is then decided over the
truncated prefix.

```
mutation: one terminator byte inserted between the member name and a traversal, on the
          already-exempt line 138 of agent-factory/config/factory.config.md

  byte delta                      +24  (backtick case)
  needle count                    3 -> 3    UNMOVED
  grep -c 'etc/passwd'            0 -> 1
  gate output                     "3 counted self-reference mention(s) on 2 line(s)"
                                  "exactly 3 mention(s) on 2 line(s) in 1 file(s), as declared"
  TRUE EXIT                       0

  measured for all NINE declared terminator bytes: 9 for 9, identical result
  POSITIVE CONTROL (no terminator, round-4 CR-03):  TRUE EXIT 1, stray named
```

The code's own comment at `:230-233` argues this cannot happen — *"a record that stops in the wrong
place is simply a different string, and a different string is still put to the same membership rule."*
A record that stops **early** is a **shorter** string that **is** in the set. The soundness argument is
falsified by measurement, and a false soundness argument in a comment is how the next reader stops
looking.

**It compounds with an unfixed round-4 info finding.** Ledger row 103 (`Owner: unassigned`) records
that `walk()` admits symlinks. Reproduced:

```
plant: agent-factory/config/evil.md -> /etc/passwd
       plus a same-line respelling of one existing mention to agent-factory/config/evil.md

  gate output    "exemption sibling set: 4 depth-1 regular file(s) in agent-factory/config/
                  [.gitkeep, evil.md, factory.config.json, factory.config.md]"
  needle count   3   (unmoved — cardinality clean)
  TRUE EXIT      0
```

The gate calls a symlink a *regular file* and admits it to the very set membership is decided against.
This matters beyond its own severity: it defeats the natural remedy for the truncation bypass, because
that remedy decides membership against this set.

## Gaps Summary

Round 5 was the most technically accomplished round of this phase. It closed all three round-4
blockers on the axes they were filed on, closed two warnings cleanly, applied the WR-03 ruling
faithfully, and produced in `(r-base-discriminating)` the first oracle in this phase that proves a
property by comparing computed behaviour instead of source text.

It also re-opened all three blockers one step out, and each time by a mechanism its own fix
introduced:

- The gate that stopped counting in the wrong **unit** started deciding on a **truncated record**.
- The class case that could not fail for its **members** cannot see a **non-member one directory
  down**.
- The function made total on its **second** argument still throws on its **first**, and the ledger
  written to bound that residual publishes a **closed enumeration** that is false.

The pattern is the one this project's own memory names: a fix that closes the axis the finding was
*written on* rather than the axis the finding was *about*. Three rounds have now closed
`check-kit-refs` on three different axes of one question — *which string is admissible* — and each
answer moved the ambiguity somewhere new. The remedy in every case is the same and is stated in the
`missing` lists: decide the question once, over the whole thing the reader sees, against a set that is
derived and counted rather than assumed; and where the question is genuinely open-set, apply D-59 and
narrow the published claim to what the mechanism decides, rather than buying one more axis.

Two things about the record deserve saying plainly. The disclosure ledger in this phase is unusually
honest — row 95 files itself as `unmet-truth` and says its own plan's stated truth is false; row 100
discloses a FAIL-OPEN it could have omitted; row 97 discloses a surprise nobody asked about. That
culture is working. What is not working is the **completeness clause**: row 95's *"four input
classes"*, row 80's earlier *hypothetical* framing, the `(r-class-authority)` title's *"nothing
outside that set"*. Each is a closed claim over an open set, in a ledger otherwise built to prevent
exactly that. An honest ledger with a false completeness clause is more dangerous than a silent one,
because it is the reason the next reader stops looking — and in this phase, four times running, that
next reader was the verifier.
