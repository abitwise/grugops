<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user repo (old v1.0 layout) → installer | the in-repo agent-factory/, the old config, and the .claude adapters are user-side artifacts the migrate reads and relocates |
| symlink adapter dest → source clone | a v1.0 symlink adapter points INTO the grugops source checkout — writing through it crosses out of the target repo |
| installer → host filesystem | migrate renames/copies/unlinks paths on a user machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-02-SYM | Tampering | materializeAdapter writing through a v1.0 symlink adapter into the source clone (THE LANDMINE) | mitigate | **HIGH severity.** migratePreSteps unlinks (`rmSync force`) any `isSymlink(dest)` resolver-adapter dest BEFORE the install run re-materializes; a RED-by-design case (`migrate: symlink adapter does not corrupt source clone`) asserts the planted source-clone file is byte-unchanged after migrate. Never `writeFileSync` through a live symlink. |
| T-17-02-DEL | Tampering | losing the user's in-repo agent-factory/ or edited config on migrate | mitigate | never-delete-first: the displaced agent-factory/ is renamed to a timestamped backup (differs-only, D-08/D-09), the old config is left as a `.bak` and copied (not moved-over) to `.grugops/` only if absent (never-overwrite seeded state, D-04). |
| T-17-02-CR1 | Tampering | unbounded marker-strip silently dropping user lines after an unterminated open marker | mitigate | migrate reuses `materializeAdapter`'s CR-01 bounded removal verbatim (buffers the block, restores it if the close marker never arrives); a `migrate: bounded marker-strip` case proves no following lines are lost. |
| T-17-02-TGT | Tampering | migrate mutating an unintended target (e.g. the grugops source checkout) | mitigate | the `--migrate` branch sits AFTER the always-on self-checkout guard (Pitfall 4); paths are resolved absolute before any write (install.ts:99-141). |
| T-17-02-NOOP | Tampering / DoS | a re-run re-mutating an already-migrated repo or growing backups unboundedly | mitigate | D-12 marker-gated no-op (a second migrate hits the marker-present path and exits 0 without re-running install) + D-09 differs-only backups; a `migrate: a second migrate is a no-op` case asserts snapshot equality and a non-growing backup glob count. |
| T-17-02-EOP | Elevation of Privilege | setting the prod deploy-approval env var | mitigate | HARD CONSTRAINT — migrate never sets it; it only relocates files. No deploy path is touched. |
| T-17-02-SC | Tampering | npm/pip/cargo installs | accept | No package installs this phase (RESEARCH Package Legitimacy Audit: not applicable, zero external packages). No `[ASSUMED]`/`[SUS]`/`[SLOP]` packages — no legitimacy checkpoint required. |
</threat_model>
