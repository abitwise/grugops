<objective>
Implement `--update` (UPD-01) and `--prune-old-kit` (D-10), plus the RED-by-design Vitest cases proving them. `--update` refreshes the central `$GRUGOPS_HOME` kit in place via `copyKit(retainBackup=true)` (the one behavioral delta from a plain re-install, D-06), is kit-home-only (D-05), and warns-then-proceeds on a downgrade (D-07). `--prune-old-kit` is the single, opt-in deletion path (D-10) that removes ONLY grugops-created backups and never runs by default (never-delete-first).

Locked decisions implemented here: D-05 (kit-home-only, no target, per-repo state untouched), D-06 (retain displaced kit as a timestamped backup), D-07 (downgrade warn-then-proceed), D-10 (one unified opt-in prune flag). SC2's "doctor names the unresolved path on failure" is already satisfied by the existing doctor (install.ts:251-363) — this plan confirms it is NOT regressed rather than reimplementing it.

Purpose: Refresh the shared kit reversibly without touching any repo's state — the deferred UPD-01 story — and ship the one safe deletion lane for the backups migrate/update leave behind.
Output: the `--update` early branch + the `--prune-old-kit` branch in install.ts; the 4 update cases + prune case + DRY_RUN arms in install.test.ts; README `--update`/`--prune-old-kit` sections; committed `.js` fresh.
