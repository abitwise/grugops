## The DI-07 sibling search (re-derived at execution, by a TypeScript parser walk of install/uninstall.ts)

Every `return` whose expression holds `"verify"`, every `outcome: "verify"`, and every `setOutcome(…, "verify")`:

| Enclosing function | Verify returns | Entry kind it reverses |
|--------------------|----------------|------------------------|
| removeFile (reverseFile) | 2 | file |
| removeOwnedEmptyFile (reverseBlock's pointer file) | 2 | file |
| removeSentinelBlock (reverseBlock) | 2 | block |
| unmergeGemini (reverseGemini) | 7 | gemini |
| removeAskRules (reverseAskRules) | 8 | ask-rules |
| removeOpenCodePermission (reverseOpenCodePermission) | 4 | opencode-permission |
| removalDecision (a RemovalDecision `act`, consumed by removeFile, removeOwnedEmptyFile and the report-only pass) | 3 | (none of its own) |

That is 25 Outcome sites and 3 decision sites. No `setOutcome` call passes a `"verify"` literal: every one passes a function's result. Every `verify(...)` inside the walk is followed by a `verify` outcome for its entry. reverseDir's outcomes are `left` (not owned, seeded or protected, `tools/` present) and `gone` (`tools/` absent). rmdirIfEmpty's outcomes are `left`, `gone` and `removed`. **No recorded verify lands on a `dir` entry.**

**One deviation from the plan's premise (step 1).** All 25 sites are of HOLDING_KINDS kinds. But an `ask-rules` entry that claims nothing (`added` empty, no `created*` flag) is of a holding kind and does not hold (install-marker.ts entryHolds). Install records one when `.claude/settings.json` already holds every ask rule. removeAskRules applies "a ledger that claims nothing is no record for the file" only in its `blocked` arm. Its four JSON-shape arms (not a JSON object or a parse error, a duplicate `permissions` key, a `permissions` that is not an object, a `permissions.ask` that is not an array) still count a verify. Reproduced by a scratch run (GRUGOPS_HOME and HOME set to scratch directories):

1. Install [claude, codex] into a target whose settings file already holds every rule.
2. Set the file to `[]`.
3. Run `uninstall --claude`. It exits 3. The marker is rewritten with `agents` [codex], and the ask-rules entry stays in the ledger.
4. The kept `left` line and the banner print `--claude` (the NAMED fallback). Run, that command reports "none of the named agents is installed here" and changes nothing.

So DI-07's arm (a partial kept arm with nothing held and a recorded verify) is reachable through an entry that does not hold, not through a directory. The printed command is never the flag-less one, so D-05 still holds. But in that arm finishCommand names an agent the rewritten marker no longer records, which is against this plan's fourth truth. Per the brief's §3, it is recorded as **DI-11** in deferred-items.md with two triage options, and it is not fixed in this plan.
