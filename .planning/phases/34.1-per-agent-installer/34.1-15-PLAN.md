## The IN-21 choice (planner's decision, D-26 lets the planner choose and asks for the reason)

**`agents` keeps the "chosen" meaning:** an agent is recorded from the install that chose it until an uninstall
removes it. Since plan 34.1-14, an uninstall never drops an agent while the ledger holds install content it owns.

**Why:**
- D-26 keeps D-04's retry of a refused agent. A refused agent owns no ledger entry, so only a field that records the
  choice can make a later `--yes` choose it again.
- The ledger alone cannot tell Codex CLI from Antigravity CLI on their shared skill (install-marker.ts, "WHY A
  RECORDED FIELD").

**What follows:**
- The meaning is written once (install-marker.ts header, README).
- The doctor gives no reach line to a recorded agent with nothing installed here: no holding ledger entry it owns and
  none of its entry paths present.
- The entry-path clause keeps the reach line, and the WARN, for an agent whose entry is the user's own file. Without
  it, kit-route.test.ts's case "the user's own AGENTS.md and shared agent skill without the route" would lose the
  warning that strands Codex and Antigravity.
- Reversibility: costly. The meaning is published in install/README.md, and it decides what an unattended re-install
  chooses. It is flagged, not gated.
