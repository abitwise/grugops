# Phase 34.1 Plan 16: CLEAN-1 teardown and terminal restore (IN-20, IN-18, DI-06) Summary

**Uninstall now removes, by record, the OpenCode containers and file install created even when the user already took
the rule out. The agent list restores the cursor and raw mode through one restore that runs both steps whatever
throws. A blank CLAUDE.md or Copilot file install created, whose block the user removed, is named on a `left` line,
kept, and finished by the printed command.**

## Accomplishments

- **IN-20 (D-26, CLEAN-1, DC-2).** removeOpenCodePermission's early `gone` for "the rule is not there any more" is now
  the rule-gone arm. A record that says install created nothing around the rule is still `gone` at once. Otherwise the
  same splice (strippedOpenCodeText) and THE ORACLE run over one OpenCodeScope:
  - each container install created goes once it is an object with no member left;
  - the file install created goes once what is left is byte for byte install's emptied file with the recorded mode.

  The `removed` and `would-remove` lines name "the empty `external_directory` and `permission` objects install
  created" (only the ones taken out) and say the rule was already gone. A run with nothing of install's left prints
  the old `skipped` line. That line also gives the kept-mode reason when the file is install's emptied file but has
  another mode.
- **IN-18 (D-26, CLEAN-1).** agent-picker.ts exports HIDE_CURSOR, SHOW_CURSOR and restoreTerminal(io). It still
  imports nothing and does no I/O of its own. pickAgents writes HIDE_CURSOR as the first statement inside the `try`.
  Its `finally` calls restoreTerminal with `process.stdout.write` and `stdin.setRawMode`, each bound to its stream. The
  comment states the signal residual as `UNKNOWN - verify`. The README paragraph names the fail-safe restore and
  `tput cnorm` (or `reset`).
- **DI-06 (D-30, CLEAN-1).** removeSentinelBlock's no-block arm sets `blankWithoutBlock` from the bytes it already read,
  using isBlankByte, the predicate blankAfter uses. removeOwnedEmptyFile acts when the block is already gone, the file
  is blank and the ledger has a `file` entry at the path. It then reports `left`: "install created it, and its grugops
  block is no longer in it; it is blank, but the bytes install wrote are not here to compare, so it was not removed;
  delete it by hand if you do not need it". The entry is held, so the owning agent stays in `agents` (D-29), and
  the kept line prints finishCommand. DRY_RUN prints the same line.
- **DI-05** is recorded in deferred-items.md for human triage. It names install/uninstall.ts unmergeGemini at about
  line 1105, proposes a remedy and says "Not fixed: kept deferred by D-30; human triage". There is no DI-06 entry.
