# Phase 34.1 Plan 27: The doctor's remedies print the builder's command Summary

**The doctor's stale-adapter remedy (DI-08) now prints `doctorInstallCommand()`, which is `agentCommand("install.js", TARGET, [], COMMAND_CONTEXT)`, in place of the hand-built, unquoted `node install/install.js --target`. Every other doctor remedy that asks the user to run install.js keeps its words and adds the command from that helper or from `doctorCheckCommand()`, so it runs from any directory with the kit home the run used. Two tests run a printed doctor command from a scratch directory and check what it did: the DI-08 case (M7) and M9.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Accuracy, DOC-1] The DI-08 tail says "renders from the checkout at <script parent>" and not "renders from this checkout"**
- **Found during:** Task 1
- **Issue:** a `--check` run given GRUGOPS_SRC renders from that checkout, but the printed command carries no GRUGOPS_SRC and renders from the checkout its install.js is in. "This checkout" would then name the wrong one.
- **Fix:** the tail names the path, `resolve(SCRIPT_DIR, "..")`.
- **Committed in:** 5af55277

**2. [Rule 2 - Accuracy] DOCTOR_NO_FLAG_CLAUSE is also printed for D11 and D12**
- **Found during:** Task 2
- **Issue:** the plan asked for the clause only on D1 and D2. D11 and D12 also follow a marker the install cannot use, so the install falls back to detection, the same as D1 and D2.
- **Fix:** the one const is printed at all four sites.
- **Committed in:** 0a72286c

**3. [Rule 3 - Blocking] The agent-flag census read the new tests' expected-word arrays as spawns**
- **Found during:** Task 2 verify
- **Issue:** `["node", join(REPO_ROOT, "install", "install.js"), ...]` matches the census's argv-vector shape.
- **Fix:** the words are compared one at a time. No exemption was added, since these are not spawns.
- **Committed in:** 0a72286c

**4. [Rule 3 - Blocking] doctorCheckCommand was added in Task 2, not Task 1**
- **Issue:** `noUnusedLocals` refuses a helper that nothing calls.
- **Fix:** Task 1's context census pin is 11 (one new call), and Task 2 pins 13.

**5. [Added test] A parser check for the class "builder in the same expression"**
- **Issue:** the plan's rule "classify a fragment only when the message does what its class says" was held for this new class only by the table, not by the parser.
- **Fix:** the new check is mutation-proven (C1).
- **Committed in:** 5af55277

**Total deviations:** 5 (2 accuracy, 2 blocking, 1 added check). **Impact:** no scope change, no census rule loosened, and no row classed just to make a test pass.
