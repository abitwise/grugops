# Phase 34.1 Plan 10: `--check` speaks only for the installed agents Summary

`install.js --check` now reports `reach` lines, carrier lines and counted kit-route findings only for the agents installed in the target. The installed set comes from `installedAgents` (recorded, or the legacy rule), or from detection with a `note` when nothing is recorded. The Claude Code adapter checks run only when Claude Code is installed. Install's route-note pass uses the same `hostsOf` / `routeCarrierSet(hosts)` / `strandedBy(..., hosts)` derivation over `AGENTS_AFTER`.

## What was built

- **Task 1 (tracer, 5474cff5).** `strandedBy` takes a third parameter, `hosts`, and it is required. Three new functions in `install.ts`: `routeCarrierSet(hosts)`, `hostsOf(ids)` and `doctorHosts(markerRead, ledgerRead)`. `kitRouteFindings` takes `hosts` and uses it for the carrier set, the `(read by …)` lists, `strandedBy` and the reach loop. The doctor reads the ledger once and works out the host set from that read and its marker read. It prints a `note` when the set came from detection and another when the marker records ids this build does not know. Tracer test: after `--codex`, `--check` prints exactly one `reach` line (Codex CLI, through `AGENTS.md` and `.agents/skills/grugops/SKILL.md`) and no line about any carrier Codex CLI does not read. The carrier list is derived. The tracer gate passed when re-run.
- **Task 2 (a3d392d8).** `claudeInstalled` is true when the host set includes the `claude-kit` row. When it is false:
  - the adapters are never read;
  - the kit-root cross-check compares only the rule and the marker (ok / cosmetic WARN / FAIL);
  - the stat lines name the marker as their reference;
  - adapter staleness is skipped;
  - the kit-version-unknown WARN names the kit the target uses;
  - the ask-rule info line says no rules are expected.

  Tests added:
  - The `strandedBy` oracle now covers every subset of HOST_TOOLS (64 subsets, count asserted) for every fact combination (128). That is 57,344 `strandedBy` calls, each subset passed in reversed order.
  - For each registry row (6, count asserted): install with only that agent's flag, then `--check` exits 0 with `ALL CHECKS PASSED` and exactly one `reach` line.
  - A legacy marker gives reach lines for Claude Code, Copilot and Pi.
  - A v2.1.0-shaped marker with no ledger gives the detection note and a reach line for Claude Code.
- **Task 3 (8b433ba4).**
  - The class-matrix follower reads the marker's `agents` field itself and limits reach, reads and stranded hosts to those agents.
  - Assertion (4) now also checks that no line is printed for a carrier that no installed agent reads.
  - New group (d): one cell per HOST_TOOLS row × AGENTS.md ∈ {current, user-without-route}, 12 cells. `CELL_COUNT` adds `2 × HOST_TOOL_COUNT`, and the axis case asserts it. The DRY_RUN and the re-install pass the cell's one flag.
  - The kit-route section of `install/README.md` now states the installed-set rule, the detection fallback and that the Claude Code checks run only when it is installed. It also says reach lines describe files, not a live host run.
