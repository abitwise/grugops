## Warnings

### WR-44: At a terminal, over an unreadable marker, one Enter press on the agent list makes detected agents "named by the user", and the refusal prints them as "the same agents again" (the WR-41 harm, one arm over)

**File:** `install/install.ts:6031` (AGENT_LIST_AT_TERMINAL), `install/install.ts:6039-6048` (the list is built from INSTALLED_IDS_BEFORE), `install/install.ts:6078` (SELECTION_NAMED_BY_USER), `install/install.ts:6171`, `install/install.ts:7714-7718`; test gap at `install/install.test.ts:11179, 11189`
**Issue:** `SELECTION_NAMED_BY_USER = SELECTED_BY_FLAG.size > 0 || AGENT_LIST_AT_TERMINAL`. Any run that gets past the
agent list counts as named by the user. But over an unreadable marker, `installedAgents` answers NONE
(install-marker.ts:1704). So `pickerRows` marks no agent as installed and pre-checks only the detected ones, and
nothing on the list says the record could not be read. Pressing Enter accepts exactly the detection-driven choice that
WR-41 removed from the unattended arm. The refusal then names those agents and says "installs for the same agents
again". The verify's own "then re-run the installer" would show the list with the recorded agents pre-checked once the
marker is fixed. So the two next steps disagree again, which is the WR-41 complaint.

`INSTALL_REFUSAL` is now known before the list is drawn (install.ts:6009), so the run already knows it will write
nothing and that its list hides the record. The plan kept the list where it was (IN-45 deferred by D-47). This is not
IN-45's UX note: it is WR-41's printed-remedy defect reproduced through the list.

Reproduced (scratch HOME/GRUGOPS_HOME, pseudo-terminal through `script -q /dev/null`):
1. `install --codex --yes` exits 0, and the marker has `agents: ["codex"]`.
2. Add `.claude/` and put a trailing comma in the marker. Run with no flags and no `--yes`. The list shows
   `[x] Claude Code (detected: .claude)` and `[ ] Codex CLI` (the installed agent is shown unchecked, with no label).
   Press `\r`. It exits 3 and prints `... install.js --target <t> --claude` "installs for the same agents again".
3. Restore the marker and run the printed command (with `--yes`) from `/`. It exits 0. The banner says
   `agents: Claude Code (named by flag)`, `.claude/agents`, `.claude/skills` and `.claude/settings.json` are written,
   and the marker's `agents` becomes `["claude","codex"]`.

The new terminal row ("the agent list over a marker install cannot use") asserts as a PREMISE that no agent is
detected (install.test.ts:11179) and that nothing is pre-checked (11189). Its only "named" arm toggles an agent by
hand, so no test covers this cell.
**Fix:** Do not show the list when the run is already refused. In SELECTION_WHY's initializer, before the terminal
branch:
```ts
if (AGENT_LIST_AT_TERMINAL && INSTALL_REFUSAL !== null) refuseOverMarker(PREVIOUS_MARKER_READ, INSTALL_REFUSAL, []);
```
This also closes IN-45: no list over a foreign read whose answer is thrown away. If the list must stay, count only the
rows the user changed against `list.checked` as named, and print the `agents:` line with each agent's reason before
the closing. Add a terminal row with `.claude/` detected beside a recorded `--codex` install and a trailing comma,
answered with `\r`. Assert that the closing prints no agent flag, follow everything printed, and assert that `agents`
is still `["codex"]` and nothing exists under `.claude/`.
