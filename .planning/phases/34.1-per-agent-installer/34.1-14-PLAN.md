## D-29: the flag-less kept arm (human, 2026-10-12, at plan check)

D-29 amends D-26 and settles the flag-less kept arm by ownership. An agent stays recorded in `agents` while it owns a
held ledger entry, counting shared entries through entryOwners. A held entry no agent owns (AGENTS.md, tools/grugops/,
the legacy `gemini` entry) keeps no agent recorded, so a flag-less kept run may write `agents: []` beside it, and the
printed flag-less command finishes the reversal. This stops `--check` and `install.js --yes` reviving agents the user
just removed. Row R6 of agents-record.test.ts pins D-29.

## Re-run remedies on uninstall (MSG-1, the checker's required property)

A flag-less uninstall removes every agent (D-05). So an uninstall message that says "re-run uninstall" without the
command can send a user who ran `uninstall.js --claude` into removing everything. Every uninstall remedy that says to
run uninstall again therefore prints a command built by agentCommand:
- `finishCommand()` (Task 1): what is left to finish, for the kept-marker `left` line and the closing banners.
- `rerunCommand()` (Task 3): this run's own command, `agentCommand("uninstall.js", TARGET, the HOST_TOOLS rows whose id
  is in REMOVE)`, for the verifies printed before or during the walk (removeAskRules, the unbound-marker and
  malformed-ledger verifies at module top, which print before NAMED exists; REMOVE is parsed with the arguments).
The install step that the unbound-marker verifies also name ("re-run install.js here") is agent-independent: every
install writes the marker and its ledger whatever agents it names (D-06), and the verify text says so. Install-side
remedies naming uninstall.js (install.ts ~6644, ~6932) are plan 34.1-15's.
