# Phase 34.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Source: `34.1-RESEARCH.md` § Validation Architecture. Decisions D-20..D-25 were added after research.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest ~4.1.8 |
| **Config file** | `vitest.config.ts` |
| **Quick run command** | `npm run build && npx vitest run --exclude '**/scripts/e2e/**' <touched test files>` |
| **Full suite command** | `npm run build && npm run check:build-parity && npm run typecheck && npx vitest run --exclude '**/scripts/e2e/**' && npm run freshness` (never `npm test`: it starts the live claude-CLI e2e lane) |
| **Estimated runtime** | quick ~30 s; full several minutes |

Any manual or scratch install sets `GRUGOPS_HOME` to a scratch directory, or it overwrites the real `~/.grugops` kit.

---

## Sampling Rate

- **After every task commit:** the touched test files plus `npx tsc --noEmit`
- **After every plan wave:** the full suite command
- **Before `/gsd-verify-work`:** full suite green and `npm run freshness` green
- **Max feedback latency:** ~60 seconds for the quick command
