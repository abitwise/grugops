# Phase 34.1: Per-agent installer - Context

**Gathered:** 2026-10-11
**Status:** Ready for planning

<domain>
## Phase Boundary

The installer installs grugops for the coding agent(s) the person names, chosen by a per-agent flag or by
an interactive checkbox list, and writes only those agents' entries, instead of laying down adapters for
every supported host. Each named agent then reaches the Orchestrator through its own native, discoverable
entry after a scripted install. Uninstall can remove one agent's files. The Gemini CLI row is replaced by
Antigravity CLI. The phase also carries Phase 34 UAT gaps G-34-R3-2 (no discoverable entry on Codex,
Antigravity, OpenCode; Copilot untested) and G-34-R3-4 (round-4 review WR-13..WR-16, IN-14..IN-17), and
absorbs backlog 999.4. Windows stays out of scope (backlog 999.5). The four-round gap-closure cap applies.

</domain>

<decisions>
## Implementation Decisions

### Selecting agents (install)
- **D-01:** One flag per agent, derived from the registry ids in `install/host-tools.ts`: `--claude`,
  `--codex`, `--antigravity`, `--opencode`, `--copilot`, `--pi`. The flag set is derived from `HOST_TOOLS`
  (D-11 of Phase 34), never hand-listed, so a new registry row gets its flag with no installer edit and a
  test asserts the flag set equals the registry set. There is no all-agents flag: an old CI command must
  never silently install an agent added to the registry later. — **Reversibility:** costly — the flag
  names become a published CLI contract in install/README.md, CHANGELOG and users' CI scripts.
- **D-02:** With a terminal on stdin and stdout and no agent flag, install shows an interactive checkbox
  list of the registry agents (arrow keys move, space toggles, Enter confirms). Agents already installed in
  this target and agents detected in it start checked. Written in Node with zero runtime dependencies (raw
  mode on stdin); an empty confirmed selection refuses with the same message as D-03.
- **D-03:** With no agent flag and no terminal, or with `--yes`, the selection is: the set already
  installed in this target (from the install ledger), else the detected set (registry `detect` paths in
  the target), else install exits non-zero and names the per-agent flags to pass. An install made before
  this phase counts as having every agent it wrote files for, so an existing CI re-run behaves as today.
  — **Reversibility:** costly — it defines what unattended re-installs do on every existing target.
- **D-04:** Install only adds. Naming fewer agents than are installed keeps the others' files and prints a
  note naming the agents left installed and the uninstall command that removes one. Install never deletes
  an agent's files because it was not named.

### Removing agents (uninstall)
- **D-05:** Uninstall takes the same per-agent flags. `uninstall.js --codex` removes only the files the
  install ledger records for Codex (owns(path) authority, 33.1 D-33). Uninstall with no agent flag removes
  everything, as today. Shared files (D-06) are removed only by a flag-less uninstall or when the last
  installed agent is removed.

### Shared and per-agent footprint
- **D-06:** Every install writes the shared footprint whatever agents are chosen: the kit home, the seeded
  per-repo state, the marker and ledger (`.grugops/install.json`), `AGENTS.md` (by its existing rules),
  and `tools/grugops/`. The Claude Code skills and adapters, the `CLAUDE.md` start-here block and the
  Claude Code ask rules in `.claude/settings.json` are written only when Claude Code is selected; the
  Copilot pointer only for Copilot; the Pi template only for Pi (this amends Phase 34 D-17, the
  unconditional Pi write).
- **D-07:** `--check` reports a `reach` line, and counts findings, only for the agents installed in this
  target, not for every registry host.

### Per-agent entries
- **D-08:** Codex gets `.agents/skills/grugops/SKILL.md`; Antigravity gets `.gemini/skills/grugops/SKILL.md`;
  OpenCode gets `.opencode/commands/grugops.md`; Copilot keeps its `.github/copilot-instructions.md`
  pointer; Pi keeps `.pi/prompts/grugops.md`; Claude Code is unchanged. Every path is project-level, never
  user-level. Each path and frontmatter shape is `UNKNOWN - verify` until research cites the agent's
  primary docs; a path research cannot confirm is not shipped as fact.
- **D-09:** Each non-Claude entry is a pointer: the start-here sentence plus `KIT_ROUTE` (Phase 34 D-26),
  fixed text the same on every machine. No absolute kit path and no install-time value enters instruction
  text (T-34-13). The Claude-style resolver with a materialized `KIT=` line stays Claude Code only.
- **D-10:** Non-Claude agents get the `/grugops` dispatcher only, one spelling across hosts (Phase 34
  D-16); the Orchestrator routes to map, plan, ticket, gate, UAT and release. The seven Claude Code
  skills stay Claude Code only.
- **D-11:** The entry texts come from one pointer template in the kit, rendered per agent with that
  agent's frontmatter shape (SKILL.md for Codex and Antigravity, a command file for OpenCode, a prompt
  template for Pi), generated and pinned by a byte freshness gate in the pattern of
  `scripts/generate-role-adapters.ts` and `scripts/adapters-freshness.ts` (single-source rule).

### Antigravity replaces Gemini CLI
- **D-12:** The Gemini CLI registry row is replaced by Antigravity CLI (id `antigravity`, flag
  `--antigravity`). Gemini CLI is discontinued; Antigravity reads `AGENTS.md` (and `GEMINI.md`) natively
  (human, G-34-R3-4 WR-14 note; research confirms from primary docs). The `gemini-settings` adapter kind,
  the `.gemini/settings.json` `context.fileName` merge, and the `gemini-context-file-name` entry gate are
  deleted. Uninstall still reverses a merge an earlier install recorded, by ledger. This dissolves WR-14,
  WR-15 and IN-15 together with the code they are about. — **Reversibility:** costly — it deletes the
  merge and gate code and its tests; bringing Gemini CLI back means rebuilding them.
- **D-13:** Antigravity is detected by `.gemini` in the target root (the old Gemini signal); research
  verifies Antigravity's project directory. If research cannot confirm it, the detect signal is marked
  `UNKNOWN - verify` in the registry docs.

### OpenCode kit-read permission
- **D-14:** For OpenCode, install merges a `permission.external_directory` allow rule for the kit into the
  project `opencode.json`, using a home-relative pattern (for example `~/.grugops/agent-factory/**`) when
  the kit is under the home directory. The merge is additive, ledger-recorded and reversed by uninstall;
  install creates `opencode.json` when the repo has none and `--opencode` was chosen. When the kit is not
  under home, or research shows OpenCode does not accept a `~` pattern there, install writes no rule and
  prints a note with the rule to add by hand. No absolute per-machine path is written into a committed
  file.

## Existing Code Insights

### Reusable Assets
- `HOST_TOOLS` and its derived consumers (`install/host-tools.ts`): the flag set (D-01), detection (D-03), entry files and `--check` reach lines all derive from it; a registry count test already exists in `install/host-tools.test.ts`.
- `readlineSync` (`install/install.ts`): synchronous byte-by-byte stdin read used by the target and confirm prompts; the checkbox list (D-02) is a new raw-mode reader beside it, with the same no-terminal fallback rule (`YES || !process.stdin.isTTY`).
- The install ledger and owns(path) (`install/install-marker.ts` readLedger/owns, 33.1 D-33): the source for "installed set" (D-03, D-05, D-07) and for per-agent uninstall.
- `KIT_ROUTE` / `carriesKitRoute`: the fixed route sentence every non-Claude pointer carries (D-09).
- `refreshable` (Phase 34 D-27 point 3): the predicate WR-13's new owner extends to cover append and create.

### Established Patterns
- One owner per rule, derived sets with asserted counts (set-literal drift is a known failure class); every new enumeration (flags, adapter kinds, entry paths) derives from the registry.
- Generated pointer files pinned by a byte freshness gate; adapters are thin pointers, never copies of role text.
- Installer contract: idempotent, additive, dry-run-capable, reversible, never writes through a link it did not create, ledger-recorded writes only.

### Integration Points
- `ROUTE_POINTERS` keyed by adapter kind: new kinds for the Codex/Antigravity skill and the OpenCode command (and the OpenCode permission merge) land here, and `gemini-settings` leaves.
- `--check` doctor's carrier and reach loops: narrowed to the installed set (D-07); the Gemini entry gate leaves with D-12.
- Uninstall's reversal of an earlier `.gemini/settings.json` merge must keep working for installs made before D-12.

</code_context>

## Specific Ideas

- The human's direction (G-34-R3-2): "do not install for every possible coding agent; either a separate install command per agent, or ask during installation which coding agent the person will use."
- The checkbox list should feel like a normal CLI multi-select: arrows, space, Enter, detected/installed agents pre-checked.
- Scratch installs in tests, reviews and verification must set `GRUGOPS_HOME` to a scratch directory, or they overwrite the real `~/.grugops` kit.
- Regression runs use `npx vitest run --exclude '**/scripts/e2e/**'`; `npm test` starts the live claude-CLI e2e lane.
