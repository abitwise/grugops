# Phase 34.1 Plan 07: Per-agent uninstall Summary

**`uninstall.js --<id>` now removes one agent: it reverses only the ledger entries that a named, installed agent owns and that no staying agent owns (`entryOwners` over the registry's `ADAPTER_FOOTPRINT`). It keeps `.agents/skills/grugops/SKILL.md` while Codex CLI or Antigravity CLI stays, leaves the shared footprint and the legacy Gemini entry to a full uninstall, and keeps the marker rewritten with the agents that stay.**

- **Duration:** about 52 min
- **Started:** 2026-10-11T22:03Z (approximate; the start time was not captured)
- **Completed:** 2026-10-11T22:55Z
- **Tasks:** 3, plus 1 follow-up fix
- **Files modified:** 10, none created

## Accomplishments

- **Registry.** `install/host-tools.ts` adds `ADAPTER_FOOTPRINT`, keyed by `HostAdapterKind`, so a new kind is a compile error. It also adds `entryOwners(entry)`, which returns owner ids in registry order:
  - an exact match;
  - a `/` prefix (Claude Code's `.claude/`);
  - for a `dir` entry, a directory on the way to a footprint path.
  - The module still has no imports.
- **Flags.** `install/uninstall.ts` parses the per-agent flags with the same `(flagHost = hostForFlag(a)) !== null` arm as install.ts.
- **Scope.** After the ledger is read, uninstall computes `INSTALLED = installedAgents(MARKER_READ, LEDGER)`, then NAMED, REMAINING, STAYING and FULL. `walkLedger` and `heldEntries` visit only entries where `inScope(e)` holds.
- **Marker on a partial run.**
  - The marker is kept (`MarkerOutcome` `kept-for-agents`).
  - `updateKeptMarker` rewrites `ledger` and `agents` and reports each change.
  - When none of the named agents is installed, the marker is not touched.
- **Closing banner.** It appends ` — agents removed: …; still installed: …`.
- **Narrowed report passes on a partial run.**
  - Claude Code kit, backups, CLAUDE.md block and ask rules: only when Claude Code is removed.
  - Copilot block: only when Copilot is removed.
  - AGENTS.md, runnables and Gemini settings: only on a full run.
- **Directory candidates.** `reportDirCandidates` derives them from the footprint and filters them with `inScope`.
- **Tests.**
  - `entryOwners` units.
  - Cases (a)-(g).
  - The class test over all 6 registry rows; 44 paths were removed in total.
  - An agent-flag census check that both argument loops ask `hostForFlag(loopVar)`.
  - closing-claims `MODE_TABLE` classifies uninstall's agent flags.
- **README.** `install/README.md` Undo has a new "Removing one agent" subsection, and exit-code row `0` names the per-agent closing line.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] inScope intersects NAMED, not REMOVE**
- **Found during:** Task 1 (design check against case (b))
- **Issue:** The plan's rule was "owners intersect REMOVE". Install still writes every agent's files until plan 34.1-08, so the ledger holds entries for agents that are not installed. Under that rule, `uninstall --pi` on an install without Pi would have removed the Pi template, which breaks "a flag naming an agent that is not installed changes nothing".
- **Fix:** Owners must include a NAMED agent, one that is both named and installed.
- **Committed in:** fc44b26d

**2. [Rule 2 - Missing critical] A recorded unknown agent id counted as not installed**
- **Found during:** a scratch repro after the full regression
- **Issue:** With `agents: ["claude","zed"]`, `uninstall --claude` was FULL. It removed AGENTS.md, tools/grugops/ and the marker, which an agent of another grugops version may still use. That acts on an id that plan 34.1-06 says is never acted on (DC-2).
- **Fix:** STAYING is REMAINING followed by the recorded unknown ids, and FULL requires it to be empty. Case (g) was added.
- **Committed in:** bf072013

**3. [Rule 3 - Blocking] Two test files outside the plan's list**
- `install/closing-claims.test.ts`: `MODE_TABLE` derives every argv literal, so it needed the 6 uninstall agent-flag rows. `MODE_TABLE_COUNT` moved from `17 + HOST_TOOL_COUNT` to `17 + 2 * HOST_TOOL_COUNT`.
- `install/host-tools-prose.test.ts` Rule B: a README bullet paragraph and a uninstall.ts comment each named every sequential host but OpenCode, and both were reworded. The README now points to "Which agents an unattended install is for", and the comment names LEGACY_ADAPTER_KINDS.
- **Committed in:** 6a884633 (closing-claims, uninstall.ts comment), 3e663e57 (README)

**4. [Plan text] installer-fs-census needed no re-pin**
- The narrowed passes moved no caller row. Its only red is the pre-existing DI-03 case.
