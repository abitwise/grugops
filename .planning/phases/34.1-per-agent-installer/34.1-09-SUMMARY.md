# Phase 34.1 Plan 09: OpenCode kit-read permission Summary

**When OpenCode is chosen and the kit is under the home directory, install adds `"~/<kit root relative to home>/**": "allow"` as the last member of `permission.external_directory` in the project `opencode.json`. It creates the file or the containers when absent, and keeps every other byte by text splice. The change is recorded as a new `opencode-permission` ledger entry, and uninstall takes out exactly that rule while `external_directory` still holds what install left. Every shape install cannot edit is a note that quotes the rule to add by hand.**

## Accomplishments

- **Ledger kind.** `opencode-permission` is in LEDGER_KINDS after `ask-rules`, and in the target scope. Its rules:
  - it names `opencode.json` only;
  - it has exactly its keys, with `fileMode` only beside `createdFile` true;
  - `createdFile` needs `createdPermission` and `createdExternalDirectory`, and `createdPermission` needs `createdExternalDirectory`.
  - `createdOpenCodeText(pattern)` is the one created text both binaries use.
- **Install.** `writeOpenCodePermission()` runs only when `opencode-command` is in SELECTED_KINDS. It runs after the whole-file entries and the ask rules, and before writeMarker. In order, it:
  - asks the marker and the ledger first;
  - builds the pattern (`kitReadPattern`);
  - reads `opencode.json` through readForWrite;
  - creates the file by exclusive create, or splices with `addMember`;
  - checks the oracle: `sameJsonValue`, plus the rule being the last member.
  - DRY_RUN decides every arm, then reports `would-add` and records the bytes (setPlanned).
- **Carry.** `nextLedgerEntries` records OPENCODE_LEDGER when OpenCode was chosen. Otherwise it carries the previous entry verbatim (D-04).
- **Uninstall.** `reverseOpenCodePermission` runs in walkLedger right after ask-rules. It:
  - edits only while `external_directory`'s record equals the entry's `content`;
  - removes the rule, then the containers install created once they are empty;
  - deletes the file only when what is left is the emptied created text and the mode matches.
  - HOLDING_KINDS and `named()` know the kind, and a reversed entry is dropped from a kept marker.
- **README.** The OpenCode touch-list bullet names:
  - the rule and the home-relative pattern;
  - the last-member placement, citing opencode.ai/docs/permissions/;
  - the record and the reversal;
  - every note arm;
  - the `UNKNOWN - verify` global merge order.
  - The "Other tools (documentation only)" paragraph no longer says grugops writes no configuration for OpenCode. It now says install writes only the kit-read rule, which governs no command.
