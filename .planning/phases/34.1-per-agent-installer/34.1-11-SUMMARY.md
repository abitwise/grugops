# Phase 34.1 Plan 11: one owner of what install writes into a route carrier, one answer to whose link it is Summary

`installWouldWrite` (refresh, append, create, or none with the reason) is now the one owner that install (ensureBlock, writeWholeFileEntry, refreshOwnFile, the AGENTS.md step) and `--check` (classifyCarrier, the absent arm) both ask. The doctor names `Re-run install.js` exactly when an install run on that state writes the carrier, including the block-carrier append that WR-13 found. `linkOwnership` reads the ledger's `link:` record and gives the doctor, install's verify and install's route note the same reason and remedy for a `--symlink` AGENTS.md link (WR-16). The IN-16 and IN-17 wording is fixed, and the README and CHANGELOG state the refresh-append-create rule.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - AUTH-1] Matrix assertion (10): an oracle from the decision.**
- **Found during:** Task 2 (mutation proof 1).
- **Issue:** Doctor and install share installWouldWrite, so an owner that never answers append left them agreeing. Assertion (5) stayed green, and the user-without-block cells could not catch that mutation.
- **Fix:** checkCell now asserts, for user-without-block carriers, that the install writes the carrier, keeps the user's bytes as the head, and that the follower then finds the route. Cell titles now read "(1)-(10)".
- **Commit:** a27d03dc

**2. [Rule 1 - VERDICT-1] A blocked carrier's reason is install's verify wording.**
- **Found during:** Task 2.
- **Issue:** Under the plan's literal rule (none → refreshable's why), a whole file behind a link install did not make would get owns' ledger reason, while install's verify says blockedAt's wording.
- **Fix:** installWouldWrite's blocked arm now gives linkOwnership's reason for an own link and blockedAt otherwise.
- **Commit:** a27d03dc

**3. [Rule 2 - AUTH-1] Install's route note gives the own-link remedy.**
- **Found during:** Task 2 sibling search.
- **Issue:** For an own link, `noteStrandingCarriers` said "add this sentence to it", which would edit the linked checkout file (WR-16's harm, on the install side).
- **Fix:** It now prints linkOwnership's reason and remedy.
- **Commit:** a27d03dc

**4. [Shape] InstallWrite's refresh act carries `how` (refreshable's ok answer).**
- **Reason:** The plan's sketch has `{ act: "refresh" }` alone. Carrying `how` lets the splice use the same read and avoids asking the owner twice. refreshOwnFile now takes the answer, `(w, rel, label)`, instead of `(ledger, rel, label)`.

**5. [Coverage] Added a counted WR-13 case.**
- **Reason:** No matrix cell has a block carrier without its block that strands a host. The new case (Copilot pointer plus the user's own AGENTS.md) covers the appendable WARN arm.
