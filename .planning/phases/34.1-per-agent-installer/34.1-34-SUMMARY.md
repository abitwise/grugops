# Phase 34.1 Plan 34: The marker remedy owner (D-35, uninstall side) Summary

**The uninstaller now reads install-marker.ts markerRemedy at every site that prints a remedy for the marker. Over a marker with one bad field and a well-formed ledger, it names the field, says to fix it by hand and never delete the marker, and prints its own command; following that remedy finishes the reversal (R38). A parser census holds the rule that every printed offer to remove the marker, in every product module, sits under the owner's yes.**

## Accomplishments

- **Module-top unreadable verify** (uninstall.ts ~2579): computes `markerRemedy(MARKER_READ, REMOVE.size === 0 ? "uninstall-full" : "uninstall-partial")`, with a comment on why REMOVE decides the run kind before FULL exists. When mayRemove is false it prints the markerUnusableText opening, then says the run uses none of the records and removes and edits nothing, then markerFixText, then `then run \`<rerunCommand()>\` again`. When mayRemove is true the old text is printed unchanged. It is still one verify.
- **removeMarker**: one owner call at the top of the not-owned block.
  - The JSON-object arm over a well-formed ledger no longer says the marker is "not install's". It says a field holds a value install never writes while the ledger is still the record, and points at the verify.
  - U3's "fix or remove it by hand" is printed only under mayRemove. Otherwise U3 prints markerFixText.
  - U4's split moved from `FULL` to `remedy.mayRemove`. Both texts are the same as before.
- **keepWithoutRecord**: asks the owner first. Inside `if (FULL)`, `if (!remedy.mayRemove) return ""` runs before the delete text. The docblock says the decision belongs to the owner, which holds D-32's FULL-run rule.
- **R38a / R38b**: install [claude, codex], set `agents` to [Codex, claude-code] by hand, then uninstall.
  - The uninstall exits 3 with exactly one verify starting `.grugops/install.json`, which names `agents is not a list of agent ids`, `by hand` and `never delete the marker`.
  - No line of the run matches DELETE_MARKER or REMOVAL_OFFER. The marker's `left` line does not say "not install's" and points at the verify. The marker bytes and both skills are unchanged.
  - After the hand fix, the printed command (run outside the checkout with no GRUGOPS_HOME) gives:
    - flag-less: exit 0, marker and both skills gone, no recorded path on a `left` line;
    - `--codex` (the command names `--codex` only): exit 0, Codex skill gone, Claude Code skill kept, `agents` = [claude], marker kept, REC-1 invariant held.
- **Census owner tag**: CensusSite gains an `owner` field ("yes" | "no" | "none"), read from conditions and statement guards whose source ends in `.mayRemove`. A new test checks that every reading offering marker removal (DELETE_MARKER or MARKER_REMOVAL) has owner "yes". Its premise requires both keepWithoutRecord FULL rows and the doctor's I1 removal reading. The delete-text test now also requires owner "yes" on its 2 sites.
- **Classes**:
  - "usable record, split by FULL" is retired. U4's two rows are now "split by the owner", with guard "either" and one yes/no pair per line.
  - I1, I5, I6 and U3's removal reading moved to "no well-formed ledger: fix or remove" (owner yes, names why the record is unusable).
  - "not a usable record" keeps only the legacy-marker verify, and its rule now refuses a removal offer.
  - "usable record, FULL only" now requires owner yes.
  - The census size stays at 33.
