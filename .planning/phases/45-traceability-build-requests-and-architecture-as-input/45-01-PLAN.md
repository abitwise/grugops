## Output grammar this plan fixes (plans 45-07 and 45-09 extend it, never rename it)

`node upstream.js requests [--root <dir>]` reads `memory-bank/plans/build-requests/` and prints, in one stdout write at the end:
- `refused BR-<n>.md: <code>` for a file the grammar refuses, sorted by name; a record whose name is not `BR-<n>.md` prints as `refused <entry not named BR-<n>.md>: bad-file-name`. No reason text is printed, only the code.
- `carry <BR> <source>: open since <raised>` for each `open` request, in numeric ID order.
- `no build requests` when the folder is absent or holds no record (a dot-named keeper such as `.gitkeep` is not a record).
- `no build request needs a human (<n> on file)` when the folder holds parsed requests and no other line printed.
Exit: 2 when any `refused` line printed, else 1 when any `carry` line printed, else 0. A run that cannot start (bad argument, no `.grugops/` directory, the folder is a link or not a directory, the folder cannot be listed) exits 2 with nothing on stdout and one `Error: ` line on stderr, as `check` does. Plan 45-07 adds the other line kinds (`carry … changed since carried`, `wait`, `answer-candidate`, `pin-moved`, `not-descendant`, `overlap`, `UNKNOWN - verify`).
