## Research disposition: Pitfall 8's optional validator cross-check (not adopted)

45-RESEARCH.md Pitfall 8 offers an optional validator warning for a ticket in `Blocked` whose bullet names an unknown or terminal build request, and for a request whose `## Blocks` ticket is not in `Blocked`. No plan in this phase implements it. Planner decision (plan-check revision, 2026-11-26; reversible, because adding the warning later moves no committed user state; within CONTEXT.md's discretion on how a bullet naming a BR is recognized):
- The per-bullet rule Task 1 writes fails toward escalation. A bullet naming an absent, `answered` or `withdrawn` request ages under `blocked_escalation_days` as usual, so a stale or mistyped BR id reaches a human through the ordinary sweep escalation, not through silence.
- No program interprets a ticket's `## Blocked` bullets: the board grammar reads no body section, and the structure validator reads only `## Upstream` (plan 45-09's board contract text). The cross-check would make the validator parse `## Blocked` bullet prose, a new reading that contract would have to admit.
- The structure validator does not run on a scripted-install host (research Pitfall 10), where Workflow 09 applies the exemption, so the warning would not reach the sweep it protects.
- Residual risk, accepted as T-45-35: a typo that names a different `open` or `carried` request keeps the bullet exempt until that request's own `wait` line prints; a ticket listed under a request's `## Blocks` but never moved to `Blocked` is caught by no program. Both are BA/PM writing errors, and Workflow 20's Done condition (Task 1 step 7) names the check.
- Revisit when a stale or mistyped BR id is seen in practice: add the check as a structure-validator and `state-check` warning in a later phase.
