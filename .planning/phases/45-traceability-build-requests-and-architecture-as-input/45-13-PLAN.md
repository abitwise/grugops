Review finding WR-03 (step 12 ignores a ticket's other blockers) is adopted here because the human-stop bullet depends on it.

How a deviation or floor-conflict request is told apart, and why BA/PM alone cannot unblock one (planner's mechanism under decision 1; plan-check revision 1). A request file has no field for it (D-05 closed key set). Two marks are used:
- The guard that holds the property is the human-stop bullet on each affected ticket, owned by a named human. BA/PM writes it in the hand-off subtask, beside the build-request bullet, because BA/PM is the role Workflow 20, ba-pm.md and the board policy already let move a build request's tickets into `Blocked` (plan-check revision 2). The Architect's role file grants no `Blocked` move. Giving it one would need a role `## Board moves` claim that the check-role-rules partition refuses (rule 4: no move out of a column the role does not own), and that is a recorded-human-decision change. Three things that BA/PM does not control fix the kind and check the bullet:
  - The observing role's sealed `Build-request:` observation note records it as a deviation or a floor conflict. The Architect records a deviation (D-16).
  - The Orchestrator's hand-off subtask names it as a deviation or a floor conflict (step 1).
  - The Orchestrator confirms afterwards that each affected ticket holds the human-stop bullet (step 1), before any floor stop.
  The bullet names, as its raiser, the role that recorded the observation. It names no request, so a withdrawal and step 12 never remove it. With WR-03, step 12 moves a ticket to `Backlog` only when no other bullet remains. A BA/PM-alone withdrawal, even one written in error against step 13, therefore leaves the ticket `Blocked`. Only a named human's word removes the human-stop bullet, and the human's-word stop bullet refuses an agent that asks otherwise.
- The second mark is BA/PM's own wording. Step 4 makes BA/PM say in `## Question` that the request records a deviation or a floor conflict. Step 13 and the stop bullet reserve the withdrawal of such a request to a named human, so the request's History names that human.

The G-45-1 path keeps the debug session's proven order (observation, then BA/PM files per steps 1 to 5, then the stop). The only additions are the bullet BA/PM already writes in that same subtask and the Orchestrator's confirmation before it stops. There is no added dispatch before BA/PM, beyond the Architect recording the observation, which the differential variant also did.

The one residual: BA/PM omits the human-stop bullet and the Orchestrator also fails to confirm it. Both roles would be departing from the same Workflow 20 text. No program checks this, because human decision 3 rules out a new check. It is accepted as T-45-47, next to T-45-35, and the Done condition names the bullet.
