<encoding_decision>
**The `encoding` probe row, answered here rather than left implicit.**

The deterministic edge probe asked, for LANG-04: *whose definition of length/equality applies — bytes, code
points, grapheme clusters, or normalized form?* For a JSON member that question is live and concrete: a
claim written into a JSON string as an escape is invisible to a raw-byte line scan and visible to a
decoded-value scan.

**Decision: the scan reads RAW BYTES, line-oriented, exactly as it reads every other member.** Reasons,
stated so the trade is visible rather than assumed:

- One matcher, one input shape. A decoded-value scan would be a second way of assembling the text a matcher
  is asked about, which is this phase's most expensive recurring defect.
- A raw-byte line scan reports `file:line:column`, which a human can check by hand against the file. A
  decoded-value scan reports a field path, which nothing else in this gate's output speaks.
- It covers the whole file — keys, values, and the second description nested inside the marketplace's plugin
  entry — so there is no claim-bearing field list to maintain, and therefore no field list to rot.

**The branch not taken is closed by a REFUSAL, not left open.** For each manifest, every decoded string
value must be byte-present in the raw text. A value written with any escape that changes its bytes — a
unicode escape, a tab, a newline, an escaped backslash — will not be byte-present, and the gate refuses by
name, stating that the manifest's shipped strings must be written in literal form so that what the line scan
reads is what a user reads. Measured on today's manifests: neither file contains a backslash, so the
assertion costs zero refusals on correct text at admission.

**A manifest that does not parse is refused by name and still scanned.** Parsing is what the canonical-form
assertion needs; the line scan needs nothing. So a parse failure removes the guarantee and says so, and
never removes the scan.

**A permanent case exists for the branch not taken**: a manifest carrying a banned literal spelled with a
unicode escape must produce the canonical-form refusal, and must not pass silently.
</encoding_decision>

<standing_rules>
The house rules of this phase, encoded rather than advised. The seven that bite hardest here:

- **Derive the set, assert the count.** Never hand-maintain a scan set, an exclusion set or a field list a
  command can derive. Where a number is pinned, this plan states the command that reproduces it.
- **Ask what BOUNDS the predicate's input.** For each predicate: which SET it enumerates, what DERIVES that
  set, and what asserts the set's COUNT. A vacuity floor catches an EMPTY denominator and never a SILENTLY
  SHORT one — derive the element count independently of the loop that consumes it.
- **A green suite is not proof for a safety invariant.** Hermetic `git archive HEAD` mirrors, sha256-verified
  gate binaries, one plant per reset mirror, the premise asserted green before the plant, the plant confirmed
  on disk before the run.
- **RED first.** Every new permanent case is shown able to fail.
- **No silent drops.** Every class left outside the scan is named with its reason; every residual gets a
  `V-` id, a live count, a direction and a remedy, escalated to plan 29-55.
- **Measure the admission cost before admitting.** This module's own admission test: an entrant is measured
  with the gate's matcher first and its live occurrence count published.
- **Build facts (D-13).** `npm run build` then `npm run freshness` after every `.ts` edit; the committed
  `.js` twin lands in the same commit. Regression is `npx vitest run --exclude '**/scripts/e2e/**'`, never a
  bare `npm test` (that lane spawns the live claude CLI, spends tokens and can hang).
</standing_rules>
