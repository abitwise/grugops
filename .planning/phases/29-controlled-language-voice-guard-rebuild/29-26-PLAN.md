  <action>
Build a cross-product corpus over the axes the four deleted predicates disagreed on, and check every
cell against structural invariants rather than against a transcribed answer.

Declare the axes as named arrays so the cell count is a product of their lengths and can be asserted
as a number:

Heading level — a level-one line, a level-two line, a level-three line, a hash run with no following
space, and a line that is not a heading at all.

Fencing — the candidate line outside any fence, inside a terminated fence, and inside an unterminated
fence that runs to end of file.

Trailing residue — no trailing whitespace, one trailing space, one trailing tab, and a trailing
carriage return, so the axis covers the residue forms even though the repository pins text files to
line-feed endings.

Leading residue — no leading whitespace, one leading space, and four leading spaces.

Position — the candidate line immediately after `from`, several lines after `from`, at the last line
of the document, and absent entirely so the document has no candidate.

Document shape — an empty string, a single blank line, a document whose first line is the heading,
and an ordinary multi-section document.

Assert the axis lengths and the resulting cell count as numbers, derived as the product, before
running the sweep. A generator that silently produced fewer cells must fail rather than report a
clean sweep; this project has recorded a vacuity floor catching an empty denominator while missing a
silently short one, so derive the cell count independently of the loop that consumes it and compare
the two.

For every cell, assert the invariants that hold by construction:

The end index is at least `from` and at most the document's line count.

When the end index is below the line count, the line at that index is not flagged by the one fence
authority and its leading hash run is at most the requested level followed by a space.

No line strictly between `from` and the end index is both unflagged and a heading of level at most
the requested level. This is the founding defect of the phase stated as a property: a predicate
satisfying it cannot adopt bytes belonging to a later section.

`unfencedHeadingIndex` returns either minus one or an index whose line is unflagged and whose trimmed
text equals the requested heading.

When `unfencedHeadingIndex` returns an index, no earlier line satisfies the same two conditions —
it is the FIRST such line, which is what the name promises.

Report a failing cell by naming every axis value that produced it, the way the existing cross-product
sweep already does. A failing cell that names only its index tells nobody anything.

Prove the sweep falsifiable: run the same invariant checks against a deliberately wrong local
implementation — one that closes only on a level-two heading, the exact defect CR-02 was — and assert
that at least one cell fails. A sweep that passes against a known-broken implementation is measuring
nothing. Build that local implementation inside the test file and never export it.

Record in the module's header what the sweep does NOT cover: setext headings, heading text containing
a fence delimiter run, tab-indented fence delimiters, documents whose line endings are not line-feed,
and any input larger than the generated cells. It is a floor over the shapes the four deleted
predicates plausibly differed on, not a proof of correctness.
