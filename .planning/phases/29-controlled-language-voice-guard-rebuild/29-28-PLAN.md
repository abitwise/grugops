reference it — round 3's brief is explicit that two competing repairs of the same lines are not to be
written.

`scripts/audit-model.ts` carries two private grammars over bytes the tree already has one authority
for:

- **CR-02** — `readRegistry` (`:893`, `:933-950`) declares a claim-heading recogniser, scans RAW lines
  for it with no fence awareness, and takes each block's end from the next index in that array. By the
  owner scan's own published definition that is a section-extent construct, and it is invisible to the
  classifier on BOTH arms. Reproduced by round 3: a claim block written inside a FENCED EXAMPLE parses
  as a live `kind: safety` row, enters `safetySurfaceUnion`, and therefore enters the D-18 exclusion
  list that LANG-02 consults to decide which files a language pass may not touch. Documentation read
  as live data, in the phase whose founding rule is that it must not be.
- **WR-02** — `parseClaimBlock` (`:986`) answers "is this line a fence delimiter" with a private
  equality while `tableUnder`, thirty lines up in the same module, answers it through `fencedLineFlags`
  and `FENCE_DELIMITER_LINE`. The two disagree on two axes: a delimiter carrying an info string, and a
  three-space-indented delimiter.

Purpose: LANG-07's literal text is "never two grammars over the same bytes", and this module carries
two. LANG-03's exclusion list is fed by the first of them. One structural fix serves both.

Output: one authority answering "which unfenced lines match this predicate", a registry parser that
composes it, a fence recogniser deleted rather than corrected in place, and a named refusal closing the
new fail-open the fix would otherwise create.
