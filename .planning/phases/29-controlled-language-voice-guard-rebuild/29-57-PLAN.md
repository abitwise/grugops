<objective>
Disclose the hard-wrap axis properly, and correct the false premise the source uses to accept it.

Round 7's review and round 7's verifier each independently reproduced the same bypass: `lineHits()`
matches each pinned literal against ONE physical line, most of the `token-economy` group's members are
multi-word, and an ordinary hard-wrapped paragraph splits such a claim across two lines at exit 0 with
the planted file never named. Live count 0. Direction FAIL-OPEN.

**The matcher is deliberately not fixed here (D-56).** The fix adds a second input assembly — new
surface, in a phase where round 6's fix produced round 7's finding — to close an axis with no live
instance, against a threat model that is DRIFT rather than an adversary. Every finding that ever caught
a LIVE claim in this phase was a corpus-SCOPE defect; every matcher-completeness finding has been at 0
live. So the axis gets a `V-` id with its counts, its direction, its reproduction and its named remedy,
and it stays open and visible instead of being closed by a fourth heuristic.

**And the source's own justification for accepting it is wrong.** `scripts/check-banned-claims.ts:60-65`
argues the bypass needs a wrap falling inside a word, which no reader would parse as a claim. The
reproduction wraps between words, which markdown soft-joins into fully legible prose — the kit's own
house style. An accepted bound argued from a false premise is worse than an undisclosed one.

Purpose: the difference between a decision and a silent drop is a written id with a live count and a
direction. This phase has spent seven rounds learning that, and this is the round where the axis that
finally has no mechanism gets the record instead.

Output: `V-29-57-01` with three derived measurements, and an in-source record that describes the actual
bypass.
</objective>
