<objective>
Close the four `check-nul-bytes` findings from round 6, in the order that makes each one's proof honest.

`WR-04` — the NUL-only offset function is **production-dead**. `runAll()` derives its NUL set from the wide
scanner's output by filtering the `bytes` array; a repo-wide grep finds the NUL-only function referenced
only by five test call sites and by comments. So the module carries **two implementations of the NUL
predicate**, and the prose declares the dead one authoritative — its doc comment says the git cross-check
"is asked" that function and that the difference is stated "at both call sites", and there are no such call
sites. That is the duplicate-authority shape this repository closes by deletion or by a declared boundary,
and it landed inside the plan whose stated subject was where the narrower duplicate was. The reviewer's
terminal sentence: *what must not survive is a comment naming a call site that does not exist.*

`WR-03` — the declaration that justifies the `bytes` field's existence asserts the exact claim the same
module measured FALSE, and its worked example is contradicted by the module's own table 190 lines below.
The code is right: arm 2 excludes any file carrying a forbidden byte, so the contradicted case never
reaches the disagreement refusal. Only the prose is wrong, and it is the prose a future editor reasons from
when deciding whether the field is still needed. This is the round's own recurring pattern — a three-site
correction that missed a fourth site — so the correction is checked against a list of addresses rather than
against a reading.

`WR-06` — two small holes in a module whose stated floor is that a stack trace is not a verdict. The
reporting loop re-reads a path the scan already read, with a bare read and no guard, so a file removed
between scan and report throws an unhandled ENOENT out of `runAll()` and the gate dies with a
`node:internal` frame instead of reporting — which is precisely what a sibling gate's test asserts never
happens. And an **initialised** submodule gitlink is a directory on disk, so the read raises EISDIR rather
than ENOENT and is misreported as a permissions or I/O error, under a header that names only the
uninitialised case.

Purpose: this module is the reason a `grep` count in any other plan's acceptance criteria can be trusted at
all. A gate that decides whether the repository's own text is greppable must not itself carry two answers
to one question, a false statement about the tool it cross-checks against, or a path to dying without a
verdict.

Output: one predicate, one read per path, a declaration that says what its field is for, and a refusal that
names the situation it found.
</objective>

<standing_rules>
The house rules of this phase, encoded rather than advised. The six that bite hardest here:

- **Prefer deletion and one authority per predicate.** Where a finding names a duplicate, plan the
  deletion, not the reconciliation. The fixes that moved the score in this phase were structural.
- **Beware relocation instead of deletion.** Round 5's "structural fix" relocated an enumeration from one
  slot to another. Absence is asserted by grep across source, committed twin, type and tests — never by the
  old call site having changed.
- **RED first.** Every new permanent case is shown able to fail, against a build made from the pre-change
  tree or by mutation.
- **A green suite is not proof for a safety invariant.** Reproductions run on hermetic mirrors or throwaway
  repositories, one plant per reset, each asserting its own premise before the plant and confirming the
  plant landed on disk before the gate runs.
- **`grep` silently skips binary-classified files.** One NUL byte makes BSD grep report ZERO matches with
  no warning. Every acceptance grep in this plan over a file that could carry a control byte uses `grep -a`
  or checks `file -b` first. This is the gate whose existence is that lesson.
- **Build facts (D-13).** `npm run build` then `npm run freshness` after every `.ts` edit; the committed
  `.js` twin lands in the same commit. Regression is `npx vitest run --exclude '**/scripts/e2e/**'`, never
  a bare `npm test` (that lane spawns the live claude CLI, spends tokens and can hang).
</standing_rules>
