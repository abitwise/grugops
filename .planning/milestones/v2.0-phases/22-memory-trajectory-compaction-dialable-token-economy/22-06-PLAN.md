<objective>
Close the 4th distinct CMP-02 bypass (whitespace / parser-projection drift) by completing the
shared-layer IN-02 contract: make the carve-out oracle's strictness PROVABLY EQUAL to the write
path's. Rounds 1–4 each shipped a fully GREEN held-out suite and each stayed bypassable, because the
oracle adopted the shared lenient PARSER (`parseNote`) but never the strict VALIDATOR (`validate()`).
`parseNote`'s kv regex (`/^([A-Za-z_]+):\s*(.*)$/`, context-io.ts:218) recognizes a key ONLY at
column 0, so an indented line, a `verified_by : value` (space-before-colon) line, or a trailing-
whitespace / CRLF variant silently projects to `""` with no parse error and no duplicate-key signal.
The oracle then keys `isVerified` and its byte-equal loop on that lenient projection, not the file
bytes — so a §14-gate-verified finding can be dropped, or an FA's `by`/`at` laundered, with exit 0
"carve-out intact".

The fix treats the CLASS, not the two named shapes (the round-1→4 lesson):
  1. parseNote records a `malformedLines: string[]` signal for any non-recognized in-fence line shape.
  2. validate() pushes a structural FAIL per malformedLines entry (write path AND CLI validate refuse them).
  3. checkCarveOut() gains two fail-closed gates on EVERY raw AND promoted note, before any survival /
     byte-equal decision: (a) reject on any malformedLines, (b) run the shared validate() and reject on
     any structural finding. (b) closes CR-03 (a well-formed column-0 finding with empty verified_by
     that (a) cannot see, but validate() rejects via the finding-needs-a-stamp rule).

Purpose: CMP-02 / SC2 is the un-cheatable mechanical floor of the body/frontmatter seam. A green unit
suite is necessary but NOT sufficient — proof is RED→GREEN reproduction against the COMMITTED .js.
Output: a hardened context-io parser+validator and compactor oracle, byte-fresh committed .js, and a
held-out RED-first line-shape matrix that pins the class, with captured build+run evidence.
</objective>
