<objective>
Close CR-01, the single BLOCKER that left Phase 21 at 3/4 (VFY-01 PARTIAL). `parseNote()` in
`scripts/context-io.ts` anchors its frontmatter fence regex on `\n` only
(`/^---\n([\s\S]*?)\n---\n?([\s\S]*)$/`). A note whose bytes are CRLF (`---\r\n…`) does NOT match,
`parseNote` returns `null`, `readContext` silently skips it (`if (!parsed) continue`), and `admit()`
therefore sees no live green §14-gate verdict and WRONGLY REFUSES a legitimately-stamped finding.
git `autocrlf=true` — the Windows default, and CLAUDE.md names Windows a first-class target —
produces exactly this. The admission guarantee VFY-01 exists to establish is materially false on
Windows until this is fixed.

The fix is one normalization line plus a RED-then-GREEN CRLF round-trip test:

1. In `parseNote`, normalize line endings to LF before matching the fence — preserve every existing
   LF parse semantic (this is a correctness fix, not a behavior change for LF input).
2. Add a CRLF round-trip test to `scripts/context-io.test.ts` exercising `readContext` AND `admit`:
   a CRLF-encoded green §14-gate verdict must be read back and must admit a matching finding. RED
   before the fix, GREEN after.
3. Rebuild the committed `scripts/context-io.js` (D-15) and verify `npm run freshness` exits 0.

Purpose: make VFY-01 SC-1 reliably TRUE cross-platform — a real green verdict on disk admits its
finding regardless of LF/CRLF encoding — so the replacement memory is trustworthy on Windows before
Phase 24 makes it the sole inter-role memory.

Output: an edited-and-recommitted `context-io.ts`/`.js` + one RED-then-GREEN CRLF round-trip test.
