<objective>
Give `verified_by` mechanical teeth in the only sanctioned write path. Phase 20 recorded the
provenance field but explicitly did not enforce its contents; this plan wires the un-cheatable
verifier mechanism (VFY-01, VFY-02) inside `scripts/context-io.ts`:

1. Extend the existing pure text→findings `validate()` with the D-09 refuse-self FAIL set and the
   D-02 reserved `by: §14-gate` impersonation flag — structural, text-only, no context read.
2. Add a NEW, isolated, context-aware admission layer (D-01/D-10) that cross-checks a
   `§14-gate#<id>`-stamped `finding` against a real GREEN verdict record in the task context
   (Posture B — format-trust alone is rejected).
3. Hard-reject a stampless/invalid `finding` (exit 1, fault named); never silently degrade it to a
   `claim` (D-11).

Purpose: this is the mechanical core of "the §14 gate as the un-cheatable verifier." The verdict
emission (Plan 02) and the WF16 protocol + role pointers (Plan 03) build on the contract this plan
defines (the `by: §14-gate` carve-out, the per-run-id grammar, the admission read).

Output: an extended-and-committed `context-io.ts`/`.js` + RED-then-GREEN vitest coverage proving
every fail mode and the workhorse admit path.
</objective>
