<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| subtask/task name → filesystem path | `task` flows into `join(queueRoot, "claimed", task)` and the pending/done rename paths; untrusted if derived from a queue file's content. |
| concurrent claimants → the claimed/ directory | Two separate-process agents may race to `mkdirSync` the same claim dir. |
| claim.md `at` → stale-sweep decision | The sweep reads a timestamp field and acts (reclaims) on it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-04 | Tampering/Elevation | `claimTask`/transitions task→path join | mitigate | Validate `task` against `^[A-Za-z0-9._-]+$`, reject `..`/separators/absolute; `join` under a fixed queue root only. |
| T-20-05 | Tampering (race) | concurrent `mkdirSync` claim | mitigate | `mkdirSync` atomic create-or-fail is the coordination signal; EEXIST = claim lost; preferred over O_EXCL (unreliable on NFS, Pitfall 2). True-NFS runtime carried as `UNKNOWN - verify` (DOGF-02/PAR-05). |
| T-20-07 | Repudiation | the stale-sweep "fresh" path | mitigate | No-fabrication: the oracle proves BOTH a reclaim (expired) AND a no-op (fresh) — the sweep can lose, not only pass. |
