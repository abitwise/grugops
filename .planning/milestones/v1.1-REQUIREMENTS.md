## Milestone v1.1 Requirements

### Shared-Home Architecture

- [x] **SHOME-01**: The kit installs once to `$GRUGOPS_HOME` (default `~/.grugops`, env-overridable as `${GRUGOPS_HOME:-$HOME/.grugops}`, resolved identically in POSIX `sh` and Node stdlib); the kit there is read-only/central and `~/.grugops` is used (not XDG split) — **Phase 7, satisfied**
- [x] **SHOME-02**: Per-repo state lives in the target repo — `plans/` (incl. runtime handoffs at `plans/handoffs/`), `memory-bank/`, and the project's `factory.config.json` under a per-repo **`.grugops/`** directory (which also holds the install marker / kit-version stamp); nothing an agent writes at runtime lands in the shared kit. The 32 config references resolve to `.grugops/factory.config.json` — **Phase 7, satisfied** (zero `agent-factory/config/` refs confirmed live)
- [x] **SHOME-03**: The ~31 role/workflow/adapter files rewritten so kit references resolve to the kit root and state references resolve repo-relative; a build gate proves **zero** bare `agent-factory/…` references remain that should point at the kit (grep-to-zero) — **Phase 7, satisfied** (`check-kit-refs.sh` exits 0 live)
- [x] **SHOME-04**: The kit root resolves by ONE rule with two homes — an installer-**materialized absolute path** (standalone) or `${CLAUDE_PLUGIN_ROOT}` (plugin). The installer writes the resolved absolute kit path into the standalone adapters, with a documented one-line bash self-heal fallback — **Phase 7, satisfied** (standalone home wired; the plugin-form half is the v2+-deferred PLUGIN-01, explicitly out of v1.1 scope)

### Install Experience

- [x] **INSTALL-03**: `install.sh` and `install.mjs` accept `--target <repo>` plus an interactive prompt (default CWD, confirm) and a `--yes`/non-TTY bypass for CI; the installer runs correctly from any working directory — **Phase 8, satisfied** (harness checks PASS)
- [x] **INSTALL-04**: The installer seeds per-repo state into the target (`.grugops/factory.config.json` from the kit default + install marker/version stamp + a `plans/` skeleton including `plans/handoffs/`) without clobbering existing files; default mode **copy** (symlink opt-in); idempotent / additive / `DRY_RUN=1` / reversible preserved; `install.mjs` byte-parity with `install.sh` (Windows home via `os.homedir()`) — **Phase 8, satisfied** (seed/copy-default/idempotent/parity harness PASS)
- [x] **INSTALL-05**: `install.sh --check` (and `install.mjs`) is a doctor that verifies every referenced path resolves, names the first failure with its referencing file, and uses clear exit codes (0 pass / nonzero fail; WARN→0; `--strict` gates WARN) — **Phase 9, satisfied** (doctor sh+Node first-failure + exit matrix; install.test.sh 18/18)

### Validation (two-root)

- [x] **VAL-02**: The structure validator is two-root aware (explicit kit root + repo root, with **no fallback to `.`**) so it cannot false-green in the dev checkout or with `$GRUGOPS_HOME` unset; a BAD fixture for a missing/unset kit root must fail. `install.test.sh` updated for the split (fresh install + seed + doctor; idempotency / dry-run / reversibility preserved) — **Phase 9, satisfied** (two-root, no `.` fallback, C3 guard live, fail-closed; validate.test.sh 18/18)

### Deferred to v1.2+ (researched, intentionally out of this milestone)

- **MIGR-01** (v1.2): `install.sh --migrate` converts an already-installed repo to the split layout — additive-then-relocate, never delete-first (rename-to-backup; deletion only behind explicit `--prune-old-kit`).
- **UPD-01** (v1.2): `install.sh --update` refreshes the central kit in place; two-stage uninstall; doctor names the specific unresolved path.
- **SKEW-01 / FIX-01 / PLUGIN-01** (v2+): per-repo kit-version pin + skew warning; doctor `--fix`; plugin-form path resolution (`${CLAUDE_PLUGIN_ROOT}`) and publishing grugops as a Claude Code plugin.

## Out of Scope (v1.1)

| Feature | Reason |
|---------|--------|
| Background auto-update of the central kit | Surprise mutation; `--update` is explicit and human-run |
| Symlink-overlay install / vendoring the kit per repo | Both were the rejected alternatives; copy to `$GRUGOPS_HOME` is the chosen model |
| TUI/wizard installer, global `$PATH` binary, telemetry | Keep it boring — sh + Node stdlib, no daemon, no data collection |
| Doctor that auto-fixes user content | `--check` reports and names; it never edits the user's repo |
| XDG base-dir split (`$XDG_DATA_HOME` etc.) | Peer tools (rustup/cargo/nvm) reject it; one `$GRUGOPS_HOME` is simpler and cross-platform |
