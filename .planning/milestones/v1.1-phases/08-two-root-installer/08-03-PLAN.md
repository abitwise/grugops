<objective>
Turn the existing single-root adapter installer into a TWO-ROOT installer, landing the change byte-parity in `install.sh` (the behavioral spec) and `install.mjs` (the Node twin) within the same plan because byte-parity is an existing contract. This is the heart of Phase 8: it fixes all three dogfood pains (DOG-02) — wrong target (`TARGET=$(pwd)`), symlink fragility (`INSTALL_MODE=symlink` default), kit never arriving (installer never touched `agent-factory/`).

The work is extend-not-rewrite: compose the existing helpers (`do_run`, `mkdirp`, `ensure_block`, `link_or_copy`, `merge_gemini`, `detect_tools`, the `uninstall.sh` awk sentinel strip) — do NOT invent a framework. The two net-new mechanisms are (a) adapter materialization (strip-then-inject the absolute `KIT=` line, idempotent by content not by `cmp`) and (b) the byte-parity install marker.

Purpose: a target works on first `/grugops` with no path error and no hunting, from any CWD, in CI, on copy-default — preserving idempotent/additive/DRY_RUN/reversible across both roots.
Output: rewritten `install.sh` + `install.mjs` that turn the Plan-02 harness GREEN.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args / env → installer | `--target`, `$GRUGOPS_HOME`, `TARGET` are untrusted strings that become filesystem write paths; must be resolved to absolute and validated before use |
| installer → shared `$GRUGOPS_HOME` | The kit copy is a persistent runtime location shared across repos; overwrite must be atomic and confined to the grugops-owned kit |
| installer → target repo | Seeded state + materialized adapters are written into the user's repo; never overwrite user content; never materialize into the source clone |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03-01 | Tampering | path traversal / arbitrary write via `--target` or `$GRUGOPS_HOME` | mitigate | Resolve both to absolute paths before any write (Security V5); never glob/hunt; the kit copy is confined to `$GRUGOPS_HOME/agent-factory` via atomic tmp→rename |
| T-08-03-02 | Tampering | self-install into the source clone materializing a machine path into source adapters | mitigate | D-07 self-checkout guard runs UNCONDITIONALLY after TARGET resolution, before any write, even under `--yes`/non-TTY (Pitfall 3); refuse-by-default, `--allow-self` to override |
| T-08-03-03 | Tampering | overwriting/deleting user content during seed or materialize | mitigate | Seed is skip-if-exists per file (D-04); materialize targets only the 2 grugops-owned adapter paths; never touches user files |
| T-08-03-04 | Denial of Service | non-atomic kit overwrite during a concurrent read | mitigate | `copy_kit` writes to a temp then `mv` (atomic rename) — a reader never sees a partial kit (PITFALLS §Performance) |
| T-08-03-05 | Spoofing / EoP | agent hunting for a missing kit and reading an attacker-planted `agent-factory/` higher in the tree | mitigate | Preserve the frozen STOP-do-not-hunt rule: materialize the absolute path + keep the self-heal + STOP intact; never add a "search" fallback (Security Domain) |
| T-08-03-06 | Elevation of Privilege | installer setting/seeding the prod-deploy approval env var | mitigate | Carry the explicit prohibition verbatim into every new code path; no new path reads/writes/seeds it (RESEARCH Runtime State Inventory) |
| T-08-03-SC | Tampering | npm/pip/cargo installs | accept | Zero external packages (stdlib-only Node, POSIX builtins; RESEARCH Package Legitimacy Audit: not applicable) |
</threat_model>
