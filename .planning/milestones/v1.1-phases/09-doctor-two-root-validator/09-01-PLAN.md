<objective>
Add the `install.sh --check` doctor — the POSIX `sh` side of the byte-parity doctor pair (INSTALL-05). It uses the parse-and-resolve strategy (D-01) — reading what the installer wrote (the two materialized adapters + the marker) and reusing the Phase-7 kit-vs-state classification (D-01). It is a non-mutating early-exit arm of the installer that re-resolves the kit root three ways, cross-checks them, then stats a deterministic ordered set of start-up load-bearing paths, failing loudly on the FIRST unresolved one with its referencing file. It implements the hard FAIL set (D-05), the non-empty WARN tier (D-06, detect-and-warn only per D-07), and the exit-code matrix (SC2). An uninstalled/dev checkout folds into the FAIL path with a distinct "not installed" message (RESEARCH Discretion §5).

Purpose: ship the verification layer that would have caught all three dogfood pains (kit never arrives / wrong target / symlink fragility), proving the kit/state split cannot silently regress. The doctor is the FIRST reader of the `.grugops/install.json` marker.
Output: `install/install.sh` gains a `--check`/`--strict` flag pair and a `doctor()` function; the Node twin (Plan 02 wave 2) keys off this as its behavioral spec.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-09-01 | Tampering / Elevation | doctor follows a symlink out of the kit/repo and validates attacker-planted content | mitigate | Resolve every path to absolute via `abspath` before stat; a dangling/escaping symlink is a FAIL (`[ -L ] && [ ! -e ]`), never a follow-and-read (D-05; RESEARCH § Security Domain row 1). |
