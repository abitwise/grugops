## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installer/env → adapter prose | `$GRUGOPS_HOME` env value is interpolated into the adapter self-heal bash; an attacker-controlled value could point the kit root at an unintended path |
| kit-absence → agent behavior | when the resolved kit dir is missing, the agent must fail closed (STOP), never fall back to hunting the repo |
| prose → LLM execution | an env var named in non-adapter prose is a dead string an LLM may "resolve" by hallucinating a path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | adapter self-heal `${GRUGOPS_HOME:-$HOME/.grugops}` | accept | This phase ships only the documented self-heal spelling (D-11); `$GRUGOPS_HOME` is a user-set env var on the user's own machine, same trust level as `$HOME`. The STOP-on-absence (step [3]) fails closed if the resolved dir is missing. No remote input. Clear-voice STOP message names the path so a wrong root is visible, not silent. |
| T-07-02 | Spoofing/DoS | kit-absence resolution | mitigate | The adapter STOPs and prints the named missing path + remediation; it explicitly does NOT hunt the repo for `agent-factory/…` (D-11/D-12).
