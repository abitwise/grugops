# Milestone v1.1: Install & Distribution

**Status:** ✅ SHIPPED 2026-06-08
**Phases:** 7–9 (numbering continued from v1.0)
**Total Plans:** 14 (incl. 2 gap-closure plans in Phase 9)

## Overview

v1.1 redesigned the grugops install experience to a **shared-location, two-root** architecture: the read-only kit installs once to `${GRUGOPS_HOME:-$HOME/.grugops}` (central) and any target repo gets a tiny, self-resolving footprint (`.grugops/`, `plans/`, `memory-bank/`). This fixes the three v1.0 dogfood pains — the kit never arrived in the target, the wrong target got written, and symlinks were fragile. The work proceeds in a forced build order: freeze the kit/state split convention and the single "one rule, two homes" resolution mechanism, then rewrite the ~31 role/workflow/adapter files so every reference resolves to the correct root (grep-to-zero gate) — Phase 7, the linchpin — then the two-root installer that resolves `$GRUGOPS_HOME`, copies the kit, materializes the absolute kit path into the standalone adapters, and seeds per-repo state (Phase 8) — then the verification layer that would have caught all three pains: the `--check` doctor and the two-root validator that refuses to false-green (Phase 9). The rewrite and the materialize mechanism are kept together so the doctor and validator key off the final ref spelling.

## Milestone Summary

**Decimal Phases:** None. Phase 9 added two gap-closure plans (09-05, 09-06) in a Wave 4 after verification surfaced 3 blocker gaps — handled inside Phase 9, not as decimal insertions.

**Key Decisions:**

- Kit home `${GRUGOPS_HOME:-$HOME/.grugops}` — NOT XDG, NOT a literal `~`; resolved identically in sh and Node.
- Default install mode **COPY**, not symlink (symlink opt-in only).
- Per-repo config at **`.grugops/factory.config.json`** with the install marker/version stamp in `.grugops/` (SHOME-02 — supersedes the older repo-root recommendation in ARCHITECTURE.md).
- Installer **materializes** the resolved absolute kit path into the standalone adapters (an LLM cannot expand `$GRUGOPS_HOME` in prose); one documented one-line bash self-heal fallback is the only env-var reference.
- Zero-dep (sh + Node stdlib, no package.json); never overwrite/delete user content.
- Single-window sequential role-load via `_role-switch-protocol.md` is the design — packaging templates grant NO spawn tool (D-08/WR-05).
- **Human-approved (Phase 8):** pull one `install.test.sh` Check-3 slice of VAL-02 forward to reconcile the byte-restore check with the two-root D-06 contract.
- **Human-approved (Phase 8):** Option A — reconcile only Check 3, leave the other 6 byte-identical.

**Gating pitfalls (held in success criteria):**

- **C1** grep-to-zero bare-refs build gate (Phase 7 SC#5) — a single missed ref out of ~137 across 31 files dangles silently; the gate is the only mechanical net.
- **C3** no-fallback-to-`.` / unset-`$GRUGOPS_HOME` BAD fixture (Phase 9 SC#3–4) — or the validator false-greens in the dev checkout. Doctor and validator resolve the kit home identically.
- **C2/migration** DEFERRED to v1.2 (MIGR-01), not phased here.
