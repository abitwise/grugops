<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → Bash tool (deploy) | Untrusted agent-issued command crosses into a potentially production-mutating shell call — the guard is the choke point |
| agent → approval signal | The agent must NOT be able to grant its own approval; only a human with shell access can |
| plugin manifest → hook script | The hook script path must resolve on any machine (no hardcoded absolute path) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-EoP-1 | Elevation of Privilege | agent self-approves by inline-setting the env var then deploying | mitigate | guard.mjs `selfApprove` detection denies any command that sets/exports the approval var (D-33); behavioral test fixture 3 |
| T-05-Tamper-1 | Tampering / EoP | prompt-injection talks the agent past a prose-only safety rule | mitigate | Mechanical PreToolUse hook deny — a prompt cannot override a hook (not prose); behavioral test fixture 1 |
| T-05-Tamper-2 | Repudiation / Tampering | guard placed in subagent frontmatter → silently ignored | mitigate | Guard lives ONLY in plugin-level hooks/hooks.json; harness proves it actually blocks a sample deploy |
| T-05-DoS-1 | DoS (of the guard) | hardcoded hook path breaks the guard on another machine | mitigate | `${CLAUDE_PLUGIN_ROOT}`-relative command (CLAUDE-03); grep forbids `/Users/`/`/home/` |
| T-05-DoS-2 | DoS / fail-open | malformed stdin crashes the guard, allowing a deploy | mitigate | Parse wrapped to fail CLOSED; only non-deploys allowed on bad input |
