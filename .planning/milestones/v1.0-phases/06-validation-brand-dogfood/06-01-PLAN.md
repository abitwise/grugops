<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sample-repo files → validator | The validator reads untrusted markdown/JSON from an arbitrary (dogfood) tree via `VALIDATE_ROOT`; content is data, never executed |
| filesystem ← validator | The validator is read-only; it must never write/delete or build a write path from file content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Denial of Service | `JSON.parse(factory.config.json / plugin.json)` | mitigate | Wrap every `JSON.parse`/read in try/catch; a parse failure becomes an ERROR finding, never an unhandled throw (mirrors guard.mjs fail-closed) |
| T-06-02 | Tampering | validator file access under resolved ROOT | mitigate | Read-only by construction; never derive a write path from ticket/file content; all paths are `join(ROOT, rel)` with fixed `rel` literals (V12) |
| T-06-03 | Input Validation | untrusted markdown/JSON read from a sample repo | mitigate | Treat all read content as data; never `eval`/execute; front-matter is regex-extracted, not interpreted (V5) |
| T-06-SC | Tampering | npm/pip/cargo installs | mitigate | None — by design the validator and harness install ZERO external packages (Package Legitimacy Audit: no packages). No `package.json` created (D-45). |
</threat_model>
