<objective>
Implement D-32, the human's answer to the audit's install-side finding (2026-09-29). Today a re-install
overwrites a kit file the user edited: materializeAdapter writes the new render over a differing file, and
linkOrCopy copies over it. No backup is made and nothing is recorded, so a user's edit is lost silently. That
is the install-side twin of Gap B (DC-2 of the gap-planning brief: act on a record, never on presence). This is
gap-closure round 2 of the 4-round cap (D-06).

D-32 fixes the behaviour exactly. Install asks whether to back up the edited files and then overwrite, and the
choice is all-or-nothing for the kit, because refreshing the unedited files while skipping the edited ones
leaves a mixed-version kit. Where no human can answer, nothing in the kit changes and install says how to opt
in. DRY_RUN lists the backups it would make. "Edited" is decided by the `kitFiles` record from plan 33.1-30. A
file with no record counts as possibly edited when it differs from the current kit source, so the first
re-install over an install made before this release asks once. Every adapter from such an install differs from
its source, because install renders the kit path into it. That is D-32's literal rule, and plan 33.1-34 states
it in the README.

Scope: the pre-flight covers every write to a kit destination in the target: every entry of plan 33.1-31's kit
plan, which already holds the skills, the rendered adapters and `--migrate`'s symlink unlinks, built and
validated before any write. `--update` writes only the kit
home, not the target, and is unchanged. Non-kit steps (the CLAUDE.md pointer, Gemini settings, ask rules,
runnables, seeded state, the marker) run as before either way. When the kit is not written, `kitFiles` is
carried forward unchanged (an absent one stays absent), and the marker keeps its previous `kitVersion`.

Purpose: a user's edit to a grugops kit file is never lost to a re-install, and the kit is never left half
updated.
Output: the pre-flight, the decision, the backups, the flag, the prompt, and uninstall's report of backups.
</objective>

| Boundary | Description |
|----------|-------------|
| re-install → grugops kit files the user may have edited | a user edit is user content (D-18, D-32) |
| agent-run install (no terminal) → consent | an agent cannot answer for the human (D-32) |
