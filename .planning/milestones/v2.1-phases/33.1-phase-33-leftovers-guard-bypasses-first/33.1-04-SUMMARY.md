# Phase 33.1 Plan 04: Read-only git-host protection check Summary

**A node-builtins-only runnable, materialized at `tools/grugops/host-protection.js`, asks the git host through `gh api --method GET -i` whether the default branch, `main`/`master`, any `--branch`, and the production environment are protected. It answers `protected` only on positive ruleset, classic-protection or required-reviewer evidence, and `UNKNOWN - verify` for every ambiguous answer. Workflow 05 step 3 (which no longer emits the retired banner) and workflow 12 step 6 run the check and record the result.**

## Decisions Made

See `key-decisions` in the frontmatter. The union rule (a requirement shown by either the ruleset or classic protection) goes past the plan's literal "classic 200 lacking either → unprotected". It only moves a case from `unprotected` to `protected` when both requirements have positive evidence, so it never claims more than the host shows.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Renamed-branch answer read as branch existence**
- **Found during:** Task 2 (read-only smoke run against this repository)
- **Issue:** GitHub answers `branches/master` with HTTP 200 and the record of `main` when master was renamed. The check added `master` as a target and then reported it `UNKNOWN - verify` from the protection endpoint's "Branch not found".
- **Fix:** A 200 counts as existence only when `.name` equals the asked branch. A 200 about another branch omits the extra branch. The `Not Found` branch probe needs the same name match, else `UNKNOWN - verify`. Two cases added.
- **Files modified:** scripts/runnable-ref/host-protection.ts, host-protection.test.ts
- **Committed in:** 956a5fd9

**2. [Rule 2 - Missing critical] Pagination, crash exit code, seam visibility, branch-name refusal**
- **Found during:** Task 2
- **Issue:** (a) A rule list longer than one page could have produced `unprotected` from a partial read. (b) A thrown error would exit 1, which the contract reads as "unprotected". (c) The `--gh-script` seam (T-33.1-42) was visible only under `--json`. (d) A `--branch` of `..` segments could resolve to a different REST path.
- **Fix:** (a) `?per_page=100`, and a `Link rel="next"` marks the list as not read in full. (b) `uncaughtException` prints a could-not-run summary and exits 2. (c) A stderr notice on every seam run. (d) Names with empty, `.` or `..` segments, control characters or a leading `-` get `UNKNOWN - verify` and no call.
- **Files modified:** scripts/runnable-ref/host-protection.ts, host-protection.test.ts
- **Committed in:** 956a5fd9

**3. [Rule 3 - Blocking] Derived-set pins moved by the new module**

- **Fix:** 90 → 91 and 10 → 11, each with a re-derived docblock entry. AUTO-06's single governance reader is unchanged.
