# Phase 33.1 Plan 21: CR-02 ownership half Summary

**Uninstall now removes an empty directory only when install created it, which install records in `.grugops/install.json` as `createdDirs`, or when the directory's own name begins with `grugops`. An empty `.github/`, `.gemini/`, `.claude/` or `.claude/agents/` that the user made survives both the real run and the preview, and is reported `left`. A new shared module, `install/install-marker.ts`, reads the marker and both of its ledgers as tri-states for both binaries. Because of that, install now fails closed on a malformed or unreadable ask-rule ledger (WR-05), as uninstall already did. Uninstall also removes only one copy of each recorded rule, so a copy the user added stays (IN-02).**

## What changed, concretely

- **`install/install-marker.ts`** imports only `lstatSync` and `readFileSync` from `node:fs`. A `createdDirs` entry is valid only if it is a non-empty relative POSIX path with no leading `/`, no `\`, no `:`, and every segment non-empty and neither `.` nor `..`.
- **`install.ts` `mkdirp`**: the `!existsSync(dir) && !DRY_RUN` guard is unchanged. Inside it, a read-only walk up the tree collects the missing ancestors. After `mkdirSync`, each of them inside TARGET is added to `CREATED_DIRS` in POSIX form.
- **`install.ts` `writeMarker`**:
  - It reads the previous marker once.
  - If the ledger is `malformed`, it reports `verify` (this also shows in a DRY_RUN preview) and writes the raw value back.
  - Otherwise it writes the sorted union of the earlier entries that are still directories and this run's `CREATED_DIRS`. The union is computed after the `.grugops/` mkdirp, so a `.grugops/` this call created is recorded too.
  - If the marker is `unreadable`, it leaves the marker byte-identical and reports `skipped`.
  - It always writes `createdDirs`, after `claudeAskRules`.
- **`install.ts` `writeAskRules` and the doctor**:
  - An unreadable marker or a malformed ledger gives a `verify` finding, and no rule is added or relabelled.
  - A malformed ledger is written back verbatim through `ASK_LEDGER_KEEP_RAW`.
  - `--check` gives a WARN naming the malformed ledger.
  - The local `readAskLedger` is deleted. `readMarker` is kept for the version check and old-layout detection, but it now delegates to the shared reader.
- **`uninstall.ts`**:
  - `MARKER` and `DIR_LEDGER` are read once, at the top of the removal sequence, before anything is removed and before `removeMarker`. An unreadable marker or a malformed ledger gives one `verify` finding that names the directory ledger.
  - `rmdirIfEmpty` asks `ownsDir` after the protected, is-directory and emptiness checks and before the DRY_RUN branch. A directory it does not own is reported `left` with one of four reasons: not in the ledger, no install marker, the marker predates the directory ledger, or the ledger could not be used.
  - `removeAskRules` reads the same `MARKER` through `readAskRuleLedger` and keeps every existing message. It walks `permissions.ask` in order and removes only the first occurrence of each ledger rule.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - one authority] install.ts's non-ledger `readMarker` now delegates to the shared reader**
- **Found during:** Task 2
- **Issue:** The plan replaced `readMarker` only for ask-ledger purposes. That would have left a second JSON parse of the same file in install.ts, used for old-layout detection and the doctor's version check.
- **Fix:** `readMarker` now returns `readInstallMarker(...).marker` when the state is `ok`, and null otherwise. The semantics are identical: absent, garbled and non-object markers all return null.
- **Commit:** 4929d5a1

**2. [Design note] `writeMarker` decides "leave an unreadable marker unchanged" from its own read**
- **Found during:** Task 2
- **Issue:** The plan described a module flag that `writeAskRules` would set.
- **Fix:** `writeMarker` already reads the marker for the directory ledger, so it skips on `unreadable` itself, at the point of the write. `writeAskRules` still reports the `verify` finding. The behaviour matches what the plan asked for, and the skip no longer depends on the call order.
- **Commit:** 4929d5a1

**3. [Rule 1 - consistency] A marker that parses to a non-object is now `unreadable` on the uninstall ask-rule path**
- **Found during:** Task 2
- **Issue:** The old inline reader in `removeAskRules` treated a marker whose JSON was `null`, an array or a scalar as "no ledger field" and printed a `skipped ... predates` line. The shared reader calls it `unreadable`.
- **Fix:** That case now takes uninstall's existing unreadable-marker `verify` message. This is stricter (fail closed), and install reads the same input the same way.
- **Commit:** 4929d5a1

**4. [Scope, test only] The malformed-`createdDirs` case covers more shapes than the plan's five**
- The plan listed `"x"`, `[1]`, `["../outside"]`, `["/abs"]` and `["a//b"]`. The case also covers `["a\\b"]`, `["c:x"]`, `["."]`, `[""]`, `null` and `{}`.

**5. [Orchestrator note, test only] The DRY_RUN prune arm in install.test.ts now asks for its empty backups directly**
- `snapshot()` records no row for an empty directory, so the arm's "nothing deleted" lines could not see a planted empty backup disappear. I added explicit `existsSync` checks. Commit 4b8c909c.

**6. [Housekeeping] The census row for `install.ts:mkdirp:mkdirSync` now cites the moved line (:430)**
- It also notes that the ancestor walk inside the guarded branch only reads. The site, count and gate are unchanged, and the census found no new mutating site or import.

## Notes for the verifier

- **Existing installs:** an install made before this release has no `createdDirs` field. On uninstall, its `.claude/`, `.claude/skills/`, `.claude/agents/`, `.gemini/` and `.github/` stay behind, each empty and reported `left` with the reason that the marker predates the directory ledger. The same goes for a target migrated with `--migrate`, whose `.claude/` came from the old layout. This is deliberate: without evidence, the uninstaller does not guess. `grugops*` skill directories and `tools/grugops/` are still removed by name.
- **A re-install over a legacy marker** writes `createdDirs` holding only what that run created. The shared-name directories from the earlier install are not backfilled.
- **The ledger is never iterated to delete anything.** `ownsDir` is only asked about the eight fixed candidates. It uses exact membership of `relative(TARGET, d)` in POSIX form, and every removal is still a non-recursive `rmdirSync` of an empty directory.
- **The DRY_RUN preview** now also prints `left` lines for empty directories it does not own. The subset invariant from plan 33.1-18 holds because both runs apply the same rule, and all 13 cases in installer-dry-run.test.ts stayed green.
- **The admission hook's frozen manifest** (`hooks/hook-entry.ts`) lists no file under `install/`. No manifest regeneration was needed.
- **Not changed:** the doctor still calls a missing `.claude/settings.json` "could not be read as JSON" (IN-01, deferred with a reason).
