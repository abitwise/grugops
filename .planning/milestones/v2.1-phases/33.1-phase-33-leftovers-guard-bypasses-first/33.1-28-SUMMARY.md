# Phase 33.1 Plan 28: createdFiles ledger — uninstall deletes a file only on install's record

**Install records every file it creates in `.grugops/install.json` as `createdFiles`. Uninstall deletes `CLAUDE.md` and `.github/copilot-instructions.md` only when that record lists the file, this run removed a terminated grugops block from it, and it is blank afterwards. It deletes `AGENTS.md` and the runnables only on the record plus a content match, and removes an empty directory only on `createdDirs`. The `grugops`-name rule and the false "grugops-created" label are gone.**

### One authority for content records (for plan 33.1-30)

`install/install-marker.ts` holds `contentRecord(bytes)`, `linkRecord(target)`, `isContentRecord(v)` and `recordHolds(root, path, record)`. The `sha256:<64 hex>` / `link:<target>` grammar is exactly plan 30's `kitFiles` grammar. `recordHolds` reads through readForWrite (regular file only, no link followed, bounded, brief DC-3) or through `wayTo` + `isOwnLink`, so plan 30's `ownsKitFile` can call it unchanged. Plan 29's `geminiSettings` and plan 30's `kitFiles` should also be added to `updateKeptMarker`, beside `malformedLedgers()`.

### The rules, stated

- **Files:** an entry survives a re-install only while the file holds exactly the recorded bytes (or link) and install did not append to it. A file re-made byte-identical to what install wrote holds nothing of the user's, so it is treated as install's. A test pins this as the stated rule, and the README says so.
- **Directories:** a re-install carries a recorded directory only if it was non-empty when the run started, because install never leaves a directory it created empty. Uninstall removes a recorded empty directory only if this run emptied it. A directory the user emptied, or deleted and made again, is left and reported: "it was already empty when this run reached it …". No timestamps or inode numbers are used, and a copied installed tree still uninstalls completely (a test covers this).
- **Ask rules:** claims and flags carry only while `permissions.ask` is the array install left there.

### Behaviour changes a user can see

- A recorded directory that is already empty when uninstall reaches it is left and reported. That covers a directory the user emptied, or one they deleted and made again. A re-install drops such a directory from the record.
- The DRY_RUN preview now names the directories the real run would empty and remove.
- Changing `permissions.ask` (or re-making the settings file) before a re-install makes every grugops rule in it count as the user's. They are reported so and left by uninstall.
- A kept marker is rewritten, and a new `edited` line reports it.
- install/README.md is corrected for each of these, including the DRY_RUN paragraph, which was false after this change.
