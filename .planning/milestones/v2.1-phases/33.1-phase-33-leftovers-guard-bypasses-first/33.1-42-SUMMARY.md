# Phase 33.1 Plan 42: Stale-approval rows on the branch floor (D-33 (d)) and the narrowed no-bypass line (D-31 Q1) Summary

**The host check's branch floor now needs two more settings before it answers `protected`: stale approvals dismissed when new commits are pushed, and approval of the most recent push. Each is read on both arms through the new `ACCEPT.enabledFlag`. True is held, false is failed, and anything else, absence included, is `UNKNOWN - verify`. The no-bypass line now claims only what both arms measure: "does not let the account the agent works under bypass it". README §5 gains the two lines, the GitHub settings that meet them, and the disclosure about administrators on a ruleset.**

## Decisions needed from the human

1. **The no-bypass line's wording (D-31 Q1, `q1-narrow-line`).** D-31 Q1's option example read "does not let the account the agent works under bypass it, and applies to administrators". This plan publishes only the measured clause, "does not let the account the agent works under bypass it", in `BRANCH_FLOOR`, README §5 and `--json` `floor.branch`. The reason: the ruleset arm reads `current_user_can_bypass` and nothing about administrators. D-31's rule is that the line states what the ruleset arm measures. The cost: on a ruleset, the line would claim something the check does not read, and a branch would read `protected` while an administrator role on the ruleset's bypass list could still bypass it (re-review WR-02). **Reversibility: one-way with D-31.** The line is the published floor text in README §5, the host check's table and the CHANGELOG Breaking entry, and those change together.
