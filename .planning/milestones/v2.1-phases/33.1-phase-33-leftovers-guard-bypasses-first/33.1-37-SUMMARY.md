# Phase 33.1 Plan 37: Kit-home overlap refusal, kit-home record, identical copy recorded only by carry Summary

**Install now refuses a kit home that overlaps the target before any write (CR-01). The kit home keeps its own record, so copyKit replaces only a kit it recorded and renames anything else aside as a recorded backup. A kit file that merely matches install's bytes is no longer adopted as install's, so uninstall can no longer delete a user's hand copy.**

## Accomplishments

- **CR-01 (Task 1).** `realPathThroughExisting` resolves the real location of a path that may not exist yet. Right after the self-checkout guard (install.ts:1574, before `if (MIGRATE)` at :4223), install compares the kit root, the kit home and the target by real path. It refuses with one stderr sentence and exit 1 when they overlap in either direction, or when a real path cannot be read. Nothing reaches stdout. DRY_RUN and `--allow-self` do not exempt it.
- **The kit-home record (Task 2).** `.grugops-kit.json` uses the same ledger grammar as the target's record, with scope `kit-home` (kinds `kit`, `backup`). It is read through `readForWrite` (no link followed, no FIFO opened) and bound to the kit home's real path. copyKit decides one of three arms before the DRY_RUN branch:
  - `fresh`: nothing is at the kit root.
  - `replace`: a kit the record names, as D-31 item 14 accepts.
  - `backup`: anything else is renamed to `agent-factory.bak.<ISO>` and recorded with a `tree:`/file/link content record.

  Staging and the displaced-kit holder are exclusive `mkdtemp` directories. The holder is removed only after `owns(..., "kit")`.
- **IN-06 / IN-01 (Task 3).** Class tests now vary the kit home:
  - `REFUSAL_VARIANTS` (4, pinned), each run real and DRY_RUN with zero bytes changed in the target and the kit home.
  - `KIT_HOME_VARIANTS` (an unrecorded kit home, a link at the kit root).
  - The DC-3 class test plants a FIFO and a directory at both kit-home read paths, imported from install-marker.js (count 2, pinned).
  - Census rows cover the new mutating sites. The ownership rule for copyKit's one `rmSync` is in place.

  README states the overlap refusal, the kit-home record and the rename-aside, and names `install/install.js` as the self-checkout marker. CHANGELOG is updated.
- **Identical copy recorded only by carry (Task 4, the human's decision of 2026-10-02).** `carriedKitRecord(previous, root, rel)` in install-marker.ts (:920) is the one rule. It returns the previous `ok` ledger's kit-true entry's own content record, and only while `owns` answers owned. `identicalKitDest` (install.ts:3176) is its one caller, for the materialize identical branch, the copy identical branch and the `--symlink` own-link branch. If the carry does not hold, install reports the path `left`, records nothing, and uninstall leaves the file. `PREVIOUS_LEDGER` (install.ts:4198) is the ledger as the run found it.

## Decisions Made

- The overlap refusal is always on. It runs after the self-checkout guard and not on `--check`, `--update` or `--prune-old-kit`; the comment at install.ts:1568 says why.
- An identical kit copy keeps a record only as a carry. The record carried is the earlier entry's own content record, so a carry never claims more than the earlier install wrote.

## Decisions needed from the human

1. **Rename-aside of an unrecorded kit root (collected by plan 33.1-43).** copyKit renames anything at the kit root that the kit-home record does not name to a recorded `agent-factory.bak.<ISO>`. That includes every kit home written before this release, since none has a record, plus a link, a file, or a user's own `agent-factory/` there. It happens on the first re-install or `--update`. This goes beyond D-31's kit-home decision of 2026-09-30: item 14 accepted overwriting a kit, and kit-home backups were deferred.
   - **Alternative:** replace without a backup, as before.
   - **Cost of the alternative:** it deletes user content whenever the kit root is not install's (CR-01's sibling, D9/D12).
   - **Cost of this choice:** one backup directory per pre-release kit home, removed by hand until `--prune-old-kit` (plan 33.1-40) can remove it.
   - **Reversibility:** reversible (installer behaviour).
2. **For information, already decided (2026-10-02):** with the identical-copy rule, a re-install over a pre-ledger (2.1.0) marker no longer adopts the kit files that are already there. A later uninstall leaves all 24 and reports them, for removal by hand. README "An install made before this release" already says so.
