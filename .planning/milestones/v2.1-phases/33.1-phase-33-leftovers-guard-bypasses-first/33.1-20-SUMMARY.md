# Phase 33.1 Plan 20: CR-01 environment rows and one enumeration of the floor Summary

The production environment is now `protected` only when the host positively shows every row of
`ENVIRONMENT_FLOOR`: the environment exists under the configured name, names at least one reviewer,
prevents self-review, does not let administrators bypass its protection rules, and allows deployments
only from protected branches (D-30 `floor-full`). install/README.md §5 is the one published
enumeration of the floor. Both of its checklist lists are bound both ways to `--json` `floor.branch`
and `floor.environment`, and every other published floor sentence points at that checklist.

## What was built

- **Task 1 (tracer), commit b2f363ed.** `ENVIRONMENT_FLOOR` rows `{ id, requirement, read }` read the
  matched environment object. Values:
  - `prevent_self_review` must be `=== true`. `false` is `failed`. Missing or a string is `unknown`.
  - `can_admins_bypass` must be `=== false`. `true` is `failed`. Missing or `null` is `unknown`.
  - `deployment_branch_policy.protected_branches` must be `=== true`. A `null` policy is `failed`. A
    custom policy is `unknown` (the check does not read which branches it allows). Any other shape is
    `unknown`.
  - `protection_rules`: `[]` is `failed`. Missing or not an array is `unknown`. A reviewer rule with
    `reviewers: []` is `failed`.

  Verdict rule as for branches. Reviewer identities are never printed; the evidence counts them.
  `--json` gains `floor.environment` and per-row `facts` on the environment target. README §5(a)
  production list = the table, word for word. The name-resolution sentence now states the order the
  code uses (WR-06). New cases: 15 per-field cases, the no-rule case, the no-identities case, the
  floor/facts contract, the second-list drift case, `WEAKEN_ENV`, and the could-not-ask facts case.
  The existing cases that meant "no protection" now say `protection_rules: []`.
- **Task 2, commit 9867f0ac.** README "Check it" now defines `protected` as positive evidence for
  every checklist item that applies to the target, from rules the checked account cannot bypass.
  `unprotected` means an item is missing or can be bypassed. §5(b) (WR-06, installer half) now
  states that the installer reads the first of `.grugops/factory.config.json` and
  `agent-factory/config/factory.config.json` that exists. Neither, or an unreadable one, means every
  rule is written. Checked against `readCheckpointConfig` (returns `undefined` on a read or parse
  failure, with no fall-through) and `checkpointsToWrite` (a non-object config gives `block` for
  all). The module header names both tables and the new `--json` shape. There is one CHANGELOG
  `### Security` bullet (clear voice).
- **Task 3, commit 7c27a9ec.** Both `hardFloor` strings and both `why` strings in audit-model.ts
  point at "the git-host setup checklist in `install/README.md` §5". A new assertion in
  audit-model.test.ts requires the pointer in each hardFloor. docs/GUARANTEES.md is regenerated.
  adapters.md and factory.config.md drop their partial lists for the same pointer. The hook manifest
  is regenerated (see Deviations).
- **Commit 240a7bef.** README wording corrected against GitHub's documentation (see Deviations).

- **Found during:** SUMMARY preparation
- **Issue:** The Task 1 README paragraph quoted "Prevent self-review" as a GitHub setting label. The
  GitHub docs (Actions deployments-and-environments reference, fetched through Context7) describe
  only "the option to prevent self-reviews". They also document two facts that matter to anyone

  protected, and on Free, Pro and Team plans required reviewers are available only for public
  repositories.
- **Fix:** The option is now described rather than quoted, and both documented caveats are stated
  in clear voice. "Required reviewers", "Allow administrators to bypass configured protection rules",
  "Protected branches only" and "Selected branches and tags" are the documented headings and stay
  quoted.
