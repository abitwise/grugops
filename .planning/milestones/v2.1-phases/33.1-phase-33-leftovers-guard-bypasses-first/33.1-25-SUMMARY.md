## Task 1 detail

- `usableRepositoryName(v)`: a string of at most 200 characters matching `^[A-Za-z0-9._-]+/[A-Za-z0-9._-]+$`, with neither part `.` or `..`. It is a plain predicate: it produces no FactState and has no census row.
- `repositoryIdentity(repo)` names the repository only when all of these hold:
  - the answer is a 200 object;
  - `full_name` passes the predicate;
  - `url` passes `readRepositoryApi`;
  - the url's last two path segments, percent-decoded, equal `full_name` exactly.
  
  Any other answer gets one of three reasons, each ending "so the check cannot say which repository it inspected": the endpoint did not name the repository (full_name), plus `answered(repo)` when it was not a 200 object; the url is absent or unreadable; or the url names another repository.
- When the repository is unnamed, `everyTargetUnknown(why)` runs. It is the same routine the could-not-ask path uses: each target is UNKNOWN - verify, and each keeps one unknown fact per row. No endpoint after `repos/{owner}/{repo}` is asked.

## Task 2 detail

- `readConfigText(path)`:
  - opens with `openSync(path, O_RDONLY | (O_NONBLOCK ?? 0))` and fstats that same descriptor;
  - returns text only for a regular file of at most `CONFIG_MAX_BYTES` (1 MiB), reading no further than the size fstat reported;
  - returns undefined for anything else, including any error, and closes the descriptor in `finally`.
  
  It imports only node builtins. `environmentName` reads each candidate through it; an undefined result falls through, as an unparseable file does.
- Path set derived: the test parses host-protection.ts, takes environmentName's single `for…of` over a string-literal array, asserts length 2 and prints it (`.grugops/factory.config.json`, `agent-factory/config/factory.config.json`).
- Cases per derived path: a FIFO (staged through the corpus's `stageShapeOrSkip`), a directory, a symlink to `/dev/zero` and a valid JSON file above 1 MiB (naming `big`). Two controls are read at each path: a regular config, and a symlink to one. The staging:
  - For candidate i, only the later candidates hold a valid config, so the special file is the first thing the check reaches.
  - The expected source is therefore the next candidate, or the documented default for the last one. A later file is the only kind the check could fall through to, so placing a config at the earlier candidate would never exercise the special path.
  - Each run gets a 20 s timeout with SIGKILL. The test asserts no error or signal, the same kind at the path, the fall-through source, and exit 0.
- No FIFO case was skipped on darwin. The skip arm was driven with `GRUGOPS_PLATFORM_SHAPES_FORCE_ABSENT=FIFO`, and it printed the corpus's counted skip line.
- RED (the Task 1 build): both FIFO cases failed at 20 s (`spawnSync node ETIMEDOUT`), and both oversize cases read the file (`environment big: …`). That is 4 failed and 8 passed; the directory cases already fell through via EISDIR.
- The `/dev/zero` case was left out of the automated RED run and probed by hand. Against the Task 1 build, `timeout 5` killed it (exit 124) with no output and 2.37 GB RSS. A 20 s run could have grown the test machine by about 10 GB.

### Findings and fixes

- **B1 (DC-1): a ruleset's source was never compared with the repository the run proved.**
  - After sourceDisagreement shows that both sides agree, `sourceNotThisRepository()` compares the agreed source with repositoryIdentity's owner and name, exactly, case included:
    - `Repository`: the source must be the proven owner/name.
    - `Organization`: the source must be the proven owner.
    - Any other type (`Enterprise`, another spelling, an undocumented value): the ruleset does not bind.
    - No type on either side: only owner/name counts. Without a type, the source could name an organization or a repository, and only the full name names this repository in either case.
  - The red-team case (`evil/other`) now reads main `UNKNOWN - verify` with exit 2.
- **B1 siblings, found by searching the answers the check reads:**
  - An environments entry's `url` must be `<repository>/environments/<its own name>`.
  - An environments entry's `html_url` must be a canonical page of this repository on its web host: github.com for api.github.com, or the same host under GHES.
  - The protected-branch list element's `protection_url` is compared the same way as a protection body's url.
  - The repository answer's `name`, `owner.login` and `html_url` must restate the proven identity.
  - A branch answer's `protection_url` is compared on both paths. On the main/master probe, a mismatch means the branch is not shown to exist. On the non-admin `branches/<b>` path, a mismatch makes the arm `elsewhere`.
  - An absent field stays neutral. Every entry of the environments list is checked, not only the matching one.
- **B3 (DC-1): garbled urls were accepted.** `readApiUrl()` (with the shared `canonicalUrl()`) is now the one authority for the repository url and for every url compared with it. A url is read only when all of these hold:
  - The raw string equals its own parsed `href`. This refuses tabs, newlines, control characters, backslashes, `..` and `%2e%2e`, an upper-case host and a spelled-out `:443`.
  - It is https, with no credentials and no `?` or `#`.
  - The path prefix is empty or exactly `/api/v3`.
  - The host is api.github.com unless that prefix is present.
  - The owner and name segments are plain, with no percent-encoding.
  
  Both checks now go through one comparison (`repositoryUrlMismatch`/`underRepository`), so `octo/%72epo` is refused on both.
- **B4 (IN-04 class): format characters in printed text.** printable() now writes every Cf, Zl, Zp and Cs character, and every other default-ignorable code point, as a visible `\u{…}` escape. C0 and C1 characters still become `?`.
- **B2 (DC-3): opening the config released a blocked FIFO writer.** readConfigText now runs `statSync` first and never opens anything that is not a regular file within 1 MiB. The open adds `O_NOCTTY ?? 0`. The fstat on the same descriptor must show a regular file within the bound, with the same dev and ino as the stat.
