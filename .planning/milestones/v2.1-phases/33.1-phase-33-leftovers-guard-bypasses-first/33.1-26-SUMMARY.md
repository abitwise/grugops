# Phase 33.1 Plan 26: installer DC-3, readUserFile Summary

**install.js now reads every user path through one helper, install/user-file.ts readUserFile. The helper stats the path first and opens only a regular file within 8 MiB (read-only, non-blocking, O_NOCTTY). It then fstats the same descriptor and requires the same dev/ino. Every other shape becomes a typed state, and the caller reports it without reading or writing. Both copies of a user config (the `--migrate` legacy config and the render mirror's config) are now written from the helper's bytes.**

## Decisions Made

- The helper stats first and never opens a non-regular path. The plan text had the helper open first and read ENOENT/ENOTDIR from the open. This follows the 33.1-25 red-team B2 finding and matches `readConfigText`.
- A dev/ino change between the stat and the open is `unreadable` with code `CHANGED`.
- The state wording lives in one place (`unreadState`), and every site uses it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Stat before open, plus O_NOCTTY (the plan specified open-then-fstat)**
- **Found during:** Task 1.
- **Issue:** Opening a FIFO with O_NONBLOCK releases a writer blocked in open() on it (33.1-25 red-team B2). The plan's design would therefore change a special file that D-18 says must be neither read nor written.
- **Fix:**
  - `statSync` runs first. ENOENT/ENOTDIR → `absent`; not a file → `not-regular`; over the bound → `too-large`.
  - Only then does the helper open, with `O_RDONLY | (O_NONBLOCK ?? 0) | (O_NOCTTY ?? 0)`.
  - fstat on the same descriptor must show the same dev/ino, a regular file and a size within the bound.
  - The census `read-only-open` gate admits O_NOCTTY as well as the two flags the plan named.
- **Files modified:** install/user-file.ts, install/installer-fs-census.test.ts.
- **Verification:** a blocked-writer test at the helper and at every site, plus the stat-first mutation proof.
- **Commit:** 384ca80c.

**2. [Rule 2 - Missing critical] linkOrCopy refuses a non-regular destination explicitly**
- **Found during:** Task 2.
- **Issue:** Routing `sameContent` alone would have answered "not the same" for a FIFO destination. The following `copyFileSync(src, dest)` would then have opened the FIFO for writing and blocked.
- **Fix:** linkOrCopy reads `dest` through readUserFile. A non-`ok`, non-`absent` state is a counted verify with no write.
- **Commit:** 64246c35.

**3. [Rule 2 - Missing critical] The --migrate seeded destination is asked through readUserFile**
- **Found during:** Task 2.
- **Issue:** The seeded-config write was gated by `existsSync`, which is false on any stat error.
- **Fix:** the write happens only when readUserFile reads `.grugops/factory.config.json` as absent (D-18: write only to a path the helper read as absent or regular).
- **Commit:** 64246c35.

**4. [Rule 1 - Bug] A structural test looked for the old read spelling**
- **Found during:** the Task 2 install/ run.
- **Issue:** the `write bound` case asserted that `adapterDestHazard(dest)` precedes `readFileSync(dest` inside materializeAdapter. That spelling no longer exists there, so the ordering compared against -1.
