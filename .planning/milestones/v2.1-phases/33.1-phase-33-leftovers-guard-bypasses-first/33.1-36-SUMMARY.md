# Phase 33.1 Plan 36: One install ledger behind one owns authority (D-33 (b) tracer) Summary

## Decisions needed from the human

1. **How a marker in the round-2 six-record shape is read (D-33 (b) did not say).** This plan reads a marker bound to this directory with no `ledger` as **no record**: `unbound` by `no-ledger`. Uninstall changes zero bytes and exits 3 with the remedy (re-run install.js here, then uninstall). Install replaces the marker and carries none of its records. A marker carrying `ledger` next to a retired record is `unreadable` and left byte for byte. **Alternative:** a migration reader that converts the six records into ledger entries. **Its cost:** a second reader of the same record, kept only for a shape no release wrote (v2.1's install.ts has none of the six names; CHANGELOG [Unreleased] introduced them). **Reversibility:** one-way with D-33 (b), as the marker shape is. A follow-up release could add a converter, but the one-reader rule would then have two readers. Plan 33.1-43 collects this.
2. **The 2.1.0 remedy changed.** README "Undo" used to say that for a 2.1.0 marker, setting `"target"` and re-running uninstall removes the six verbatim skills. A 2.1.0 marker has no `ledger`, so with target set it now reads `unbound` by no-ledger and changes nothing. The only remedy is to re-run install, then uninstall. README was rewritten to say so. This follows from item 1 and from the removal of the byte-identity fallback. Please confirm.
