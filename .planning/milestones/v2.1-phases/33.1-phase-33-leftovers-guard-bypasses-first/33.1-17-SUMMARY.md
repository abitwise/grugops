# Phase 33.1 Plan 17: Canonical branch floor for the host check (CR-01 branch half) Summary

The read-only host check now answers `protected` for a branch only when all four rows of the one
`BRANCH_FLOOR` table (pull request, at least one approving review read as an integer >= 1, force pushes
blocked, deletions restricted) are positively shown by the ruleset arm or the classic arm. The two arms are
combined by an explicit union rule. The README checklist is bound to the code by a drift test, and the
human chose `floor-full` as the floor definition that plans 33.1-19 and 33.1-20 implement.

## Floor decision

**Option chosen: `floor-full`.** Answered 2026-09-29 by the named human (the repository owner, Olger
Oeselg) through an interactive prompt at the 33.1-17 Task 2 checkpoint (gap-closure round 1, CR-01). No
wording changes to any checklist line were requested. Recorded as D-30 in 33.1-CONTEXT.md under
`### Guard retirement`.

Branch floor, for each protected branch:

- requires a pull request before merging
- requires at least one approving review
- blocks force pushes
- restricts deletions
- does not let administrators or the account the agent works under bypass it (classic
  `enforce_admins.enabled` true with no pull-request bypass allowances; every ruleset that shows a row
  reports `current_user_can_bypass: "never"`)

Production floor:

- a deployment environment exists under the configured name
- it requires at least one reviewer
- it prevents self-review (`prevent_self_review` true)
- it does not let administrators bypass (`can_admins_bypass` false)
- a deployment branch policy allows deployments only from protected branches

The check answers `protected` only when every line is positively shown; anything unreadable, absent or
oddly shaped is `UNKNOWN - verify`. install/README.md §5 becomes the one enumeration; audit-model.ts,
GUARANTEES.md, adapters.md and factory.config.md point at it. That published-text and code work belongs to
plans 33.1-19 and 33.1-20, not this plan. No replan is needed (the plans were written for the `floor-full`
options).

Date note: the plan allowed "2026-09-28 or the actual date"; the entry uses 2026-09-29, the date the human
took the decision.

  too. The case asserts only on the weakened row's `facts` state and the verdict; documented in the test.
