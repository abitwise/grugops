# Phase 34.1 Plan 55: WR-38, every line about an unusable marker is the owner's Summary

**removeMarker now asks the run's read before the path's shape. A link, a directory, a FIFO or a `.grugops` link at the marker path gets `left .grugops/install.json (left in place — it could not be read as a JSON object; see the verify line above)` instead of "not the marker install writes". kitPreflight's edited-kit reason uses the owner's clause. A parser census holds both retired wordings at zero about the marker.**

## Accomplishments

- install/uninstall.ts removeMarker:
  - The not-present arm stays first.
  - The `MARKER_READ.state === "unreadable"` arm comes next, before wayTo and kindAt. It prints `${MARKER_REL} (left in place — ${markerDefectText(MARKER_READ.defect)}; see the verify line above)`. That line is now built in one place; the second copy in the D-37 arm is gone.
  - The path-shape arm now runs only when the run read the marker as absent, unbound or ok, and the path has since become a link, a directory, a FIFO or a link on the way. Its wording depends on the read's state:
    - absent at start: "<what>; it was not present when this run started, so this run read none of its records; left in place — run `<rerunCommand()>` again to read it";
    - ok or unbound at start: "<what> now; it changed after this run read it, so this run read none of what is there now; left in place — run `<rerunCommand()>` again to read it".
  - The unbound arm, the not-present-at-start arm and U4 are unchanged. The comments above the arms now state the order and the rule.
  - Behaviour is unchanged: every arm that returned `left` before still returns `left`.
- install/install.ts kitPreflight: for an unreadable read, `noRecord` is `${MARKER_REL} ${markerUnusableText(marker)}`, the same wording pruneRoots uses. Every other branch is unchanged, and the same files are treated as edited.
- Reader-state matrix: 9 defects, 23 shapes, **115 cells**. No gated or platform skip on this host (darwin, not root).
  - Each install cell asserts exactly one `skipped` line for the marker holding `(left unchanged — <markerDefectText>; see the verify line above)`. The `ledger` defect is excluded because it is written back under a verify.
  - Each uninstall cell asserts exactly one `left` line holding `(left in place — <markerDefectText>; see the verify line above)`, or U4's malformed-ledger line for `ledger`. That makes 88 marker-line assertions in all.
  - All 115 cells assert that no line matches /not install's|not the marker install writes/.
  - The foreign-only skipped/left check from plan 34.1-54 is replaced by this check over every defect.
- R48e: the link row's uninstall `left` line is the owner's blocked line and does not contain "not the marker install writes".
- R53 (new, beside R44): install --claude --codex, then a line appended to `.claude/skills/grugops/SKILL.md`. Three marker shapes were each tested and restored before the next: `installMode` banana (field), a trailing comma (not-json), and a user's own object (foreign). For each, install --claude:
  - exits 3;
  - prints exactly one `edited-kit` line for the skill, holding `(.grugops/install.json <markerUnusableText(read)>, and it differs from the kit source)`;
  - prints no "not install's" line;
  - keeps the marker verify's wording ("never delete the marker" for field and not-json, "if it is yours, leave it" for foreign);
  - leaves the skill's bytes unchanged.
- D-43 census (`describe("D-43: no printed reading says the marker is not install's")`): the parser walks every reading of the nine product modules.
  - It finds **3 hits**, all about the kit-home record:
