## D-30: what this plan fixes for DI-06, and how it reads it

D-30 brings DI-06 into this round as CLEAN-1: a CLAUDE.md or Copilot file install created, whose block the user
already removed, is named on a `left` line with a by-hand remedy and is not deleted. DI-06, as the human saw it in this
plan's sibling table, is the blank file: it stays with no line naming it, because the bytes from before a removal,
which the file rule compares with the record, are not available when the user removed the block. This plan:
- names that blank file on a `left` line, with the remedy "delete it by hand if you do not need it";
- keeps its entry held (outcome `left`), as removeOwnedEmptyFile's other `left` arms do and as the Outcome vocabulary
  defines `left`. So the agent that owns the file (Claude Code for CLAUDE.md, GitHub Copilot CLI for the Copilot file)
  stays recorded (D-29), and plan 34.1-14's kept line prints the command that finishes the reversal once the file is
  deleted;
- leaves a file that still holds lines the user wrote unchanged and unnamed (`gone`): nothing of install's is in it,
  the same answer removeOwnedEmptyFile gives (`reversed`) when this run removes the block and the user's lines remain.
