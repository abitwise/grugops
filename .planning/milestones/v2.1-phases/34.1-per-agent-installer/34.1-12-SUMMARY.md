# Phase 34.1 Plan 12: the agent checkbox list (D-02) Summary

**At a terminal with no agent flag and no `--yes`, install now shows a checkbox list of the six registry agents, with the installed and detected agents pre-checked and labelled why. Arrows or j/k move, space toggles, Enter confirms. Ctrl-C and an empty confirm both exit 1 through `refuseSelection` with nothing written. The list is a pure state machine in `install/agent-picker.ts`, driven by a synchronous raw-mode reader in `install.ts` that restores the terminal in a `finally` block.**

## Performance

- **Duration:** about 55 minutes (02:28Z to 03:23Z), including one full regression of about 26 minutes
- **Tasks:** 2 (Task 1 was a tracer)
- **Files:** 3 created, 10 modified

## Accomplishments

- **`install/agent-picker.ts`** (pure, imports nothing, no I/O):
  - `decodeKeys(chunk, carry)` handles the arrow keys in both encodings, `j`/`k`, space, CR/LF and `0x03`. Every other byte or sequence decodes as `other`. An escape sequence split across reads is carried to the next read.
  - `step` wraps at both ends, toggles the cursor row, confirms with a copy of the checked list, and aborts.
  - `render` paints the header plus one line per row. A repaint moves up exactly the previous frame's screen-line count and clears below.
  - `pickerRows` pre-checks exactly installed ∪ detected.
- **`install.ts`:**
  - `readStdin` is the one stdin read.
  - `pickAgents` hides the cursor, sets raw mode, reads up to 16 bytes per read, decodes, steps and repaints. Its `finally` always runs `setRawMode(false)`, shows the cursor and writes a newline. Nothing in the loop exits.
  - `SELECTION_WHY` asks the list before the D-03 chain. No new `process.exit(` site: the mid-script pin stays at 10.
- **Tests:**
  - **17 pure cases** cover all 256 single bytes, 13 escape sequences split at every point (32 splits), the plan's two named splits, a three-read split, ESC plus a letter, unknown and broken CSI, several keys per read, step over the whole class, render, and pickerRows over all 64 installed × detected subsets.
  - **6 pty cases** run under script(1):
    1. Down, space, Enter installs exactly the second registry row (`codex`), `chosen at the prompt`.
    2. A detected agent starts checked and labelled.
    3. Ctrl-C.
    4. Empty confirm.
    5. A question after the list reads a typed line, which shows raw mode is off while the run continues.
    6. On an 80-column terminal the repaint moves up the wrapped header.
- **Censuses:**
  - `NON_TEST_MODULE_COUNT` 97 → 98, with a history entry.
  - The fs census asserts `agent-picker.ts` is scanned and has no import of any kind.
  - Agent-flag `EXEMPT_COUNT` 4 → 5.
  - mode-census `SOURCE_FILE_COUNT` 8 → 9 and `INSTALL_TEST_FILE_COUNT` 33 → 34; path-spelling-census `SCANNED_FILE_COUNT` 8 → 9 and `TEST_SCANNED_FILE_COUNT` 33 → 34. Each moved with the reason that the new file has no chmod, mode or path code.
- **install/README.md:** new section "The agent list at a terminal". It covers the pre-check rule, the keys, that unchecking does not remove an agent (D-04), the two refusals, what skips the list, and terminal restore. The exit-1 row and the "What the installer touches" line now mention the list.

- **Helper:** BSD script refuses a socket as standard input (`tcgetattr/ioctl: Operation not supported on socket`, measured), so both forms read through `cat |`. - **Restore check:** It compares the raw-mode flags from `stty -a` (brkint icrnl inpck istrip ixon echo icanon iexten isig cs8 onlcr), not `stty -g` bytes. macOS sets PENDIN whenever a terminal returns to canonical mode (measured: lflag 5cb before, 200005cb after). That is the kernel's doing, not something the installer left behind.
- **Extra cases:** I added the detected-pre-check case, the question-after-the-list case and the 80-column case on top of the plan's three.

## Known limitations (for the verifier and plan 34.1-13)

- **End of input is not pty-tested.** `readStdin` returning 0 cancels the list (`answer` stays null). A pty cannot easily deliver end of input: closing script's stdin makes BSD script type Ctrl-D (0x04), which the list reads as `other`. Ctrl-D therefore does nothing at the list, and Ctrl-C is the way out. That path is proven only by reading the code.
- **A terminal resized while the list is on screen** can strand lines. Each paint uses the width at that moment, but the previous frame was wrapped at the old width.
- **Windows:** the pty cases skip where script(1) is absent (WINDOWS.md row 322, `skipped-test`). Raw-mode key handling on a Windows console is `UNKNOWN - verify`.
- **Human check (plan's `<human-check>`, D-02):** queued, not run. In a real terminal, run `GRUGOPS_HOME=$(mktemp -d) node install/install.js --target $(mktemp -d)`. Toggle two agents and press Enter; the banner's `agents:` line names them. Run it again and press Ctrl-C; it exits 1, writes nothing, and typed characters echo and the cursor shows afterwards.
