# Phase 34.1 Plan 54: DI-18, a JSON object install never wrote reads `foreign` Summary

**A JSON object at `.grugops/install.json` that holds none of D-40's five install fields now gets its own reader state, `foreign`. `--check`, install and uninstall all say "not written by install; if it is yours, leave it". Nothing follows that phrase: no next step, no never-delete line, no removal offer. The next-step decision moved into `markerFixText`, so no caller can print a step after "leave it". Every record install wrote is worded byte for byte as before.**

  - `INSTALL_RECORD_FIELDS` holds `grugopsHome`, `kitRoot`, `installMode`, `target` and `LEDGER_FIELD`.
  - `MARKER_DEFECTS` gains `foreign` (9 members).

  - `markerFixText(remedy, then)`:
    - for `foreign` it returns ".grugops/install.json was not written by install (<problems>); if it is yours, leave it" and ignores `then`;
    - for every other defect it returns the old text plus "; then <then>".
- The eight callers (install.ts 6, uninstall.ts 2) pass their step as the second argument: "run `<check>`", "re-run the installer", or "run `<this run's command>` again". markerUnreadable's FAIL subject is "the file at <path>" for a foreign read.   - uninstall left line: ".grugops/install.json (left in place — it holds none of install's fields, so it was not written by install; if it is yours, leave it; see the verify line above)".
- Behaviour over a foreign read is unchanged:
  - uninstall changes zero bytes and exits 3 (FD, FM);
  - install leaves the file byte for byte, writes no marker and exits 3 (B3);
  - `--check` FAILs with exit 1 (matrix).

  - Every other cell now also asserts the converse: no line says "not written by install".
