## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Selecting agents (install)
- **D-01:** One flag per agent, derived from the registry ids in `install/host-tools.ts`: `--claude`,
  `--codex`, `--antigravity`, `--opencode`, `--copilot`, `--pi`. The flag set is derived from `HOST_TOOLS`
  (D-11 of Phase 34), never hand-listed, so a new registry row gets its flag with no installer edit and a
  test asserts the flag set equals the registry set. There is no all-agents flag: an old CI command must
  never silently install an agent added to the registry later. — **Reversibility:** costly — the flag
  names become a published CLI contract in install/README.md, CHANGELOG and users' CI scripts.
- **D-02:** With a terminal on stdin and stdout and no agent flag, install shows an interactive checkbox
  list of the registry agents (arrow keys move, space toggles, Enter confirms). Agents already installed in
  this target and agents detected in it start checked. Written in Node with zero runtime dependencies (raw
  mode on stdin); an empty confirmed selection refuses with the same message as D-03.
- **D-03:** With no agent flag and no terminal, or with `--yes`, the selection is: the set already
  installed in this target (from the install ledger), else the detected set (registry `detect` paths in
  the target), else install exits non-zero and names the per-agent flags to pass. An install made before
  this phase counts as having every agent it wrote files for, so an existing CI re-run behaves as today.
  — **Reversibility:** costly — it defines what unattended re-installs do on every existing target.
- **D-04:** Install only adds. Naming fewer agents than are installed keeps the others' files and prints a
  note naming the agents left installed and the uninstall command that removes one. Install never deletes
  an agent's files because it was not named.

#### Removing agents (uninstall)
- **D-05:** Uninstall takes the same per-agent flags. `uninstall.js --codex` removes only the files the
  install ledger records for Codex (owns(path) authority, 33.1 D-33). Uninstall with no agent flag removes
  everything, as today. Shared files (D-06) are removed only by a flag-less uninstall or when the last
  installed agent is removed.

#### Shared and per-agent footprint
- **D-06:** Every install writes the shared footprint whatever agents are chosen: the kit home, the seeded
  per-repo state, the marker and ledger (`.grugops/install.json`), `AGENTS.md` (by its existing rules),
  and `tools/grugops/`. The Claude Code skills and adapters, the `CLAUDE.md` start-here block and the
  Claude Code ask rules in `.claude/settings.json` are written only when Claude Code is selected; the
  Copilot pointer only for Copilot; the Pi template only for Pi (this amends Phase 34 D-17, the
  unconditional Pi write).
- **D-07:** `--check` reports a `reach` line, and counts findings, only for the agents installed in this
  target, not for every registry host.

#### Per-agent entries
- **D-08:** Codex gets `.agents/skills/grugops/SKILL.md`; Antigravity gets `.gemini/skills/grugops/SKILL.md`;
  OpenCode gets `.opencode/commands/grugops.md`; Copilot keeps its `.github/copilot-instructions.md`
  pointer; Pi keeps `.pi/prompts/grugops.md`; Claude Code is unchanged. Every path is project-level, never
  user-level. Each path and frontmatter shape is `UNKNOWN - verify` until research cites the agent's
  primary docs; a path research cannot confirm is not shipped as fact.
- **D-09:** Each non-Claude entry is a pointer: the start-here sentence plus `KIT_ROUTE` (Phase 34 D-26),
  fixed text the same on every machine. No absolute kit path and no install-time value enters instruction
  text (T-34-13). The Claude-style resolver with a materialized `KIT=` line stays Claude Code only.
- **D-10:** Non-Claude agents get the `/grugops` dispatcher only, one spelling across hosts (Phase 34
  D-16); the Orchestrator routes to map, plan, ticket, gate, UAT and release. The seven Claude Code
  skills stay Claude Code only.
- **D-11:** The entry texts come from one pointer template in the kit, rendered per agent with that
  agent's frontmatter shape (SKILL.md for Codex and Antigravity, a command file for OpenCode, a prompt
  template for Pi), generated and pinned by a byte freshness gate in the pattern of
  `scripts/generate-role-adapters.ts` and `scripts/adapters-freshness.ts` (single-source rule).

#### Antigravity replaces Gemini CLI
- **D-12:** The Gemini CLI registry row is replaced by Antigravity CLI (id `antigravity`, flag

## Summary

This phase turns an "install for every host" installer into a per-agent one, and it touches every
seam the last three phases hardened: the host registry (`install/host-tools.ts`), the one install
ledger and its ownership authority (`install/install-marker.ts` `owns`), the ledger-walk uninstaller,
and the `--check` doctor's carrier/reach machinery. The primary-source research changes three locked
details (X1-X3). The biggest structural fact is that Codex and Antigravity share one entry file,
`.agents/skills/grugops/SKILL.md`. That one fact decides the "installed set" question in CONTEXT's
discretion list. A set derived purely from ledger file records cannot tell a Codex install from an
Antigravity install, so the installed set must be a **recorded** marker field. For markers written
before this phase there is a one-time legacy derivation from the ledger.

The interactive checkbox list does not need event-driven input. Measured this session on Node
v26.11.0 under a pseudo-terminal (`script -q /dev/null`): `process.stdin.setRawMode(true)` followed by
the same synchronous `readSync(0, …)` + `EAGAIN` → `Atomics.wait` loop that `readlineSync` already uses
returns one chunk per key: `"\u001b[B"` (down), `" "` (space), `"\u001b[A"` (up), `"\r"` (Enter), and
`"\u0003"` for Ctrl-C, which raises no SIGINT in raw mode. The picker therefore fits the installer's
synchronous top-level control flow unchanged. It should be a pure state machine plus a thin I/O shell,
so it can be unit-tested with an injected key stream.

The largest execution risk is blast radius, not new code. Every installer test helper spawns
`install.js --yes` with no agent flag into an empty target. Under D-03 that run must now refuse (no
ledger, nothing detected), so roughly 30+ helper and raw spawn sites, the derived write-path VARIANTS
behind the DC-2/DC-3 class tests, two product scripts and the pinned mid-script exit count all move
together. Deleting the Gemini row also trips the derived prose scan (Rule B), because every prose list
"Codex, Gemini, OpenCode, Copilot, Pi" then names all but one sequential host.

**Primary recommendation:** Add the agent dimension in this order. (1) Registry: replace the Gemini row
with Antigravity; derive the flags; add an `agent-skill` and an `opencode-command` adapter kind; delete
`none`, `gemini-settings` and the entry-gate kinds. (2) One `installedAgents(marker, ledger)` function
that reads a recorded `agents` marker field and falls back to a legacy ledger derivation. (3) One
`entryOwners(entry)` footprint function driving per-agent uninstall. (4) Generated, freshness-pinned
whole-file entries copied from `GRUGOPS_SRC`, following the skill-twins pattern that `carrierWant`
already uses for `AGENTS.md`. (5) The WR-13 `installWouldWrite` owner and the WR-16 link owner.
(6) The picker. Re-pin the test helpers by derivation in the same wave as the D-03 refusal.

## Project Constraints (from CLAUDE.md)

- Tooling layer is TypeScript compiled with `tsc` to **committed `.js`**, freshness-checked. **Node 22+**. **Zero runtime dependencies** on hosts. Dev deps only `{typescript, vitest, @types/node}`. **No new package may be added.**
- **Installers:** idempotent, additive, dry-run-capable (`DRY_RUN=1`), reversible, never overwrite or delete user content.
- **Single-source:** role text lives once; per-tool adapters are thin pointers, never copies.
- **No fabrication:** unknown commands are `UNKNOWN - verify`; never fake a gate, test or citation.
- **Safety (hard):** git host is the hard floor; the Claude Code ask rules are a speed bump. (Unchanged by this phase. The ask rules become Claude-only per D-06.)
- **Minimal AGENTS.md** (Codex 32 KiB cap). Do not grow it for per-agent instructions.
- **Voice:** clear professional voice in every installer, report and safety string; caveman voice only in role prompts.
- **Brand:** lowercase `grugops`.
- **GSD workflow enforcement:** edits only through GSD commands.
- Memory and briefs: scratch installs **must set `GRUGOPS_HOME`** to a scratch dir. Regression command `npx vitest run --exclude '**/scripts/e2e/**'` (never `npm test`). No agent runs `git push`. The per-plan red-team is retired. The four-round gap-closure cap applies.

### Pattern 1: Flags derived from the registry (D-01)
**What:** one function owns the flag spelling. Both binaries parse with it, and a test asserts set equality and no collision.
```ts

export const agentFlag = (h: HostTool): string => `--${h.id}`;
export function hostForFlag(arg: string): HostTool | null {
  return HOST_TOOLS.find((h) => agentFlag(h) === arg) ?? null;
}
// install.ts / uninstall.ts arg loop, before the unknown-argument arm:
//   const host = hostForFlag(a); if (host !== null) { SELECTED.add(host.id); continue; }
```
Test: `new Set(HOST_TOOLS.map(agentFlag))` equals the flags the README documents. No `h.id` equals an existing flag stem (`target`, `yes`, `y`, `allow-self`, `force`, `symlink`, `check`, `strict`, `migrate`, `update`, `prune-old-kit`, `backup-edited-kit`). Derive that stem list from the arg loop with a syntax-tree census, not a hand list. Decide how agent flags combine with `--update` (kit-home-only) and `--prune-old-kit`: recommend **bad usage, exit 2**. `--check` with agent flags: recommend bad usage too, because D-07 reads the installed set and a narrowing flag would be a second source.

### Pattern 2: One derivation of "installed set" (D-03, D-04, D-05, D-07)
**What:** a recorded marker field plus a legacy fallback, both inside one function in `install-marker.ts`.
```ts
// install-marker.ts (pure over its inputs; imports host-tools.js for ids/footprint)
export type InstalledAgents =
  | { readonly source: "recorded"; readonly ids: readonly string[]; readonly unknown: readonly string[] }
  | { readonly source: "legacy"; readonly ids: readonly string[] }   // derived from ledger entries
  | { readonly source: "none"; readonly ids: readonly [] };         // no usable marker/ledger
export function installedAgents(marker: InstallMarkerRead, ledger: LedgerRead): InstalledAgents;
```
- **Recorded:** `marker.agents` is an array of strings. Ids not in `HOST_TOOLS` are kept verbatim in `unknown` and never acted on; a note names them. Treat a non-array or a non-string member as an unusable marker (fail closed, `installMarkerProblems`).
- **Legacy** (an `ok` marker with no `agents` field, i.e. written before this phase): a host counts when the ledger holds a non-dir entry that only that host's footprint claims and that "claims something": a `.claude/` kit file or the CLAUDE.md block → `claude`; the Copilot block → `copilot`; the Pi template file → `pi`. **The `gemini` entry does not count**: it is written on every fresh marker (verified above), and the Gemini row is gone. Codex and OpenCode wrote nothing before this phase, so they are never legacy-installed. This matches D-03's "every agent it wrote files for".
- **Writes:** `writeMarker` records `agents = sorted(previous ∪ selection)` (D-04: install only adds). Uninstall rewrites it to `agents − removed` in `updateKeptMarker`.
- **Why not pure derivation:** `.agents/skills/grugops/SKILL.md` belongs to both `codex` and `antigravity` (X1), so a ledger record cannot say which was chosen.

### Pattern 5: OpenCode permission merge (D-14)
**What:** a ledger-recorded, reversible splice into `opencode.json`, modeled on the ask-rules entry (`AskRuleLedger`).
- New target ledger kind (e.g. `opencode-permission`, path `opencode.json` only), recording: `pattern` (the exact string added), `createdFile`, `createdPermission`, `createdExternalDirectory`, `content` (sha256 of the `external_directory` object as install left it), and `fileMode` when the file was created. Add it to `LEDGER_KINDS`/`KINDS_BY_SCOPE.target`, `entryProblem`, `normalize`, `ledgerJson`, `HOLDING_KINDS`, `entryClaimsNothing` and the walk order (before `dir`).
- Pattern = `"~/" + posix(relative(homedir(), KIT_ROOT)) + "/**"` only when `KIT_ROOT` is under `homedir()` and the relative path holds no `*`, `?` or control byte. Otherwise write nothing and print a `note` quoting the rule to add by hand.
- **Refuse with a note** (not a counted verify; OpenCode still reaches, it just asks per read): a commented or trailing-comma file (strict tokenizer), a non-object `permission`, a string `external_directory` (`"ask"`/`"deny"`; converting it to a map would change text the user wrote), a duplicate key, or an existing `opencode.jsonc` with no `opencode.json` (do not create a second config file). If the object already has a rule for the same pattern, record nothing and change nothing.
- Append the new member **last** in the `external_directory` object ("last matching rule wins"), so a user's broader earlier `"*": "ask"` does not shadow it. If the user has a later, narrower `deny` matching the kit, it still wins, which is correct.
- Create path: `{ "$schema": "https://opencode.ai/config.json", "permission": { "external_directory": { "<pattern>": "allow" } } }`. The `$schema` value is `[CITED: opencode.ai/docs/config/]`. Whether to include it is discretion.

### Pattern 6: The checkbox picker (D-02)
**What:** a pure state machine plus a thin synchronous raw-mode shell.
```ts
// install/agent-picker.ts (pure: no fs, no process)
export type Key = "up" | "down" | "toggle" | "confirm" | "abort" | "other";
export function decodeKeys(bytes: Buffer, carry: string): { keys: Key[]; carry: string }; // buffers a split ESC sequence
export interface PickerState { readonly cursor: number; readonly checked: readonly boolean[] }
export function step(s: PickerState, k: Key, n: number): PickerState | { done: "confirm" | "abort" };
export function render(s: PickerState, names: readonly string[], firstFrame: boolean): string; // ANSI repaint
// Bytes: "\x1b[A"/"\x1bOA" up, "\x1b[B"/"\x1bOB" down, also "k"/"j"; " " toggle; "\r" or "\n" confirm; "\x03" abort.
```
I/O shell in install.ts. The same `readSync` + `EAGAIN` wait as `readlineSync`, wrapped in `try/finally` that **always** runs `setRawMode(false)` and shows the cursor (`\x1b[?25h`):
```ts
// Measured 2026-10-11, Node v26.11.0, macOS, under `script -q /dev/null`:
//   keys: "\u001b[B" " " "\u001b[A" "\r"       ← down, space, up, Enter
//   keys: "\u0003" "x" "y" "z"                   ← Ctrl-C arrives as a byte, no SIGINT
//   non-TTY: process.stdin.setRawMode is undefined
process.stdin.setRawMode(true);
try { /* loop: readSync(0, buf, 0, 16, null) → decodeKeys → step → stdout.write(render(...)) */ }
finally { process.stdin.setRawMode(false); process.stdout.write("\x1b[?25h"); }
```
- Gate: `process.stdin.isTTY && process.stdout.isTTY && !YES && SELECTED.size === 0`. `DRY_RUN` still shows the picker at a terminal (it changes no file); tests drive `DRY_RUN` without a TTY.
- Order: TARGET (existing prompt) → read marker and ledger → `installedAgents` and `detectTools` → picker → the `-- kit --` run. The picker must run **after** the `--check`, `--update`, `--prune-old-kit` early exits and the self-checkout and overlap guards, so a refused run never asks.

### Anti-Patterns to Avoid
- **Hand-listing flags, entry paths or footprints anywhere but the registry.** This is the set-literal drift class.
- **Deriving "installed" from presence on disk** (for example `existsSync(".agents/skills/grugops")`). That is DC-2. Only the ledger and the recorded field count.
- **Keeping the D-17 unconditional writes "for test coverage".** D-06 removes them. Coverage comes from all-agent variants (Pitfall 1).
- **Deleting by "agent was not named" in install.** Forbidden by D-04.
- **A product env var that injects picker keys.** It would be a hidden input channel. Test the pure module instead.
- **Writing `$ARGUMENTS`, `` !` `` or `@` sequences into the skill or command body** (Pitfall 8).

## Common Pitfalls

### Pitfall 1: The derived class tests stop covering per-agent paths
**What goes wrong:** `VARIANTS.default` runs `--yes` with no flag into an empty target. Under D-03 it refuses, or with a flag it writes only one agent's paths. The DC-2 never-installed and user-edit tests and the DC-3 special-files test then never plant at the other agents' paths (Phase 34 Pitfall 10, D-17's stated reason).
**How to avoid:** in `installer-paths.test-support.ts` derive `ALL_AGENT_FLAGS = HOST_TOOLS.map(agentFlag)` and pass it in every variant (the union of writes). Add one **per-agent** variant per registry row to prove "only that host's entry" (`writes(agent) ⊆ shared ∪ footprint(agent)`, count asserted). The test support may import `host-tools.js`.
**Warning signs:** a write-set count that drops, or a variant whose `run.status !== 0`.

### Pitfall 2: Every existing installer test turns red at once
**What goes wrong:** `runInstall` helpers (`installer-paths.test-support.ts:338`, `install.test.ts:381,596`) and about 30 raw `spawnSync("node", [INSTALL_JS, "--yes"…])` sites in `install.test.ts` (lines 662, 835, 864, 898, 915, 1068, 1088, 2397, 2445, 3058, …) pass no agent flag. Two product scripts do the same: `scripts/coordinator-resolution-precheck.ts:285` and `scripts/capture-live.ts:1616`, both `[INSTALLER, "--target", target, "--yes"]`.
**How to avoid:** land the D-03 refusal in the **same plan** that routes every spawn through helpers adding `ALL_AGENT_FLAGS` (or `--claude` where only Claude is under test). Add a census test: every spawn of `install.js` in tests either goes through a helper or carries an agent flag. The product scripts pass `--claude` (they exercise Claude Code adapters).
**Warning signs:** "names the per-agent flags to pass" in a test's stdout.

### Pitfall 3: The terminal is left in raw mode
**What goes wrong:** an exception, an early `return`, or Ctrl-C (byte `0x03`, no SIGINT in raw mode, as measured) exits with the TTY raw and the cursor hidden.
**How to avoid:** `try/finally` around the whole loop. Handle `0x03` as abort. Never call `process.exit` inside the loop; break, restore, then refuse.

### Pitfall 4: The shared `.agents/skills/grugops/SKILL.md`
**What goes wrong:** `uninstall --codex` deletes the file Antigravity still uses, or the per-agent write-set test asserts disjoint footprints and fails.
**How to avoid:** the owners-intersection rule (Pattern 4). Footprints may overlap; the test asserts `writes(agent) ⊆ shared ∪ footprint(agent)`, not disjointness.

### Pitfall 5: Pinned counts move
**What goes wrong:** new refusals add `process.exit(` sites. `install.test.ts:5706/5710` pins 9 and 10. `HOST_ADAPTER_KINDS` count tests, `routeCarriers` call-site pins (`host-tools.test.ts:731`), the reachVia/strandedBy table dimensions (`:793`), and the kit-route matrix host counts also move.
**How to avoid:** route the D-03 refusal, the empty-confirm refusal and Ctrl-C through **one** refusal function (one new exit site), and re-pin with the comment's reason in the same commit.

### Pitfall 6: A registry id collides with an existing flag
**What goes wrong:** a future row with id `check` or `update` would silently become a mode flag.
**How to avoid:** a collision test derived from the arg loop (Pattern 1).

### Pitfall 7: Detection pre-checks surprise the user
**What goes wrong:** `.github` (Copilot's detect) exists in almost every GitHub repo, so Copilot is pre-checked everywhere and an unattended first install (D-03 detected set) installs the Copilot pointer into most repos. `.gemini` pre-checks Antigravity for any repo with legacy Gemini wiring (v2.1 installs wrote it).
**How to avoid:** this is accepted D-03/D-13 behaviour, but the closing note must name each selected agent and say why it was chosen ("detected: .github"). Flag it for the human (Open Question 3).

### Pitfall 8: OpenCode template expansion inside the pointer
**What goes wrong:** OpenCode command bodies expand `` !`cmd` `` (shell output) and `@file` (inclusion) [CITED]. A future template edit containing either would run a shell command or inline a file on every `/grugops`.
**How to avoid:** the generator refuses a template body containing `` !` `` or an `@` followed by a non-space, with a test. Today's `KIT_ROUTE` and start-here sentence contain neither (read this session).

### Pitfall 9: "Behaves as today" is not literally possible
**What goes wrong:** D-03 promises an existing CI re-run behaves as today. Today's run writes Gemini settings (deleted by D-12) and the Pi template unconditionally (removed by D-06). v2.1.0 targets have no ledger, so they fall to detection.
**How to avoid:** state the actual mapping in CHANGELOG and README. Ledger installs from unreleased builds → `{claude, copilot, pi}` by legacy derivation (the entries they always wrote). v2.1.0 installs → the detected set (`.claude` → claude, `.github` → copilot, `.gemini` → antigravity, `.pi` → pi if present). Get human sign-off (Open Question 1).

### Pitfall 10: The live-host claims (DOC-1)
**What goes wrong:** README, CHANGELOG or notes say "Codex reaches the Orchestrator" from a `--check` reach line.
**How to avoid:** reach lines report files. Every live claim stays `UNKNOWN - verify` until the D-19 UAT row passes. Copilot is never claimed.

### Decoder for split escape sequences (sketch)
```ts
export function decodeKeys(bytes: Buffer, carry: string): { keys: Key[]; carry: string } {
  let s = carry + bytes.toString("latin1");
  const keys: Key[] = [];
  while (s.length > 0) {
    if (s[0] === "\x1b") {
      if (s.length < 3) return { keys, carry: s };                    // wait for the rest of ESC [ A
      const t = s.slice(0, 3);
      keys.push(t === "\x1b[A" || t === "\x1bOA" ? "up" : t === "\x1b[B" || t === "\x1bOB" ? "down" : "other");
      s = s.slice(3); continue;
    }
    const c = s[0]; s = s.slice(1);
    keys.push(c === " " ? "toggle" : c === "\r" || c === "\n" ? "confirm" : c === "\x03" ? "abort"
      : c === "k" ? "up" : c === "j" ? "down" : "other");
  }
  return { keys, carry: "" };
}
// A lone ESC that never completes: treat as "other" after the next read returns nothing new (discretion).
```
