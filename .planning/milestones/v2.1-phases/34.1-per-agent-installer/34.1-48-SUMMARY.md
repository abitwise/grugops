# Phase 34.1 Plan 48: Every printed command states its install mode and kit checkout (D-38, mode and checkout half) Summary

**scriptCommand now prints `GRUGOPS_HOME=<k> INSTALL_MODE=<copy|symlink> GRUGOPS_SRC=<checkout> node <install.js>` and `GRUGOPS_HOME=<k> GRUGOPS_SRC=<checkout> node <uninstall.js>`, and never `--symlink`. The follow-as-printed harness runs every printed command under conflicting INSTALL_MODE, GRUGOPS_SRC and TARGET values. R50 follows WR-25's mode reproduction to a copy install that stays a copy install.**

## Accomplishments
- **One builder change.** `CommandContext` holds `installMode` and a `src` path, never null, and `commandContextFromRecord` takes the mode from an `ok` record or from the run. `RunInvocation` loses `symlink` and `checkout`. The `ctx.src === null` and `ctx.symlink` branches are gone, so a sibling-search grep for them over install/*.ts prints nothing. The COMMAND_CONTEXT literals in install.ts and uninstall.ts, and the comments above them, now state D-38.
- **The harness can no longer hide the mode or the checkout.** `runPrintedCommand` sets INSTALL_MODE to the mode the text does not state. GRUGOPS_SRC is set to an empty scratch directory with no kit in it, and TARGET to an empty scratch directory. Only the printed assignments override them.
- **D-38's shape is checked before a command runs.** An install.js command must state all three words. An uninstall.js command must state GRUGOPS_HOME and GRUGOPS_SRC and no INSTALL_MODE. The printed GRUGOPS_SRC must match `expectSrc`, which is now the checkout path the row expects (this checkout when omitted) and no longer a boolean opt-in. The premise reports each conflicting value, what the child held before the printed assignments, and whether the conflicting TARGET is still empty.
- **R50 reproduces WR-25's mode half and follows the remedy as printed.** Every follow-as-printed row in the 13 targeted files now runs under the conflicting values and passes.
