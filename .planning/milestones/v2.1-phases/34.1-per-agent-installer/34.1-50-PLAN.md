<objective>
Close WR-24 under D-38: one `--check` run derived the kit home twice. Since round 3 its printed commands take the kit
home from the record (commandContextFromRecord), while its header, the kit-root cross-check, the stat checks and the
stale-adapter wording used the run's own. A plain `--check` on a custom-home install therefore FAILed "kit-root sources
DISAGREE (stale/moved install)" and kept failing after the printed remedy was followed. This plan makes the doctor read
one kit home, COMMAND_CONTEXT's, everywhere, and keeps a real stale or moved install failing.

Purpose: `--check` agrees with itself and with the command it prints.

The plan check (2026-10-13) asked that the fix be held by a class guard, not only by rows. A parser walk over every
function the doctor reaches, run while revising this plan, found one site the line search over doctor() missed:
transformAdapter (install.ts ~4570) writes KIT_ROOT, the run's kit root, into the KIT= line of the adapter the doctor's
stale-adapter compare renders. Under a plain `--check` on a custom-home Claude Code install every adapter therefore
reads as stale (a FAIL under `--strict`), and the printed re-install, which writes the recorded kit root, cannot clear
it. Task 3 adds the WR-24 census (D-38), shows it catches that site, fixes it, and records mutation proofs.

Output: the doctor reads one kit home; R52 and its controls; R52c; the WR-24 census with mutation proofs; the WR-21
row 1 premise inverted.
</objective>
