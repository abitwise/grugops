# Phase 34.1 Plan 03: Install-side Gemini deletion Summary

**Install no longer touches `.gemini/settings.json`. The merge, the `gemini-context-file-name` entry gate, the `gemini-settings` adapter kind, `entryGates` and the dead `hostsReading` export are deleted. The Gemini row now shares Codex CLI's `.agents/skills/grugops/SKILL.md`. A legacy `gemini` ledger entry is carried verbatim, and uninstall still reverses it from its record.**

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The red window starts at Task 1, not Task 2**
- **Found during:** Task 1
- **Issue:** Removing the `mergeGemini()` call means deleting mergeGemini, GEMINI_RECORD and GEMINI_SEEN (noUnusedLocals). That reds about 80 install-side tests that only Task 3 converts. The plan's per-task commit would therefore put a red commit on main, which the plan's own truth forbids.
- **Fix:** The fixture got its own commit (835bbf89). Everything else is one commit (91231f1d), made after the full regression.
- **Committed in:** 835bbf89, 91231f1d

**2. [Rule 3 - Blocking] scripts/generate-host-entries.ts edited**
- **Issue:** `ENTRY_SHAPES` is `Record<HostAdapterKind, …>`, so its `"gemini-settings"` key no longer compiles. After that change, host-tools-prose Rule B flagged the docblock for naming every host but Gemini.
- **Fix:** Deleted the key. Added one comment sentence saying the `.gemini`-detected row shares the agent-skill entry. The render is unchanged: `freshness:host-entries` still reports 3 entries with 0 byte differences.

**3. [Rule 3 - Blocking] Test files outside the plan's list**
- **Files:** installer-write-set, installer-special-files, installer-user-edit, installer-never-installed, ledger.test and mode-census.
- **Why:** They pinned the Gemini write or needed the legacy seed (see the table above).

**4. [Rule 1 - Consequence of D-20] AGENTS.md no longer strands any host**
- **Found during:** Task 3
- **Issue:** Eight kit-route cases had a premise that "AGENTS.md strands some host".
- **Fix:** They were re-derived, or given the user's own agent skill without the route, case by case (see the table). host-tools AGENTS_ONLY_COUNT is pinned at 0.

**Total deviations:** 4 (all blocking or consequential). **Impact:** no scope added beyond the deletion; coverage of the counted WARN/FAIL arms is kept.
