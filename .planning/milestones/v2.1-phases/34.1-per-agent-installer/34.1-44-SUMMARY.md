# Phase 34.1 Plan 44: D-37 core, the owner without a removal answer Summary

**The doctor and the installer no longer offer removing a marker they cannot read. Over the reviewer's trailing comma, `--check` names the cause and its line, says fix by hand and never delete the marker, and prints only the check command; followed as printed, the check passes and a flag-less uninstall removes everything. `markerRemedy` lost its removal answer: it returns `{ defect, fix }` or null, where `defect` comes from the new `MARKER_DEFECTS` list of what the reader reports. The skipped and left lines name the cause the reader saw through `markerDefectText`.**

## Decisions Made
See key-decisions in the frontmatter. In short:
- A throwing `?? noMarkerRemedy(site)` guard keeps each markerRemedy call in its own function.
- MARKER gets a narrower type, so no defect is invented for an unbound read.
- The field clause also names a missing field.
- A local `remedy` const keeps site labels out of printed string expressions.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] uninstall.ts built an unreadable read by hand**
- **Found during:** Task 2.
- **Issue:** `MARKER` folds an unbound read into `{ state: "unreadable", why, jsonObject }`. With `defect` and `problems` required, that no longer compiled, and giving it a defect would have invented a reader cause it never saw.
- **Fix:** a local `MarkerUse` type, whose unreadable arm holds only what every pass reads. Remedies read MARKER_READ.
- **Commit:** df92e96b

**2. [Rule 3 - Blocking] ledger.test.ts built an unreadable read by hand**

- **Commit:** df92e96b

**3. [Rule 1 - Bug, IN-33 class] The planned `field` clause named the wrong cause for a missing field**
- **Found during:** Task 3.
- **Issue:** installMarkerProblems also reports "no grugopsHome" and similar for a user's JSON object at the marker path. "a field in it holds a value install never writes" is false there, which is exactly IN-33's defect.
- **Fix:** the clause is "a field in it holds a value install never writes, or a field install writes is missing". It keeps the planned words as its prefix, so R44's field-only check is unchanged.
- **Commit:** 87eead65

**4. [Rule 3 - Blocking] installer-never-installed.test.ts pinned removeMarker's old JSON-object line**
