## The kit home and install mode a printed command carries (D-33, with the planner's reading)

D-33: "prefixes GRUGOPS_HOME=<dir> only when the run used a non-default kit home".
- install.ts, every mode (install, --check, --migrate, --update, --prune-old-kit): the run resolves GRUGOPS_HOME and
  uses it. The context's kit home is that value, null when it equals the default
  (canonicalPathSpelling(resolve(homedir(), ".grugops"))). In a doctor run given a kit home other than the one the
  marker records, the doctor already reports the kit-root disagreement; its printed commands carry the kit home the
  doctor itself used. The install mode is this run's INSTALL_MODE (`--symlink` or INSTALL_MODE=symlink), so a
  `--check` run made without `--symlink` prints copy-mode install commands; plan 34.1-23's README sentence says so.
- uninstall.js reads neither GRUGOPS_HOME nor INSTALL_MODE (its process.env reads are GRUGOPS_SRC, DRY_RUN and
  TARGET), and `--symlink` is an unknown argument to it (exit 2). So scriptCommand gives an uninstall.js command no
  prefix and no `--symlink`, whatever the context holds. The kit home and install mode uninstall.ts's own context
  carries (for the install commands it prints) are plan 34.1-24's.
