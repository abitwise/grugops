# Phase 34.1 Plan 06: Unattended agent selection Summary

**A flag-less unattended install now chooses the agents recorded in `.grugops/install.json` (new `agents` field), else a pre-34.1 install's Claude Code, Copilot and Pi, else the detected agents, and otherwise exits 1 before writing anything, naming every per-agent flag. Copilot is detected only by its instructions file.**

## Accomplishments

- `installedAgents(markerRead, ledgerRead)` in `install/install-marker.ts` is the one derivation of the installed set:
  - `recorded`: known ids in registry order, unknown ids split out.
  - `legacy`: an `ok` marker with an `ok` ledger and no `agents` field gives the hosts of `LEGACY_ADAPTER_KINDS` (`claude`, `copilot`, `pi`).
  - `none`: absent, unreadable, unbound (this includes v2.1.0 no-ledger markers) and malformed ledgers.
- `installMarkerProblems` refuses an `agents` field that is not a list of distinct ids matching `^[a-z][a-z0-9-]*$` ("agents is not a list of agent ids"). The marker then reads unreadable, so it fails closed.
- `install.ts` reads the marker once (`PREVIOUS_MARKER_READ`) and computes `SELECTION` right after `START_HELD_DIRS`, before `--migrate`. The order is: flags, then recorded or legacy, then `detectedHosts()`, then `refuseSelection`.
  - `refuseSelection(why)` is the single exit 1 for a selection refusal.
  - `writeMarker` records `agents: AGENTS_AFTER` between `target` and `ledger`. AGENTS_AFTER is the union of the agents installed before and the agents chosen now, followed by unknown ids.
  - The banner prints `agents: <name> (<reason>), …` after `tools detected:`.
  - A recorded unknown id gets a `note`.
- The Copilot row's `detect` is `.github/copilot-instructions.md`.
- `install/README.md` has a new section, "Which agents an unattended install is for". Exit-code row `1` names the refusal, and the CI example is `--yes --claude`.
