## Summary

Every mechanism this phase needs already exists on the tree and was exercised this session. The
generator is a self-contained top-level script whose only inputs are `agent-factory/roles`, a
four-module committed-`.js` import closure, and an optional `models` block resolved against a fixed
`ROOT`; `scripts/adapters-freshness.ts` already mirrors exactly that into a temp tree and spawns it.
I reproduced the mirror by hand with **four** twins plus `agent-factory/roles`, and it produced 17
adapters under zero config (`preset: none`, `aliases:["inherit"]`), 4×`opus`/13×`sonnet` under
`{"models":{"preset":"tiered"}}`, and **exit 1 writing nothing** with a named refusal on stderr for
an illegal alias and for an illegal preset. Total wall time for build-mirror-plus-spawn was measured
at **0.076 s**, so D-01 costs the install run nothing a user will notice.

The work is therefore not discovery — it is careful integration against a gate surface that is
unusually literal-pinned. Three tree facts change the plan's shape and none of them is in
CONTEXT.md: (1) the generator's import closure is **four** modules, not the five CONTEXT names —
`canonical-frontmatter.js` is not in it; (2) `install/install.test.ts` **pins the count of
`process.exit(` occurrences in `install.ts` at 6 code / 7 raw**, so any new abort path or any prose
that spells the call reds a case; (3) `scripts/model-dial-consistency.test.ts:1355-1363` asserts
`agent-factory/config/factory.config.md` still contains the strings `"Disclosed limitation"` and
`"Phase 29.2"`, so **D-15's prose rewrite reds that test unless it is edited in the same commit**.
A fourth fact bounds D-14: `scripts/adapter-byte-baseline.test.ts` freezes the committed adapters
against a pre-29.1 commit, so the banner slot **must not change one byte of generated output** — the
sentinel cannot be added to the generator, only recognised by the installer.

**Primary recommendation:** Replicate `scripts/adapters-freshness.ts`'s mirror shape inside
`install/install.ts` as a single private `renderAdaptersInMirror()` helper serving both the install
loop (D-01) and the `--check` doctor (D-09); keep `srcAdapterFiles(GRUGOPS_SRC)` as the install
**set** authority and use the mirror only as the **byte source** per member, asserting set equality
and the announced member count; report the installer's own refusals through the existing `verify()`
channel and add **no new `process.exit(` call**.

const KIT_ROOT = process.env.CHECK_ROOT ? process.env.CHECK_ROOT : SCRIPT_ROOT;

const tmp = mkdtempSync(join(tmpdir(), "grugops-adapters-fresh-"));

Notes on each element, for the install-side replication:

- **No `cwd` is set, and none should be.** The generator resolves `ROOT = join(import.meta.dirname,
  "..")` from its own location inside `<tmp>/scripts/`, so it writes to `<tmp>/.claude/agents` and
  reads `<tmp>/agent-factory/roles` regardless of the parent's working directory.
  [VERIFIED: scripts/generate-role-adapters.ts:143-145]
- **No `shell` option.** Keep `shell:false` (the default). See §10.
- **`agent-factory/packaging` is copied although the generator never opens it.** Keep copying it —
  the header at `:205-209` records why, and the cost is a handful of files.
- **`agent-factory/config` is deliberately NOT copied.** That is what makes D-06 true by
  construction: `readModelsConfig`'s second candidate cannot exist inside the mirror.
  [VERIFIED: scripts/model-tiers.ts:283-286 + the mirror layout above]
- **`mkdirSync(join(tmp, ADAPTER_DIR))` before the spawn.** The generator does `mkdirSync(OUT_DIR,
  {recursive:true})` itself (`:537`), so this is belt-and-braces; keep it.
- **Cleanup discipline.** `process.on("exit", cleanup)` registered the line after `mkdtempSync`, plus
  explicit `cleanup()` calls on every exit path. `install.ts` already registers no exit handler; the
  helper should own its own `try { ... } finally { rmSync(dir,{recursive:true,force:true}) }` so the
  installer's many call paths cannot leak a temp tree. `rmSync` with `recursive:true, force:true` is
  what the tree already uses everywhere. [VERIFIED: install/install.ts:773,1064,1082]

## 4. `materializeAdapter()` strip-then-inject mechanics

```ts
// install/install.ts:1091-1138 (structure, abbreviated)
function materializeAdapter(src, dest, label) {
  if (!existsSync(src)) { report("skipped", `${label} (source missing: ${src})`); return; }
  if (DRY_RUN)          { report("would-materialize", `${label} (KIT=${KIT_ROOT})`); return; }
  mkdirp(dirname(dest));
  const lines = readFileSync(src, "utf8").split("\n");
  const out = []; let inblk = false; let buf = [];
  for (const line of lines) {
    if (line === MAT_OPEN) { inblk = true; buf = []; continue; }
    if (inblk) { if (line === MAT_CLOSE) inblk = false; else buf.push(line); continue; }
    if (line === MAT_SLOT) { out.push(MAT_OPEN); out.push(`KIT="${KIT_ROOT}"`); out.push(MAT_CLOSE); out.push(line); continue; }
    out.push(line);
  }
  if (inblk && buf.length > 0) for (const line of buf) out.push(line);  // CR-01 bounded removal
  writeFileSync(dest, out.join("\n"));
  report("materialized", `${label} (KIT=${KIT_ROOT})`);
}
```

The three properties a second slot must preserve:

- **Whole-line equality, never a pattern.** `line === MAT_SLOT` and `line === MAT_OPEN`. The routing
  predicate `srcCarriesSlot()` (`install.ts:215-221`) uses `.split("\n").includes(MAT_SLOT)` — the
  header at `:212-213` says explicitly that routing and injection use the same test "so routing and
  injection can never disagree."
- **Bounded removal (CR-01).** An unterminated prior block is buffered and **restored** at EOF, so no
  content is ever swallowed. A second slot's stripper must carry the same bound.
- **Content-idempotence.** Strip every prior injected block first, then inject fresh; a re-run
  produces identical bytes.

### Where the second (banner) slot should live

**Do not add a sentinel to the generator's output.** `scripts/adapter-byte-baseline.test.ts` freezes
the committed adapters byte-for-byte against a commit pinned at 2026-08-19 and derives the file set

On Windows this resolves through `PATH` and `PATHEXT`; it works when `node.exe` is on `PATH`, which the runner guarantees, but it is a `PATH` dependency the installer does not otherwise have. | **Use `process.execPath`** — the absolute path of the running interpreter. No `PATH` lookup, no shell. |
| `shell:true` | Not used and must not be. `shell:true` on Windows routes through `cmd.exe`, which re-parses the path and would break on a temp dir containing a space (`C:\Users\First Last\AppData\Local\Temp\…`). | Keep `shell:false` (the default) and pass the script path as an argv element. |
| Path separators | Everything goes through `join()` from `node:path`, which emits `\` on Windows. The generator's own `OUT_DIR` and `readModelsConfig` candidates are built the same way (`join(repoRoot, ...rel.split("/"))`, `model-tiers.ts:1586`), so a POSIX-spelled constant still yields a platform-correct path. | Use `join()` everywhere; never string-concatenate a mirror path. Note `install.ts`'s `toPosix()` (`:130`) is applied to `GRUGOPS_HOME`/`KIT_ROOT` only, for byte-identical `KIT=` lines — do **not** apply it to mirror paths handed to `spawnSync`. |
| Temp dir | `mkdtempSync(join(tmpdir(), "grugops-…"))` — `os.tmpdir()` is correct on Windows. | Same prefix convention; use a distinct prefix (e.g. `grugops-install-render-`) so a leak is attributable. |
| Cleanup | `rmSync(dir, {recursive:true, force:true})` is what the tree uses. On Windows, a file briefly held open by an antivirus scanner can make `rmSync` throw `EBUSY`/`EPERM`. | Add `maxRetries: 3` (and optionally `retryDelay`) to the mirror's `rmSync`. `install.ts`'s existing `rmSync` calls do not use it; adding it on the new call only is a strict improvement, not a behaviour change elsewhere. |
| Line endings | `tsconfig.json` sets `newLine: lf`; adapters are written with `out.join("\n")` (`install.ts:1136`) and `lines.join("\n")` (`generate-role-adapters.ts:527`). | The byte-compare in D-09 is over bytes both sides produced with `\n`; no normalization is needed and none should be added. |
| Non-ASCII in the banner | The `PROVENANCE` literal carries U+2014 (`—`). Files are read/written as `utf8` throughout. | Read and write `utf8` explicitly, as `materializeAdapter` already does (`:1101`); never a default-encoding `Buffer` compare on the banner path. |

### Recommended structure inside `install/install.ts`

No new file. Everything lands in `install/install.ts` between `copyKit()` (`:1056-1085`) and
`materializeAdapter()` (`:1091`), so the render helper is declared above both call sites and above the
doctor's use of it. **The doctor branches at `:509`, which is ABOVE `copyKit` — so the helper must be
hoisted.** Two options, both legal:

- a `function` declaration (hoisted; `updateKitHome`/`copyKit` already rely on this — the `--update`
  branch at `:519` calls `updateKitHome()` declared at `:1330`), or
- move the helper up beside the other early helpers at `:231-273`.

**Prefer the `function` declaration**, matching the existing precedent recorded at `install.ts:517-518`
("The helper functions it calls (updateKitHome / copyKit) are hoisted declarations defined below").
Do **not** use a `const` arrow — the const temporal dead zone is the exact hazard `:231-236` documents.

### Pattern 1: One render authority, two consumers

**What:** a single `renderAdaptersInMirror(targetConfigPath: string | null): RenderResult` returning a
discriminated result (`{ok:true, dir, adapters, preset, assignment}` | `{ok:false, reason}`), never
throwing.
**When:** install (`:1468` loop) and doctor (`:463` WARN block).
**Why:** D-09's "one render path serves install and the doctor, so there is no second frontmatter
grammar in `install/`". The discriminated-result-never-throw shape is `model-tiers.ts`'s own
(`ModelsConfigResult`, `:1312-1315`) and `kit-source.ts`'s three-state contract.

### Pattern 2: Derive the set, assert the count

```ts
// the shape to copy, from scripts/adapters-freshness.ts:407-445
const extra   = committedNames.filter((n) => !rebuiltNames.includes(n));
const missing = rebuiltNames.filter((n) => !committedNames.includes(n));
if (extra.length > 0 || missing.length > 0) { /* name each member */ }
// ...and only then, over a provably set-equal pair:
if (assignment.value.roles !== rebuiltNames.length) { /* the announced count vs an independent derivation */ }
```
Applied here: `srcAdapterFiles(GRUGOPS_SRC)` is one side, the mirror's `.claude/agents` listing is the
other, and `assignment.value.roles` is the announcement. All three must agree; any disagreement is a
`verify()` finding naming the members.

### Pattern 3: Report, don't abort

`install.ts` finishes every other class and names the one it could not complete. The channel is
`verify()` (`:245-249`), which increments `VERIFY_FINDINGS`; the tail at `:1579-1650` prints
`== install INCOMPLETE — <n> item(s) need verification ==` and sets `process.exitCode = 3`.
**Never `process.exit()` — see §6 pin 1.**

### Anti-Patterns to Avoid

- **A `model:` regex in `install.ts`.** D-09 rejects it explicitly; it is a second frontmatter grammar
  on a new safety surface, which is what `canonical-frontmatter.ts` exists to prevent.
- **A generator-side output flag.** `OUT_DIR` is a fixed literal as a path-traversal mitigation
  (T-27-28, ASVS V12); the mirror exists precisely so no flag is needed.
- **Importing anything from `scripts/` into `install/`.** Path literals + `cpSync` are the boundary.
- **Making the mirror listing the install SET.** Keep `srcAdapterFiles(GRUGOPS_SRC)` — it is the same
  derivation `uninstall.ts` uses, and a narrower removal set than install set is a reversibility gap
  (the D-28/CR-02 defect, reproduced end-to-end once already).
- **Copying `agent-factory/config` into the mirror.** It would break D-06 and re-open the whole-file
  shadowing the docs warn about.
- **Re-authoring the generator's refusal sentence.** Relay `stderr`; add only the target path.

## Common Pitfalls

### Pitfall 1: The install set and the removal set silently diverge
**What goes wrong:** install lays down adapters derived from the mirror's output while `uninstall.ts`
derives its removal set from `srcAdapterFiles(GRUGOPS_SRC)`. A member in one and not the other
installs and never reverses.
**Why it happens:** the mirror's listing is the natural thing to iterate — it is the thing holding the
bytes.
**How to avoid:** iterate `srcAdapterFiles(GRUGOPS_SRC)`; use the mirror as a byte lookup; assert set
equality both directions and name every extra/missing member.
**Warning signs:** a `for (const f of rebuiltNames)` loop; a `readdirSync` of the mirror feeding the
install loop.
**Precedent:** this exact class shipped once — a symlinked source adapter installed by `install.js` and
never removed by `uninstall.js`, under `== uninstall complete ==` at exit 0. [VERIFIED: install/kit-source.ts:8-27]

### Pitfall 2: The banner slot matches zero lines and nobody notices
**What goes wrong:** the generator's wording changes; `install.ts`'s recogniser stops matching; every
target keeps a banner naming `node scripts/generate-role-adapters.js`, a command the target cannot
run — the exact thing D-14 exists to delete — and nothing goes red.
**Why it happens:** a hand-synced literal across a deliberate module boundary; the fix direction
(match nothing) is silent.
**How to avoid:** assert **exactly one** banner match per rendered adapter across all 17, refuse by
name on 0 or ≥2, and pin the spelling against `generate-role-adapters.ts`'s source text in a test.
**Warning signs:** an `if (matched)` with no `else`; a `.replace()` whose return value is not checked.

### Pitfall 3: Skip-if-identical hides a stale target
**What goes wrong:** D-11's skip compares the **rendered** bytes to the **target** bytes. If the
comparison is taken before the `KIT=` and banner slots are materialized, every re-run reports
"materialized" (never identical); if it is taken against the wrong side, a genuinely stale file
reports "skipped (identical)".
**How to avoid:** materialize into a buffer first, compare the **final** bytes against the target's,
then write only on difference. This is also exactly what D-09's like-for-like comparison needs, so one
function serves both ("The doctor's comparison is like-for-like: it materializes the `KIT=` and banner
slots into its temp render before comparing").
**Warning signs:** two different comparison sites; `sameContent(mirrorFile, targetFile)`.

### Pitfall 4: The illegal-config path writes a partial adapter directory
**What goes wrong:** the mirror exits 1 after some adapters were already laid into the target.
**Why it does not happen today:** the generator refuses **before** writing anything (`:293-310` runs
above the build loop; `:531-543` builds everything then writes). Measured: on both illegal inputs the
mirror's `.claude/agents` was untouched.
**How to keep it:** run the render to completion and check `status` **before** the first
`materializeAdapter` call into the target. Never interleave render and materialize.

### Pitfall 5: A new `process.exit(` reds a pinned count
See §6 pin 1. Also: do not write the literal `process.exit(` into a new comment in `install.ts` — the
raw count is pinned at 7 and the paragraph at `:1604-1609` explains that the scan is deliberately dumb.

### Pitfall 6: D-15's prose rewrite reds `model-dial-consistency.test.ts`
See §8. `expect(pointer).toContain("Disclosed limitation")` and `toContain("Phase 29.2")`. Edit the
test in the same commit; keep its deliberate no-wording-pin posture.

### Pitfall 7: A `.ts` edit ships without its `.js`
`scripts/freshness.ts` reads the committed side with `git show HEAD:<path>` and derives its set from
`git ls-tree -r HEAD`. A build step cannot repair it. `model-tiers.js`, `install.js` and any other
touched module must be rebuilt and committed in the same commit.

### Pitfall 8: The doctor renders from the wrong kit
See Open Question 3.

## Open Questions

1. **How does `install.ts` read the announced preset without importing `scripts/model-tiers.ts`?**
   - *What we know:* D-04 says to reuse the resolved-preset grammar `model-tiers.ts` exports rather
     than spelling a new literal. `install/` imports nothing from `scripts/` (D-18/D-28), and
     `model-tiers.ts`'s own header at `:288-297` says "neither site spells the marker."
   - *What's unclear:* the two rules are in direct tension for the installer.
   - *Recommendation, in preference order:*
     (a) **Do not parse the preset at all in `install.ts`.** D-04's banner needs *the resolved preset
     and the file it was read from*. The **file** is known to the installer independently
     (`TARGET/.grugops/factory.config.json`, or "no configuration file — resolved nothing"). For the
     **preset**, relay the generator's own announcement line **verbatim** into the run banner — a
     line the installer forwards but never parses. That satisfies "reusing the grammar rather than
     spelling a new literal" in the strongest sense: the installer holds no grammar at all. The
     per-adapter `(model=<alias>)` half comes from the rendered file's own `model:` line, which the
     installer already has as bytes it is about to write — no parse of a *config* is involved, though
     it is a read of a frontmatter line (see (b) if that is judged a second grammar).
     (b) If the plan needs the parsed values (for the member-count cross-check, which **does** need
     `assignment.roles`), spawn a **second one-liner** against the mirrored `model-tiers.js`:
     `spawnSync(process.execPath, ["-e", "<script that imports <tmp>/scripts/model-tiers.js and prints JSON>"])`.
     The grammar stays in `model-tiers.ts` and `install/`'s module graph is untouched.
     (c) Refuse and record: skip the member-count cross-check, relying on the set-equality check
     against `srcAdapterFiles`. **Not recommended** — CONTEXT.md's `<code_context>` names the count
     assertion explicitly, and "derive the set, assert the count" is the pattern the milestone exists
     to enforce.
   - **This needs a user/planner ruling before the first task is written.** It is the one place where
     two locked decisions point in different directions.

2. **Where does the banner sentinel live, and by which rule is the old line recognised?**
   - *What we know:* it cannot go in the generator (byte baseline); it is not in
     `agent-factory/packaging/subagent.frontmatter.md` today (`grep` returns nothing); a literal in
     `install.ts` would be a sixth hand-synced copy of a cross-boundary literal.
   - *Recommendation:* declare it once in `install.ts` beside `MAT_OPEN`/`MAT_CLOSE`/`MAT_SLOT`
     (`:183-185`), pin it byte-equal to `generate-role-adapters.ts`'s `PROVENANCE` by a case in
     `install.test.ts` that reads the `.ts` **source text** (the module cannot be imported — it
     writes 17 files at load, which is exactly why `coordinator-resolution-precheck.ts:107-112`
     restates its own copy), and assert exactly-one-match-per-adapter across all 17. Add the
     declaration to `subagent.frontmatter.md` as documentation only if the planner wants the upstream
     record; it cannot be the mechanical authority because no module can read markdown at install time
     without adding a parse.

3. **Which kit's `agent-factory/roles` does the DOCTOR render from — `GRUGOPS_SRC` or `KIT_ROOT`?**
   - *What we know:* install renders from `GRUGOPS_SRC` (which is also what `copyKit` ships to
     `KIT_ROOT`, so on a fresh install they agree). For a target installed from an older checkout they
     can differ, and the doctor already has a separate `kit-version skew` WARN for that
     (`install.ts:466-479`).
   - *Recommendation:* **render from `GRUGOPS_SRC`.** The finding D-10 emits names the remedy
     "re-run `node install/install.js --target <repo>` from this checkout", so the comparison must
     answer *"would that re-run change this file?"* — which is a `GRUGOPS_SRC` question. Say so in the
     finding's own wording, so a user reading a stale-adapter WARN beside a kit-version-skew WARN
     understands they are two views of one fact.

4. **Does `--dry-run` print the doctor's staleness verdict?** CONTEXT leaves this to the planner
   provided D-04's dry-run resolution report stands. *Recommendation:* no. `DRY_RUN` already prints
   `would-materialize … (KIT=…)`; extending it to `would-materialize … (model=<alias>)` satisfies
   D-04 and keeps the modes separate. Two verdicts in one run is a second report surface for the same
   fact.

### Known Threat Patterns for this change

| Pattern | STRIDE | Standard Mitigation |
|---|---|---|
| Path traversal via a config value reaching `OUT_DIR` | Tampering | Unchanged: `OUT_DIR` is `join(ROOT, ".claude/agents")`, a fixed literal; no output flag exists. The installer reads the mirror's output directory, it does not tell the generator where to write |
| Command injection through the spawn | Tampering / EoP | `shell:false` (default) + `process.execPath` + a `join()`-built script path. **Never** pass a target-derived string as an argv element or through a shell |
| Symlink attack on the temp mirror | Tampering | `mkdtempSync` under `os.tmpdir()` with a mode-0700 directory; `cpSync` writes only into it |
| Temp-tree accumulation (slow DoS on the host) | Denial of Service | `try/finally rmSync({recursive,force,maxRetries})`. `adapters-freshness.ts:166-180` records the reproduced leak this closes (T-27-117) |
| Writing through a live symlink into a source clone | Tampering | The existing `--migrate` LANDMINE pre-step at `install.ts:894-926` unlinks symlinked adapter destinations before materializing. The new render changes the SOURCE, not the DEST, so this control is unaffected — **confirm with `install.test.ts:1262`** |
| Env-var inheritance pointing the render back at the tree under judgement | Tampering | `adapters-freshness.ts:240-246` deletes `CHECK_ROOT` from the child env for exactly this reason. The generator honours **no** env override today (`generate-role-adapters.ts:143`, `:87-97`), so the install-side spawn needs no deletion — **but record the rule**: if a future revision adds any resolution-affecting variable, it must be deleted from the child env by name |
| A refused config silently downgrading to `inherit` | Repudiation | D-03/D-11 forbid it: the generator refuses hard and writes nothing; the installer relays the refusal and reports INCOMPLETE at exit 3 |
