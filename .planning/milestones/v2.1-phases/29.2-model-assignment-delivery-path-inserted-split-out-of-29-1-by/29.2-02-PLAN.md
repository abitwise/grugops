<objective>
Make the write idempotent and visible, make the target's banner true, and make `--check` able to say
that a configuration edit has not reached the adapters yet.

`materializeAdapter` gains a second content-idempotent slot for the GENERATED banner and a
skip-if-identical comparison taken over the FINAL bytes; the `--check` doctor reuses plan 01's one
render authority to byte-compare every target adapter against a fresh render and names each stale
file. A block of structural pins closes the two silent-set hazards the design carries: a twin list
that could go one short, and a banner recogniser that could match nothing.

**No requirement is new or re-opened.** This plan continues the installed-target delivery half of
MODEL-01 through MODEL-05.

Purpose: a re-run must be a visible no-op and a refresh a visible change; a stale target must be
detectable without reading bytes by hand.
Output: the second slot, the skip-if-identical writer, the staleness verdict, and the pins.

<planner_ruling id="R-2" reversibility="reversible">
**Where the banner recognition rule lives (RESEARCH Open Question 2).**
Whole-line equality against a constant declared in `install/install.ts` beside the existing
materialization sentinels, pinned byte-equal against `scripts/generate-role-adapters.ts`'s
`PROVENANCE` **source text** by a case in `install/install.test.ts` (the generator module cannot be
imported - it writes seventeen files at load). The sentinel is NOT added to the generator, because
`scripts/adapter-byte-baseline.test.ts` freezes the committed adapter bytes against a pinned commit.
It is NOT declared in `agent-factory/packaging/subagent.frontmatter.md` either: that file carries no
such string today, nothing can read markdown at install time, and adding it would create a sixth
hand-synced copy of a cross-boundary literal with no mechanical reader - the exact drift class this
milestone exists to delete. The count floor is what closes the silent direction: exactly one match
per rendered agent adapter, refused by name on zero or on two or more.
Rejected: an anchored prefix rule (a second, weaker grammar over the same bytes); a generator-side
sentinel (moves frozen bytes).
</planner_ruling>

<planner_ruling id="R-3" reversibility="reversible">
**Which kit the doctor renders from (RESEARCH Open Question 3): `GRUGOPS_SRC`.**
The remedy the staleness finding names is a re-run of install from this checkout, so the comparison
must answer the question "would that re-run change this file?" - which is a `GRUGOPS_SRC` question,
not a `KIT_ROOT` one. The finding's own wording says so, so a reader meeting a stale-adapter WARN
beside the existing kit-version-skew WARN understands the two are views of one fact.
</planner_ruling>

<planner_ruling id="R-4" reversibility="reversible">
**D-16's flagged item: the `--allow-self` arm is recorded, not fabricated.**
The pinning test covers the DEFAULT arm - a source-shaped fixture carrying a `models` block is
refused before any render happens. The `--allow-self` arm is bypassed by design, and
`--allow-self --target <the real checkout>` is a user action outside any test's reach; a test that
pretended to prove it would be a false claim. The case's own comment records that the arm relies on
the CI backstop - `npm run freshness:adapters` pinned to a zero-config resolution plus
`guard_model_assignment` - and names both by name.
Rejected: extending the `--allow-self` arm with a source-shaped fixture and calling the resulting
green a proof; adding a zero-config pin inside the install render for a path the guard already blocks.
</planner_ruling>
</objective>
