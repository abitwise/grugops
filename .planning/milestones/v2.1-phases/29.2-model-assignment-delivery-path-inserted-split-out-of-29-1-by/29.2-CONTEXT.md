# Phase 29.2: Model Assignment Delivery Path - Context

**Gathered:** 2026-09-03
**Status:** Ready for planning

<domain>
## Phase Boundary

A `models` block written into a target repository's `.grugops/factory.config.json`
changes the `model:` line of the 17 Claude Code sub-agent adapters that repository's
session loads from `.claude/agents/grugops-*.md`. This closes the disclosed limitation
Phase 29.1 shipped with ("a per-repo `models` block is inert for an installed target").

In scope: the install-time render of a target's adapters from the target's own config
(via the installer, `install/install.ts`), the `--check` doctor's staleness assertion,
per-adapter idempotent reporting, a target-true GENERATED banner, the removal of the
29.1 "inert" disclosures from kit prose, and the CHANGELOG entry this reachable
behaviour change owes.

Out of scope: any change to the resolver, the alias set, the preset table or the
refusal contract (all shipped and gated in 29.1); `--update` writing into a target;
shipping the generator's import closure into `$GRUGOPS_HOME`; a second preset; any
measured cost claim (D-14/D-16 stand); the four non-Claude-Code host CLIs (MODEL-06
stands); per-checkpoint autonomy (Phase 30).

**No requirement is new or re-opened.** This phase completes the delivery half of
MODEL-01 … MODEL-05 for installed targets. 29.1's D-01/D-02/D-03 were dropped by D-17
and are **re-decided from scratch below** against the three tree facts the roadmap
records; nothing here inherits from them.

</domain>

<decisions>
## Implementation Decisions

**Facts every decision below was taken against (verified on the tree 2026-09-03):**

- `install/install.ts` lays every adapter through `materializeAdapter()` (~line 1091),
  which `writeFileSync`s unconditionally and injects only the `KIT=` line above the
  `MAT_SLOT` sentinel. All 17 adapters carry the slot, so `INSTALL_MODE` never reaches
  an agent adapter and the old D-03 symlink divergence does not exist.
- The adapter loop (~lines 1451/1472) runs before `seedState()` (~line 1555), and the
  seed carries **no** `models` key, so a freshly seeded target resolves to `inherit` in
  every case.
- `--update` is kit-home-only by its own D-05 and never touches a target's adapters.
- `install/kit-source.ts:29` records that `install/` deliberately does **not** import
  `scripts/kit-model.ts`; `install.ts` imports nothing from `scripts/` at all.
- The committed `.js` twins the generator needs (`scripts/generate-role-adapters.js`,
  `scripts/model-tiers.js`, `scripts/kit-model.js`, `scripts/frontmatter.js`,
  `scripts/canonical-frontmatter.js`) exist in the checkout (`GRUGOPS_SRC`), not in
  `$GRUGOPS_HOME`. `scripts/adapters-freshness.ts` already mirror-spawns that generator
  into a temp tree and reads its resolved-preset line back out of stdout.
- `readModelsConfig` reads `.grugops/factory.config.json` then
  `agent-factory/config/factory.config.json`, first-existing-file-wins-whole.
- The `--check` doctor (~line 376) reads only the adapter's `KIT=` line, never
  frontmatter; it has a WARN tier promoted to nonzero under `--strict` (~line 492).
- `install/uninstall.ts` removes adapters by **derived name** over the kit source
  (`srcAdapterFiles`), never by content, so a per-target rendered adapter is still in
  the removal set.
- `--allow-self` / `--force` (line 96) overrides the D-07 self-checkout guard.

### Generation site and the coupling boundary

- **D-01: Install mirror-spawns the committed generator against the target's config.**
  The installer `cpSync`s the generator's committed `.js` import closure, the kit
  sources the generator reads (`agent-factory/roles`, `agent-factory/packaging`) and —
  when it exists — `TARGET/.grugops/factory.config.json` (placed at
  `<tmp>/.grugops/factory.config.json`) into a temp tree, `spawnSync`s the mirrored
  generator, reads the 17 rendered adapters out of `<tmp>/.claude/agents`, and lays each
  into the target through `materializeAdapter()`. The spawn is the boundary:
  `install/` still imports nothing from `scripts/`, so `kit-source.ts`'s decoupling is
  **preserved, not reversed**, and the generator remains the **one renderer** of the
  `model:` line. `OUT_DIR` stays a fixed literal with no output flag (T-27-28 intact).
  Rejected: an install-side `model:` slot rewrite fed by a new `model-tiers.js --resolve`
  CLI (a second emitter of the model line plus a new CLI surface); importing
  `model-tiers.js` into `install.ts` (couples the installer to the `scripts/` layout by
  reversing a recorded decision for no gain the spawn does not give).
  — **Reversibility:** costly — every target installed under this path holds adapters
  the copy path cannot reproduce, and D-06/D-07/D-09 all hang off the render existing.
- **D-02: The render runs from the checkout only.** `GRUGOPS_SRC` is always present
  because install is invoked as `node install/install.js` from it. A target refresh is a
  re-run of install from the checkout. `copyKit` ships nothing new into
  `$GRUGOPS_HOME`, and the kit-home / uninstall mirror contracts are untouched.
  Rejected: copying the twins into `$GRUGOPS_HOME` so a refresh could run without the
  checkout (widens the kit-home contract and its reversal for a convenience nobody asked
  for).
- **D-03: An illegal target `models` block refuses the adapter class by name.** The
  generator's all-or-nothing posture (T-27-32, D-11) carries through the spawn: no
  adapter is written, the finding names the role, the offending value and the legal set,
  the run exits nonzero, **every other install class still completes and is reported**
  (kit-source's report-don't-abort contract), and any adapters already in the target are
  left exactly as they were. Rejected: writing `inherit` adapters with a WARN (the
  silent-downgrade shape D-11 rejects for the generator); aborting the whole install
  (strands a user over one config key).
- **D-04: The run reports the resolution.** The run banner names the resolved preset
  **and the file it was read from**, reusing the resolved-preset grammar
  `scripts/model-tiers.ts` exports rather than spelling a new literal; each per-adapter
  report line carries the model it was rendered with; `--dry-run` performs the read-only
  resolution and reports `would-materialize … (model=<alias>)`. A run that resolved
  nothing states that it resolved nothing.

### Ordering and which config is resolved

- **D-05: The four-step sequence is not reordered.** copyKit → adapters → seedState →
  marker stays as pinned. The mirror receives `TARGET/.grugops/factory.config.json`
  **only if it already exists**; when it is absent the generator's own zero-config path
  produces `inherit` for every role — the same answer the seeded file gives, since the
  seed carries no `models`. The roadmap's ordering conflict therefore dissolves: a fresh
  install never has a non-`inherit` answer to miss, and a re-run always sees the file.
  Rejected: moving `seedState()` ahead of the adapter loop (reorders a sequence
  `uninstall.ts`, the report ordering and the tests all mirror, for an invariant D-05
  already delivers).
- **D-06: The mirrored generator resolves against `TARGET/.grugops/factory.config.json` and nothing else.** The mirror never receives an in-kit
  `agent-factory/config/factory.config.json`, so `readModelsConfig`'s second candidate
  cannot fire inside a target and the whole-file-wins shadowing the docs already warn
  about cannot recur there. Rejected: honouring a vendored `agent-factory/config` in the
  target.
- **D-07: `--update` stays kit-home-only.** It does not gain a target-adapter refresh.
  The kit states, in clear voice, that a `models` edit — or a kit-side adapter change —
  reaches an installed repository by re-running
  `node install/install.js --target <repo>` from the checkout.
- **D-08: The seed keeps `models` absent.** Zero-config first: absent resolves to
  `inherit`, and `agent-factory/config/factory.config.md` §`models` documents the block.
  Rejected: seeding `"models": {"preset": "none"}` for discoverability (a new field every
  fresh install carries, for a dial the docs already name).

### Staleness after a config edit

- **D-09: `--check` re-renders through the same mirror path and byte-compares.** The
  doctor runs install's render (D-01) into a temp directory — including the `KIT=`
  materialization, so the comparison is like-for-like — and compares every target adapter
  byte-for-byte against the fresh render, **naming each stale file**. One render path
  serves install and the doctor, so there is no second frontmatter grammar in `install/`
  and no hand-listed expectation; and because it compares whole files it catches a stale
  kit-side adapter as well as a stale model line. The temp write is outside the target,
  so the doctor still mutates nothing there. The doctor's expected side is a fresh
  render and its actual side is the committed target file, so the two sides do **not**
  move together — this is not the CR-01 regenerate-and-compare shape D-12 rejected.
  Rejected: a provenance block plus config hash (proves the config changed, not that the
  adapter is wrong); parsing the `model:` line with a regex in the doctor (a second
  frontmatter grammar).
- **D-10: A stale adapter is WARN by default and FAIL under `--strict`**, matching the
  doctor's existing contract. The finding names the stale files and the re-run remedy.
  Rejected: always FAIL.
- **D-11: `materializeAdapter()` becomes skip-if-identical, with a rewrite reported by name.** An identical render reports `skipped (identical)`; a differing one reports
  `materialized … (model=<alias>)`. A re-run is then a visible no-op and a refresh a
  visible change, matching `linkOrCopy`'s existing identical-copy report. Rejected: the
  unconditional write (a refresh is indistinguishable from a no-op in the output).
- **D-12: No provenance block is added to a target adapter.** The byte-compare is the
  record; the `model:` line is the only per-target byte the model dial contributes.

### Ownership of installed adapters

- **D-13: A target's installed agent adapter files are kit-owned derived artifacts.** (`.claude/agents/grugops-*.md`) A differing target adapter is rewritten on re-run and reported by name; a
  hand-edited `model:` line is lost, deliberately — the config is the one place to set
  it. This is the fact already on the tree made explicit, and CLAUDE.md's
  never-overwrite rule protects user content, which a generated file marked "do not
  hand-edit" is not. Rejected: `materializeRunnable`'s never-overwrite-when-differing
  contract (a `models` edit could then never reach an adapter someone once touched, and
  the doctor would WARN forever).
- **D-14: The GENERATED banner is materialized target-true.** Today it names
  `node scripts/generate-role-adapters.js`, which does not exist in a target. Install
  rewrites that line — a second slot handled like `KIT=`, strip-then-inject, content-
  idempotent — to name the install re-run and `.grugops/factory.config.json` as the model
  source. The kit's committed adapters keep the generator wording. Nothing in a target
  may name a command the target cannot run.
- **D-15: The 29.1 "inert for an installed target" disclosures are rewritten to current truth, and a `CHANGELOG.md` `### Changed` entry ships.** Sites: `scripts/model-tiers.ts`
  header (§"SCOPE, AS OF PLAN 29.1-02"), `agent-factory/config/factory.config.md`
  §"Disclosed limitation", and any other kit-facing prose a grep for the disclosure
  finds. A stale disclosure is a false claim in the kit, so kit prose states what is true
  now. Annotate-never-rewrite continues to apply to verifier records, ROADMAP phase
  records and CONTEXT files. The changelog entry is owed under the WR-03 ruling's own
  terms: this is a reachable, observable behaviour change. Rejected: annotating in place
  (a reader meets a refuted sentence first).
- **D-16: D-04 of 29.1 (the kit's own committed adapters stay `inherit`) is protected by the D-07 self-checkout refusal, pinned by a test.** Install refuses to target its own
  checkout, so the kit's committed adapters can never be rendered from a target config
  through this path. The planner adds a test binding that refusal to this contract.
  **Flagged, not decided:** `--allow-self` / `--force` overrides that guard. The freshness
  gate (`scripts/adapters-freshness.ts`, pinned zero-config by 29.1 D-04) and
  `guard_model_assignment` remain the CI backstop that goes red if a committed adapter
  ever changes; the planner decides whether the pinning test also covers the
  `--allow-self` arm or records it as relying on that backstop. Rejected: an extra
  zero-config pin inside the install render (machinery for a path the guard already
  blocks).

### Claude's Discretion
- The temp-tree layout, cleanup and Windows spawn handling — follow
  `scripts/adapters-freshness.ts`'s proven shape, including its `mkdtempSync` /
  `rmSync` discipline and its hand-tracked twin list.
- How the doctor reports when the checkout's committed `scripts/*.js` twins are missing
  (a partial checkout): a named finding in the doctor's existing voice; never a silent
  "no stale adapters".
- Whether `--dry-run` also prints the doctor's staleness verdict — planner's call,
  provided D-04's dry-run resolution report stands.
- Exact finding and report wording — clear professional voice throughout; this is an
  installer and a money-adjacent dial.

## Existing Code Insights

### Reusable Assets
- **Mirror-spawn harness** (`scripts/adapters-freshness.ts`): cpSync twins + kit sources
  into a temp tree, spawnSync the mirrored generator, read results and the resolved-
  preset line out. D-01 (install) and D-09 (doctor) are the sixth and seventh uses. The
  one new input is the target's config file dropped at `<tmp>/.grugops/`.
- **`materializeAdapter()` strip-then-inject** (`install/install.ts`): the content-
  idempotent slot mechanism D-14 extends to a second slot and D-11 makes skip-if-identical.
- **`linkOrCopy()`'s `sameContent` identical-copy report**: the report shape D-11 adopts.
- **Doctor WARN tier + `--strict`**: the severity contract D-10 slots into.
- **The three stdout grammars in `scripts/model-tiers.ts`**: D-04's banner reuses the
  resolved-preset reader; nothing new is spelled.

### Established Patterns
- **One authority per predicate; delete the second grammar.** The generator renders
  `model:`; the installer and doctor spawn it rather than re-implementing any part of it.
- **Report, don't abort** (`kit-source.ts` fail-loud contract): the installer finishes
  its other classes and names the one it could not complete (D-03).
- **Named refusal over silent skip**: every refusal names the member and the legal set.
- **Derive the set, assert the count**: the 17 rendered adapters are read from the
  mirror's output directory, never listed by hand; the count is asserted against what
  the generator announced (`RESOLVED_ASSIGNMENT_PREFIX` carries the member count).
- **A green suite is not proof of a safety invariant**: the install path is a
  delivery mechanism for a money-adjacent dial; expect code review plus adversarial
  reproduction before the phase is called complete (see memory of P22–P29 bypass logs).
- **Annotate-never-rewrite is scoped** (D-15): verifier records, ROADMAP phase records
  and CONTEXT files are annotated; kit prose states current truth.

### Integration Points
- `install/install.ts` adapter loop → replaced by "render into temp, materialize each
  rendered adapter into the target" (D-01); `materializeAdapter()` gains skip-if-identical
  (D-11) and the banner slot (D-14); banner + per-adapter report (D-04); the `--check`
  doctor gains the staleness compare (D-09/D-10).
- `agent-factory/packaging/subagent.frontmatter.md` — if the banner slot needs a stable
  sentinel line, it is declared once here (the single upstream source for adapter body
  shapes), not spelled in install and in the generator separately.
- `scripts/model-tiers.ts` header, `agent-factory/config/factory.config.md`,
  `CHANGELOG.md` — D-15 prose.
- `install/install.test.ts` — new cases: fresh install resolves `inherit`; re-run after a
  `models` edit rewrites and reports; illegal block refuses the class and leaves other
  classes complete; `--check` names stale adapters (WARN / `--strict` FAIL); idempotent
  re-run reports skipped-identical; self-checkout refusal pinned to this contract (D-16).
- `install/uninstall.ts` — expected unchanged; confirm by test that per-target rendered
  adapters are still removed by derived name.

<specifics>
## Specific Ideas

- The install mirror places the target's config at `<tmp>/.grugops/factory.config.json`
  and never places an `agent-factory/config/` file, so the generator's first candidate is
  the only one that can exist inside the mirror.
- The doctor's comparison is like-for-like: it materializes the `KIT=` and banner slots
  into its temp render before comparing, so a current adapter compares byte-equal.
- Report wording for the model must carry the alias exactly as resolved (one of the four
  legal aliases), never a full model id.
- The `--allow-self` override of the self-checkout guard is a known reach-around for
  D-16; the CI freshness gate and `guard_model_assignment` are the backstop and are
  named as such wherever D-16's test records its scope.

</specifics>
