<objective>
Gap-closure round 4 (the last round under the cap). This is the WR-01 regression created by 33-25:
`promoteAdmitted` reads the destination through the now-seal-filtered `readRawNotes` walk, so an
UNSEALED occupant at the destination id is invisible to the `destination-id-occupied` clause. The
route then appends a GOV-02 `re_bound: true` event for a human-disposed high-severity finding and
ONLY THEN fails at `writeNoteFile` because the destination holds different bytes. The audit trail
records a finding the store does not hold, and a later legitimate promotion of that id appends
nothing. 33-VERIFICATION.md reproduced this against the committed `scripts/context-io.js`
(dest ledger lines 1, occupant byte-unchanged, `readContext(dest)` = 0 notes).

This is round-4 must-fix set item 3. The fix is the review's prescription: decide occupancy from the
raw file, not from the admitted view — occupancy is a fact about the filename. The same fix applies
to `admitAndAppend`'s gated branch, which also appends the ledger before the chokepoint.

Gap mapping (33-VERIFICATION.md gap 5 `missing` and `regressions[WR-01]`):
- "Decide destination occupancy from the raw file at `{to}/{task}/notes/{id}.md` before any ledger
  read/append; extend CONTROL 2b with the ledger assertion; apply the same to admitAndAppend's gated
  branch" -> Tasks 1-2.

Decisions honored: the 31-18 CR-11 invariant ("the decline is taken before the write chokepoint;
nothing was written"), restored for unsealed occupants; the 31-21 CR-12 bound (a non-regular file at
the note path is a named refusal, never a wedge); the 33-25 seal (the READER still refuses unsealed
notes — this plan does not weaken that; it only decides occupancy differently).

Purpose: the audit trail never records a disposition the store does not hold, on either write route,
whatever the occupant's seal.
Output: the raw-file occupancy read on both routes, CONTROL 2b's ledger assertion, and the
legitimate-input re-run proving no new refusal.
</objective>
