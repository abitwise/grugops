<objective>
Close the two remaining actionable findings from `31-REVIEW.md` that neither blocker plan owns, and the
one Warning the round-3 verifier singled out as compounding the CR-08 blocker.

`31-14` fixes the Claude-Code half of the compaction defect: a legitimate human-adjudicated finding is
no longer wrongly refused on promotion. **WR-15 is the same defect's other half, in the opposite
direction, on the other four hosts.** `trustedRepoRoot()` answers the Claude Code project-directory
variable, else the kit's own install root. Under the shipped two-root install that is `~/.grugops`,
whose only configuration is the shipped lean default. So on Codex, Gemini CLI, OpenCode and Copilot CLI
— the four hosts D-12 identifies as the ones where the attended lane is absent by design and the
in-script refusal is therefore the ONLY tier available — the refusals Workflow 16 promises are
evaluated against a dial that says `off`, whatever the target repository's configuration says. The
verifier reproduced it directly as spot-check row 6: the same promotion that the Claude-Code path
wrongly REFUSED is wrongly ADMITTED with the variable unset, because the dial was never read.

That is not an edge case under the shared-install model this project ships. It is the primary path on
four of five supported hosts, and it makes UATX-01's evidence floor conditional on which CLI happened
to launch the agent.

This plan also closes WR-16 (a doc comment describing a mechanism the function does not have, in a
Tier-1 oracle whose entire doctrine is that the claim matches the mechanism) and IN-08 (that same
oracle writing admission-ledger lines into whatever host project the ambient root resolves to — a
consequence of the very root resolution this plan changes, which is why the two move together).

Purpose: leaving WR-15 open would ship a round whose fix helps one host and leaves the other four in
the opposite failure. This repository's own recorded pattern is that the defect reappears one register
over; WR-15 is that register, already measured.

Output: a documented, single-place resolution order for the trusted governance root with the previous
behaviour as its final step, a monotonicity proof and a control, a corrected oracle docstring, an
explicit lean root for the oracle's writes, and a qualified sentence in Workflow 16.

**Ordering note:** wave 3 and `depends_on: ["31-14"]` because this plan and `31-14` both modify
`scripts/context-io.ts` and `scripts/context-io.test.ts`; sequencing them removes the conflict and lets
this plan's monotonicity control run against a tree where the proof-gated route already exists.
</objective>
