<objective>
Give the write path ONE authority for "which repository owns this action", shaped so a consumer
cannot fall open, and separate the governance-DIAL root from the LEDGER root so a caller-supplied
destination can no longer decide whose configuration adjudicates an admission.

Two Criticals, one module, one generator:

- **CR-26 (UATX-01)** — `admitAndAppend`'s gated branch (`scripts/context-io.ts:5399`) derives its
  ledger root with a nullish fallback onto the caller's `repoRoot`. When `contextRoot` does not
  resolve to a governed store the record lands in the caller's repository while the note lands in the
  ungoverned one — the split CR-22 was raised on, still reachable, on the route
  `agent-factory/workflows/18-context-compaction.md` names by hand as writing both together. The
  sibling `promoteAdmitted` refuses that identical shape by name. One fix, two arms, two opposite
  dispositions.
- **CR-27 (UATX-01)** — `promoteAdmitted`'s fall-through (`scripts/context-io.ts:2577`) passes the
  derived destination into `appendNote`'s single `repoRoot` parameter, which `admit()` uses for the
  governance-dial read as well as the ledger record. Reproduced: a trusted root whose own
  configuration is deliberately unparseable — the shape D-14 requires a fail-closed refusal for —
  REFUSES when the destination is the caller's own store and ADMITS when the destination names a
  different, permissively-configured store.

Both are the same defect one level up from the code: round 7 installed its rule as an EXPRESSION AT A
CALL SITE. An expression at a call site is a place where the next consumer chooses its own fallback,
and eight rounds of this phase have now shown that the next consumer does. The fix removes the
freedom: one authority, a discriminated answer with no null member, two separate parameters for the
two separate questions, and the rule consumed at the one point where a second half is actually
written.

Purpose: the shared verified context is this project's only memory between agents. A human-disposed
finding whose audit record lives in another repository is a record that cannot be trusted at the
moment it matters, and a governance dial a caller can re-aim is not a dial.
Output: the `actionOwnerRoot` authority; a ledger-owner parameter on `appendNote`, `admit` and
`admitAndAppend` distinct from the dial root; a deliberate `admit()` unfreeze with a dated record and
a re-baselined `ADMIT_FROZEN_SHA256`; a full four-arm cross-product probe; decision `D-39` recorded.
</objective>

<assumption_delta_decision>
The advisory detector fires on this phase's scope, and there IS a genuine delta in this round — not
the one the detector's snippets quote (those are prior-round narrative), but the one CR-26 and CR-27
between them measure.

**The noun that is now primary: the GOVERNANCE-DIAL ROOT.** Until this round, one parameter named one
repository and answered two questions — whose governance configuration adjudicates the admission, and
whose audit trail records it. Round 7 demonstrated, and round 8 reproduced, that those are two
questions: aiming the record moved the dial with it. So "the repository" has stopped being one noun.

**Decision: `promote`, not `add-alongside`.** The DIAL root is promoted to the primary identity — it
is `WR-10`'s ONE trusted answer every tier asks, it keeps the parameter position and the name it
already has, and it decides where nothing lands. The LEDGER address is demoted to a detail of the
particular action: a second parameter, defaulting to the answered owner of the store the note lands
in, that no caller may use to influence the dial. Adding a second co-equal root parameter and letting
each caller decide which one governs is precisely what produced CR-27; the generalised intent is that
one of the two is trusted and the other is merely addressed.

**The companion invariant test is not optional here, and it is already in the plan.** Task 3's
four-arm cross product is the contract test for the generalised intent: it goes red the instant a
future round re-collapses the two roots onto one parameter, or lets a caller-supplied value answer the
dial at any arm. `31-40`'s derived census is the second half — it goes red the instant a new call site
supplies either root from a value its own inputs do not derive.
</assumption_delta_decision>
