Round 4 fixed the modifier ban's membership. Round 4's fix created CR-09 and CR-10. Round 5 fixed the

language. A block-scoped function declaration was handed the whole module's range. A `using`
declaration was classified as hoisting. A fixture exemption was granted at a position wider than the
map it exempts for. The scenario body was read from a fixed argument index the framework's own
documented overload set contradicts.

Every one of the nine members of `UNRESOLVABLE_CALLEE_RESIDUALS` ends with the same phrase: *without a
type checker.* The target repository is REQUIRED to ship `typescript` — that is D-13, and it is why
`loadTypeScriptFromTarget` exists. The runnable already loads that module. Its checker API resolves
aliases, block scope, hoisting, cross-file re-exports, destructured bindings, and the declared type of
a callback parameter regardless of which argument position it sits in. **A banned call becomes one
whose resolved symbol is a Playwright modifier by IDENTITY, not by spelling.** The census
(`deriveDeclaredBindings`, `resolveBinding`, `listHoists`, `bindingRangeFor`,
`enclosingFunctionLike`), the fixture-position exemption (`isFixtureBindingPosition`), the fixed-index
body read (`deriveTestInfoParameterNames`) and the chain-step bound are all DELETED — not patched —
because each exists only to approximate an answer the checker gives exactly.

The failure direction is decided in the same edit and it is not a degrade. Today a parser lacking
predicates makes the resolver quietly fall back to the pre-D-18 rule — a weaker ban, applied without
saying so, which is RR-07 and which is a gate lowering rather than a disclosed limit. After this plan,
a target repository whose `typescript` cannot create a Program exits through the D-28 could-not-run
boundary with exit 2 and its own named reason. A check that could not run has made no claim about the
specs, and it never silently makes a smaller one.

Purpose: stop deciding a safety ban by spelling. Decide it by identity, with the authority the target
repository is already required to ship.

Output: symbol-identity resolution replacing five deleted hand-authored predicates; a program-creation
failure routed to exit 2; four now-true could-not-run reasons; a REWRITTEN and SHORTER
`UNRESOLVABLE_CALLEE_RESIDUALS`; a corpus carrying every evasion spelling from rounds 1 through 6;
corrected recipe passages; and decision **D-30** appended to `31-CONTEXT.md`.

the plan most likely to leave one.

<assumption_delta_decision>
**Decision: `promote`.** The assumption-delta scan surfaces the pluralization directly: "the second
callback parameter" was the singular noun the fixture derivation was built around, and Playwright's
own overload set makes it plural — the body is argument 1 in one form and argument 2 in another, and
the TestInfo parameter follows it. This plan PROMOTES the type-based identity to primary: the body is
whichever argument the checker says is the scenario callback, and the TestInfo binding is whichever
parameter has TestInfo's declared type. The positional noun is not kept alongside — it is deleted,
because keeping a positional rule beside a type-based one is exactly the two-grammars shape this
repository keeps paying for. The scan's other two signals are already decided as D-14 and D-21.
