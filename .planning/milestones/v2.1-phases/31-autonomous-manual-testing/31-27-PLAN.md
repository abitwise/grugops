Round 5's `31-21` closed CR-12 by extracting one non-blocking regular-file reader in
`scripts/context-io.ts` and routing the note-write chokepoint, the ledger look and the configuration
reader through it. That closure is real and is re-measured here as a control. What it did not do is
carry the rule to `hooks/hook-entry.ts` — the file `hooks/hooks.json` names, the process the host
actually spawns for every `Bash` tool call and every `mcp__grugops__*` call. `verifyDeciderClosure`
hashes thirteen agent-writable manifest paths with a bare blocking read, and it does so BEFORE the
`spawnSync` that `DECIDER_TIMEOUT_MS` bounds. One `mkfifo` at any of those thirteen paths therefore
wedges the PreToolUse guard itself: measured, `timeout 12` → EXIT=124, zero bytes of stdout, zero
bytes of stderr, against a control that returned EXIT=0 immediately. A hook that does not answer does
not block, and this is the tier that decides whether a force-push or a deploy pattern runs at all.

This is the SIXTH consecutive round in which a fix landed in the module the finding named and the
next Critical appeared at the coordinate the fix did not reach. So the fix here is a property of the
wrapper rather than a second habit inside it: **the wrapper performs no unbounded operation before it
can answer.** Two edits establish it. The manifest reads go through one inline non-blocking
regular-file reader with a stated ceiling — restated inline because this file may import only `node:`
builtins, and bound to the module's own reader by a derived two-member cardinality and one shared
corpus driven through both. And the fd-0 payload read is DELETED: fd 0 is inherited by the child, so
a host that opens the pipe and never closes it now stalls a process `DECIDER_TIMEOUT_MS` already
bounds, and the existing `child.signal !== null` branch answers for it with no new code path.

Tier 0 is the other half. Every member of `TRUSTED_ROOT_RESIDUALS` ends with the same criterion — a
root the calling process cannot influence, resolved by the host from outside the agent's process
tree, delivered through a channel the agent cannot write. On Claude Code that channel exists and this
plan uses it: the host builds the environment of the hook subprocess, the wrapper is byte-frozen, and
the wrapper hash-verifies the decider before the decider runs. The wrapper reads `CLAUDE_PROJECT_DIR`
from its own host-built environment, canonicalises it, shape-checks it, and delivers it to the decider
under a name it sets itself. Tier 0 is strictly narrower than the tier 1 it precedes — today tier 1
accepts any non-empty string — and that is MEASURED by a differential case rather than argued.

Purpose: make the PreToolUse wrapper answer in bounded time on every input it can be given, and give
the governance root a tier whose delivery channel the agent cannot write on the one host where such a
channel exists.

Output: an inline non-blocking regular-file reader in the wrapper with a named refusal; the wrapper's
fd-0 read deleted and fd 0 inherited into the timed child; a derived two-implementation parity axis in
a new `scripts/nonblocking-reader-parity.test.ts`; a canonicalised module-own exclusion; an exported
`hostDeliveredRoot` tier 0 with `TRUSTED_ROOT_TIERS`; a `hosts` field on every
`TRUSTED_ROOT_RESIDUALS` member; a re-taken `FROZEN_HOOK_ENTRY_LOGIC_SHA`; a `.temp/**` test-runner
