## Deviations from Plan

**1. [Rule 1 - Harness bug] The note position's ordinary outcome is made reachable by IDENTICAL BYTES, not by a fresh note id alone**

- **Found during:** Task 1, MOVEMENT 2.
- **Issue:** The plan (and `31-REVIEW.md`) prescribed "a fresh, unoccupied note id per run" so the ordinary case would be a `write`. Measured, that is not sufficient: the CONTROL shape plants a regular file AT the note path derived from whatever id is chosen, so a fresh id relocates the collision rather than removing it. An empty file at a fresh id draws the same `destination already holds a DIFFERENT note` refusal.
- **Fix:** The fresh id is implemented as specified (and is the right hygiene), and the reachability is delivered by `writeNoteFile`'s own decided identical-bytes arm — the CONTROL plants the exact note the driver is about to write, composed by driving the real writer once into a throwaway store rather than by restating its format anywhere.
- **Files modified:** `scripts/check-platform-shapes.ts` (`freshNoteId`, `composeOrdinaryNote`).
- **Verification:** The composition was measured deterministic across two runs (162 bytes, byte-identical) before being relied on; `composeOrdinaryNote` throws rather than returning bytes if its own drive does not produce a `write`. The note-position CONTROL rows now read `ordinary outcome (correct)` and go red under the seam.
- **Committed in:** `d6f2164`.

**2. [Rule 1 - Harness bug] `verdict === "answered"` does not discriminate at the manifest position**

- **Found during:** Task 1, MOVEMENT 1.
- **Issue:** `driveHookEntry` computed `verdict = r.status === 0 ? "answered" : …`, and the wrapper exits 0 both for the decider's own decision and for its own fail-closed deny. A positive assertion against a predicate that cannot see the failure is the same class one register over.
- **Fix:** The verdict classifies which tier answered (`no-answer` / `signal=…` / `status=N` / `fail-closed` / `answered`), reading the wrapper's own fail-closed marker; the premise that the marker OCCURS in the committed `hooks/hook-entry.js` is asserted in `main`, and a second premise asserts the classifier produced more than one verdict class at that position on this run.
- **Files modified:** `scripts/check-platform-shapes.ts`.
- **Verification:** Under the STALE_CONTROL seam the manifest rows report `verdict=fail-closed, expected answered`, and the discrimination premise fires unprompted as a fifth failure.
- **Committed in:** `d6f2164`.
