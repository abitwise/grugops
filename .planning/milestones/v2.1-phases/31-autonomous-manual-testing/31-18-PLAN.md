<objective>
Close CR-11, WR-17 and WR-18 of `31-REVIEW.md` — a Critical the round-4 verification classified as a
REGRESSION introduced by this phase's own previous gap-closure round, plus the two Warnings that make
it reachable and that make one route disagree with another about the same rule.

**CR-11 is the most severe finding of the round, and it is in code that did not exist before `31-14`.**
`promoteAdmitted` was built to close round 3's CR-08, and it does — independently re-verified. But it
takes its write id from `sourceId`, an argument, where every other writer in the module derives its id
and can therefore only ever ADD a file. It never reads the destination. `writeNoteFile` checks only
path containment and `atomicWrite` renames onto whatever is there. The verification reproduced the
consequence directly: a legitimate `observation` admitted into a shared destination context the normal
way was silently replaced by a forged `finding` carrying a fabricated `human:mallory` stamp, under the
same id, with the same id returned, no exception, no diagnostic, and no admission check reached at all.
The original note's text and provenance are gone from the permanent audit trail — not superseded, not
folded out by replay, deleted. This is reachable WITHOUT an adversary: promoting into a destination that
already carries the origin note rewrites the destination file with no diagnostic.

**WR-17 is why no forgery is needed.** The proof's left operand is `readRawNotes(task, from)`, and
`from` is an ordinary unvalidated parameter. A caller who authors a directory and names it produces any
proof it wants. The route's own header says the only thing that skips the frozen human-stamp arm is a
proof over bytes that ALREADY EXIST at the origin; that sentence is not true of the mechanism, and it
is the sentence a future reader will rely on — which is exactly the claim-matches-the-mechanism contract
this phase is being held to.

**WR-18 is one rule with two answers.** The route reads the governance configuration only to ask whether
it is READABLE; `human_admission`'s value has zero occurrences in the function body. So under `off` and
under an absent config — the lean default this project ships and the posture most repositories run — the
route carries a `human:NAME` stamp forward that `admitAndAppend`'s W3 arm refuses on the identical note,
on the explicit ground that accepting it would forge a `disposed_by` audit record.

Purpose: UATX-01's floor is that an agent's narration or self-supplied claim never becomes evidence.
Round 4 found that floor reachable through the newest writer this phase's own gap-closure round
introduced. Fixing only the reviewer's probe shape would be the fifth round of this pattern; the fix
must close the class at the point of effect and derive the axis nobody drove.

Output: an append-only invariant enforced at the write chokepoint; a named `destination-id-occupied`
decline clause with the idempotent case decided rather than defaulted; a derived refusal-family axis
that exercises every writer against a pre-existing destination; a constrained proof operand with what
is deliberately left open named as a residual; the dial's VALUE consulted through the one gated
authority under a derived dial set; a decided disposition for the no-ledger premise; and a dated
sub-decision extending D-19.

**Ordering note:** wave 3 and `depends_on: ["31-17"]`. This plan and `31-16`/`31-17` all modify
`.planning/phases/31-autonomous-manual-testing/31-CONTEXT.md`, and this plan and `31-19` both modify
`scripts/context-io.ts`, `scripts/context-io.js` and `scripts/context-io.test.ts`. Sequencing removes
both conflicts — the same serialization `31-14` used behind `31-13` for the same shared decision file.
