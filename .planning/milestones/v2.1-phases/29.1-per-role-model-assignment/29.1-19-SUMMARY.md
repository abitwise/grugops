## The synthetic inputs, in prose

**The appended-step workflow** (`withAppendedStep`, both reader files): the
committed `ci.yml` text, then `STEP_MARKER` itself — not a hand-typed `- name:`
line, so the input and the bound's needle cannot drift apart — then the synthetic
step name, then a `run: |` block whose single command is one the gate block
**already runs**. The bounded read must return the committed occurrence count; the
unbounded read returns one more.

**The prefix-spelled reader** (`(r-class-prefix)`): three lines of source text
locating the block by `ci.indexOf(<prefix>)` and slicing by `<prefix>.length`,
with the prefix injected from `UBUNTU_BLOCK_STEP_PREFIX` via `JSON.stringify` so
the input cannot drift from the predicate measuring it. The old exact-name
predicate does not count it; the new prefix predicate does.

**The assembled consumer** (`(o-one-consumer)`): a root read from
`process.env.CHECK_ROOT`, escaped into a local through the tree's own regex-escape
idiom, 400 bytes of unrelated code, the local concatenated with a boundary into a
second local, and that second local handed to `new RegExp(`. What follows
`new RegExp(` is `pattern`, not `ROOT`, so the 300-byte forward window sees
nothing.
