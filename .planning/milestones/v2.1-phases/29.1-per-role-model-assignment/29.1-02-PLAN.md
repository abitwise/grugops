<objective>
Give every role a tier and a reason, and make every illegal input a named refusal.

This plan turns the tracer's zero-config resolver into the full mechanism: the shipped
`tiered` preset with a rationale required by the type (D-08, D-09, D-10), the closed preset
name set (D-07), the two-location config read (D-05), the unknown-role-key refusal (D-06),
and the illegal-alias refusal split by consumer (D-11).

Purpose: MODEL-03 says the role-to-tier map is derived against `listRoles()` with an asserted
count, so role 18 cannot arrive silently unassigned — the set-literal drift class that caused
the Phase-23 spawn defect (7 granted names, 0 adapter files). MODEL-04 says only four aliases
are legal, because a full model id rots into exactly that stale literal. Both are one
mechanism here: a table whose type requires a reason, whose cardinality is pinned two-sided,
and whose membership is exact string equality against four constants.

The config key shape is a ONE-WAY decision — `models` becomes a published config-dial
contract, and changing its shape afterwards needs a migration in `install --migrate` and
breaks every repo already carrying the block. Task 1 is a blocking decision checkpoint for
exactly that reason.

Scope note: D-01, D-02 and D-03 are OUT OF SCOPE and moved to Phase 29.2 by D-17. No
install-side file is read for modification, changed, or tested here.

Output: `scripts/model-tiers.ts` complete, with its committed `.js`, and a test file whose
every corpus is derived at run time.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-editable `factory.config.json` → resolver | Untrusted JSON from a file any user may hand-edit crosses into a build-time process |
| resolved alias → emitted frontmatter | A resolved value becomes YAML the Claude Code runtime parses |
| config-derived role key → derived stem set | A user-supplied string is compared against a filesystem-derived set |
