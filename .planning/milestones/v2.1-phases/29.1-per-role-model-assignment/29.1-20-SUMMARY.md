## `citableForm` — the one declared canonical form, and both call sites

```ts
function citableForm(line: string): string {
  return line.replace(/`/g, "").trimEnd();
}
```

Its docstring states that it is a declared form and not a parser, that it does nothing beyond
stripping inline code delimiters and normalising trailing whitespace, and that if a future citation
cannot be brought under it the remedy is to change the citation's **spelling**, not to widen the form.

**Both call sites, and there are only these two — one per side, inside one function:**

```ts
function unlandedCitations(authorityText: string, citedSurfaceText: string): string[] {
  const forms = new Set(sectionHeadingsIn(citedSurfaceText).map(citableForm));
  return sectionCitationsIn(authorityText).filter((cited) => !forms.has(citableForm(cited)));
}
```

The heading side and the citation side go through the **same** function in the **same** expression.
There is no second normalisation anywhere in the file. (The injectivity case calls `citableForm`
again, over the same heading set, to count the forms — that is the floor below, not a second grammar.)

Measured on the live tree:


## The citation reader's bound, and its named throw

`sectionCitationsIn` locates `` `###  `` and ends at the closing `` ` ``, throwing by name rather
than running to end of file. Proven as a **permanent assertion** on an in-memory scratch string with
the close removed:

```ts
expect(() => sectionCitationsIn("…the `### unclosed sub-fields section of that document.")).toThrow(
  /UNCLOSED SECTION CITATION/,
);
```

The throw it catches:

> model-dial oracle: UNCLOSED SECTION CITATION — an inline code span opening "`### " at offset N is
> never closed by "`". Refusing to read to end of file: an unbounded citation adopts the rest of the
> document and then matches, or fails to match, on text nobody wrote as a citation. Remedy: close the
> span.
