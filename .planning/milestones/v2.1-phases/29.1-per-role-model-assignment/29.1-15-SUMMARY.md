Both orders were built and the WHOLE oracle executed under each, with per-case results captured to
file and diffed:

| Order | Cases | Failed | Per-case diff vs the other order |
|-------|-------|--------|----------------------------------|
| A — Floor 0 (preset) then Floor 0b (overrides) | 100 | 0 | — |
| B — Floor 0b then Floor 0 | 100 | 0 | `diff` printed nothing |

**Measured result: NO existing case moved under either order.** Recorded as the measured result
rather than left unstated. The reason is structural rather than lucky: every case carrying a bad
preset hands over no overrides, and every case carrying overrides hands over a legal preset, so the
two floors are disjoint over the suite as it stands.

The one input that distinguishes them is a caller with BOTH defects:

```
ORDER A dual-defect caller => model-tiers: null is not a legal preset name. The legal set is
                              exactly: "none", "tiered".
ORDER B dual-defect caller => model-tiers: the overrides argument is null rather than a Map of
                              role stem to alias. An AB…
```

**Order A was chosen.** A caller with two simultaneous defects receives the PRESET finding, because
the preset decides which base map is built and the overrides are applied on top of that base —
reporting the topping before the base would name the second mistake first. The source comment states
this as a claim about which of two refusals is returned, explicitly NOT as a guarantee about either
floor's reach.
