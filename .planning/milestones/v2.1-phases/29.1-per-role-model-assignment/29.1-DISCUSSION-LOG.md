## Delivery path

**Scout finding presented first:** `install/install.ts` copies the kit's already-generated
adapters into the target and the generator never runs there, so a per-repo `models` block is
inert. (An initial statement that adapters are symlinked by default was corrected in-session:
copy is the default per D-05, `--symlink` is opt-in.)

| Option | Description | Selected |
|--------|-------------|----------|
| A — install-time generation | Install mirror-spawns the generator against the target's resolved config; config→adapter becomes a derivation; `--symlink` + non-default `models` gets a named arm; zero-config stays byte-identical | ✓ |
| B — post-install regeneration | Install keeps copying; user re-runs the generator. Cheapest, but a stale adapter is silent | |
| C — kit-level only | `models` lives in the kit config at `~/.grugops`; one machine, one tier map | |

**User's choice:** A.
**Notes:** The mirror-spawn shape from `adapters-freshness.ts` keeps `OUT_DIR` a fixed literal
with no output flag, so the T-27-28 path-traversal posture is untouched rather than relaxed.

## Preset assignment + rationale

**Framing presented:** MODEL-03 names three strong and three cheap roles, leaving 11 of 17
unassigned, while the asserted-count clause requires all 17 carry a position and a reason.
A naming objection was raised unprompted: `"preset": "cost"` is itself a cost claim, which
MODEL-07 forbids shipping unmeasured.

| Option | Description | Selected |
|--------|-------------|----------|
| `opus` ×4 / `sonnet` ×13, no `haiku` | orchestrator, architect-design, security-nfr, compliance-officer on opus; avoids a thin tier on roles whose output degrades past the gate rather than into it | ✓ |
| Literal to MODEL-03: `opus` ×3 / `haiku` ×3 / `sonnet` ×11 | Follows the requirement's wording and exercises all three aliases | |
| `opus` ×5 / `sonnet` ×12 | As recommended plus incident-responder on opus | |

**Notes:** `incident-responder` recorded as the genuinely arguable assignment — time pressure and
blast radius coincide, but the role is procedural and hands to a named human. Left on `sonnet`
with the reasoning recorded so it can be disputed.

## Refuse vs degrade + guard home

**Framing presented:** MODEL-04 and MODEL-05 read as contradictory but describe different inputs;
MODEL-05's "never to a *pinned tier*" implies a fallback path, and that path is a reader rather
than the generator.

| Option | Description | Selected |
|--------|-------------|----------|
| Split by consumer | Generator refuses hard on present-but-illegal; other readers degrade to `inherit`; absent stays `inherit` | ✓ |
| Degrade everywhere, report loudly | Nothing blocks; a user's intended tier silently is not applied | |
| Refuse everywhere | Strictest; a stale config can hard-fail the tool needed to fix it | |

| Option | Description | Selected |
