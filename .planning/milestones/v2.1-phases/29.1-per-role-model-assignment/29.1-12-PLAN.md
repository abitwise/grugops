<objective>
Close R2-CR-01, the round's only blocker and the only finding that moves the phase score.

`scripts/check-foundation-guards.ts:374-376` takes `ROOT` from `process.env.CHECK_ROOT` verbatim —
no `resolve()`, no absoluteness check, no refusal. `:1917-1925` compiles that value into a global,
unanchored regex with no requirement that a path separator follow the matched root. With
`CHECK_ROOT` set to a relative value the pattern degenerates into "any period followed by
non-whitespace, anywhere in any rendered line", and the helper built to keep absolute paths OUT of
a published verdict instead deletes bytes from a real, correctly-resolved path.

Reproduced on this tree, independently, twice — by the round-2 reviewer and again by the round-2
verifier: `CHECK_ROOT=. node scripts/check-foundation-guards.js` exits 0 and publishes a green PASS
line naming a configuration file that does not exist. The same helper is applied to `config.reason`
and `resolution.reason`, so a FAILING verdict's refusal text can be corrupted the same way, sending
an operator to a fabricated file name.

This is the WR-08 defect class — a verdict that misdescribes the run it performed — reintroduced by
the very fix (plan 29.1-09, the IN-02 closure) that closed WR-08. It survived 442 passing tests
because every planted mirror in the suite constructs its root with an absolute path, so no case in
the repository can see it. MODEL-05 regressed from Complete to Gaps Found on exactly this.

This plan leads the round because it is the one closure that moves the score, and because every
later plan that re-touches this file must build on a fixed `relativeToRoot` rather than race it.

Output: a guard whose verdict describes the run it performed under every documented invocation
shape, proven by an equality a mutation can break in either direction.
</objective>
