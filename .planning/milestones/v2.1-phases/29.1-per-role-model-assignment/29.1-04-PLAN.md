<objective>
Give the emitted model value a second opinion that cannot move with the generator.

`adapters-freshness.ts` regenerates and byte-compares. Both of its sides come from the same
generator over the same tree, so it proves determinism: a generator that emitted a pinned tier
for all 17 roles, with the committed adapters updated in the same commit, passes it. That is
structurally the CR-01 defect Phase 29 spent rounds on — a check that parses components out of
a run and compares them to a tally over the same live document.

`guard_model_assignment` is independent because of its INPUT, not its algorithm. It reads the
committed adapter bytes on disk, which the generator's run does not touch, admits them through
the canonical admission reader, and compares each declared value against a resolution computed
fresh from the config and the derived role set. `adapters-freshness` proves the bytes are a
faithful regeneration; this guard proves the regeneration's value is the config's. Neither
substitutes for the other, and the guard's header says so.

Per D-15 the reader is `admit()` from `scripts/canonical-frontmatter.ts`, not
`scripts/frontmatter.ts`. D-12 named the latter "the one authority", which was true of the tree
before plan 27-65; `guardReferentialIntegrity` reads through `admit()` today, and
`canonical-frontmatter.ts`'s own header states that the eleven-round parser's reach must not be
inherited onto a new safety surface. D-15 follows D-12's intent — one authority per predicate,
no second grammar — and changes only which module that authority is. `CANONICAL_SCHEMA` already
carries `model` and `model` is not in `DOUBLE_QUOTED_KEYS`, so all four aliases admit as plain
scalars unchanged: no schema change.

Scope note: D-01, D-02 and D-03 are OUT OF SCOPE and moved to Phase 29.2 by D-17. No
install-side file is read for modification, changed, or tested here.

Output: one new guard, registered in the ordered run block, with four planted mutations proven
RED by name.
</objective>
