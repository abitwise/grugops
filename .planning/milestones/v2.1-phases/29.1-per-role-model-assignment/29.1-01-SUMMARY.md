## Decisions Made

- **`ModelAlias` is derived from the `MODEL_ALIASES` tuple** rather than declared twice. A union member absent from the tuple would be an alias the type system accepts and the membership check refuses — a rot direction that reads as a bug in the caller.
- **`render()` is observed by mirror-spawn with a substituted twin, not by import.** `generate-role-adapters.js` is top-level script code that writes 17 files and calls `process.exit` on import, so `render` cannot be imported at all. The substitution exercises the shipped path end to end rather than an exported fragment of it.
- **One `stemOf` rule in the generator.** The resolved map is keyed by one stem expression and read by another; a disagreement would surface as a lookup that quietly found nothing rather than as an error.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The `ROLE_COUNT` floor was moved out of `resolveModels` into its own named predicate**

- **Found during:** Task 3 (wiring the resolver through the generator)
- **Issue:** Task 2's behavior block specified that `resolveModels` refuse "a stem set whose length is not `ROLE_COUNT`". Implemented literally, this refused **22 committed test cases** immediately. The adapter generator runs over hermetic **mirrors** carrying a **subset** of the role corpus — its own suite mirrors six roles, and `adapters-freshness.ts` plus the foundation-guard harnesses mirror whatever tree they are judging. Reproduced directly: a six-role mirror returned `model-tiers: the stem set holds 3 stem(s) against the kit authority's ROLE_COUNT of 17` and exited 1. A smaller set is **correct** there, not broken.
- **The deeper reason it was wrong:** it is a **second authority** for a predicate that already has one. `listRoles` itself does not assert `ROLE_COUNT` — verified by reading it, it refuses only an EMPTY corpus — and the two-sided cardinality is asserted by `guard_kit_counts` over the LIVE tree. The copy inside a shared resolver fires where the stronger one correctly does not, which is the shape this repository's own rule ("delete the second authority rather than teach it a case") exists to refuse.
- **Fix:** `resolveModels` keeps the EMPTY floor and the DUPLICATE floor — both properties of its own input, decidable without knowing the live tree — and the cardinality relationship became `roleCorpusCardinalityRefusal(stems): string | null`, a named export that consumers judging the live corpus ask out loud. The full argument, including the measurement, is recorded in the function's own doc comment so a later reader finds it rather than rediscovers it.
- **What still satisfies D-05:** D-05 requires that "role #18 cannot arrive unassigned". `resolveModels` assigns a value to **every** stem it is handed, so on any tree — live or mirrored — an eighteenth role is assigned rather than skipped. From plan 29.1-02, when `TIERED` carries per-role rows, the binding check becomes the strictly **stronger** "every stem has a row", which names the unassigned stem instead of reporting a number that disagrees, and which is correct on a mirror as well.
- **Files modified:** `scripts/model-tiers.ts`, `scripts/model-tiers.js`, `scripts/model-tiers.test.ts`
- **Verification:** a new case pins the accepting direction (`resolveModels ACCEPTS a MIRROR-SIZED subset`); the refusing direction moved to `roleCorpusCardinalityRefusal` with both numbers still named; a second new case pins that the predicate accepts the live corpus, so it is not simply always-refusing.
- **Committed in:** `c79849f`
- **FLAGGED FOR THE REVIEWER:** this changes a behavior the plan specified explicitly, and it constrains how plan 29.1-02 builds the preset check. Carried as coverage item **D5** with `human_judgment: true`.

**2. [Rule 3 - Blocking] `model-tiers.ts` imports only `ROLE_COUNT`, not `listRoles`**

- **Fix:** import `ROLE_COUNT` only, and record in the module header why `listRoles` is deliberately absent. The key link's intent is preserved exactly: the role-set authority remains the only source of stems (the generator derives them through `listRoles`; `model-tiers.test.ts` derives its corpus the same way), and there is **no private readdir** anywhere.
- **Files modified:** `scripts/model-tiers.ts`
