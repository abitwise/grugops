canonical-spelling class check bounded what a file *contains* and not what its reader *computes*.

## Critical Issues

### CR-01: `resolveModels`'s refusal path still THROWS — and plan 21 added a throw where there was none

**File:** `scripts/model-tiers.ts:1196-1233` (and the identical `scripts/model-tiers.js:1000-1035`)

**Issue.** Plan 21 made `quoteValue` total for the rejected **value** and deleted the second
spelling. It left the **key** side of the same two template literals untouched:

```
`model-tiers: the override for role "${stem}" is ${quoteValue(alias)}, …`
`model-tiers: the override names the role stem "${stem}", which is not one of the …`
```

`overrides` is a `Map`, whose keys are `unknown` at run time on hosts (the module's own standing
argument: "the declared type above is advisory at run time … a floor that holds only under `tsc`
is not a floor"). A `symbol` key, or an object key with a throwing `toString`, throws out of the
refusal — the exact defect R3-WR-02 named, at the other position.

Reproduced against the committed `scripts/model-tiers.js` at HEAD:

```
resolveModels(stems, {preset:'none', overrides: new Map([[Symbol('x'), 'opus']])})
  -> TypeError: Cannot convert a Symbol value to a string
resolveModels(stems, {preset:'none', overrides: new Map([[Symbol('y'), 'nope']])})
  -> TypeError: Cannot convert a Symbol value to a string
resolveModels(stems, {preset:'none', overrides: new Map([[{toString(){throw new Error('boom')}}, 'opus']])})
  -> Error: boom
```

The first case is a **regression this round introduced**. Verified against `model-tiers.js` at
`e9907f5`:

```
OLD SYMKEY-LEGAL {"ok":true,"value":{}}        <- silently skipped by `if (!value.has(stem)) continue;`
NEW SYMKEY-LEGAL THREW: TypeError Cannot convert a Symbol value to a string
```

The oracle cannot see this: `SHAPE_CORPUS` in `scripts/model-tiers.test.ts:1660-1673` varies only
the **value** (`new Map([[stems[0], make()]])` — the key is always a real stem), while the describe
block it lives in is titled *"the refusal path RETURNS on every input"*. That is a totality claim
strictly wider than the axis its corpus measures — this module's own named defect.

**Fix.** Route the key through the same single authority, and widen the corpus to the key axis:

```ts
// scripts/model-tiers.ts — both refusal sites
`model-tiers: the override for role ${quoteValue(stem)} is ${quoteValue(alias)}, which …`
`model-tiers: the override names the role stem ${quoteValue(stem)}, which is not one of the …`
```

`quoteValue` already renders a string as `"stem"` via `JSON.stringify`, so the wording for every
legal key is byte-identical; only the illegal shapes change from a throw to a description. Then in
`model-tiers.test.ts`, drive `SHAPE_CORPUS` over the **key** as well as the value —
`new Map([[make(), 'opus']])` — so the describe block's title becomes a claim its corpus actually
measures. Rebuild the committed `.js`.

### CR-02: R3-CR-01 is NOT closed — the gate still publishes a number in a unit it does not count

**File:** `scripts/check-kit-refs.ts:185-216, 351-366, 500-503` (and the committed `.js`)

**Issue.** The constant declares its unit by a measurement command:

```
// Exactly THREE exempt MENTIONS. Measured 2026-08-20 on this tree by
// `grep -o 'agent-factory/config/' agent-factory/config/factory.config.md | wc -l` = 3
const CONFIG_SELF_REF_MENTIONS = 3;
```

The gate does **not** count that. `exemptMentions += named.length` counts captures of
`CONFIG_NAMED_PATH` — `agent-factory/config/([A-Za-z0-9._-]+)` — which is a *different* unit from
occurrences of `CONFIG_REF_NEEDLE`, the substring `grepSubstring` actually greps for. The two
disagree on any mention that names the directory without naming a file. The test's own helper
`mentionsIn(haystack, needle)` (`check-kit-refs.test.ts:191`) measures the *needle* unit, so the
oracle's premise and the gate's published number are in two different units again — the precise
shape R3-CR-01 was filed about.

Reproduced on the live tree. Appending one bare directory reference to the already-exempt line 138
of `agent-factory/config/factory.config.md`:

```
The legacy directory agent-factory/config/ is retired. This whole-file precedence is deliberate…
```

```
$ grep -o 'agent-factory/config/' agent-factory/config/factory.config.md | wc -l
       4
$ node scripts/check-kit-refs.js
  PASS  no agent-factory/config/ refs remain (3 counted self-reference mention(s) on 2 line(s) exempt, …)
  PASS  the config self-reference exemption is exactly 3 mention(s) on 2 line(s) in 1 file(s), as declared
EXIT=0
```

Four occurrences of the path D-08.1 forbids in shipped kit prose, an un-argued and uncounted new
one among them, and the gate prints `3` and passes. (Restored; `git diff --exit-code` clean.)

**Fix.** Count the published unit from the same needle the gate greps for, so the number and the
declaration describe the same thing:

```ts
// exemptConfigSelfRefs, inside the exempt branch:
exemptMentions += line.split(CONFIG_REF_NEEDLE).length - 1;   // the NEEDLE unit, as declared
```

and keep `named` for the membership decision only. Then add the missing arm to the predicate: a
hit whose needle-occurrence count exceeds its `named.length` names the directory without naming a
file and must be a **stray**, not an absorbed mention — the "at least one" floor already makes that
argument for a line with *zero* captures, and it is the same argument for a line with *fewer
captures than mentions*. Mirror `mentionsIn` in the test as the single premise unit.

### CR-03: R3-CR-02 is NOT closed — a path that leaves the directory is still certified as a reference inside it

**File:** `scripts/check-kit-refs.ts:216` (`CONFIG_NAMED_PATH`), `258-283` (`configSiblingFiles` /
`isConfigSibling`)

**Issue.** Plan 18 replaced `existsSync(join(dir, base))` with membership in the derived depth-1
regular-file set. That closes `.`, `..` and a subdirectory **at the basename position**. It does
nothing about bytes *after* the basename, because `[A-Za-z0-9._-]+` stops at the first `/` and the
predicate never sees the rest of the path. The docstring's claim — "the set cannot contain a name
the directory does not carry, so no spelling has to be anticipated" — is therefore wider than the
mechanism: the mechanism does not judge the path, it judges the path's first segment.

Reproduced on the live tree. Line 138 of `agent-factory/config/factory.config.md`, with the
existing mention respelt (so no cardinality can move):

```
…then `agent-factory/config/factory.config.json/../../../../etc/passwd`.
```

```
$ node scripts/check-kit-refs.js
  PASS  no agent-factory/config/ refs remain (3 counted self-reference mention(s) on 2 line(s) exempt, …)
  PASS  the config self-reference exemption is exactly 3 mention(s) on 2 line(s) in 1 file(s), as declared
EXIT=0
```

All three cardinalities — files 1, lines 2, mentions 3 — are exactly as declared, and the shipped
document points a reader four levels out of the kit. `check-kit-refs.test.ts` has cases for
`../`, `./`, a subdirectory and a ghost filename at the **basename** position, and none for a
traversal at the **suffix** position. (Restored; `git diff --exit-code` clean.)

**Fix.** Capture the whole path the line names, not its first segment, and require the *whole*
captured path to be a member:

```ts
// One capture per named path, up to whitespace / a markdown delimiter — never stopping at `/`:
const CONFIG_NAMED_PATH = /agent-factory\/config\/([^\s`"'()\[\],;]+)/g;
```

Then `isConfigSibling` is asked about `factory.config.json` (a member) versus
`factory.config.json/../../../../etc/passwd` (not a member, because the sibling set holds
basenames), and the refusal is a consequence of the one rule rather than of a new special case.
Add a RED case for the suffix position beside the four basename cases already in the oracle.

### CR-04: `(r-class-prefix)`'s two requirements CANNOT FAIL for either existing member — the R3-IN-03 fix does not discriminate

**File:** `scripts/check-foundation-guards.test.ts:10912, 10936, 11225-11290`

**Issue.** The case requires every derived member to carry the right-bound marker and the slice
base "in its canonical source spelling", tested as `textOf(f).includes(<spelling>)`. Both spellings
are satisfied by the files' own **constant declarations**, independently of what their readers
compute:

```
scripts/check-foundation-guards.test.ts:10912:  const STEP_MARKER = "\n      - name: ";
scripts/check-foundation-guards.test.ts:10936:  const UBUNTU_BLOCK_SLICE_BASE_SOURCE = ".slice(at + UBUNTU_BLOCK_STEP_NAME.length)";
scripts/skill-twins-freshness.test.ts:286:     const STEP_MARKER = "\n      - name: ";
```

Requirement 1 is unconditionally satisfied for both members by line 10912 / line 286. Requirement 2
is unconditionally satisfied for `check-foundation-guards.test.ts` by line 10936 — the constant that
*declares* the requirement is itself the text the requirement searches for. A predicate its own
subject satisfies is not a predicate; the file's own commentary makes exactly this argument two
hundred lines earlier ("the authority does not satisfy this scan itself, because it assigns the
render to a local rather than composing the two calls"), and then does not apply it here.

Reproduced by mutation — I reverted this file's reader to the *exact* divergence R3-IN-03 named:

```diff
-    const rest = ci.slice(at + UBUNTU_BLOCK_STEP_NAME.length);
+    const rest = ci.slice(at);

```
$ npx vitest run scripts/check-foundation-guards.test.ts -t "r-class-prefix"
 Tests  1 passed | 263 skipped (264)
$ npx vitest run scripts/check-foundation-guards.test.ts

The class is once again certifying two readers of one class while they read different regions —
the state round 3 found, with the fix in place. (Restored; `git diff --exit-code` clean.)

The diff discloses a *related* residual ("a member that spells both … while computing something
else entirely … is FAIL-OPEN"). That disclosure is about a hypothetical future member. This finding
is stronger: for the two members that exist today the assertions are **structurally incapable of
failing**, so the disclosure understates the hole by exactly the amount that matters.

**Fix.** Compare behaviour, not text. The one thing both members already share is a workflow file
and a step name, so compare their *outputs*:

- Export nothing; instead, in `(r-class-prefix)`, for each derived member, extract its reader region
  and assert the member's **computed block** equals this file's — or, more cheaply and without a
  second parser, require the canonical spelling to occur **outside** any `const <NAME> =`
  declaration line (strip declaration lines of the two constants before the `includes` test), so
  the constant that states the requirement no longer answers it.
- Better: assert the two members' bounded reads agree on the committed workflow by having each
  member export its `ubuntuBlockCommands` from a shared `*.testkit.ts` consumed only by tests, and
  assert `a.join("\n") === b.join("\n")`. That is one authority over "does this class read one
  region", which is what the case claims to be.

### WR-01: Assertion 3's positive half compares two path spellings — a guaranteed false RED on Windows, under a comment claiming the opposite

**File:** `scripts/check-kit-refs.ts:137, 396-400, 599-619`

**Issue.** `ghLegal` is built from `ADAPTER_FILES` (produced through `join()`) plus the literal
`PACKAGING_TEMPLATE = "agent-factory/packaging/subagent.frontmatter.md"`, while `ghActual` comes
from `grepFilesWithMatch(SCAN, …)` → `walk()` → `join()`. On Windows those disagree:

```
$ node -e "console.log(require('path').win32.join('agent-factory/packaging','subagent.frontmatter.md'))"
agent-factory\packaging\subagent.frontmatter.md
```

so on Windows `ghIllegal` and `ghSilent` are both non-empty for the same file and Assertion 3
fails red on a correct tree — printing "carries the resolver slot but never names $GRUGOPS_HOME
(its self-heal is gone — this adapter cannot find the kit)" about a file that is perfectly fine.

The comment directly above the derivation asserts the opposite:

> `join()` (not a `/` template) keeps these byte-identical to the paths `walk()` produces on Windows
> as well as Unix — Assertion 3 compares the two sets directly, so a separator mismatch would break
> it silently.

The reasoning is right and the application is incomplete: `PACKAGING_TEMPLATE` enters the same set
as a raw forward-slash literal. This predates round 4, but the file is under review, the claim is
in it, and it is **not** in `.planning/WINDOWS.md` (rows 73/77/79 cover other things).

**Fix.**

```ts
if (existsSync(abs(PACKAGING_TEMPLATE))) ghLegal.add(join(PACKAGING_TEMPLATE));
```

and, for the same reason, normalise the direct-file `SCAN`/`GH_SCAN` entries the same way in
`walk()` (`acc.push(join(rel))`), so every path in every set this gate compares is produced by one
spelling authority. Add a `path.win32`-based unit case, or log the row in `.planning/WINDOWS.md`.

file's to choose: `typeof`'s codomain is fixed by the language at EIGHT results". The denominator is

### WR-04: the `String(JSON.stringify(` / two-sites scan runs over the `.ts` only, and its comment strip can hide a site

**File:** `scripts/model-tiers.test.ts:1782-1806`

**Issue.** Two problems in one case that is presented as a one-authority proof.

1. It reads `scripts/model-tiers.ts`. The artifact hosts execute is the committed
   `scripts/model-tiers.js`. Build parity is enforced separately (`check:build-parity`), so this is
   not currently exploitable — but the case's own claim is "the quoting operation has ONE spelling
   in **this module**", and the module that ships is the one it does not read.
2. The comment strip is `line => !/^\s*[/*]/.test(line)`, which drops whole-line comments only. A
   `JSON.stringify(` occurring after code on a line (`const x = 1; // JSON.stringify(y)`) is
   counted, and a third real site placed on a line beginning with `*` inside a template literal is
   not. The pinned `.toBe(2)` therefore measures a slightly different set than the sentence claims.

**Fix.** Run the scan over **both** `model-tiers.ts` and `model-tiers.js` (the `.js` has no
`String(JSON.stringify(` either, so it passes today and pins the shipped artifact), and state the
comment-strip's limits in the message rather than in prose — the case already knows how to write a
disclosed residual.

### IN-01: `describeShape(null)` renders the null-overrides refusal as "an object rather than a Map"

**File:** `scripts/model-tiers.ts:1080-1088`, `1294-1298`

`typeof null === "object"`, so Floor 0b — written specifically for R2-WR-01's first repro,
`overrides: null` — tells the user "the overrides argument is an object rather than a Map". That is
the least useful possible rendering of the exact case the floor exists for.
**Fix:** special-case it in `describeShape`: `if (value === null) return "null";`.

### IN-02: `join(CONFIG_SELF_REF_DIR) + sep` is computed in two places

**File:** `scripts/check-kit-refs.ts:259` and `:342`

`configSiblingFiles()` and `exemptConfigSelfRefs()` each derive `dirPrefix` independently. It is the
same operation written twice in a module whose thesis is that a second spelling is a second thing to
drift away from. **Fix:** hoist to one `const CONFIG_DIR_PREFIX = join(CONFIG_SELF_REF_DIR) + sep;`
and have both read it.

### IN-03: `walk()` follows symlinks with no cycle guard, and admits them to the exemption's sibling set

**File:** `scripts/check-kit-refs.ts:232-244`, `258-265`

`statSync` follows symlinks. A directory symlink pointing at an ancestor under any `SCAN` entry
recurses until the stack overflows; and a file symlink inside `agent-factory/config/` (e.g.
`config/notes -> ../../README.md`) is `isFile()`, so it joins `configSiblings` and becomes an
exemptable basename — narrowing the docstring's "the set cannot contain a name the directory does
not carry". Low likelihood in this repo; cheap to close.
**Fix:** use `lstatSync` in `walk()` and skip `isSymbolicLink()` entries, or track visited
`dev:ino` pairs.

### IN-04: `sectionCitationsIn` throws on a lone backtick-`###` sequence anywhere in the authority

**File:** `scripts/model-dial-consistency.test.ts:490-513`

The reader scans the **whole** document for `` `###  `` and throws `UNCLOSED SECTION CITATION` when
the next backtick is missing. The throw is the right default, but it is unbounded in scope: any
future prose or fenced block in `agent-factory/packaging/subagent.frontmatter.md` producing that
byte sequence without a closing backtick reds a case about *section citations* with a message about
an unclosed span. Worth bounding to the citing region (`modelBulletRegion()`), which the case
already derives and already asserts the citation set is confined to.
