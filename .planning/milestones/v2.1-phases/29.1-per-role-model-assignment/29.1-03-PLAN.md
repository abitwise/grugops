<objective>
Make the generator refuse an illegal resolution before it writes anything, and make the
freshness gate's zero-config pin an observable property of the run rather than an accident of
what the mirror does not copy.

Two independent hazards land in one plan because they share the same two files.

The first is T-27-32. The generator's posture is all-or-nothing: a structural miss prints a
finding and exits 1 writing nothing. `render()` runs inside `adapters.map()`, so a refusal
raised there would break that posture and leave a partial adapter directory. The resolution
must therefore be validated once, above the loop. The proof is not the exit code — it is the
directory: after a refused run in a hermetic mirror, every adapter file is byte-unchanged.

The second is Pitfall 3. `adapters-freshness.ts` satisfies D-04 today by pure absence: the
mirror copies `agent-factory/roles` and `agent-factory/packaging` and nothing else, so a
config-reading generator running inside it resolves nothing. Absence is not a pin. The day
someone adds a config directory to the twin list — a plausible, well-intentioned edit, since
the existing comment already justifies mirroring `packaging` although the generator does not
currently open it — the gate silently becomes config-dependent and D-04 evaporates while
everything stays green. The remedy is RESEARCH.md option (c): the generator prints its
resolved preset and the gate asserts it reads `none`.

Scope note: D-01, D-02 and D-03 are OUT OF SCOPE and moved to Phase 29.2 by D-17. No
install-side file is read for modification, changed, or tested here.

Output: a generator that refuses loudly and writes nothing, and a freshness gate whose
zero-config claim is asserted rather than inherited.
</objective>
