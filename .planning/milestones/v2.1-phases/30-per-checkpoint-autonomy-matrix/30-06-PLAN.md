<assumption_delta_decision>
**Noun now primary:** the checkpoint id and its per-checkpoint disposition. The single `autonomy`
scalar loses its monopoly as the project's autonomy vocabulary; a per-id matrix cell replaces it, and
a single admission key is joined by a second, per-floor key.

**Decision: promote.** CONTEXT.md D-05 already requires it — the scalar is retired, the validator
refuses a present key with a message naming the replacement, and the five registry rows that depended
on it are remapped in plan 30-02. There is no coexistence mode, no "matrix wins on conflict" rule and
no compatibility shim. Making this explicit here so the choice reads as a decision rather than as an
omission: `add-alongside` was available and was rejected, because two live autonomy vocabularies over
one question is the second-authority defect class this milestone exists to close.

**Accepted debt:** none from coexistence. The cost paid instead is a one-time migration burden on
already-installed repositories, discharged by the mechanical legacy grade table in the config markdown
and by the installer's report-do-not-rewrite behavior (Task 3).

**Suggested (not required) invariant:** a test asserting that the singular key name appears in no
shipped config surface and in no validator required-key list, so a future phase that reintroduces the
scalar goes red the moment it lands rather than at review time. Author it as a derived scan over the
shipped config surfaces with an asserted denominator, never a hand-listed path array.
</assumption_delta_decision>

<objective>
Retire the `autonomy` scalar everywhere it lives: flip the validator's polarity from requiring it to
refusing it, add form-checking for the checkpoint matrix, update the three live config surfaces and
the sixteen fixture config files together, correct the two prose statements in the config markdown
that are already wrong, and publish the mechanical legacy translation for repositories that carry the
old value.

Purpose: a scalar that enforced nothing but appeared in seventeen role files, five documents and every
fixture is exactly the kind of documentary posture this phase replaces with a mechanism. Retiring it
half-way leaves two vocabularies for one question.

Output: a validator that refuses the old key and form-checks the new object, eight fixtures that each
still fail for their one reason, and a translation table a user can act on.
</objective>
