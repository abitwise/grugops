<objective>
Close the three harness- and configuration-integrity findings, all of which are instances of the same
class this phase has now diagnosed repeatedly: **a device that reads like a floor and cannot actually
hold the weight.**

**WR-04 — the dead-code flags reach nothing.** The two flags are on, but the shipped-source typecheck
config excludes every `.test.ts` file, and the test runner transpiles the harness without type
checking. So the flags have no reach into the surface this phase actually grew — the frontmatter
harness gained over twelve hundred lines in round 10 alone, and rounds 11's plans add more. There are
no violations today, so this is latent rather than live, but the remedy as configured cannot see the
code it was turned on for.

**IN-02 — the fence-authority claim is half mechanised.** The derived, sorted, cardinality-pinned set
is a genuine improvement and its classifier constructs are each proven load-bearing. But the claim it
backs is that exactly one implementation answers the general question, and that half is mechanised for
only one of the three non-authority members; the other two are excused as harness-local in prose. A
future edit that makes either a general document-level answer keeps the set at four and the claim
green.

**IN-03 — the source-scan pin is brittle in two measured ways.** Its slice assumes no line in the
function body begins at column zero with a closing brace — true today, silently truncating tomorrow,
and a truncated body makes its positive assertion fail confusingly rather than informatively. And its
negative assertion matches comments as well as code, so a future comment explaining why a shape is
wrong will false-red it: the same comment-versus-code confusion the comment-stripping helper was
introduced to solve, one file over.

Purpose: this round's closure claims rest on the harness. A harness whose own devices cannot fail is
not evidence, and this phase's record shows its verification harness produced a false result in six
instances across four straight rounds.

Output: a test-inclusive typecheck target proven to reach the tests and proven able to fail, a
mechanical discriminator replacing the prose half of the fence claim, a bounded and comment-stripped
source-scan pin, and every repaired assertion proven able to fail.

Implements D-19 (a recorded, derivable measurement rather than a promise), the round-9 IN-03 and
round-10 WR-03 discipline (assert the slice is the thing before inspecting it; an assertion that
cannot fail is not a floor), and this project's own set-literal-drift doctrine applied to the harness.
</objective>
