<objective>
Discharge the one check that requires a human, and record what actually happened.

Everything discharge-able by command has been discharged. The adapters exist and are byte-gated, the
coordinator carries its marker and an enumerated grant whose every name resolves, the materialized
kit path is absolute and exists, and the precheck built in the previous plan asserts all of it in one
run. What remains is two observations of a live session: whether the startup header names the
coordinator agent, and whether asking for work that routes to a specialist causes a distinct role
agent to resolve and run rather than the coordinator working the task inline.

That is the whole reason this requirement is open. The previous plan performed the observable steps
and refused to claim the rest, which was correct. This plan supplies the missing input — a person —
and turns their observation into a committed artifact.

The plan is deliberately structured so it cannot be completed by an agent alone. The interactive step
is a blocking checkpoint. The transcription step copies what the human reports and nothing else. And
the status update is conditional: it happens only if the observation matched, because a requirement
marked complete on a green suite is exactly the failure this phase exists to fix.

Purpose: close the requirement with evidence, or leave it open with a finding — both are acceptable
outcomes, and a fabricated pass is not.
Output: a filled recording surface and, only on a matching observation, an updated status.
</objective>

  <name>Task 1: observe a real session and report exactly what appeared</name>
  <what-built>
    Every observable precondition of the coordinator-resolution check is now discharged by one
    command. `scripts/coordinator-resolution-precheck.js` performs a scratch install into a temporary
    target with an isolated kit home, enumerates the installed adapters, locates the coordinator by
    its marker, reports the grant size and how many granted names resolve to an installed adapter
    file, resolves the materialized absolute kit path, and reports the installed platform version
    against the advertised floor and the known-bad window. It spends no tokens and starts no session.

    What it cannot do is look at a terminal. The session startup header is an interactive element and
    whether a distinct role agent resolved cannot be observed from any command in this repository.
    Those two observations are what this checkpoint asks for.
  </what-built>
  <how-to-verify>
    Takes about three minutes.

    1. From the repository root, run the precheck with its keep-scratch-target option:
       `node scripts/coordinator-resolution-precheck.js --keep`
       It exits 0 and prints the scratch target path plus the two remaining steps. If it exits
       non-zero, stop and report the named precondition — do not continue to the interactive step.

    2. Change into the scratch target path the precheck printed.

    3. Start a session with the documented full-capability command, which the precheck prints
       verbatim — it is the flag form naming the coordinator agent, not the skill entry.

    4. Observe the session startup header. Copy its text exactly, including whether it names the
       coordinator agent. Do not paraphrase.

    5. In that session, ask for work that routes to one specialist — for example, ask it to map this
       repository. Observe whether a distinct role agent resolves and runs, or whether the coordinator
       works the task inline. Note the exact agent name if one appears.

    6. If any of the three probe conditions happens to be exercised, note it: whether an adapter of a
       different scope carrying the same agent name was resolved instead, the exact error text if no
       adapter matched a requested name, and the observed order if more than one role agent was routed
       in a single turn. None of these is required — record only what you actually saw.

    7. Report back: the platform version the precheck printed, the exact header text, whether a role
       agent ran and its name, and anything from step 6.

    If the header does not name the coordinator, or the coordinator works the task inline, that is a
    valid and useful result. Report it as seen. Do not re-run until it agrees.

    Finally, remove the scratch target directory when finished.
  </how-to-verify>

## Flagged Assumptions (probe-unresolved)

The three backstop items for this requirement — adapter-scope precedence when two adapters share an
agent name, the exact error text when no adapter matches, and the ordering of several role agents
routed in one turn — are carried into this plan as recorded-if-encountered slots. A single routed
subtask may exercise none of them, in which case they remain open and are stated as such in the
evidence file rather than being closed by silence. They are claims about a runtime this repository
does not own, and they abstain and escalate rather than passing.
