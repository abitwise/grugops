<objective>
Establish the kit-set authority (KIT-01) and stand up the referential-integrity oracle (KIT-03) so
that every later plan in this phase is measured against a derived truth rather than a hand-listed
one. This is the load-bearing first step the ROADMAP demands: the sets become derived and the oracle
starts failing RED **before** a single adapter file is authored.

`scripts/kit-model.ts` becomes the sole answer to "which roles and workflows exist", taking the kit
root as an explicit argument (D-22) so it never invents a fourth root env var alongside the existing
`CHECK_ROOT`, `VALIDATE_ROOT` and `VALIDATE_KIT_ROOT`. Enforcement is deliberately two-tier (D-21):
the library **throws** on a vacuous set because continuing is unsafe, while a guard **fails red** on
an exact-count mismatch because continuing is safe and CI going red is the right signal. The count is
exact in both directions (D-20) — adding role #18 must force an author to walk every derived
consumer.

The oracle implements D-09: `grant ∪ {coordinator} == adapters == roles`, with no exception list
anywhere.

Purpose: the milestone's founding defect is a fully green guard suite over a structurally broken
tree. This plan makes the suite tell the truth about that tree before anything is built on top of it.
Output: a derivation module, one re-pointed consumer proving the seam end-to-end, an exact-count
guard, a three-way set-equality oracle, and permanent fixture tests that pin both the RED and the
GREEN behaviour.

**Expected and intended consequence:** from the end of Task 3 until plan `27-06` commits the 17
adapters, `node scripts/check-foundation-guards.js` exits non-zero with **exactly one** FAIL —
`guard_referential_integrity`. That is the RED evidence ROADMAP success criterion 2 requires. Do not
suppress it, do not skip the oracle, do not weaken it to a warning.
</objective>
