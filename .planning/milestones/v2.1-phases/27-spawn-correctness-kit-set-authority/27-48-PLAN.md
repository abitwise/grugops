## Why the exception is an INDENT and not a flag

A block sequence genuinely admits a node start at every item. If the node-started fact were raised by
the first item, the second item's dash would become text and the shipped block-sequence idiom every
skill and adapter writes would collapse into one scalar. So the item path records the INDENT at which
items begin, and only a line at that indent beginning with a dash re-enters the item rule. A dash on a
more-indented continuation of an item is text, which is what YAML says and what the loader computes.
The exception is one field with one stated reason, not a second grammar.

## Why WR-03 lands here

`hasSpawnGrant` is a boolean. The fact the KIT-03 closure equality and coordinator-resolution-precheck
are computed over is the NAME SET. Both round-8 harnesses agree with the loader on the boolean only, so
row a1 — the module's own declared founding-failure direction, reproduced — passes both of them today.
The exclusion's stated reason is sound as far as it goes (the module joins a block sequence with a
comma-space by contract, so BYTE equality of the flattened value is not available), but that argues
only against comparing bytes. Name sets are order-free, de-duplicated and directly comparable once both
sides are flattened the same way.
