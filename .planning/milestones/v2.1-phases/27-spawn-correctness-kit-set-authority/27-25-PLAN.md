<objective>
Close CR-02 structurally, per D-28.

`install/install.ts` and `install/uninstall.ts` carry what the foundation guards' own set-literal
record calls a declared BYTE-IDENTICAL PAIR (inventory entries #9 and #10) — two hand-synced
derivations of one predicate. That pair has now drifted twice inside this single phase: round 1
re-synced it, then plan 27-22 moved `install.ts` onto `statSync` and left `uninstall.ts` on `Dirent`
flags. A `Dirent` for a symlink is neither a file nor a directory, so a symlinked source adapter is
installed by `install.js` and never removed by `uninstall.js` — reproduced end-to-end with
`== uninstall complete ==`, exit 0, and the leftover file confirmed. That is a live violation of the
CLAUDE.md hard constraint that installers stay reversible, and it is precisely the drift class KIT-02
exists to delete, surviving in the one place this phase deliberately chose not to couple to the
shared authority.

D-28 (user decision, this round) amends D-18: the pair collapses into ONE shared module inside
`install/` that both files import. It still does not import `scripts/kit-model.ts` — D-18's actual
rationale is decoupling the installer from the `scripts/` layout, and a shared file *inside*
`install/` preserves that in full. D-18's separation-of-duty half is untouched: the installer still
faithfully installs whatever exists, and `kit-model` plus the KIT-03 oracle still guarantee at CI time
that what exists is correct.

WR-02 rides along because it is the forcing function that was missing: the round-trip case asserts
symlinked-skill coverage over a fixture that contains no symlinked skill, so it compares two
unmodified derivations and would pass identically if the helper had never changed. A fixture that
cannot express the failure is not coverage.

Purpose: one answer to one predicate, and a reversal that cannot be narrower than its install.
Output: `install/kit-source.ts` as the single derivation, both installers rewired onto it, a fixture
that actually contains the shapes it asserts about, and a committed record that matches the tree.
</objective>
