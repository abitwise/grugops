<objective>
Close WR-01: both installers print `INCOMPLETE` and exit **0**. Plan 27-13's stated goal was that a
run which installed nothing must not claim completion. The banner became conditional; the machine
signal did not. The fail-loud contract is therefore loud only to a human reader, and the new
`coordinator-resolution-precheck.ts` — whose gate is `r.status !== 0` — narrates
`the installer ran cleanly` over a run that refused a whole class, and can reach `PRECONDITIONS HOLD`
on the strength of it.

This is a contract change on a published surface. The exit code of `install.js` is what a CI step, a
chained shell command and the documented scripted-install path all read, so the decision gets a
blocking checkpoint before the code moves, and all four moves — the two installers, the test pins and
the precheck gate — land as one atomic change. A partial application leaves the precheck narrating a
clean run over a refused install, which is worse than the current state because it looks fixed.

Purpose: make the machine-readable signal agree with the banner.
Output: a distinct incomplete exit code in both installers, moved test pins, a tightened precheck
gate, a documented code list, and a swept consumer set.
</objective>

  <decision>Which exit status does a run that printed the INCOMPLETE banner return?</decision>
  <context>
This changes a published contract. Today `install.js` exits 0 on an incomplete run, so any consumer
written as `install.js &amp;&amp; next-step` proceeds. After the change that consumer stops. That is the
point — but it is a behaviour change on a surface users are documented to script against, and undoing
it later means re-cutting the installers, the test pins, the precheck gate and the README together.
Reversibility is rated one-way for that reason, so a human chooses rather than the executor.

The installer already uses 0 for success and non-zero for the doctor-mode refusal, so a bare 1 would
merge "incomplete" with "refused" and lose the distinction a reader needs.
  </context>

      <pros>The review's own recommendation. Machine signal agrees with the banner; incomplete stays distinguishable from crashed; the precheck's status gate becomes meaningful without further work; the code list is documentable in one README line.</pros>
      <cons>Chained consumers that today proceed will now stop — which is the intent, but it is a real break. Reserves 2 for a usage error that does not exist yet.</cons>
