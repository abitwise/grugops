# Phase 27 Plan 59: A Corpus That Can See What It Claims Completeness Over Summary

This plan changes **no shipped behaviour**. It touches `scripts/frontmatter.test.ts` and
`scripts/fixtures/frontmatter-singleline-pre-d54.json` only. No production source file was edited, no
dependency was added, `package.json` is byte-unchanged, and the exemption list is the same length
before and after.

Its whole point is the phase's most-repeated lesson: *a corpus that cannot generate an input cannot
prove the fix that input needed.* Round 10 shipped three live bypasses past a green 312-cell loader
differential, a green foundation gate and a 210-green file.

## The class this plan is about, and why it is a DERIVATION

The five previous rounds each closed a "the corpus could not express this" report by adding **one base
member for the one shape a review named**. That is a corpus grown per reported family — circular over
the FAMILY structure exactly as a per-arm corpus was circular over the ARM structure. The fourth
family, the one nobody has reported yet, would be outside the shape space again and the differential
would go on printing a green line about inputs it never generated.

So `27-59` adds **no base member at all**. It declares each header-bearing shape's block-scalar header
as PARTS (`line`, `indent`, `intro`, `key`, `property`, `indicator`) and crosses those parts:

| | before | after |
|---|---|---|
| `AXIS_KEY_LINE_BASE` (hand-written) | **26** | **26 — deliberately unmoved** |
| header-derived shapes | (n/a) | **321** |
| derived key-line axis | **53** | **348** |
| enumerated cells | **2,544** | **16,704** |
| loader-ACCEPTED | 1,526 | **12,349** |
| loader-REJECTED (printed skips) | — | **4,355** |
| token-presence disagreements | — | **78**, every one covered by E1 or E2 |
| NAME-SET disagreements | — | **0** |
| exemption list length | **2** | **2** |

**The base length staying at 26 while the corpus grows sixfold is the claim.** Every axis carries a
two-sided cardinality pin, the derived header length is asserted EQUAL to the sum over the base shapes
of each one's own participation product with the arithmetic in the message, and the cell total is
asserted equal to the product of the four axis lengths.

**The parts must really spell the shape.** `blockHeader` is a second description of a line whose bytes
already exist in `lines`, and a second description that can drift is this repository's diagnosed
set-literal failure class wearing a struct — so every declaring shape's header line is RECOMPUTED from
its own parts and compared byte for byte before it can generate 321 wrong documents.

**And the derivation is proven to be one.** A case collapses the key-spelling axis and asserts the
derived length moves BY THE DERIVATION rather than by a constant — the only way to tell a derivation
from a number that happens to agree with one today.

## The capture is REGENERATED — and it turned out to be a COMPOSITE nobody had written down

Regenerating exposed a fact no summary states in one place. Measured over the committed 24-state
cross product:

| mirror | reproduces `shortened` | reproduces `state` |
|---|---|---|
| `git archive 62b8b53` (pre-D-54) | **0 mismatches** | 1,514 mismatches |
| `git archive d5c69e0` (pre-`27-51`) | 4 mismatches | **0 mismatches** |

Regenerating both halves from ONE commit would have silently re-baselined the other — the "the build
equals itself" tautology this file rejects by name. So **each half was regenerated at its own commit**:

```
git archive 62b8b53 | tar -x -C <textMirror>
git archive d5c69e0 | tar -x -C <stateMirror>
node regen48.mjs <textMirror> <stateMirror> 62b8b53 d5c69e0 <out>
```

The fixture now records both commits, the cross product and the measured composite fact in a
`provenance` key, and a case asserts them — including that both commits are real objects here.

**Verified against the capture it replaces.** The new 48-state capture's COUPLED sub-slice (cells where
`nodeStartAtOffsetZero === entering.nodeMayBegin`) equals the committed 24-state capture exactly:
**0 text, 0 state, 0 sparse-presence mismatches** across all 6,194 inputs. Nothing is
`UNKNOWN - verify`; every cell of the new dimension was OBSERVED.

## The harness premise produced a FALSE result TWICE MORE, and both were caught

The eleventh and twelfth instances in this phase. Neither would have been visible without the
exit-code assertions the record already demands.

1. **The inverse-patch approach silently did not apply.** `git show 8a2f435 -- scripts/frontmatter.ts |
   git apply -R` failed (`patch does not apply`) and the row still printed **`268 passed`**. Read
   without `mutate exit=1` it says *"the corpus does not pin 27-55"* — which happens to be true, for
   entirely the wrong reason. Replaced by targeted mutations that assert their own target text before
   and after.
2. **`npx tsc` failed with `TS6133: 'stripNodeProperties' is declared but its value is never read`**,
   emitted NOTHING, left the UNMUTATED `.js` in place, and the row printed **`268 passed`**. The direct
   probe caught it in the same breath: `27-57 property` still returned `{ok:true,value:true}`, which a
   truly mutated build cannot do. After a `void stripNodeProperties;` reference so the build EMITS, the
   same revert reds with **8,190** disagreements and the probe returns a refusal.

**And a third, smaller one, recorded because it produced a wrong number in a transcript.** `diff` is a
shell FUNCTION in this environment (`git diff --no-index --color-words`), so `diff a b | grep -c '^>'`
counted **0** for a mutation that had plainly applied. Every later comparison uses `cmp -s` or
`/usr/bin/diff`.

## Deviations from Plan

**1. [Rule 2 — Missing critical functionality] The property crossing is scoped, and its complement is
adjudicated in a case of its own.**
- **Found during:** Task 1, on the first full run of the widened corpus.
- **Issue:** crossing the node-property axis over ALL header introductions produced **1,440**
  disagreements — every one `module=refuse / loader=grant`, the LOUD direction, and every one at the
  bare-header or block-sequence-item introduction. The D-52 differential requires every divergence to
  be covered by a NAMED exemption, so making them pass would have meant a THIRD exemption rule.
- **Why it is not a defect:** `27-57` measured exactly these as controls P and S and recorded them as
  *"deliberate, byte-unchanged … not open as a defect"*. Verified independently here by direct probe.
- **Fix:** the product's property crossing is scoped to the mapping-separator introduction — the
  introduction the plan's own behaviour section names ("between a mapping indicator and a block
  indicator") — and the complement is generated by the SAME derivation through a parameterised
  participation predicate and adjudicated under the plan's own stated discipline: both never-exemptible
  partitions asserted EMPTY, the loud arm REPORTED with its count. The complement is asserted DISJOINT
  from the product so nothing is judged twice.
- **Why this is not narrowing-to-go-green:** the shapes are still GENERATED, still adjudicated against
  the same loader, and their count is printed on every run. The alternative — dropping the axis — would
  have hidden them, and the other alternative — a third exemption — is prohibited.
- **Commit:** `630764b`

**2. [Rule 3 — Blocking] The revert sweep's method changed twice, both times because its own premise
failed.** Inverse patches of the four fix commits do not apply (later commits moved the same regions),
and the first targeted 27-57 mutation failed `tsc` and emitted nothing. Both were caught by the
exit-code assertions and are documented above rather than repaired silently. **Commit:** `9f3039f`

**3. [Housekeeping] An env-gated disagreement dump was added to the D-52 differential.** Vitest
intercepts console output and truncates a long failure message, so an investigation needing every row
would otherwise read a silently shortened one. Nothing is written unless a caller sets
`GRUGOPS_D52_DUMP_DISAGREEMENTS`, in keeping with this file's existing `GRUGOPS_D52_DUMP_CORPUS`
idiom. **Commit:** `630764b`

**4. [Process] The tracer feedback gate was satisfied by re-running the automation rather than by
emitting a checkpoint.** `27-59` declares `autonomous: true` and carries no `checkpoint:*` task; each
task's `<verify>` is `<automated>` entries only, all re-run end-to-end and green before the next task
began. A `checkpoint:human-verify` whose entire content is CLI commands would violate the protocol it
is issued under. Same disposition as `27-55` through `27-58`.
