WHAT IS BEING MEASURED, AND WHY IT IS CODE POINTS RATHER THAN BYTES
-------------------------------------------------------------------
The count below is of CONTROL CODE POINTS in the DECODED captured stderr — C0
(U+0000..U+001F) minus the line-terminating newline the writer adds, DEL
(U+007F), and C1 (U+0080..U+009F). A raw-byte count is the wrong instrument
here: the diagnostic's own em dash is UTF-8 E2 80 94, whose continuation bytes
sit inside the C1 byte range, so a byte count would report a nonzero "control"
tally for a line carrying no control character at all. A baseline measured with
an instrument that cannot return zero measures nothing.

COUNTER SOURCE (count-controls.mjs)
-----------------------------------
  import { readFileSync } from "node:fs";
  const text = readFileSync(process.argv[2], "utf8");
  const hits = [];
  for (const ch of text) {
    const cp = ch.codePointAt(0);
    if (ch === "\n") continue;
    if ((cp >= 0x00 && cp <= 0x1f) || (cp >= 0x7f && cp <= 0x9f)) {
      hits.push("U+" + cp.toString(16).toUpperCase().padStart(4, "0"));
    }
  }
  console.log(`${process.argv[2]}: controlCodePoints=${hits.length} [${hits.join(" ")}]`);
