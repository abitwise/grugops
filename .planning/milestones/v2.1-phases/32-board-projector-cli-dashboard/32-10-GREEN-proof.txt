THE THIRD ENTRY IS THE ARM THE PLAN'S OWN SKETCH WOULD HAVE LEFT OPEN. `plans/traceability.md`
does not exist under the linked directory, so `realpathSync` answers ENOENT. Admitting on ENOENT
alone — which is what the sketched arm 2 said — would have admitted it, and the check would then
expire the moment the attacker created the file. The implemented arm asks the question about the
deepest ANCESTOR that does exist, so an absent path under an out-of-tree parent is refused now
rather than read later. (It is also what keeps `repoSubpath(root, "../escape")` refused, which the
pre-existing `scripts/board-tracer.test.ts` case asserts.)

The queue and context sources under `.grugops/` are untouched: one linked ancestor refuses the
three sources that live under it and leaves the rest readable (D-12).

PART THREE — THE ADVERSARIAL BATTERY (probed, not assumed)
═══════════════════════════════════════════════════════════════════════════════════════════════

One tree, five shapes planted at once under `plans/tickets/`, one run of the shipped CLI:

    shape                                       marker on stdout / stderr   readErrors code
    ------------------------------------------  -------------------------   ---------------
    RELATIVE symlink (../../../rel-target.md)   0 / 0                       OUTSIDE-ROOT
    symlink CHAIN (link → link → outside)       0 / 0                       OUTSIDE-ROOT
    symlinked DIRECTORY named `DIR-1.md`        0 / 0                       OUTSIDE-ROOT
    self-referential symlink LOOP               n/a                         ELOOP
    HARD LINK to a file outside the tree        1 / 1                       (not refused)

    tickets source: "stale", value ["ABC-101"]  — the legitimate ticket beside all five survives.

THE LOOP IS REPORTED UNDER ITS OWN ERRNO, NOT AS AN ESCAPE. `ELOOP` is a path this module cannot
resolve; an escape is a path that resolves somewhere it may not go. Collapsing the two into one
code would be CR-02's discarded errno, one register over.

THE HARD LINK IS NOT CLOSED, AND THAT IS RECORDED RATHER THAN LEFT TO BE FOUND. A hard link is not
a reference to another path — it IS a directory entry for the inode — so `realpathSync` correctly
answers with a location inside the root and there is no second path to compare against. No
path-based rule can refuse it. Refusing on `nlink > 1` was considered and declined: it is a
heuristic over a legitimate filesystem property, and this repository's own record is that a
heuristic in place of a structural rule is the shape that produces the next round's bypass.

Bounded by: creating the link requires write access to the tree, which is the same access that
would let an attacker paste the bytes into a ticket file directly; hard links cannot cross a
filesystem; and both Linux (`fs.protected_hardlinks`, on by default) and macOS restrict linking to
files the caller may already read. It is recorded in `insideRoot`'s docblock, in
`agent-factory/contracts/board.md` § Staleness, in 32-10-SUMMARY.md and in `.planning/WINDOWS.md`,
and `scripts/board-read.test.ts` pins the MECHANISM so the day the platform changes, the suite
says so.
