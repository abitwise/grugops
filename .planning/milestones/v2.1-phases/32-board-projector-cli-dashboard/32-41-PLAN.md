<objective>
End gap-closure round 4 — the last round this phase's own four-round cap allows — with the gate
sweep, the ledger reconciliation, and the human decision that closes the phase.

**Why this plan ends in a decision rather than a fix.** The cap exists because this project measured,
across Phase 31's eight rounds and this phase's three, that the per-round ratio of defects CREATED BY
THE PREVIOUS FIX never fell. Round 3 moved this phase's score from 2/5 to 4/5 and left one narrow gap;
an unverified fix pass then landed eight more commits. Plans `32-38`, `32-39` and `32-40` measure what
that produced. Whatever remains after them is not a thing to spend a fifth silent round on — it is a
thing a human decides about, with the evidence in front of them and the override text already written.
`32-VERIFICATION.md` itself offered that route, recording an `overrides:` block as available and not
applied.

**What this plan must not do.** It must not flip `REQUIREMENTS.md`'s eight `DASH-0x` checkboxes, and
it must not flip `ROADMAP.md`'s Phase 32 status. Commit `f8c84e06` did exactly that during round 3 and
commit `1b8e0eab` had to revert it before the verifier could run. It must not hand-edit `STATE.md`,
which this project has recorded producing a superlinear escape-doubling defect. And it must not write
a raw control byte into any planning document, because the repository gate refuses the byte and a
single one makes plain searching report zero matches for strings that are present.

Purpose: D-21 makes the read-only proof mechanical, and a mechanical proof that nobody ran this round
is an assertion. The stack constraint this repository ratified makes the committed build the shipped
artifact, so the parity and freshness gates are what make every other number in this round mean
anything. D-13's zero-runtime-dependency posture is what makes the gate sweep cheap enough to run in
full.

Output: one gate record, one reconciled ledger, one drafted override, and one recorded human decision.
</objective>
