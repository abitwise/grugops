<objective>
The last plan of gap-closure round 1. It writes no production code by default. Its job is to re-run
the verifier's OWN reproductions against the tree the round produced, to ask of every new gate how it
is REACHED rather than only what it refuses, and to record honestly whatever that finds.

This exists because of a measured project history, not as ceremony. Across Phases 22-31 every
gap-closure round's fixes created the next round's bypasses — eight rounds on the compactor, twelve
on the frontmatter parser, eight on the admission guard — and in each case the round ended with a
green suite and a self-report that the gap was closed. Phase 32's own first verification found four
blockers while a 4687-test suite was green throughout. A green suite is not proof of a safety
invariant. This plan is the step that treats the verifier's transcripts, not the executors' summaries,
as the oracle.

Phase 31). If this review finds a bypass it cannot close inside the files this round already touched,
it records the finding and stops — it does not start a fifth fix in a sixth file.
