--------------------------------------------------------------------------------
A BOUNDARY THE RUNS MEASURED, STATED RATHER THAN LEFT IMPLIED
--------------------------------------------------------------------------------

The plan for this work asked the poll-path case to assert that the document delivered by
the poll CARRIES a watch-failure record. It does not, and the reason is in the loop rather
than in the test: a poll tick runs `armAll()` and THEN `refresh()`, and a successful re-arm
deletes that directory's record (WR-06 — the record is a state, and a repaired watch has
nothing current to report). So a failure the next tick repairs is never carried by a
document the poll itself emits.

Measured, with every watch forced dead: the change arrived at 997-1003 ms and NO document
in the run carried a `watch` read error. That is asserted in the case rather than only
noted here, so the boundary is pinned instead of remembered — M4 above is the mutation that
turns it red.

The record IS published when a document is emitted between the failure and the re-arm, and
the suite measures that too, through a still-living sibling watch: `.grugops/context` forced
dead, `plans` alive, and the edit to `plans` publishes the context directory's record at
274-275 ms — in the document and on stderr — carrying its own promise that it will be
re-armed on the next poll tick. The next tick keeps that promise and the record is gone at
888-900 ms, which is the half of WR-06 a count of records cannot catch.

What this means for the verifier's expectation, which asked that a watch-arm failure surface
as a diagnosable state rather than silently stopping updates: in both regimes the updates do
not stop (997-1003 ms, measured, with every watch dead), and a failure that outlives one
tick is visible in the document and on stderr. A failure the next tick repairs is invisible
to a consumer by design, and that is now a measured, asserted property rather than an
unexamined one.

--------------------------------------------------------------------------------
WHAT WAS NOT MEASURED
--------------------------------------------------------------------------------

WINDOWS TIMING IS `UNKNOWN - verify`, AND THIS RUN DOES NOT CHANGE THAT. Every number above
was taken on darwin/arm64 with Node v24.12.0. Node documents that on Windows `fs.watch`
events may not be emitted at all, that a watched directory which is moved or renamed emits
nothing, and that deleting one reports EPERM. None of that can be demonstrated from this
tree. The `windows-latest` leg is Phase 33's CAP-02, and Phase 32's Windows caveat in
.planning/ROADMAP.md is unchanged by this plan — it was not edited and it stands exactly as
it stood.

The suite does NOT skip on any platform. `process.platform` appears in the printed
measurements and in every failure message, never in a condition that decides whether a case
runs, because a conditional skip converts an unmeasured platform into a green (T-32-22-03).
The consequence is stated plainly rather than discovered later: CI runs this file on
`windows-latest` as well as `ubuntu-latest`, and three of the five cases (event path, watch
record, debounce) depend on the platform delivering directory events at all. If the Windows
leg reds on those cases, that red IS the Phase 33 measurement arriving early, and it names
the platform and the milliseconds it saw. It is not a defect in the suite and it must not be
answered with a platform conditional.

Not measured either, and out of scope here: the ten-second production poll floor itself. The
runs use the `--interval` override at its 1000 ms hard floor so the poll path is observable
inside a bounded suite. The relationship the cases assert is between the debounce, the
configured period and the delivery, and it is the same relationship at either value.

--------------------------------------------------------------------------------
THE CONTRACT
--------------------------------------------------------------------------------

agent-factory/contracts/board.md was read at its watch section. It carries exactly one watch
sentence — "The projector arms its filesystem watches against the same resolved root it
reads against, and it opens no watch on a source it refused" — which is a containment
statement, not a timing one. The contract states no poll period, no debounce and no
latency, either as measured fact or as reasoning.

So neither branch of this plan's reconciliation instruction applies, and the contract was
left unchanged. Adding a timing sentence to a public contract on the strength of two runs on
one platform would be exactly the conversion that instruction refuses.
