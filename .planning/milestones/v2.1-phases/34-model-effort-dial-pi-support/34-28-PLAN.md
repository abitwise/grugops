<objective>
Make the route reach installs that already exist, and say when it cannot. Install refreshes its own
unedited route carriers (closing deferred IN-03, "the Pi template is create-only"). The CLAUDE.md pointer
gains the route. A user's own carrier without the route gets a note that names the hosts it leaves
without a route.

Purpose: every install made before 34-27 holds a Pi template, a Copilot block, a CLAUDE.md block and
often an AGENTS.md copy with no route. Without a refresh they stay broken after a re-install. That
includes the human's own UAT target, whose Pi template is install's own. Without a note, a user whose
AGENTS.md is their own cannot know that Codex, OpenCode and Gemini have no route.

Output: the refresh rule for files and blocks with its tests, the shared block-span finder, CLAUDE_PTR
with the route, the derived carrier map in host-tools.ts, and the notes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a re-install to files in the user's repository | the installer replaces bytes in files it once wrote; the user may have edited them since |
| the install ledger to the refresh decision | a user-writable record decides whether a file may be written |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-73 | Tampering | the refresh overwriting a user's file or an edited pointer | high | mitigate | Written only when owns says the ledger record still holds (files) or exactly one span matches the block record (blocks); readForWrite first; user-edit, user-owned and two-copy rows; mutation m1 |
| T-34-74 | Repudiation | a refreshed file losing its ledger claim, so uninstall leaves install's bytes behind | medium | mitigate | The new bytes are recorded (file and block, and the whole file when install created it); uninstall-after-refresh rows; mutation m2 |
| T-34-75 | Tampering | a hand-edited ledger record that matches a user's file, so the refresh overwrites it | low | accept | The ledger is the user's own repository state; a record matching the bytes is the same proof uninstall already acts on (33.1 D-33) |
| T-34-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed; package.json and the lockfile are unchanged |
</threat_model>
