## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The first launcher died on an absent `setsid` before the lane was ever invoked**

- **Found during:** Task 3 (launching the one authorized run)
- **Issue:** The launcher put the lane in its own process group with `setsid` so a watchdog could signal the whole tree. macOS has no `setsid`. The launcher exited 127 after 1 second with `setsid: command not found` and a 163-byte log containing only that error. **`npm test` was never invoked** — no vitest process started, no CLI call was made, nothing was spent, and the single-run property is intact.
- **Fix:** Replaced with `perl -e 'setpgrp(0,0); exec("npm","test")'`, and **proved the repaired exec path reached npm with a harmless probe** (`exec("npm","--version")` printed `11.7.0`, exit 0) **before** spending the one authorized run on it.
- **Files modified:** none in the repository — scaffolding only, in the session scratchpad
- **Verification:** the repaired launcher produced a real run whose results are in the transcript
- **Recorded in:** `32.1-10-LIVE-TRANSCRIPT.txt` section 7, so the aborted launch cannot later be miscounted as a first run

**2. [Rule 1 - Bug] The watchdog's hang heuristic was invalid for a buffered runner and would have killed a healthy run**

- **Found during:** Task 3 (mid-run, at roughly 11 minutes)
- **Issue:** The watchdog treated "no new output for 900 s" as a hang. Vitest buffers per-file output when stdout is not a terminal, so the capture still held only its 172-byte header at 11 minutes into a run that was working correctly. The watchdog was about three minutes from killing the one authorized run and recording it as a hang that never happened.
- **Fix:** Suspended the watchdog so it could not signal the lane. The lane was never signalled and ran to natural completion.
- **Cost, stated rather than hidden:** the harness treated the watchdog's suspension as its child terminating and reaped the watchdog shell, which orphaned the lane to init — still running, still healthy — but removed the `wait()` that would have returned the exit status. This is the sole reason the exit code is derived rather than measured.
- **Verification:** the lane printed its own terminating summary block and its pid disappeared on its own; `git status --porcelain` is identical before and after
- **Recorded in:** `32.1-10-LIVE-TRANSCRIPT.txt` sections 4 and 7, including the lesson for any later plan that needs to bound this lane (bound on total wall-clock, not on an output interval, and capture the status in a process that is not the one making the kill decision)

**2. A stale claim in a safety-relevant docblock, found by reading it.**

`scripts/e2e/uat-live.test.ts`'s docblock states the lane "is kept OUT of the default `npm test` green path via the `test:e2e` script". That is false of this tree: `npm test` is `vitest run` with no exclusion, `vitest.config.ts` excludes only `**/scripts/runnable-ref/fixtures/**` and `**/.temp/**`, and the run proves collection happened. Anyone trusting that docblock would run the live lane believing they were running the regression lane. Not patched here — this plan modifies no source — and handed to plan 32.1-11.

**3. Token spend, floored rather than totalled.**

The `total_cost_usd` values visible in the three failure envelopes sum to **4.33 USD**. That is a floor: A1's capture is empty and A3-live-N passed, so neither reports a cost, and both made real calls. The true spend is higher by an amount this run did not measure.

**4. Local claude plugin state moved, and is named rather than cleaned up.**

`~/.claude/plugins/installed_plugins.json` is byte-unchanged (sha256 identical). `known_marketplaces.json` changed, and the change is confined to two `lastUpdated` timestamps — the marketplace SET is identical in membership (`claude-plugins-official`, `grugops`, both pre-existing).
