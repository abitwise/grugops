--- 2.1  THE `path` CLASS — DISPROVED BY PLAN 32.1-12's REPRODUCTION --------------------------------

REGISTER: `.planning/WINDOWS.md` row 220 (`open`), with the transcript at
`.planning/phases/32.1-board-dashboard-deferred-residuals/32.1-12-RED-baseline.txt` section 1.

THE CLAIM THE CLASS MADE, quoted from the builder's docblock as it stands at this tree: "A path in
these sentences is one this process JOINED from a resolved repository root and a constant subpath,
so an author reaches it only by creating a filesystem entry, and the entry NAME that lets them is
itself content-derived and escaped above."

THE ROUTE THAT DISPROVES IT. The second clause is false. `childPath(root, dir, name)` composes a
path from the root, a directory and an entry name, and the COMPOSED value is a different binding
from `name`. The sentence quoting the composed path carries no separately escaped copy of the entry
name, so escaping `name` at the sites that quote `name` does nothing for the sites that quote the
composition. Plan 32.1-12 measured it end to end: a repository root named `repo<U+0085>x`, a
claimed-queue task with no `at:` line, and the published JSON document stating
`.../repox/.grugops/queue/claimed/task-no-at/claim.md` about a tree that carries no such directory.
A reader who searches for what the document prints finds nothing.

AND IT IS NOT ONE ARM. Section 1.3 above reproduces the same route at three FURTHER arms, in two
further readers, at three further declarations (`taskDir`, `indexPath`, `absPath`). The class was
not narrow; it was unmeasured.

--- 2.2  THE `internal` CLASS — DISPROVED BY MEASUREMENT AT HEAD, RECORDED HERE ---------------------

REGISTER: this section. Probe script and transcript below; reproduced at HEAD a2c5bd60 before any
source change in this plan.

THE CLAIM THE CLASS MADE, quoted from the builder's docblock as it stands at this tree: "INTERNAL —
a count, a retry number, a bound, a refusal code, a module constant, and the text of an error the
platform handed up. The process generated these itself; none can carry a code point a renderer
deletes unless the platform's own error text does, and that text names a path rather than a
document's bytes."

The carve-out NAMES its own exception in its second half and then excuses it. A path is exactly what
a platform error text names, and that path is composed from a directory listing's entry name — the
value section 2.1 just showed is not covered by escaping `name`.

THE ARM: `scripts/board-dashboard.ts:1431`, the substitution `(e as Error).message`, resolving to
declaration `lib.es5.d.ts#message`, class `internal`, receiver `arg:warn#1` — a PUBLISHED position.

THE ROUTE, STEP BY STEP:
  1. `resolveRepoRoot` (`scripts/board-read.ts:549`) calls `realpathSync(absolute)` on the caller's
     repository root.
  2. The platform throws `ENOENT: no such file or directory, lstat '<absolute>'`. The platform
     composed that sentence and it NAMES THE PATH, including whatever code point the directory
     entry name carries.
  3. `scripts/board-read.ts:557` quotes it into a `BoardReadError`. That site is NOT in the
     denominator, and the census's own comment says why: it "constructs an `Error` whose text some
     published position above quotes LATER — and that quotation is itself in the denominator, at the
     position where the sentence is published".
  4. The quotation IS in the denominator, at `board-dashboard.ts:1431` — and the `internal` class
     excuses it there. So one table takes the site out of scope by pointing at the other, and the
     other takes it out of scope by class. Both ends excuse it and nothing owns it.
  5. `warn` applies `sanitizeCell`, which DELETES the code point on the way to stderr.

THE MEASUREMENT (probe: spawn the committed `scripts/board-dashboard.js` against a non-existent root
whose own entry name carries U+0085):

  exit= 2
  stderr= "board-dashboard: board-read: the repository root
           /private/var/folders/.../grugops-internal-class-eJt5cn/repox does not resolve
           (ENOENT: no such file or directory, lstat
           '/private/var/folders/.../grugops-internal-class-eJt5cn/repox').
           Refusing to report a snapshot for a tree that was never read."
  stderr names `repox` (the point DELETED): true
  stderr names the SPELLED entry:           false

The refusal names `repox` TWICE and `repox` does not exist. That is F-14's defect — a sentence
misquoting the thing it names — reached through the `internal` class rather than through the `path`
class. The class-based bound is measured wrong in both of the two classes it draws, which is why
this plan deletes the question rather than redrawing the line a third time.
