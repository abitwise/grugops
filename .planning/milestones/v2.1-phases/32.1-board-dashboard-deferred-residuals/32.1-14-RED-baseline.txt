2.1  THE SOURCE-LEVEL FACT THE REPRODUCTION RESTS ON
-------------------------------------------------------------------------------------------------

scripts/loader-oracle.test-support.ts:151-155 at 152bec0c, quoted exactly:

    execFileSync(process.execPath, [scriptPath, join(root, entryRel), resultPath], {
      cwd: root,
      encoding: "utf8",

`execFileSync` with no `timeout` waits forever. The only assertion protecting the premise this
oracle rests on — `treeBefore === treeAfter` in scripts/board-readonly.test.ts — is reachable only
AFTER that call returns. So the failure mode of the guard is a HUNG worker, and a run that reports a
timeout naming nothing. A guard whose failure mode is silence is the shape this repository's ledger
records repeatedly; a hung gate is not a red gate.

-------------------------------------------------------------------------------------------------

The pre-change child shape is reproduced verbatim in a throwaway script and pointed at a script that
does not return (`setInterval(() => {}, 1000)` — what "the entry's main ran" looks like from the
outside: a live watch loop with nothing to return to). The reproduction itself is run under an

                                  "code":"ETIMEDOUT","signal":"SIGKILL","status":null}

The pre-change shape DID NOT RETURN within the bound. It had to be killed from outside; nothing in
the shape itself would ever have stopped.

A SECOND MEASURED FACT, recorded because it is not obvious: killing the intermediate process left

`execFileSync` does not merely hang the worker — when something upstream finally kills the worker,
the load it started keeps running. This is why the bound belongs on the invocation rather than on
whatever runs the suite.

  post-reproduction sweep: `pgrep -f never-returns.mjs` -> no stray children remain.

`code === "ETIMEDOUT"` and `signal === "SIGKILL"` are the two fields the consumer's arm reads, and
this run is where their spelling is measured rather than assumed.
