--- 1.0  WHERE THE CODE POINT IS PLANTED, AND WHY IT IS NOT WHERE THE PLAN SAID -------------------

The plan's action text said to create "a claimed-queue directory whose NAME carries a C1 code
point". Measurement refuses that plant, and the refusal is recorded here rather than worked around
silently:

  $ (scope premise, driven by the same reproduction harness)
  planted `.grugops/queue/claimed/task<U+0085>x/claim.md`
  queue readError codes: ["unsafe-task-name"]
  message: board-read: the claimed-stage entry `task<U+0085>x` under /private/var/.../claimed is
           not a plain path segment. [...]

`isSafeTaskName` (scripts/board-read.ts:795-799) admits only `[A-Za-z0-9._-]`, so a claimed-stage
entry carrying a C1 point never reaches `childPath` at all — it leaves by the `unsafe-task-name`
arm, which is ALREADY built through the builder and already spells the byte. The plan's literal
plant therefore reproduces nothing.

The composed path `{root}/.grugops/queue/claimed/{task}/claim.md` has exactly two variable segments:
the repository root and the task name. The task name is allowlisted. So the REPOSITORY ROOT'S OWN
DIRECTORY ENTRY NAME is the one position from which a deleted code point reaches the `no-at` and
`tampered` sentences. It is a directory entry name joined into a composed path, which is precisely
the class D-07 names. Every case below plants there, and the fourth case in the new `describe` block
asserts the `isSafeTaskName` refusal above rather than assuming it — if that allowlist is ever
widened, the case reds and the plant has to be revisited.

--- 1.2  WHAT THE THREE POINTS SAY, AND ONE PLAN PREMISE DISPROVED BY MEASUREMENT -----------------

The plan predicted "at the pre-change tree point 1 carries the byte raw and points 2 and 3 carry it
deleted". Measured, that is right about points 1 and 3 and WRONG about point 2.

  point 1  the model's own sentence   FAILS   carries the code point RAW — built outside the builder
  point 2  the rendered stderr frame  PASSES  already spelled, and not by the sentence's own doing
  point 3  the published document     FAILS   the code point is DELETED; the sentence names `repox`,
                                              a directory entry that does not exist on the tree

Point 2 passes because `scripts/board-dashboard.ts`'s `emit()` applies `spelled` a SECOND time at
the stderr chokepoint — `spelled\`${readError.message}\`` — so the raw byte the model handed up is
escaped on the way to that one channel. That is a property of the dashboard's frame, not of the
sentence: the model's own value and the JSON document both carry the defect, and a consumer that
parses the document (DASH-07's whole point) sees a path that does not exist. Recording this here
rather than restating the plan's prediction is the difference between a measurement and a citation.

The observable damage is therefore exactly F-14's, one register over: a published sentence states
`.../repox/.grugops/queue/claimed/task-no-at/claim.md` about a tree on which that path does not
exist. A reader who searches for what the document prints finds nothing; a reader who re-types it
reaches a different path.
