**Two modules whose headers outran their code now implement them: a recovering parse is a named refusal carrying its diagnostic count instead of a closure short by an unknown number of imports at exit 0, and the loader oracle's child is bounded so its failure mode is a red with a cause instead of a hung worker — with all seven of the review's information items dispositioned, four fixed and three written out as register rows with named owners.**

## Accomplishments

- **The closure module's header is now a description rather than an aspiration.** It said it "REFUSES RATHER THAN RETURNS SHORT". `ts.createSourceFile` never throws on a syntax error — it recovers and hands back a partial tree — and the walk read that tree without asking whether the parse was clean. Measured against the committed build output exactly as it stood: an unterminated block comment after the first import answered `["./a.js"]` with an empty unreadable list, at exit 0, short by `./b.js`. The diagnostic count is now read off the parse and a non-zero count is a named `ImportClosureError` carrying it.
- **A review premise was disproved by measurement, and it changed the plan's structure.** The review filed the non-literal declaration specifier as "a syntax error rather than a live shape". On this parser in `ScriptKind.JS`, `import a from foo;` and `export * from bar;` each produce **zero** parse diagnostics and an `ImportDeclaration`/`ExportDeclaration` carrying an `Identifier` specifier. That is what makes the two changes independently provable: had the premise held, the diagnostics refusal would fire first and the declaration-arm case would have been green for the other change's reason.
- **Every one of the five behavioural changes was watched failing alone.** Six mutation runs — the diagnostics refusal removed, the declaration recording removed, the bound spread removed, the guard condition disarmed, the guard unwired from the child, the realpath resolution removed — each reddening exactly one case with every sibling case green.
- **The oracle's silent failure mode is gone, and the reproduction recorded something nobody had asked for.** The pre-change child shape, pointed at a script that does not return and run under a 5000 ms bound of the harness's own, did not return — and killing the intermediate process left the non-returning **grandchild orphaned and running**. An unbounded `execFileSync` does not merely hang the worker; the load it started outlives whatever finally kills the worker. That is why the bound belongs on the invocation.
- **The registration guard is proved by running its own bytes.** The absence it refuses cannot be created on a runtime that has the function, so `ORACLE_REGISTRATION_GUARD` is exported and executed against both an absent and a present stub namespace, with a separate case asserting the shipped child is built from exactly those bytes and finds the function through a namespace import — because a *named* import of an absent export is a link-time `SyntaxError` and could never be the thing that checks.
- **Nothing was dropped.** Seven information items, seven dispositions: four fixed with evidence, one part-fixed with its register row, two carried as rows with a named owner. Every reason states a limit or a decision; none states a schedule.
