## Accomplishments

- **The second grammar is gone.** `moduleSpecifiers` parses with `ts.createSourceFile(…, ScriptKind.JS)` and walks a node set written down in the module header: import and export declarations through their module specifier, `import(x)` and `require(x)` through their first argument. A specifier's VALUE is read through `isStringLiteralLike`, so a no-substitution template resolves to what it means and an escape resolves to the character it denotes.
- **Four deletions, each with the measurement that disproved the claim that kept it.** The regular-expression arm (WR-02, F-16), `SPECIFIER_PATTERNS` (F-17), the literal recovery table (WR-03), and `scanSource` with its exported view `stripNonCode` — the last one a decision measured rather than assumed.
- **The parser never enters the shipped surface.** `createRequire(import.meta.url)` behind a memoized accessor, validated member-by-member in one place, with a named `ImportClosureError` when it cannot be acquired. The committed `scripts/js-import-closure.js` carries exactly three static imports: `node:fs`, `node:module`, `node:path`.
- **Four reproductions, measured failing before and passing after.** `32.1-06-RED-baseline.txt` § 2 records each against the pre-change committed build output; `32.1-06-GREEN-proof.txt` § 1 records the same four after.
- **A third authority now decides the closure.** The static walk, an independent parse-built closure, and Node's own resolver are asserted equal per entry in one case, with both premises floored.
- **A shipped-surface rule that is scoped by derivation.** Six non-test tracked sources under `install/` and `hooks/`; floored three ways (set non-empty, installer tree contributes, hook tree contributes); the non-test plant reds naming the file and the test-file plant does not.

## Decisions Made

- **The human answered the checkpoint `proceed`** (Task 0, `checkpoint:decision`, gate `blocking-human`). The one-way D-08 cutover was confirmed before any deletion: rewrite the extractor over a real tokenizer with a lazily acquired parser (the D-20 route), delete the regular-expression arm, the specifier pattern list and the literal recovery table with deletion notes, delete the tests written against them, keep `jsImportClosure(root, entryRel)`'s signature so all six consumers are unchanged, and re-assert the five freshness gates plus the DASH-06 read-only import guard against the new parser's output. The alternatives (`oracle-only`, `defer`) were declined. **Rationale as the checkpoint stated it:** `oracle-only` does not satisfy D-08's text — the second grammar survives, so the next counter-example is another arm, which is the class this phase exists to close; `defer` leaves five of nineteen items open with a live instance of that class.
- **`createRequire`, not `await import`.** D-20 admits either injection or a lazy load. An async dynamic import would have made `moduleSpecifiers` — and therefore `jsImportClosureFacts` and `jsImportClosure` — async, which changes all six production call sites including the one on every CI leg. `createRequire(import.meta.url)` keeps the signature exactly, and it is the in-repo precedent (the ruling at `uat-spec-integrity.ts:729-734`, the call at `:1053`). Resolution is from the MODULE's own location rather than the caller's cwd, so a gate invoked from elsewhere still finds the checkout's parser.
- **`scanSource` and `stripNonCode` both deleted, on a measurement.** RESEARCH flagged assumption A4 as an assumption to re-measure. Measured: `stripNonCode` had two code referents (its own definition and its build twin) and six referents in `board-readonly.test.ts` — one test name, four comments, one failure message — and appears in no import list in the repository. `scanSource` was module-private with two callers, both in its own file, one of them the deleted extractor.
- **The three `stripNonCode`-named cases were re-homed, not deleted.** The plan says to delete the tests written against the deleted structures. These assert properties of `moduleSpecifiers` (a specifier written only in a comment, only in a template literal, and one inside a template SUBSTITUTION that must still be SEEN) and merely named `stripNonCode` in prose. Each still decides a real property under a tokenizer, so deleting them would have traded a false claim for a real hole. The prose was corrected and the substitution case renamed, because its old name asserted the existence of a function that no longer exists.
- **`require(x)` is in the node set, and the oracle gained it too.** RESEARCH's node-set table lists it as absent from the old oracle; the plan's action names it. An oracle whose node set is narrower than its subject's reports every extra edge as a fabrication, which measures the gap between two node sets rather than the correctness of one extractor. The independence that matters is the traversal, the predicates and the value extraction — plus the third authority, Node's resolver, which shares neither code nor parser.
- **The independent oracle asks `classifySpecifier` about class.** The first draft of the parse-built closure tested `spec.startsWith("./")` inline and the suite's own rule *"this file decides no specifier's class itself — it asks the one authority"* reddened on it, naming both arms. That rule is right: a second prefix test beside `classifySpecifier` is the exact fourth-arm shape 32-31 removed. What is cross-checked in that case is the CLOSURE, not the partition.
