<objective>
Close the round: diagnose the live lane's three failures without spending a token, ask for one
informed go, and then make the phase's completion contract cover what this round found.

Three things are open. The live claude-CLI lane ran once under a human go on 2026-09-18 and returned
a red on three cases, one of which — the prod-deploy deny — touches the hard safety invariant this
project states mechanically: an agent never deploys to production without named human confirmation,
and that must be enforced by code rather than by prose. The phase honestly recorded the red and
re-homed it with a named owner rather than smoothing it over, and the verifier routed it to a human.
What nobody has done is work out WHY. The transcript says so in as many words: whether the cause is
the kit, the suite's expectation, the CLI version on this box, or this host's configuration is not
determined by the run that occurred.

That question is largely answerable on disk. The shipped hook manifest, the guard's stdout and exit
contract, the matcher's structural requirements, and the documented envelope format for the CLI
version on this box are all inspectable at zero cost. So the diagnosis comes first and the go, if it
is given, is spent on what the diagnosis could not settle.

Then the completion contract. The phase's ledger derives a nineteen-item denominator from three named
sources, and this phase's own review is not one of them — which is exactly how its findings ended up
outside the count while the phase read as complete. This plan makes that review a fourth named source,
re-derives the denominator in the tool rather than in a sentence, and records the reconciliation the
way the file already records the nineteen-versus-twenty one.

Purpose: a safety-relevant red that nobody diagnosed is worse than a red nobody found, and a
completion equality that cannot see its own review is an equality over the wrong set.
Output: one diagnosis note per live case with a named cause class and evidence, one blocking human
checkpoint naming the spend, at most one gated re-run, a fourth-source denominator the tool derives,
and every row of this round terminally dispositioned in the register.
</objective>
