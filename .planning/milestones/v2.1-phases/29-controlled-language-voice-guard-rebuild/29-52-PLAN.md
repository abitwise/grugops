<objective>
Close **CR-01** — the sole carve-out is bounded positionally and not at all by content.

`BANNED_CLAIM_EXEMPT_REGION` is the only carve-out left standing after D-53 deleted the co-occurrence
alternative, and it is pinned by two **cardinalities** only: how many occurrences it lifts, and how far it
reaches. Nothing pins its CONTENT. Both the round-6 reviewer and the round-6 verifier reproduced this
independently, on fresh `git archive HEAD` mirrors with sha256-verified gate binaries: replacing one honest
denial line inside the region with a live, disproven token-economy claim leaves `suppressed` at exactly 14
and `extent` at exactly 62, and **all seven repository gates exit 0**. The kit would ship a disproven claim
inside the section whose stated purpose is to deny claims. The wholesale form is worse: replacing the whole
61-line body with banned claims plus filler also holds both pins and `check-banned-claims` exits 0 — there,
the only thing that reds is a verbatim freeze on two paragraphs owned by a **different gate**.

The case that looks like the pin is not one. It parses components out of the run and compares them to a
tally over the **same live document**, so both sides move together; its own comment concedes the mirror's
region is degenerate by construction. It is a self-consistency check.

**This axis now carries four open residuals that are one defect wearing different clothes** — CR-01
(content unbound), `V-29-47-02` (unbounded at the bottom), `V-29-47-03` (position pinned by nothing) and
`V-29-32-01` (a closed-fence count-preserving swallow). All four exist because the carve-out is defined by
**position over a cardinality**. Six rounds of one-more-pin is what has failed here, so the fix is
structural: **require every suppressed occurrence to sit on a line inside a registry-anchored, byte-frozen
block**. A content-bound carve-out is invariant under translation and needs no bottom boundary, so it
subsumes the other three rather than adding a fifth pin beside them.

Purpose: `guard_banned_claims`'s PASS line claims the shipped kit carries no conformance, token-economy or
comprehension claim outside one named exemption region. Today that claim is false of any tree where one
line inside the region was swapped. This plan makes the sentence true.

Output: every banned-claim-bearing line inside the region frozen against a registry row; a suppression rule
that reads the freeze; four residuals subsumed; and both independently reproduced bypasses shown to red by
name.
</objective>

<decision_reconciliation>
**This changes D-48/D-53's MECHANISM, not its INTENT, and the user may overrule it here.**

D-48 concluded, and D-53 extended: *"Every axis a bare term can be paired against is an open class; the
only bounded thing in this design is the one named exemption region, and a region is POSITIONAL."* That
conclusion produced the current design — unconditional literals, no marker lists, one positional carve-out
— and it was right about the matcher. CR-01 shows it was incomplete about the carve-out: a region bounded
only in position has no bound on what is written inside it.

What this plan changes, stated plainly so it can be refused:

- **The matcher stays exactly as D-48/D-53 left it.** No lexical axis returns. No verb list, no subject
  list, no co-occurrence window, no conditional field on the literal type. The gate still enumerates WHAT
  IS BANNED and nothing about HOW IT IS SAID. Every one of D-48's forbidden weakenings stays forbidden.
- **The carve-out stays POSITIONAL.** The region is still a file, a section and a reason; a line outside
  the region is still never exempt.
- **What changes: the exempted BYTES become FROZEN.** Inside the region, a line lifts the prohibition only
  if it also sits inside a registry-anchored block, and the anchors gate already byte-compares those blocks
  against the registry. Editing a frozen line requires updating its registry row in the same commit.
- **That requirement is not new.** D-01(a) already names the claim-registry verbatim anchors as one of the
  three frozen sources, and D-04 already requires the same-commit companion edit for any change
  intersecting them, with no override tier. This plan applies an existing locked decision at the one place
  D-48/D-53 left unbound; it does not invent a policy.

**Assessed as reconcilable, not as a reversal.** If the user disagrees — if D-48/D-53's positional intent
was meant to exclude a byte freeze as well as a lexical axis — this is the decision point, and the
alternative on the table is the reviewer's cheaper complement (pinning the suppressed count PER GROUP),
which reduces the substitution class from any-group to same-group and **does not close CR-01**. That
complement is planned here as a secondary measure with that limitation stated in the source, precisely so
nobody later reads it as the fix.
</decision_reconciliation>

<standing_rules>
The house rules of this phase, encoded rather than advised. The seven that bite hardest here:

- **A green suite is not proof for a safety invariant.** Every closure claim is reproduced on a hermetic
  `git archive HEAD` mirror with a sha256-verified gate binary, ONE plant per mirror, mirror reset between
  attempts, the mirror's own premise asserted green BEFORE any plant, and the plant confirmed on disk before
  the gate runs.
- **Assert the verification harness's own premise.** This phase has produced a false harness result in six
  instances across four straight rounds, including one produced by round 6's own adversarial pass. A
  transcript whose premise was not asserted is not evidence.
- **Derive the set, assert the count.** The exempt block set comes from the registry, not from a list, and
  its cardinality is asserted two-sided.
- **Ask what BOUNDS the predicate's input.** Name which SET each predicate enumerates, what DERIVES it, and
  what asserts its COUNT. A vacuity floor catches an EMPTY denominator and never a SILENTLY SHORT one.
- **Never weaken a matcher and never reach green by deleting correct text.**
- **No silent drops.** Every residual this plan subsumes gets its closing MEASUREMENT, not a transcription;
  anything not closed gets a `V-` id, a live count, a direction and a remedy, escalated to plan 29-55.
- **Build facts (D-13).** `npm run build` then `npm run freshness` after every `.ts` edit; the committed
  `.js` twin lands in the same commit. Regression is `npx vitest run --exclude '**/scripts/e2e/**'`, never a
  bare `npm test` (that lane spawns the live claude CLI, spends tokens and can hang).
