<objective>
Build the gate that makes LANG-03 real without ever writing down a protected sentence.

The collision this phase opens with is that the Phase 28 exclusion list names 41 files and says no
text in a listed file is reworded by a style pass — and those 41 files are all 17 roles, all 19
workflows and the 4 public documents, exactly the corpus LANG-02 tells the profile to govern. Read
literally, this phase may reword nothing. Phase 28 named that limit rather than manufacturing
variance: the flag is per file, and the question LANG-02 actually faces is which sentences are
load-bearing, a granularity a per-file column cannot express.

D-01 resolves it by deriving the frozen set from three gates that already exist, and refusing a
hand-written protected-sentence file outright, because that file is the set-literal drift class this
milestone exists to eliminate. D-03 records the rejected alternative with its reason — a
permission-bearing-sentence heuristic is decidable and list-free, and it is also a strict subset of
the real predicate, which is the shape that cost this project three separate eight-round closures.
Recording it is not decoration: it is what stops a later phase re-proposing it as an optimisation.

D-05 inverts the enforcement. Rather than enumerate what is protected, the gate enumerates what
changed and requires each change to be dispositioned. One side is derived from the filesystem and the
other from git, so neither can go stale. D-04 makes the frozen intersection hard RED with no override:
the bytes may change, but no kit text changes alone — a changed anchor sentence takes its registry row
in the same commit, a changed guard literal takes the guard's literal, a changed structural section
takes its disposition row.

This gate has no close analog in the tree. Nothing here computes changed content from git and requires
per-change disposition. The git-subprocess seam has one precedent to copy exactly, and the
set-intersection half has one, but the assembled predicate is new shape. Budget it as new work.

Purpose: give every content plan from wave 5 onward a gate that says whether its rewrite touched
something load-bearing, and forces the answer into the same commit.
Output: a standalone gate wired at both ends, a disposition directory with a recorded base commit, and
the RED-before evidence proving the frozen intersection actually refuses.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git history → gate input | The diff is the entire left-hand side of the predicate. An unresolvable base or a shallow clone silently empties it. |
| derived frozen set → refusal | The right-hand side. A derivation that returns short shrinks what is protected without any visible failure. |
| disposition row → human judgement | The row records that a change was considered; whether the consideration was right is not mechanically decidable. |
