<objective>
Close **CR-01** of `29-REVIEW.md` (round 4) and the **LANG-06 failed truth** of `29-VERIFICATION.md`.
They are the same defect: `SEC_VOICE_FILES` — the one hand-maintained half of `guard_voice`'s scan set —
is pinned by CARDINALITY (`SEC_VOICE_FILE_COUNT = 2`) where MEMBERSHIP is what matters.

A one-token SUBSTITUTION of one member for any other existing `agent-factory/**.md` path leaves every
published number unchanged (`visited` 19, `expected` 19, the declared count 2, `secVoicePinMismatch`
silent, the path-shape assertion satisfied) and drops a real security surface out of `guard_voice`
entirely, with the gate at exit 0. It was reproduced end to end, independently, by BOTH the round-4
reviewer and the round-4 verifier on hermetic mirrors.

The declaration at `check-foundation-guards.ts:1990-2001` says the remedy applied here is "the one
already used for the role half: DECLARE the number, then compare the DERIVED set against it." **There is
no derived set for this half and none is compared.** That sentence is the claim-wider-than-its-assertion
class, written inside the pin built to prevent it.

Purpose: per D-01 a hand-written list is the set-literal-drift class this milestone exists to delete, and
per D-04 a hand-maintained set is only legitimate when it fails CLOSED against a same-commit companion.
This plan gives the half both: a declared two-sided roster AND a derived per-member property, so a
substitution fails a NAME comparison and a PROPERTY floor, not merely a count.

Output: a membership pin that reds on substitution, a falsifiability probe carrying the substitution arm
beside the existing add/remove arms, and a declaration comment that describes what ships.
</objective>
