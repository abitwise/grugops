<objective>
Build the one authority CR-01's fix needs, and prove it changes nothing while it exists alone.

The round-6 review's stronger fix for CR-01 is to **require every suppressed occurrence to sit on a line
inside a registry-anchored, byte-frozen block**, extending the mechanism `check-claim-anchors` already runs
over `C-28-039` and `C-28-042`. That fix cannot be written honestly until the mechanism exists in one
place. Today it is spread across `scripts/check-claim-anchors.ts`: the anchor grammar is declared there,
the line assembly is declared there, the block's extent is computed inline from the registry row's line
count, and the byte comparison is performed inline. If plan 29-52 asked the same questions from
`scripts/check-banned-claims.ts`, this repository would acquire a **second grammar over the same bytes** —
which is the exact defect LANG-07 names, and the one this milestone has closed three times at eight rounds
each.

So this plan lands the authority first, in `scripts/audit-model.ts` — the library both gates already trust
for the registry, and a library rather than a gate, so no importer inherits another module's refusal
channel (the WR-05 defect plan 29-49 just closed one seam over).

The round's own probe applies to this plan directly: **when you unify two things into one authority, that
authority's SCOPE becomes a new degree of freedom.** Phase 29 has already paid for it once, when a
section-anchored fence reader searching to end-of-file adopted an unrelated later block. So the authority's
reach is pinned here, at its declaration, with its bounds named and its edges tested — before any consumer
spends it.

Purpose: plan 29-52 binds the sole safety carve-out by content. It must do that by asking a question this
repository already answers in one place, not by writing a second answer next to the first.

Output: one anchor grammar, one line assembly, one block-extent-and-byte-identity function, a gate that
declares none of them, and six mutation-proven refusals showing the verdict did not move.
</objective>

<standing_rules>
The house rules of this phase, encoded rather than advised. The six that bite hardest here:

- **One format-aware authority per predicate.** The structural fix that closed Phase 22, Phase 25 and Phase
  27 after eight rounds each — never another heuristic arm, never a second grammar over the same bytes.
- **When you unify, pin the scope.** A unified authority's reach is a new degree of freedom. Name what
  bounds it, and test its edges before a consumer spends it.
- **Ask what BOUNDS the predicate's input.** For every predicate here, name which SET it enumerates, what
  DERIVES that set, and what asserts the set's COUNT. A vacuity floor catches an EMPTY denominator and never
  a SILENTLY SHORT one.
- **RED first, and by mutation for a refactor.** A refactor's equivalence claim is worthless from a green
  suite: the cases that pass after are the cases that passed before. Mutate, on both builds, and diff.
- **Never weaken a comparison to accommodate a case.** The claim comparison is EXACT — no trimming, no
  whitespace collapse, no line-ending rewrite, no case folding. A legitimate divergence gets a named
  exemption.
- **Build facts (D-13).** `npm run build` then `npm run freshness` after every `.ts` edit; the committed
  `.js` twin lands in the same commit. Regression is `npx vitest run --exclude '**/scripts/e2e/**'`, never a
  bare `npm test` (that lane spawns the live claude CLI, spends tokens and can hang).
</standing_rules>
