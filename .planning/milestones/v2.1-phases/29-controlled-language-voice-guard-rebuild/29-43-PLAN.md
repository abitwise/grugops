<objective>
Close **CR-01** — the banned-claim gate publishes a prohibition over "the public documents" while scanning a
set from which one public document was already subtracted, by another gate, for another gate's reason.

`check-banned-claims.ts` imports `publicDocsScan()` with an explicit and correct argument: deriving root
markdown a second time would be a second membership rule over one corpus. The consequence is the defect.
`publicDocsScan()` does not answer *what is a public document*; it answers *what is a public document that
the dead-vocabulary check applies to*. `check-public-docs-vocabulary.ts` classifies `CHANGELOG.md` as a
root public document and then subtracts it — and that exemption's own bound paragraph states, in terms,
that it "does not exempt `CHANGELOG.md` from any other gate." It does, by construction.

This is live, not theoretical. `CHANGELOG.md:30` and `:68` carry `token economy` / `token-economy` — the
disproven claim this gate's founding D-44 transcript calls "the drift this gate exists for" — unscanned.
A planted D-44 conformance claim in `CHANGELOG.md` exits 0 with the file never named, while the identical
bytes in `README.md` exit 1 and are named twice.

Purpose: a prohibition whose published scope is wider than the mechanism behind it is this round's whole
subject, appearing here at the SCAN SET rather than at the matcher. The fix is not to weaken anything and
not to re-derive anything twice: it is to make the two questions **separately askable and separately
named**, so a consumer states which one it wants.

Output: `publicDocsCorpus()` exported pre-exemption; the banned-claim gate consuming it; the document
count moved in the same commit with the entrant named; the two `CHANGELOG.md` sentences rewritten; a
permanent case that would have caught this; and every remaining unscanned class dispositioned by name.
</objective>
