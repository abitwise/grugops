<objective>
Author the writing profile the whole phase applies, and make LANG-04's "nowhere in the kit is
conformance claimed" mechanical instead of disciplinary.

LANG-01 wants a grugops-authored profile derived from ASD-STE100, never a copy of it. The IP line is
not inferred: the official Issue 9 PDF sets its copy-text permission bit to disallowed, which is the
publisher's own machine-readable statement of intent, and ASD and STEMG publish directly that they do
not endorse or certify any software tool and that no provider may claim approval. So the profile
states derivation, authors its own rules in its own words, and ships a derived project Technical Names
and Verbs set — which the standard's own specification sanctions as its documented extension point
for company and project terms, not as a deviation.

D-16 makes the surface split part of the claim rather than an implication. Three of LANG-02's six
named surfaces are runtime artifacts that do not exist at build time, so the guard is a build-time
gate over kit files and the runtime surfaces carry the profile as instruction. Claiming the guard
governs a note an agent writes at runtime would be exactly the overstated-claim class Phase 28
registered thirty-eight of. D-17's rejected alternative — a style check inside the sanctioned
note-write path — is recorded with its reason so a later phase does not re-propose it.

D-29 turns the conformance prohibition into a gate, because the voice guard is this project's own
proof of what discipline without mechanism does over a full milestone. D-44 is why that gate is not
vacuous: the standard's name appears in zero kit files today, so a check landed against this tree
would go GREEN having never been watched fail. The sequence is therefore author the profile
containing a deliberate draft conformance sentence, land the gate RED naming that line, remove the
sentence to GREEN, and keep a planted hermetic fixture so the gate stays provably non-vacuous after
the tree can never again contain the claim. Step four is the durable half.

D-11 and D-34 are the paperwork this plan owes. The placeholder guard name is itself the claim
LANG-04 forbids, and it survives in three live planning documents; the rename lands here so the name
and the requirement stop disagreeing. The token-count claim is currently asserted at three different
confidence levels across three documents while research located no evidence in either direction, and
its stated reasoning targets the fenced caveman blocks, which LANG-02 explicitly excludes from the
profile. D-34 softens it to UNKNOWN - verify in both directions and keeps every measured half.

D-33 registers the profile's own falsifiable claims, because a document asserting what it achieves is
exactly the class the claim registry exists to hold, and Phase 30's claim-dropping mechanism needs
them to carry ids.

Purpose: give the corpus-rewrite plans a written profile to apply, and a gate that makes the
conformance prohibition falsifiable.
Output: the profile document, a standalone gate wired at both ends, registry rows, and three
corrected planning documents.
</objective>
