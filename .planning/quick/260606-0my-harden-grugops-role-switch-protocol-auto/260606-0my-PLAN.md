<objective>
Harden the grugops kit against two failures surfaced by the DOG-02 live Claude Code dogfood:

1. **Role-switch with no mechanism.** Every entry point says "activate the right specialist role(s)" with no procedure, so the Orchestrator silently morphs between roles inside one context window and earlier-role scratch context bleeds into later roles. Fix = a single-source 5-step **role-switch protocol** that keeps ONE context window everywhere (no sub-agent spawning) and makes the handoff packet a role's sole memory of earlier roles. The now-vestigial `Agent` tool is REMOVED from every skill/agent.

2. **No artifact is ever committed.** No workflow issues `git commit`, so tickets/board/trace/metrics accumulate uncommitted and the auditable trail the project promises never gets recorded. Fix = a single-source **commit convention** (branch guard + message format + humans-hold-merge note) and a `## Commit` step in every plans-mutating workflow. The validator gains structural checks for both fixes and the self-test stays honestly fail-capable.

Purpose: make grugops's two core promises — clean role boundaries and an auditable requirement->code->test trail — actually hold when the kit runs live.
Output: 2 new single-source files, 16 edited workflow/role files, 15 skill/agent edits (Agent removal), an extended validator, an extended self-test with a new BAD fixture.

LOCKED DECISIONS (do not revisit): harden sequential role-load (one window, no Agent spawning, Agent is removed as vestigial); auto-commit to a working branch only (never a protected branch); single-source (each rule lives in ONE file, everything else references by path); leave examples/03-ticket-to-pr.md's real capture history honest; humans hold merge and deploy.

NOTE — branch: work is ALREADY on working branch `grugops/quick-harden-role-switch-autocommit`. Do NOT create another branch. Commit on this branch.
</objective>
